# テスト概要

この文書は、現在の `godot-dotnet-mcp` test system の全体構造、coverage、既知の境界をまとめます。

test system は現在、CI gate surface を 1 つに絞っています。

1. `Godot Headless Harness`

---

## 現在の状態

### 実装済みのもの

- `tests/godot_plugin_harness_fixture/tests/` には、plugin runtime、tool loading、routing behavior を覆う複数の headless case があります。
- plugin は現在、HTTP routing、JSON-RPC、editor lifecycle、runtime fallback、runtime replies、runtime control、user tools、Config workflow、Dock、tool loader、runtime bridge に対する安定した testing seam を持っています。
- `validate-plugin.yml` は plugin harness を main CI gate として使い、required subset だけを hard-enforce します。通常の headless required case は batch で走り、editor probe case は isolated のままです。

### すでに確認済みの結果

- Plugin harness required subset: 通常 headless case は batch で通過し、editor probe case は isolated で通過する
- Plugin headless harness は leak warning なしで終了する。ただし editor probe case は harness により許可されます

---

## 現在の構造判断

### すでに妥当な点

- test は single smoke script から独立した harness layer へ移り、validation が 1 つの entry point に積み上がらなくなりました。
- plugin test は runtime helper と index helper を fake collaborator で検証しており、すべての test が real runtime に依存するわけではありません。
- Config page runtime chain は serializer、inspection、file transaction、launcher adapter contract を含むようになっています。

### 現在の境界

#### 1. Plugin contract test は private method name に依存しなくなったが、seam はまだ締められる

`http_server_contract_test.gd` と `runtime_bridge_contract_test.gd` は public entry point を通るようになり、underscore method に直接依存しなくなりました。これにより、内部 rename が先に test を壊す risk はかなり減りました。

#### 2. Environment-dependent test は CI で完全 hard gate にはなっていない

`validate-plugin.yml` は先に Godot 4.6 を download し、その後 plugin harness を走らせます。つまり plugin test layer は、optional fast check ではなく、すでに強い CI gate です。

## 設計原則

- test capability は first-class structure concern として扱う
- private implementation detail ではなく、外部 behavior に対する stable seam test を優先する
- large file は先に split してから変更する。test にも同じ rule を適用する
- public tool behavior、UI structure、lifecycle semantics、workflow behavior が変わる場合、影響する contract test を同じ batch で更新する
- review が test や docs の古い structure reference を見つけたら、repair item として扱う
- environment-dependent case は gate policy を別に宣言し、fast-check layer と混ぜない

---

## 結論

test system は安定した governance state に入りました。現在の focus は、harness test、fixture cleanup、testing seam を明確に分離し続けることです。
