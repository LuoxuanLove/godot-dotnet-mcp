# 設定と永続化

この文書は、プラグインが使う設定 path、永続化 file 形式、import / export の制約をまとめます。

---

## 永続化 path

| path | type | 役割 |
|---|---|---|
| `user://godot_dotnet_mcp/settings.json` | JSON | plugin setting |
| `user://godot_dotnet_mcp/profiles/*.json` | JSON | custom tool profile |
| `user://godot_dotnet_mcp/captures/editor/` | directory | editor 全体 screenshot の default directory。root-level `user://file.png` を渡すとここに収束する |
| `user://godot_dotnet_mcp/captures/editor_controls/` | directory | control screenshot と `activate_ui` 付き screenshot の default directory。root-level `user://file.png` を渡すとここに収束する |
| `user://godot_dotnet_mcp/runtime/captures/<session_id>/` | directory | runtime screenshot と低頻度 frame sequence の default session temporary artifact。`capture_dir` を渡すと指定 directory に変えられる |
| `user://godot_dotnet_mcp/runtime/events.json` | JSON | runtime bridge fallback event cache |
| `user://godot_dotnet_mcp/logs/user_tool_audit.log` | log | User Tool audit log |
| ユーザー指定 path | JSON | `plugin_developer` が使う tool config の import / export |

## plugin setting file

path。

```text
user://godot_dotnet_mcp/settings.json
```

主な field。

| field | 説明 |
|---|---|
| `port` | 内蔵 server の port |
| `host` | listen address |
| `auto_start` | 自動起動するか |
| `debug_mode` | debug log を出すか |
| `log_level` | log level |
| `permission_level` | 現在の permission level |
| `disabled_tools` | 無効化した tool の full name list |
| `tool_profile_id` | 現在選ばれている profile |
| `language` | 現在の language |
| `show_user_tools` | Tools page に User category を出すか |
| `collapsed_categories` | 今折りたたんでいる category list |
| `collapsed_domains` | 今折りたたんでいる domain list |
| `collapsed_system_tools` | Tools page で既定で折りたたむ system tool 名の list。公開 builtin tool 名を上書きする |

足りない field は読み込み時に `PluginRuntimeState.build_default_settings()` で補います。

## cache と cleanup

plugin は起動時に `user://` を勝手に消しません。まだ必要な検証 screenshot や diagnostic file を誤って消さないためです。古い version の root-level cache を整理したいときは、まず次を呼びます。

```json
{"action": "cleanup_legacy_cache", "dry_run": true}
```

今の screenshot cache を一覧したいときは `system_userdata_maintenance(action=list_capture_cache)` を使います。`captures/editor/`、`captures/editor_controls/`、`runtime/captures/` の cache file を消したいときは、まず `system_userdata_maintenance(action=cleanup_capture_cache, dry_run=true)` で予行し、そのあと `dry_run=false` にします。今の screenshot cache cleanup は symlink、Windows junction、reparse point を飛ばし、結果の `skipped_links` にそれらを返します。

legacy 候補を確認したあとで、明示的に `system_userdata_maintenance(action=cleanup_legacy_cache, dry_run=false)` を呼びます。この cleanup 入口は旧 runtime event、User Tool audit log、profile file を移し、旧 version で `user://` の root に散らばった MCP temporary screenshot を消します。

現在の形式。

```json
{
	"name": "My Profile",
	"disabled_tools": [
		"scene_scene_run",
		"plugin_evolution_plugin_evolution_delete_user_tool"
	]
}
```

説明。

- file name は profile id と同じとは限りません。profile id は `custom:<slug>` です
- `disabled_tools` は string array でなければなりません
- profile を rename するときは、新しい file を書いてから古い file を消します

## tool config import / export file

`plugin_developer_export_config` / `plugin_developer_import_config` が使います。

現在の形式。

```json
{
	"format_version": 1,
	"profile_id": "default",
	"disabled_tools": [
		"scene_scene_run"
	]
}
```

検証規則。

- `profile_id` は空にできない
- `disabled_tools` は string array でなければならない
- array 内の要素は空文字にできない

import が成功しても file format はそのまま変えません。structured data に読み直してから plugin state に渡します。

## client config の書き込み方針

desktop client の config 書き込みは `ClientConfigService.write_config_file()` が担当します。

方針。

1. まず UI で見えている JSON text を parse する
2. target file があれば、既存の JSON を読んで parse する
3. `mcpServers` node だけを触る
4. `godot-mcp` の項目だけを更新し、ほかの server は消さない
5. directory がなければ再帰的に作る

つまり、plugin の書き込みは「最小 merge」であって、「全 file を template で上書き」ではありません。

- `user`
- `project`

scope 切替は生成される command text だけに効き、ほかの setting には影響しません。

## HTTP CORS security 設定

内蔵 HTTP MCP service は既定で wildcard CORS を有効にせず、すべての response に `Access-Control-Allow-Origin: *` を書きません。`Origin` のない local CLI / desktop MCP client は `http://127.0.0.1:<port>/mcp` にそのまま繋げます。`Origin` 付きの browser request は、allowlist に精密一致しなければなりません。

allowlist は環境変数で設定します。

```text
GODOT_DOTNET_MCP_ALLOWED_CORS_ORIGINS=http://localhost:5173,http://127.0.0.1:5173
```

規則。

- 複数 origin は英語の comma か semicolon で区切る
- 完全一致だけを使い、suffix、prefix、wildcard の一致はしない
- `Origin: null` と allowlist 外の origin は拒否する
- Host 検査は既定で loopback と現在の listen host を許可する。`GODOT_DOTNET_MCP_SERVER_HOST` か setting file で非既定 host に変えたら、CLI / desktop client config もその host にそのまま繋ぐ
- CORS は browser の cross-origin read だけを制御し、認証機構ではない。local HTTP authentication token は将来の別の hardening 項目です

## client install detection cache

client install detection は `ClientInstallDetectionService` が memory 内で短期 cache を持ちます。

- cache TTL: `5000ms`
- cache の中身: client executable path、config entry state、runtime running state
- cache は `user://` へ書きません

今の cache invalidation 入口。

- Config page で client path を手動選択またはクリアしたとき
- Config の write / delete が終わったとき
- Dock が Config page に切り替わったとき

つまり client detection は永続化設定そのものではなく、runtime projection state です。

---

## localization resource

language resource は `user://` に書かず、直接次から来ます。

- `localization/locale_*.gd`

今の language switch 方針。

- setting file にユーザー選択 language を記録する
- plugin 起動時にその language を復元する
- すべての UI text は `LocalizationService` で取る

---

## runtime bridge の永続化に関する制約

runtime bridge は Autoload として project に入ります。

- 名前: `MCPRuntimeBridge`
- path: `res://addons/godot_dotnet_mcp/plugin/runtime/mcp_runtime_bridge.gd`

これは Godot project settings に書き込むもので、plugin 自身の `user://` JSON ではありません。

## よくある調査点

- scene の margin を変えたのに反映しない: まず、その page tab script が runtime でその property を上書きしていないか確認する
- profile import が失敗する: `profile_id` が空でないか、`disabled_tools` が string array かを先に見る
- client への一括書き込みが失敗する: target directory が書き込み可能か、既存 JSON が parse できるかを先に見る
- language を切り替えたら key がそのまま見える: 対象 `locale_*.gd` に key が欠けていないかを先に見る
