# ディレクトリツリーと file の役割

この文書は、`addons/godot_dotnet_mcp` の主な file 構成と責務分担を、directory tree の見方で説明します。maintainer が実装入口をすぐ見つけられるようにするためです。

---

## トップレベル directory

```text
addons/godot_dotnet_mcp
├─ custom_tools/
├─ docs/
├─ localization/
├─ plugin/
├─ release/
├─ tools/
├─ ui/
├─ plugin.cfg
├─ plugin.gd
└─ README.md
```

---

## トップレベル file

| path | 役割 |
|---|---|
| `plugin.gd` | plugin 入口、ライフサイクル総協調、安定 bridge 入口、最上位 Dock 呼び出し入口 |
| `plugin.cfg` | Godot plugin の宣言と version 情報 |
| `README.md` | 外向けの使用と接続の説明 |
| `docs/en/CHANGELOG.md` / localized changelog entry points | repository 全体の version 増分記録と多言語入口。plugin package tree の一部ではない |
| `.gitignore` | `.backup/` など runtime artifact を含む ignore rule |

## `docs/`

public docs は locale ごとに整理され、各 locale は同じ tree shape を保ちます。

- `インターフェース/`
- `テスト/`
- `プロセス/`
- `付録/`

文書も project の一部なので、code とそろえて保守します。

## `localization/`

### 主要 file

| path | 役割 |
|---|---|
| `localization_service.gd` | language dictionary の装着、現在 language の切り替え、text lookup |
| `locale_en.gd` | 英語 baseline dictionary |
| `locale_zh_cn.gd` | 簡体字中国語 |
| `locale_zh_tw.gd` | 繁体字中国語 |
| `locale_ja.gd` | 日本語 |

| path | 役割 |
|---|---|
| `plugin_runtime_coordinator.gd` | plugin runtime 協力者。user tool watch、runtime bridge autoload、editor debugger bridge、local endpoint reachability の編成を担当する。watcher の外部 refresh は action router の明示 callback から入る |

## `tools/`

### ルート層

| path | 役割 |
|---|---|
| `tool_registry.gd` | builtin executor 登録の事実源。category、domain_key、script path、hot-reload metadata を定義する |
| `tool_manifest.gd` | tool directory access layer。`MCPToolManifest` を安定入口として保ち、domain / category metadata を出す |
| `base_tools.gd` | 共有基礎 helper |
| `mcp_debug_buffer.gd` | log buffer |
| `mcp_file_utils.gd` / `mcp_json_utils.gd` / `mcp_node_utils.gd` / `mcp_type_utils.gd` | 通用 helper |
| `mcp_script_parser.gd` | script parse helper |
| `*_tools.gd` | 共有 root-level script だけが残る。builtin tool domain の正式入口はすべて `tools/<category>/executor.gd` |

### `tools/core/`

| path | 役割 |
|---|---|
| `tool_loader.gd` | tool platform facade。対外 public API と最上位協調入口 |
| `tool_lsp_diagnostics_adapter.gd` | loader-owned GDScript LSP diagnostics の lifecycle、runtime bridge binding、debug snapshot |

各 tool domain directory には普通 `executor.gd` があります。正式 builtin load chain は、`tools/tool_registry.gd` に登録された category に従います。

### `tools/system/`

system domain はほかより複雑です。今は executor、impl file、project/script の子 directory に分かれています。

| file | 責務 |
|---|---|
| `executor.gd` | scheduler。system subdomain executor を初期化し、`custom_tools/` を scan して読み込み、`execute` と `execute_async` を routing する |
| `atomic_bridge.gd` | atomic bridge。`call_atomic(executor_name, tool_name, args)` で下位 executor を動的に読み込む。`custom_tools/` を除いて `res://addons/godot_dotnet_mcp/` の変更を止める write protection を持つ |
| `impl_editor.gd` | `system_editor_control` を実装。main screen の切替、editor screenshot、control enumerate、coordinate mapping、control の local click、popup interaction をまとめる |
| `impl_runtime.gd` | `runtime_control` と、統一 runtime I/O 入口 `runtime_step(action=step|capture|input)` を実装する |
| `impl_scene.gd` | `scene_validate`、`scene_analyze`、`scene_patch` を実装する |
| `impl_index.gd` | internal index cache、`project_symbol_search`、`scene_dependency_graph` を実装する |
| `impl_project.gd` | `project_state`、`editor_state`、`project_configure`、`project_run(action=run|stop)`、`runtime_diagnose` を実装する |
| `impl_script.gd` | `bindings_audit`、`script_analyze`、`script_patch` を実装する |

## `ui/`

| path | 役割 |
|---|---|
| `mcp_dock.tscn` / `mcp_dock.gd` | Dock root scene と controller |
| `server_panel.tscn` / `server_tab.gd` | Server tab の主 controller。投影の書き戻し、layout、signal を担当する |
| `server_tab_model_projection.gd` | Server tab の pure projection 協力者。overview、自診断、option model 生成を担当する |
| `tools_tab.tscn` / `tools_tab.gd` | Tools tab scene と主 controller。TreeItem rendering、tree interaction coordination、context menu、selection、search、preview、collapse state の戻り flow をまとめている |
| `config_panel.tscn` / `config_tab.gd` | Config tab |

今の UI は scene ベースで、`plugin.gd` はもう Dock 全体を動的に組み立てません。

---

## `custom_tools/`

これは User tool directory です。普通は次のような内容が入ります。

- user script
- self-evolution scaffold の出力
- 削除前の backup directory `.backup/`

これは runtime で変わる領域なので、builtin tool domain と混ぜないでください。

---

## `release/`

外向け release に関する内容を置きます。plugin runtime wiring には関わりません。

---

## 普通の feature work ではあまり読まなくてよい file

### `tests/`

- `godot_plugin_harness/` と `godot_plugin_harness_fixture/` がある
- plugin headless harness と contract test の実行基盤が入る

### `.github/workflows/`

- `dotnet-build`、`validate-plugin`、`publish-release`、`publish-plugin`、`draft-release-notes` などの CI / release workflow がある
- workflow 名が変わったら、CI と文書の説明もそろえる必要がある
