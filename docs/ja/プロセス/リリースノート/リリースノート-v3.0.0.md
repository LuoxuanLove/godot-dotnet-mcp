## 🧩 Godot .NET MCP v3.0.0: Companion Sessions

Godot .NET MCP v3.0.0 は、optional Companion direction を project-scoped .NET contract layer から開始します。最初の要素は、editor が開いていない時にも static project analysis を使えること、そして matching Godot editor bridge が online になった後だけ editor-live automation を使えることを定義します。

### ✨ Live 状態を装わない static analysis

Companion contract は static/headless capabilities と live editor capabilities を分離します。Project sessions は C# と resource-analysis 系の work を公開できますが、editor bridge が接続されるまでは selected node、Inspector、Dock、screenshot、runtime validation state を明確に公開しません。

static analyzer はこの layer 向けに read-only project inventory を生成します。project root が Godot project か、どの `.csproj` files が存在するか、plugin directory が installed か、そして editor bridge が online でない間に editor-live capabilities が利用できない理由を示します。

project XML から unevaluated .NET workspace graph も記録します。SDK names、target frameworks、package references、project references、compile include/remove items を扱い、restore、build、MSBuild condition evaluation なしで初期の C# structure insight を得られます。

Static resource analysis は text `.tscn` / `.tres` files を reference graph として index します。External resources、sub-resources、`uid://` markers、`res://` preload/load usages、missing targets、project-boundary warnings、unsupported binary `.res` files を、editor で project を load せずに記録します。

この graph はそれらの signal を厳格に保ちます。`preload()` と `load()` は別々に分類され、壊れた external-resource fallback path は報告され、symlink や junction 型 reparse point を通る `res://` reference は通常の project-local file として扱わず diagnostic として残します。

### 🔐 Project-scoped sessions

Tool calls は `project_id` と `session_id` の両方を持つ必要があり、broker は別 project への session reuse を拒否します。これにより multi-project orchestration を追加する前に、v3.0 line の isolation boundary が明確になります。

Project sessions は lifecycle metadata も持つようになりました。Issued time、last-used time、lease expiry、stopped state を記録し、broker は active lease の renewal、明示的な session stop、stale session id の rejection を行えます。これにより leaked id が broker lifetime 全体で有効なまま残ることを避けます。

Broker は新しい session を開く前に expired sessions も prune し、project ごとおよび broker 全体の active session count に上限を設けます。これにより early v3 session model は long-running companion process になる前から lifetime と capacity boundary を明確にします。

Bridge upgrade contract は editor-side handshake states を記録します。Project session が editor-live になるには、bridge が同じ project で online、compatible plugin version を報告し、空でない `editor_session_id` を提供する必要があります。

Companion contract はこの boundary を code でも enforcement します。Missing、malformed、古い major、新しい major、または explicit version-mismatch の bridge version は static/headless のままとなり、editor-live capabilities を unlock しません。

Bridge version contract は JSON status schema と runtime compatibility parser の両方で、同じ optional `v` prefix と prerelease/build metadata rule を受け入れます。そのため compatible online bridge payload は一貫して判定されます。

### ✅ Compatibility and Upgrade Notes

この段階の Companion layer は contract library です。background process、port、Godot launch は開始せず、既存の editor-native plugin startup behavior も変更しません。Broker manifest はこの約束を explicit boundary として記録し、broker startup、loopback HTTP transport、project registration、editor launch はすべて明示的な user または client action を必要とします。
