## 🧩 Godot .NET MCP v2.0.0: Protocol Refactor Draft

これは unreleased v2.0.0 protocol refactor line の release note draft source です。現在 changelog の `Unreleased` に置かれている user-visible changes を要約します。正式に publish されるまでは release announcement ではありません。

v2.0.0 は大規模な protocol と internal service の refactor であり、見た目だけの cleanup ではありません。目的は Godot .NET MCP を first-class MCP 2025-11-25 server に近づけることです。passive context は Resources へ、再利用できる workflow planning は Prompts へ、Tools は actions と computed results に集中し、editor Dock は MCP clients が受け取るものと同じ metadata を preview します。これにより clients は推測で discovery する必要が減り、大量の legacy helper tools を呼ばずに済み、plugin はより小さく、明確で、強く検証された public surface を保ちながら、複雑な internals をその背後に置けます。

### ✨ Protocol-First MCP Surface

default MCP protocol target は 2025-11-25 に移ります。`initialize` は v2.0 server description と protocol baseline を advertise し、public tool names は invalid public names を防ぐ guard を通り、public metadata の default schema dialect は JSON Schema 2020-12 になります。

public surface は MCP の役割に合わせて再編されます。

- Resources は guide text、project/editor state、editor logs、activity views、tool catalogs などの passive context を公開します。
- Prompts は workflow orientation を保持し、clients が passive help tool を呼ばずに structured planning を取得できるようにします。
- Tools は actions、mutations、captures、diagnostics、computed workflow results に集中します。

legacy discovery-style public tools は primary entry point ではなくなります。compatibility が残る場合も、retired entries は Resources、Prompts、canonical action tools への explicit replacement guidance を返します。

### 🌊 Streamable HTTP and Stdio

default endpoint は `http://127.0.0.1:3000/mcp` のままですが、endpoint は v2.0 Streamable HTTP shape に沿います。protocol/session headers、JSON/SSE `Accept` negotiation、Origin/CORS checks、GET SSE streams、resumable event history、finite POST SSE responses、heartbeat events、queued server-to-client delivery、`DELETE /mcp` session termination を含みます。

Stdio は current MCP clients 向けに newline-delimited JSON-RPC を default にします。legacy `Content-Length` framing は explicit compatibility mode としてのみ残るため、古い local launchers を壊さずに default transport を新しい方向へ進めます。

Transport validation も強化されます。HTTP と stdio は malformed requests、response envelopes、disabled tools、duplicate/conflicting HTTP body headers、session validation について deterministic な JSON-RPC envelope behavior を共有します。

### 🧭 Resource and Prompt UI

Dock は first-class Resources と Prompts tabs を得ます。Users は protocol catalog counts、resource / prompt IDs の copy、resource previews、prompt argument inputs、generated prompt messages の preview、bounded icon rendering を確認できます。

Tools tab も shared catalog fact path へ移ります。Titles、icons、annotations、input schemas、output schemas、previews、search、schema copy actions、visible tool families は separate private UI catalog model ではなく shared protocol metadata から render されます。

これにより Dock は MCP server surface の preview になり、別の解釈を持つ parallel UI ではなくなります。client-visible metadata が変われば、UI も同じ facts を示すことが期待されます。

### 🧠 C# Semantic Runtime

C# semantic tooling は installation contract の一部です。Asset Library と prepared addon installs は framework-dependent Roslyn runtime files を含み、machine に .NET 8 runtime がある場合に semantic read / patch workflows を installation 後も使えるようにします。

この bundle は host project compile surface から隔離されています。shipped addon は user projects に plugin Roslyn や bridge source files の compile を求めないため、dependency conflicts を減らしつつ semantic C# capabilities を維持します。

Clean install validation はこの contract の両側を検証します。exported addon installs は plugin bridge/Roslyn source files を除外し、framework-dependent Roslyn runtime files が local `dotnet` host から利用可能であることも証明する必要があります。

### 🛠️ Tooling, Catalogs, and Compatibility

`tools/list` は input schema、output schema、annotations、JSON Schema 2020-12 metadata を持つ flat callable tool list を返します。Tree/group presentation data は catalog resources と shared Dock presentation snapshots に移ります。

Catalog snapshots、catalog resources、`/api/tools`、Dock model metadata、Tools tab previews、search、schema-copy paths は `ToolCatalogManifest` と `ToolCatalogSnapshotService` を shared catalog fact path として使います。これにより client discovery、HTTP diagnostics、editor UI previews の drift を減らします。

v2.0 line は多くの large root domain implementations を focused executors に分割し、compatibility が必要な場所では public facades を残します。audio、animation、signal、TileMap、UI、filesystem、node、project、resource、scene、group、geometry、material、lighting、navigation、particle、physics、shader、debug、editor domains はより小さな implementation units へ移ります。

### ✅ Compatibility and Validation

この draft は feature text だけでなく refactor guardrails も含みます。Validation は public tool removals、root monolith closure、catalog facts、optional capability advertisement、changelog structure、release-note draft wording、Roslyn runtime bundle shape、clean Asset Library installs、safe bridge writes、MCP 2025-11-25 conformance contracts を対象にします。

Compatibility は明示的です。older discovery calls と legacy transports は compatibility paths として document され、default client guidance は Resources、Prompts、canonical Tools、Streamable HTTP、newline stdio を指します。

### 📦 Upgrade Notes

- Existing clients は legacy public discovery tools より `resources/list`、`resources/read`、`resources/templates/list`、`prompts/list`、`prompts/get`、canonical action tools を優先してください。
- HTTP clients は `MCP-Protocol-Version: 2025-11-25` を送り、`Mcp-Session-Id` を扱い、`Accept: application/json, text/event-stream` を advertise してください。
- Stdio launchers は明示的に legacy `Content-Length` compatibility mode を選ぶ場合を除き、newline-delimited JSON-RPC を使ってください。
- C# semantic workflows は host project 内で plugin Roslyn source を compile するのではなく、shipped framework-dependent Roslyn runtime files に依存し、.NET 8 runtime を必要とします。
- Antigravity users は Config tab で app の検出と起動、Godot MCP configuration の copy、`.gemini/config/mcp_config.json` への `godot-mcp` entry の write / remove を利用できます。
