## 🧭 Godot .NET MCP v1.3.0: Semantic Editor Automation and Evidence

Godot .NET MCP v1.3.0 は、editor-facing tool の集合を、より一貫した automation layer に進める release です。Agent は relevant editor surface を見つけ、raw control より semantic workflow を優先し、guarded high-level task で value を read / change し、result を verify し、実際に観測した対象を説明する evidence を添えられます。

### 🧭 Semantic Editor Control

v1.3.0 の core design direction は明確です。semantic workflow を最優先し、control-level operation を次に使い、mouse / coordinate fallback は最後に使います。settings workflow、Inspector property task、menu selection、tab navigation、tree selection、popup button、focus、text edit、numeric value edit が使える場面で、Agent が screen click を default path にしないための方針です。

`system_editor_control(action="wait_for_ui")` は、client が次の automation step に進む前に editor state を bounded に待てるようにします。control existence、visibility、text match、enabled / disabled state を poll し、matched UI evidence または最後に観測した state を含む timeout payload を返します。

pointer behavior が必要な workflow でも、click fallback は診断しやすくなりました。`click_control` と `right_click_control` は input-dispatch metadata と Button-like target observation を返し、before/after state、signal count、mouse input が delivery されたが activation evidence がない場合の hint を示します。

### ⚙️ Trusted Settings Workflows

`system_settings_dialog` は、この release で最も大きい workflow consolidation です。Project Settings と Editor Settings を loose coordinate や raw control list ではなく task surface として扱います。client は surface を open し、表示を待ち、search、tab list、tab activate、category list、unique category focus、conservative row model list、unique row resolve、value read、value editor focus、supported value write、expected value verify、evidence capture、close を実行できます。

この workflow は read-only discovery と mutation を意図的に分けます。text、number、bool row は、row が unique に resolve され、visible で、confidence が十分で、正しい value editor に支えられている場合にだけ write されます。enum value は read / verify できますが、complex editor type は guess せず unsupported として扱います。

`run_task` は safe path を composition します。surface を open して scope を絞り、unique row を resolve し、before value を read し、必要なら supported value を write し、result を verify し、capture evidence を添えます。selector が ambiguous、hidden-control write が要求された、confidence が低すぎる、または required pre-write evidence を作れない場合、task は interaction の前に mutation を拒否します。

### 🧩 Inspector Property Automation

`system_inspector` は同じ philosophy を Inspector に広げます。Agent は visible property model を list し、unique property を resolve し、typed value を read し、value editor を focus し、supported text / number / bool value を set し、result を verify し、property evidence を capture し、current edited object または prepared node/resource target に対して trusted property task を実行できます。

Inspector workflow は保守的です。hidden-control write、ambiguous property、disabled value editor、resource picker、color、array、dictionary、object selector、file selector などの complex editor は、専用の safe workflow ができるまで拒否されます。これにより、client は raw editor control に下りる前に property-level path を使えます。

### 🪟 Evidence-Aware Capture

screenshot は単なる image file ではなく、target と confidence boundary を持つ evidence として扱われます。`system_editor_evidence` は editor、control、popup、active-dialog、automatic surface を capture でき、requested surface、actual backend、target path、visible popup、fallback reason、degradation state、capture policy を報告します。

Settings と Inspector workflow も、より明示的な capture behavior を使います。Settings capture は visible settings popup / window bounds を優先し、次に dialog control bounds、最後に wider editor screenshot に fallback します。client は exact target capture と broader fallback を区別でき、fallback が misleading になる場面では strict policy を使えます。

この release では `system_editor_control(action="get_popup")` と `system_editor_control(action="capture_popup")` も追加され、floating editor window と popup menu が first-class evidence surface になりました。

### 🚀 Project Runtime Lifecycle

project execution は lifecycle surface として表現されます。`system_project_lifecycle(action=start|stop)` の start action は main scene / specific scene launch、marker wait、success / failure marker match、marker timeout、auto-stop behavior、foreground-window fallback guidance を扱います。stop action は同じ lifecycle entry から現在の running project session を閉じます。

古い project run / stop tool name は alias として残さず、意図的に削除されました。新しい名前は実際の contract を表します。client は one-off launch command ではなく、capability context と verification hook を持つ runtime session を制御します。

### 🔎 Tool, Activity, And User Diagnostics

`system_tool_catalog` は current tool catalog の searchable view を提供します。Agent は query、category、domain で検索し、match reason、action、parameter、visibility、enabled state、optional schema を確認してから次の tool を選べます。

`system_tool_activity` は state、tool、slow-call、failure-focused query を support します。long-running / parallel automation でも、client は unrelated activity record を取得せずに active / recent work を inspect できます。

User-tool naming もより明確です。listing、scaffold preview、compatibility report は declared name、normalized name、public MCP tool name を表示します。legacy `user_` prefix declaration は diagnosable で、generated scaffold は resource path 経由で base tool を継承するため headless catalog scan でより安定します。

### 🛠 Scene, Plugin, Project, And Cache Workflows

`system_scene_inspect` は `validate`、`analyze`、`full` action を持つ read-only scene inspection entry です。既存の scene validation / analysis tool は、直接呼ぶ client のために引き続き利用できます。

`system_plugin_maintenance` は plugin status、reload、update-status、update-source、update-start workflow を grouped します。lower-level reload / update tool は削除されず、maintenance response は reload / update sync 中に client が必要とする reconnect / tool-refresh guidance を保持します。

project configuration inspection も広がりました。client は sensitive option key と local absolute export path を redacted した export preset summary を read でき、deadzone と concrete input binding を含む individual input action も inspect できます。

managed user-data maintenance は explicit で dry-run-first のままです。client は capture cache を inspect し、removal を apply する前に cleanup を preview できます。symlink、junction、reparse point guardrail も維持されます。

### ✅ Compatibility and Upgrade Notes

public plugin version、.NET bridge metadata、protocol facts、localized changelog、release-note source は `1.3.0` を target にします。

古い project run / stop tool name を使う client は、`system_project_lifecycle(action=start)` と `system_project_lifecycle(action=stop)` に migrate する必要があります。これは v1.3.0 の主要な intentional compatibility break です。

既存の scene validation / analysis tool は利用可能です。`system_scene_inspect` は additive combined route です。

`system_plugin_maintenance` は additive high-level wrapper です。既存の `system_plugin_reload` と `system_plugin_update` call は引き続き support されます。

complex settings / Inspector editor は conservative のままです。unsupported editor は future dedicated workflow、または explicit evidence を伴う lower-level UI operation で扱うべきで、guess して write しません。
