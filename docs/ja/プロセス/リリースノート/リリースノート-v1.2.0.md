## 🧩 Godot .NET MCP v1.2.0: 再接続を意識した Agent ワークフロー

Godot .NET MCP `v1.2.0` は、プロジェクト、プラグイン、custom tool が変化している間も Godot に接続し続ける Agent 向けの信頼性と editor control のリリースです。再接続案内、multi-client diagnostics、Godot UI automation、User tool observability、protocol guardrail を改善しつつ、Godot 4.6+ .NET support、Godot Asset Library install、source copy install、既存の high-level tool name との互換性を保ちます。

### 🔁 再接続を意識した複数クライアントセッション

health、plugin reload、plugin update の response は、maintenance window state、reconnect expectation、retry timing、stale tool list guidance を報告するようになりました。client は切断が一時的なものか、schema を再取得すべきか、update sync や lifecycle reload がまだ進行中かを判断できます。

HTTP health reporting には、安定した connection ID、request ID、client summary、active session、最近切断された session も含まれます。複数の MCP client や Agent session が同時に接続しているとき、plugin は接続状況と reload 後の復帰方法をより分かりやすく示します。

### 🖱️ より強い Godot エディター UI 制御

`system_editor_control` は、Godot editor UI のより多くの流れを直接扱えるようになりました。Agent は top menu を列挙し、`MenuButton` popup を開き、visible な `PopupMenu` row を text、index、id で選択し、登録済み editor main screen を切り替え、distraction-free mode を制御し、tooltip や floating panel の確認に hover / leave event を送れます。

これにより、editor automation は OS レベルの mouse movement への依存を減らせます。popup menu automation は hidden popup、disabled row、separator、submenu row、重複 text match、競合 selector も拒否するため、誤った menu item を静かに選ぶのではなく、より明確な理由で失敗します。

### 🧰 ツール活動と User tool diagnostics

新しい `system_tool_activity` は、実行中の tool call、最近の完了記録、実行順序、client が任意で渡す自己申告 `_mcp_context` を報告します。並行して動く Agent は、別の長時間 operation を始める前に、すでに何が進んでいるかを軽く確認できます。

User tool runtime diagnostics は、plugin evolution diagnostics と project health から、検出された custom tool、load failure、watcher state、compatibility summary、最近の audit entry を表示します。diagnostics は read-only で custom-tool loading behavior を変えませんが、extension tool の失敗原因を調べやすくします。

### 🛡️ より安全なプロトコルとデバッグ境界

HTTP と stdio は、malformed JSON-RPC top-level `params` を標準 `-32602` error として一貫して扱います。一方、invalid `tools/call.arguments` は通常の MCP tool-result error として報告され続けます。Resource と Prompt Guide output にも size protection が入り、過大な file-backed resource は高コストな読み込み前に失敗し、短縮された prompt text は `_meta` truncation detail を持ちます。

DAP debugger call は、過大な frame と過剰な timeout を明確な limit error で拒否するようになりました。script editing でも、生成された空の C# method に明示的な `NotImplementedException` guard body を使い、曖昧な generated body behavior を減らします。

### 🌐 ローカライズ文書とリリースノート

公開文書 tree は、英語、簡体字中国語、日本語、韓国語で保守され、localized directory と file name を使います。Dock UI には韓国語 coverage が加わり、対応言語全体で tool metadata、client guidance、Prompt Guide text、reconnect guidance、fallback label も広く補完されました。

`v1.2.0` release notes は 4 言語すべての documentation tree に保存されます。GitHub Release body は英語 note から rendering されますが、note 自体は他の言語版へ link しているため、読者は自分に合う documentation language を選べます。

### ✅ 互換性とアップグレード注意事項

既存の high-level tool name は互換性を維持します。editor control、tool activity、User tool diagnostics が新しい capability を公開するため、public tool schema version は変わります。upgrade 後、client は再接続して tool list を再取得してください。

既存 install に file layout migration は不要です。Godot Asset Library installation path または source tree から `addons/godot_dotnet_mcp/` を直接 copy する方法を引き続き使えます。plugin reload や update sync の間、client は health を poll し、transport が切断された場合は再接続し、maintenance window が schema stale の可能性を示したら tool を refresh してください。
