## 🧩 Godot .NET MCP v1.2.0: 再接続を意識した Agent ワークフロー

この release は、複数の MCP client や Agent session が同時に plugin を使う場面での復旧を分かりやすくします。maintenance window reporting、reconnect guidance、transport resilience、health diagnostics、update-sync refresh behavior を強化し、plugin reload や update sync の後に client が安全に再接続して tool list を取り直せるようにしました。

### ✨ ハイライト

- health、plugin reload、plugin update の response に maintenance window metadata を追加し、一時的な切断、retry timing、tool list refresh requirement を client が判別できるようにしました。
- `/health` に HTTP client session identity と request audit field を追加し、安定した connection ID、request ID、client summary、active session、最近切断された session を確認できるようにしました。
- 対応する Dock 言語で reconnect guidance をローカライズしました。

### 🔧 修正

- service routing、.NET support、UI flow、tool-domain index に関する英語と日本語の文書 facts を修正しました。
- plugin update sync が file を書き込んだ後、plugin lifecycle reload を schedule する前に Godot editor file system を refresh するようにしました。
- 壊れていた、または古くなっていたローカライズ用のプレースホルダーを、現在のユーザー向け内容に置き換えました。
- 日本語 README の無効な screenshot reference を削除しました。
- HTTP keep-alive handling を改善し、async tool execution の後も、すでに buffer された pipelined request が drain され続けるようにしました。
- multi-client recovery 向けの reconnect backpressure safeguard を追加し、pending request buffer の上限と response write failure 後の connection cleanup を行います。
- stdio burst processing と lifecycle reload scheduling を強化し、古い response や失敗した reload schedule が誤解を招く pending state を残さないようにしました。
- project file reimport は、project settings、text file、sidecar metadata、未対応 path に対して明確な `not_importable_resource` error を返すようになりました。

### ✅ 互換性とアップグレード注意事項

- 既存の tool name は互換性を維持します。
- Update sync は lifecycle reload step の前に editor へ plugin file の rescan を要求します。
- client は update sync や plugin reload 中に health を poll し、transport が切断された場合は再接続し、maintenance window が schema stale の可能性を示す場合は tool list を再取得してください。
- file layout や tool schema の migration は不要です。
- 既存の install に migration は不要です。
