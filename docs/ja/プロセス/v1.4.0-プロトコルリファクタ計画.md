# v1.4.0 プロトコルリファクタ計画

Godot .NET MCP v1.4.0 は、負債整理と protocol surface の純化を中心に進めます。MCP 2025-06-18 の役割分担に合わせ、context、state、catalog は Resources に戻し、workflow guidance は Prompts に残し、Tools は実際に action や計算的 workflow を実行する入口に絞ります。

目標は、少数の canonical public tools、resource-first の認知入口、単一の tool catalog fact source、そして speed、isolation、behavior、migration status で分割できる layered test gates です。

## Key Changes

- canonical resource URI を追加します: `guides/index`、`guides/capabilities`、`guides/ui-automation`、`state/project/summary`、`state/editor`、`activity/status`、`activity/recent`、`activity/call/{id}`、`tools/catalog/exposed`、`tools/catalog/visible`。
- 6 つの workflow prompt は維持しますが、最初に `system_help` を呼ぶ案内はやめます。client は guide resources、または `prompts/list` / `prompts/get` を使います。
- cognitive / duplicate public tools を `tools/list` から削除します: `system_help`、`system_tool_catalog`、`system_tool_activity`。旧 call は明確な error と replacement resource URI を返します。
- 重複する high-level tools を統合します。`system_scene_validate` と `system_scene_analyze` は `system_scene_inspect(action=validate|analyze|full)` に、`system_plugin_reload` と `system_plugin_update` は `system_plugin_maintenance(action=reload|update|...)` に統合します。read-only `system_editor_log` usage は log/activity resources に移します。
- `tools/list` は standard MCP tool list に戻し、callable tools、schema、annotations、必要な `_meta` だけを返します。tree、group、atomic、action の presentation data は catalog resources に置きます。
- tool result に `structuredContent` と optional `outputSchema` を追加します。互換性のため text JSON は残しますが、internal contract の canonical field は `structuredContent` になります。
- read-only project file、scene、script、resource text access は resource templates に移します。`system_project_files` は write、move、delete、scan、reimport などの action 用に残します。

## Implementation Plan

### 1. Test Guardrails First

- contract case manifest を追加し、field を `name`、`layer`、`domain`、`behavior=current|migration|deprecation|removal_guard`、`speed=fast|headless|editor|release`、`isolation=pure|user_fs|stage_root|editor`、`v1_4_disposition=keep|rewrite|delete|expires` に固定します。
- hard-coded required cases を manifest label selection に置き換えます。
- 旧 behavior test を、残すべき compatibility、migration window、旧構造を復活させない removal_guard に分類します。

### 2. Protocol Surface Purification

- `mcp_resources_service.gd` に guide、state、activity、catalog resources を実装します。
- 既存の project/info、diagnostics、tools/catalog resources が同じ snapshot data を使うようにします。
- prompt text を更新し、認知 path を resource、prompt、canonical tool、resource/activity verification に固定します。
- `mcp_tool_rpc_router.gd` と tools list construction を更新し、public tools を canonical action tools だけにします。
- `resources/list`、`resources/read`、`prompts/get`、`tools/list`、`tools/call` が HTTP と stdio で一致する contract を追加します。

### 3. Public Tool Debt Cleanup

- redundant public tools を削除します: `system_help`、`system_tool_catalog`、`system_tool_activity`、`system_scene_validate`、`system_scene_analyze`、`system_plugin_reload`、`system_plugin_update`、`system_editor_log`。
- old internal aliases を削除します: `filesystem_file`、`debug_log`、`resource_manage`。
- 削除前にすべての internal references を置き換えます。
- test を「not exposed」から「not callable / not present in visible catalog」へ強化します。
- 必要な safety / migration layer は残します: protocol facts fallback、runtime fallback event store、legacy user data cleanup、`trace` to `debug` normalization、old user-tool settings key migration、client config read migration。

### 4. Tool Catalog Refactor

- category、domain key、executor path、source、exposure、hot-reloadability、presentation order を持つ単一の `ToolCatalogManifest` を追加します。
- `MCPToolManifest` と `MCPToolRegistry` は duplicate fact source を消せるまで adapter としてだけ残します。
- `ToolCatalogSnapshotService` を追加し、exposed / visible / all tools、domain states、presentation tree、search index を一度に生成します。
- RPC、Tools API、Dock、catalog resources は同じ snapshot を consume します。
- `atomic_bridge` を `AtomicToolFacade` に降格し、write guard と helper は維持しつつ、execution は unified internal execution に委譲します。
- system impl ごとの schema、handler、atomic dependencies を declarative specs にまとめ、`SystemTreeCatalog` を specs から派生させます。

### 5. Old Monolith Removal

- すでに `tools/<domain>/executor.gd` がある domain では、root-level `tools/<domain>_tools.gd` monolith を移行して削除します。
- `base_tools.gd` と本物の shared helper は削除対象外です。
- final contract は「split executor 完了後に削除すべき」ではなく、旧 monolith file が存在しないことを直接 assert します。
- 優先順は contract が明示している audio、animation、signal、tilemap、UI、その後 filesystem、debug、resource、node、project、scene などの大きな domain です。

### 6. Internal Service Convergence

- `MCPToolLoader` を runtime facade、definition catalog、execution service、visibility policy、activity recorder に分割し、すべての caller が移行するまで external adapter を残します。
- HTTP と stdio は同じ JSON-RPC method router、tool router、result normalization、resources/prompts dispatch path を共有します。
- tiny callable context bags を service graph または ports object に収束させます。
- 最後に `plugin.gd` を slim 化し、EditorPlugin lifecycle と service wiring だけを残します。update、user tools、diagnostics、Dock models、configuration actions は dedicated feature service に移します。

## Test Plan

- Fast static gates: .NET build、manifest lint、refactor guardrails、version policy、documentation localization、workflow lint。
- Headless smoke gates: resource-first MCP contracts、canonical `tools/list`、`tools/call` `structuredContent`、removal guards、tool snapshot parity。
- Headless integration gates: domain-sharded runtime、resources/prompts/tools、client config migration、user tools、localization、transport parity。
- Editor probes: plugin entrypoint、settings persistence、real editor-only lifecycle、UI evidence、settings、inspector workflows。
- Migration / deprecation gates: old user-tool naming、old client config、old stdio config、old C# reference path-first behavior は migration diagnostics の検証に限定し、旧実装を永久保護しません。
- Release preflight: full harness、clean install build、release-note rendering、changelog/i18n、version/tag boundary validation。

## Assumptions

- v1.4.0 は breaking cleanup を許容します。対象は public tool-name convergence と old internal alias removal に集中します。
- Resources / Prompts support が弱い client に protocol surface を合わせません。plugin は MCP specification に従い、clear errors と replacement URIs を返します。
- `script_references` legacy path-first behavior は、専用の C# reference-system task が開かれるまで削除しません。この計画では関連 tests を migration / deprecation candidates に分類するだけです。
- 各 PR は test guardrails、protocol surface、public tool cleanup、manifest/snapshot、monolith removal、loader/atomic convergence、plugin slimming のいずれか 1 つの refactor axis を扱います。
