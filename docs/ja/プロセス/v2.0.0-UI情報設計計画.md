# v2.0.0 UI 情報設計計画

## 概要

v2.0.0 の protocol refactor では、public MCP tool surface を canonical な `system_*` と `user_*` entry に絞る。一方で、実装側には多くの internal executor category が残る。Dock はこの二つの層を明確に分ける必要がある。既定ページでは Agent またはユーザーが呼び出す、読む、要求する対象を表示し、深い表示では構成と運用状態を説明する。

この計画は Tools、Resources、Prompts ページを対象にする。段階的な PR の設計目標であり、release note ではない。

## 共通表示モデル

Dock ページは category 名、URI 断片、prompt 名から独自ツリーを組み立てず、共有 presentation model を消費する。各 node は明確な field を持つ。

## Tools ページ

Tools ページは既定で Agent Tools view を開く。この view は「何を呼び出せるか」に答える。

既定 group:

```text
Agent Tools
├─ Project & Context
├─ Editor Automation
├─ Scene & Resource
├─ Script & C# Semantics
├─ Runtime & Debugging
├─ Plugin Maintenance
└─ User Tools
```

ルール:

- canonical public tools と user tools だけを既定表示する。
- internal executor categories は既定ツリーに表示しない。
- removed または legacy tools を通常 tool として表示しない。
- resource または prompt discovery entry を通常 callable tool として表示しない。
- 既定合計には既定表示される public tools だけを数える。
- 重複 node ではなく implemented by executor などの cross-link で関係を示す。

Tools ページは二つの深い view も持つ。

- Structure view: 選択した public tool の actions、inputs、outputs、data sources、services、internal executors を表示する。
- Diagnostics view: exposure、callability、source file、manifest entry、policy decision、load status、schema status、recent activity、replacement guidance を表示する。

Internal executors は明確に labelled advanced section に置く。

```text
Internal Executors
├─ core
├─ visual
├─ gameplay
├─ interface
├─ plugin
└─ user
```

各 internal executor row は loaded state、enabled tool count、total tool count、source path、load errors、reload status、hot reload status、public tools produced、internal tools produced を表示する。

## Resources ページ

Resources ページは既定で Resource Catalog view を開く。この view は「何を読めるか」に答える。

既定 group:

```text
Resources
├─ Guides
├─ Project State
├─ Editor State
├─ Activity & Logs
├─ Tool Catalog
├─ Resource Templates
└─ Advanced Resources
```

ルール:

- `resources/list` と `resources/templates/list` から canonical resource URIs と templates を表示する。
- title、description、icons、MIME type、template parameters、stable URI を表示する。
- 既定 resource tree に tool-like actions を混ぜず、関連 tools へ link する。
- `_meta.resourceKind` または同等の catalog metadata がある場合、Dock は URI substring で分類しない。
- templates は再利用できる読み取り対象であり、callable tools ではない。

Resources ページに含める view:

- Reader view: 選択 resource content、MIME type、metadata を preview し、copy URI を提供する。
- Template view: template parameters、examples、validation hints を表示し、copy expanded URI を提供する。
- Diagnostics view: source service、resource kind、visibility、last read status、content size、template binding errors、stale cache status、fallback guidance を表示する。

Protocol と safety rules:

- `resources/list`、`resources/templates/list`、`resources/read` をページ内容、preview、error behavior の source of truth とする。
- logs と diagnostics の redaction behavior を維持する。
- template path validation、traversal rejection、absolute/user path rejection、binary rejection、oversized content handling を維持する。
- Compatibility resources は compatibility entries として label し、canonical resources より上に置かない。

Resources の受け入れ条件:

- Guides、state、activity、logs、catalog、templates は既定 catalog に一度だけ出る。
- Template entries は tools に数えない。
- Resource kind は共有 metadata から来る。
- Resource preview は大きな内容、空の内容、未対応 MIME type、read errors でも重なりなく表示する。
- Diagnostics は missing、hidden、failed resource reads を説明できる。
- Resource preview semantics は `resources/read(uri)` と同等であり続ける。

## Prompts ページ

Prompts ページは既定で Prompt Catalog view を開く。この view は「どの workflow guidance を要求できるか」に答える。

既定 group:

```text
Prompts
├─ Project Understanding
├─ Editor Workflow
├─ Runtime Validation
├─ Script & C# Workflow
├─ Plugin Maintenance
└─ Advanced Prompts
```

ルール:

- `prompts/list` から prompts を表示し、title、description、icons、arguments、stable name を示す。
- Prompt entries は tools と resources から分離する。
- Prompt arguments は child tools ではなく arguments として表示する。
- metadata がある場合、prompt name substring で prompt kind を推測しない。
- required、optional、enum、bool、path-like arguments を視覚的に区別する。

Prompts ページに含める view:

- Prompt builder view: argument editors、validation hints、preview request、copy prompt name。
- Message preview view: rendered messages、roles、text content、resource/tool links。
- Diagnostics view: prompt source、prompt kind、argument schema、unknown-argument policy、type validation status、last render error、related resources/tools。

Protocol と safety rules:

- `prompts/list` と `prompts/get` をページ内容、preview、error behavior の source of truth とする。
- prompt unknown-argument と wrong-type validation semantics を維持する。
- prompt service が提供する truncation metadata、localized title、description、argument text を維持する。
- Prompt preview semantics は `prompts/get(name, arguments)` と同等であり続ける。

Prompts の受け入れ条件:

- Workflow prompts は既定 catalog に一度だけ出る。
- Arguments は narrow panel で layout を壊さず、label に重ならない。
- Unknown と wrong-type arguments は validation concerns として表示される。
- Rendered messages は role と content を明確に保つ。
- Diagnostics は prompt visibility、argument validation、render failures を説明できる。

## 共通操作ルール

複数深度を持つページでは共有 mode switch を使う。

```text
Default
Structure
Diagnostics
Advanced
```

検索は全 mode で共通だが、各 result は type badge を持つ。

```text
Public
Internal
Legacy
Removed
Disabled
Error
Resource
Template
Prompt
Argument
```

Preview panel は安定した寸法と compact labels を使う。Buttons は可能な限り icon を使い、不慣れな action には tooltip を付ける。Disabled または non-callable nodes には run-style actions を表示しない。

## PR 計画

### PR 1: 計画とモデル契約

- この計画を docs tree に保存する。
- Tools、Resources、Prompts の presentation model contracts を追加する。
- UI 変更は最小にする。

### PR 2: Agent Tools 既定 view

- Tools tab の既定 tree を canonical public tools plus user tools に切り替える。
- executor categories を advanced または diagnostics path に移す。
- 既定 count と重複 DAP/runtime/project 系 row を直す。

### PR 3: Resources と Prompts の既定 view

- Resources と Prompts が明確な presentation models を消費する。
- 安定 previews、argument/template panels、metadata badges を追加する。
- 共有 metadata がある場所では私的な Dock 分類推測を取り除く。

### PR 4: Structure と Diagnostics views

- Tools、Resources、Prompts に深い view を追加する。
- exposure、callability、data source、validation、activity、replacement、load/read/render status を表示する。
- errors、hidden entries、legacy entries、internal entries、disabled entries の filter を追加する。

### PR 5: Visual verification と polish

- desktop と narrow-panel rendering を検証する。
- labels、buttons、previews、schemas、badges が重ならないことを確認する。
- Tools、Resources、Prompts の visual evidence を取得する。

## 受け入れ基準

- 既定 Tools ページは canonical callable tools を一度だけ表示し、internal executor categories を既定 count から除外する。
- DAP、runtime、project、scene、resource capabilities は同格の通常 tool として重複表示されない。
- Removed legacy tools は Agent Tools に出ず、diagnostics で replacement guidance とともに見える。
- Resources ページは resource entries と templates を一度だけ表示し、metadata-driven kinds と安全な previews を使う。
- Prompts ページは prompts を一度だけ表示し、argument editors と message preview を tools から分離する。
- Structure と diagnostics views は non-callable nodes を明確に non-callable として示す。
- 各 view は entry が visible、hidden、disabled、removed、failing である理由を説明できる。
- 実装 PR 後、visual verification は Tools、Resources、Prompts を対象にする。
