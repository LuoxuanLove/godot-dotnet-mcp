# v2.0.0 リファクタ進捗トラッカー

この tracker は v2.0.0 protocol refactor plan を実行 checklist に分解します。各行は review、test、v2.0 refactor branch への merge が可能な PR-sized work に対応します。

Status:

- `Done`: 実装、検証、review が完了し、v2.0 refactor branch に merge 済み。
- `Partial`: 有効な進捗はあるが、必須 follow-up が残っている。
- `Pending`: まだ実質的な実装がない。
- `Blocked`: 明確な外部 prerequisite がある。

## Current Phase

v2.0.0 line は計画された protocol-purity と UI metadata refactor scope を完了しました。refactor target は default で MCP 2025-11-25 conformance で、以前の 2025-06-18 alignment は compatibility foundation として残ります。branch には強い test scaffolding、明示的な MCP 2025-11-25 aggregate conformance gate、広い protocol/UI metadata coverage、release-contract Streamable HTTP coverage、loader / transport / atomic bridge / plugin lifecycle wiring を monolithic facade に戻さない service-convergence guards があります。将来の作業は v2.0 plan debt ではなく、新しい scoped requirement として追跡してください。

## Release Scope Decision

v2.0.0 は、下記の editor-native protocol refactor、Streamable HTTP/stdio compatibility、shared catalog/UI metadata、isolated Roslyn runtime、update hardening、release validation scope を中心に切ります。idle diagnostics budgeting と v2 branch policy coverage はこの line に landing 済みで、open release decision ではありません。

Optional external/headless companion capabilities、つまり static project graph analysis、resource reference graph analysis、broker manifests、bridge semantic-version negotiation、project-session lifecycle controls は v2.0.0 release scope に含めません。これらは current refactor branch に対して再設計され、独立して検証され、editor-native plugin が hidden background companion に依存しない形で ship できるまで、post-2.0 / v3 candidate direction として扱います。

## Tracking Rules

- breaking removal は必ず error に replacement method または resource URI を含める。
- 削除した public tool は `tools/list`、visible catalog resource、successful call から消えたことを test で証明する。
- Prompt guidance は resource-first path を説明し、削除済み discovery tool を出発点にしない。
- default v2.0 endpoint は MCP Streamable HTTP としての `http://127.0.0.1:3000/mcp` です。legacy `/api/tools`、`/health`、JSON-only POST behavior、`Content-Length` stdio は compatibility surface と明記します。
- UI catalog models は shared catalog snapshot metadata を consume し、別の private catalog facts を作りません。
- future Tools tab context actions は shared manifest/snapshot metadata 上に置き、private tree fact sources を作りません。
- future atomic helper / collection behavior は `AtomicBridgeHelperService` / system implementation helper services に置き、`AtomicBridgeExecutionService` や bridge facade に戻しません。
- Changelog entries は `Added / Changed / Fixed / Documentation / Internal` 順序を守り、同一 version 内で section を重複させない。
- PR は local validation、関連 GitHub check、全 conversation、Codex review gate が完了するまで v2.0 refactor branch に merge しない。
