# v1.4.0 リファクタ進捗トラッカー

この文書は v1.4.0 protocol refactor plan を実行チェックリストに分解します。各項目は、レビュー、検証、v1.4 refactor branch への merge が可能な PR 単位に対応します。

Status:

- `Done`: 実装、検証、レビューが完了し、v1.4 refactor branch に merge 済み。
- `Partial`: 有効な進捗はあるが、必須の follow-up が残っている。
- `Pending`: まだ実質的な実装がない。
- `Blocked`: 明確な外部 prerequisite がある。

## Current Phase

v1.4.0 は初期 guardrail を越え、protocol surface の準備中盤にあります。refactor target は default で MCP 2025-11-25 conformance になり、これまでの 2025-06-18 alignment は compatibility foundation として残します。現在の branch には test scaffolding と複数の MCP protocol improvement が入っていますが、2025-11-25 transport/schema/metadata gates、breaking public-tool cleanup、single catalog fact source、旧 monolith removal、internal service convergence はまだ完了していません。

## Next PR Queue

1. MCP 2025-11-25 conformance gate taxonomy と protocol-version/schema/tool-name metadata contracts を追加する。
2. `http://127.0.0.1:3000/mcp` を default Streamable HTTP endpoint と定義し、version/session/Accept/SSE/Origin contracts を追加する。
3. newline-delimited stdio を default mode にし、`Content-Length` は明示的な legacy compatibility として残す。
4. Resources、Resource Templates、Prompts、Tools に 2025-11-25 icons/title/description/schema metadata を追加する。
5. Dock / Tools UI model を shared catalog snapshot metadata から render するようにし、private tree facts を持たない。
6. 残りの Dock と Tools/RPC catalog consumer を `ToolCatalogManifest` / `ToolCatalogSnapshotService` へ移行する。
7. debug、resource、node、project、scene など大きな monolith domain の cleanup を続ける。
8. `atomic_bridge` を unified internal execution facade の背後へ移す。
9. snapshot service 安定後に `MCPToolLoader` の責務を分割する。
10. catalog consumer が manifest/snapshot path を共有した後、internal service convergence を続ける。

## Tracking Rules

- breaking removal は必ず error に replacement method または resource URI を含める。
- 削除した public tool は `tools/list`、visible catalog resource、successful call のすべてから消えたことを test で証明する。
- Prompt guidance は resource-first path を説明し、削除済み discovery tool を出発点にしない。
- default v1.4 endpoint は MCP Streamable HTTP としての `http://127.0.0.1:3000/mcp` です。legacy `/api/tools`、`/health`、JSON-only POST behavior、`Content-Length` stdio は compatibility surface と明記します。
- UI catalog models は shared catalog snapshot metadata を consume し、別の private catalog facts を作りません。
- Changelog は `Added / Changed / Fixed / Documentation / Internal` 順序を守り、同一 version 内で section を重複させない。
- PR は local validation、関連 GitHub check、全 conversation、Codex review gate が完了するまで v1.4 refactor branch に merge しない。
