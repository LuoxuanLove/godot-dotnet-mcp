# v1.4.0 リファクタ進捗トラッカー

この文書は v1.4.0 protocol refactor plan を実行チェックリストに分解します。各項目は、レビュー、検証、v1.4 refactor branch への merge が可能な PR 単位に対応します。

Status:

- `Done`: 実装、検証、レビューが完了し、v1.4 refactor branch に merge 済み。
- `Partial`: 有効な進捗はあるが、必須の follow-up が残っている。
- `Pending`: まだ実質的な実装がない。
- `Blocked`: 明確な外部 prerequisite がある。

## Current Phase

v1.4.0 は初期 guardrail を越え、protocol surface の準備中盤にあります。現在の branch には test scaffolding と複数の MCP protocol improvement が入っていますが、breaking public-tool cleanup、single catalog fact source、旧 monolith removal、internal service convergence はまだ完了していません。

## Next PR Queue

1. `system_help` を public tool list から削除し、legacy call に replacement error を返す。
2. Prompt と localization から `system_help` 起点の古い guidance を削除する。
3. public catalog discovery を `system_tool_catalog` から catalog resources へ移す。
4. `system_plugin_reload` と `system_plugin_update` を `system_plugin_maintenance` に統合し removal guard を追加する。
5. single declarative source として `ToolCatalogManifest` を導入する。
6. `ToolCatalogSnapshotService` を導入し catalog resources、search、presentation を移行する。
7. filesystem、debug、resource、node、project、scene など大きな monolith domain の cleanup を続ける。
8. `atomic_bridge` を unified internal execution facade の背後へ移す。
9. snapshot service 安定後に `MCPToolLoader` の責務を分割する。
10. HTTP と stdio の JSON-RPC routing と result normalization を統一する。

## Tracking Rules

- breaking removal は必ず error に replacement method または resource URI を含める。
- 削除した public tool は `tools/list`、visible catalog resource、successful call のすべてから消えたことを test で証明する。
- Prompt guidance は resource-first path を説明し、削除済み discovery tool を出発点にしない。
- Changelog は `Added / Changed / Fixed / Documentation / Internal` 順序を守り、同一 version 内で section を重複させない。
- PR は local validation、関連 GitHub check、全 conversation、Codex review gate が完了するまで v1.4 refactor branch に merge しない。
