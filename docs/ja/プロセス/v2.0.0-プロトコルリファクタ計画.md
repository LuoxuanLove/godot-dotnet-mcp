# v2.0.0 プロトコルリファクタ計画

## Summary

Godot .NET MCP v2.0.0 は「負債整理 + protocol surface の純化 + 2025-11-25 conformance」を軸に進めます。MCP 2025-11-25 specification に合わせ、context、state、catalog は Resources に戻し、workflow guidance は Prompts に残し、Tools は実際に action または計算型 workflow を実行する entry に絞ります。

これまでの MCP 2025-06-18 alignment は compatibility foundation として残します。v2.0.0 release target は、default MCP surface が 2025-11-25 に conform する形へ切り替えます。public tool surface では breaking cleanup を許容しますが、削除には必ず replacement entry、replacement metadata、removal guard tests が必要です。

目標形は、少数の canonical public tools、resource-first cognitive entry points、単一の tool-catalog fact source、2025-11-25 transport/schema/metadata gates です。

## Key Changes

- protocol baseline を `protocolVersion = 2025-11-25` に切り替え、`serverInfo` / `Implementation` に `description` などの human-readable metadata を追加します。
- canonical resource URI を維持します: `guides/index`、`guides/capabilities`、`guides/ui-automation`、`state/project/summary`、`state/editor`、`activity/status`、`activity/recent`、`activity/call/{id}`、`tools/catalog/exposed`、`tools/catalog/visible`。さらに 2025-11-25 の `icons` / title metadata を追加します。
- 6 つの workflow prompts は維持します。`system_help` を最初に呼ぶ案内はやめ、prompt `icons`、argument schemas、path/enum/bool argument guard を追加します。
- cognitive / duplicate public tool entries の削除を続けます: `system_help`、`system_tool_catalog`、`system_tool_activity`、scene aliases、plugin reload/update aliases、editor log aliases、old internal aliases。
- `tools/list` は standard MCP tool list とし、callable tools、`inputSchema`、`outputSchema`、annotations、icons、必要な `_meta` のみを返します。tree、group、action presentation data は catalog resources にだけ置きます。
- `inputSchema` / `outputSchema` は JSON Schema 2020-12 を default dialect とします。legacy schema の互換性が不明な場合は `$schema` を明示します。
- tool-name guard を追加します: 長さ 1-128、case-sensitive、ASCII letters/digits/`_`/`-`/`.` を推奨し、client parsing を壊す文字を禁止します。
- Dock と Tools UI design を更新し、resources/snapshots から 2025-11-25 catalog metadata（`icons`、title、description、schema dialect、output schema、exposure state）を consume し、private presentation tree を再構築しないようにします。
- default MCP endpoint は `http://127.0.0.1:3000/mcp` のままにしますが、plugin-private JSON-RPC API ではなく MCP 2025-11-25 Streamable HTTP transport として定義します。
- default HTTP request shape は `POST /mcp`、`Accept: application/json, text/event-stream`、`Content-Type: application/json`、`MCP-Protocol-Version: 2025-11-25` とします。
- `/api/tools`、`/health`、old JSON-only POST behavior、old `Content-Length` stdio は legacy compatibility surfaces とします。
- default stdio は 2025-11-25 newline-delimited JSON-RPC に移行します。old `Content-Length` framing は legacy compatibility mode のみです。
- HTTP は complete Streamable HTTP semantics に移行します: `MCP-Protocol-Version`、`Mcp-Session-Id`、`Accept`、invalid-Origin 403、SSE polling/resumption を検証します。
- Sampling、Elicitation、Tasks は optional capabilities として扱います。default では advertise せず、advertise した場合は 2025-11-25 contracts を満たします。

## Implementation Plan

### 1. Test Guardrails First

- contract case manifest を `mcp_version=2025-11-25|2025-06-18|legacy` と `conformance=required|compat|optional` で拡張します。
- lifecycle、stdio、Streamable HTTP、Tools、Resources、Prompts、schema、metadata を覆う `mcp_2025_11_25_conformance_contracts` を追加します。
- old 2025-06-18 tests は compatibility / migration guards に再分類します。release target を表すものではありません。
- breaking removal はすべて、`tools/list` からの absence、visible catalog からの absence、legacy-call replacement errors を証明します。

### 2. Protocol Surface Purification

- `initialize` から `2025-11-25`、standard capabilities、serverInfo description を返します。
- `mcp_resources_service.gd` は guide/state/activity/catalog entry point として維持し、icons/title metadata を追加します。
- prompt text は resource -> prompt -> canonical tool -> resource/activity verification の path を一貫して示します。
- `tools/list` から presentation trees、groups、atomic internals、action-only presentation data を削除します。
- HTTP と stdio は、1 つの JSON-RPC router、result normalization path、resources/prompts/tools dispatch を共有します。

### 3. Transport Adaptation

- Godot editor が開いていて client が現在の editor session を制御する場合、`http://127.0.0.1:3000/mcp` を default MCP Streamable HTTP endpoint とします。
- remote MCP 対応 client には Streamable HTTP URL を優先します。local command のみ対応する client には Godot headless stdin/stdout stdio launcher を提供します。
- newline-delimited JSON-RPC を default stdio mode にし、すべての logs は stderr に出します。
- legacy `Content-Length` stdio は明示的な compatibility configuration のみで有効化し、migration warning を出します。
- Streamable HTTP POST JSON-RPC、GET SSE/polling、session ids、resumption、server-initiated disconnects を support します。
- invalid Origin には HTTP 403 を返します。
- HTTP request/response contracts で `Accept`、`MCP-Protocol-Version`、`Mcp-Session-Id`、SSE event id behavior を覆います。

### 4. Public Tool Debt Cleanup

- redundant public tools を削除し、一貫した `removed_public_tool` structured error を返します。
- replacement metadata は canonical resource URIs、canonical tools、または prompts を指します。
- input validation failures は Tool Execution Errors を優先します: `isError=true` と `structuredContent.success=false`。tool-argument repair cases では JSON-RPC protocol errors を避けます。
- 必要な migration layers は残します: protocol facts fallback、runtime fallback event store、legacy user data cleanup、`trace -> debug`、old user-tool settings migration、client config migration。

### 5. Tool Catalog Refactor

- category、domain key、executor path、source、exposure、hot-reloadability、presentation order、icons、schema dialect を持つ `ToolCatalogManifest` を追加します。
- `MCPToolManifest` と `MCPToolRegistry` は adapters として残し、その後 duplicate fact sources を削除します。
- `ToolCatalogSnapshotService` で exposed/visible/all tools、domain states、presentation trees、search indexes、metadata を一度に生成します。
- RPC、Tools API、Dock、catalog resources、search は同じ snapshot を consume します。
- Dock / Tools UI models を protocol metadata 中心に再設計します。icons は quick scanning、title/description は display text、schema dialect/output schema indicator は inspection、exposed/visible/internal state は明示的な状態表示に使います。
- UI controls は compact で operational に保ちます。marketing-style catalog surface は追加せず、`tools/list` や catalog resources と分岐する private catalog facts を残しません。
- `atomic_bridge` を facade に降格し、execution path は unified internal execution を通します。

### 6. Optional Capability Boundaries

- Sampling: server が client-side LLM work を本当に必要とする場合だけ advertise します。実装時は `tools` と `toolChoice` を support します。
- Elicitation: URL mode を優先します。form mode は passwords、API keys、access tokens などの sensitive fields を収集してはいけません。
- Tasks: run validation、batch audits、update sync、full-project scans などの long-running durable workflows に限って使います。
- Authorization: local editor mode は default で OAuth を要求しません。remote HTTP mode は OIDC discovery、Protected Resource Metadata、`WWW-Authenticate` scope challenges に従います。

### 7. Old Monolith Removal and Internal Service Convergence

- root-level `tools/<domain>_tools.gd` monolith の migration / deletion を続け、split executors を唯一の stable entries にします。
- `MCPToolLoader` を runtime facade、definition catalog、execution service、visibility policy、activity recorder に分割します。
- `plugin.gd` を EditorPlugin lifecycle と service wiring に slim 化し、updates、diagnostics、Dock models、configuration actions は dedicated feature services に移します。

## Test Plan

- Fast static: dotnet build、manifest lint、tool-name lint、schema 2020-12 lint、refactor guardrails、version policy、docs localization、actionlint。
- Protocol conformance: initialize、tools/list、tools/call、resources/list/read/templates、prompts/list/get。
- Transport: newline stdio、legacy stdio migration、Streamable HTTP、SSE polling/resumption、Origin 403。
- Public cleanup: removed tools absence、visible catalog absence、replacement errors、structuredContent parity。
- Metadata: icons/title/description/schema dialect/outputSchema snapshot parity。
- UI adaptation: Dock / Tools page models は shared catalog snapshot から render し、icons、titles、descriptions、schemas、exposure state を保持し、別の catalog fact source を作らないこと。
- Optional features: Sampling、Elicitation、Tasks は capabilities を advertise した場合だけ required contracts を走らせます。
- Release preflight: full harness、clean install build、release-note rendering、changelog/i18n、version/tag boundary。

## Assumptions

- v2.0.0 は breaking cleanup を許容し、default protocol target は MCP 2025-11-25 です。
- 2025-06-18 behavior は migration / legacy compatibility layer としてのみ残し、2025-11-25 default shape を妨げません。
- Sampling、Elicitation、Tasks は optional capabilities です。未成熟な実装は advertise してはいけません。
- 各 PR は transport、protocol surface、public cleanup、manifest/snapshot、monolith deletion、loader/atomic、optional capability のいずれか 1 つの refactor axis を扱います。
