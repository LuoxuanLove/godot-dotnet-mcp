# サービスと routing

この文書は、plugin の service 入口、session layer、routing の方向を説明します。

今の核心原則は次です。

- plugin 内 MCP HTTP service が唯一の公開入口
- plugin 内 Roslyn は Godot .NET runtime の内部で syntax-first で動く
- 外部 host も child process もない

---

## service 入口

### 公開入口

plugin の MCP service は `plugin/runtime/mcp_http_server.gd` が提供します。

- HTTP listen は `http://127.0.0.1:3000/mcp`（または現在設定の port）
- tool registration と dispatch は `tools/core/tool_loader.gd` が管理する
- MCP Resources と Prompts は JSON-RPC method layer から直接提供し、project information、diagnostics summary、安全な file template、guidance prompt を読む

外部 MCP client は次に接続します。

```text
http://127.0.0.1:3000/mcp
```

### protocol method

`POST /mcp` は JSON-RPC 2.0 を使い、次の一等 MCP method を支えます。

| Method | 用途 |
|---|---|
| `initialize` | protocol version、tool schema version、server info、`tools`、`resources`、`prompts` capability を返す |
| `tools/list` / `tools/call` | 高レベル tool list を公開し、tool call を実行する |
| `resources/list` / `resources/templates/list` / `resources/read` | built-in server resources を列挙し、scene/script/resource 読み取り template を公開し、厳格な `res://` path check で読み取り専用内容を読む |
| `prompts/list` / `prompts/get` | built-in prompt を列挙し、project orientation、content authoring、diagnostic triage、reference integrity、runtime validation、editor UI control の 6 つの parameterized workflow guidance を返す |
| `ping` | 空結果を返し、connection keep-alive に使う |

### 内部 component

Prompts と Tools の境界は分けて保ちます。`prompts/get` は会話の context に入れる workflow 説明だけを返し、editor action は実行しません。実際の読み取り、検証、修正、実行は `tools/call` の高レベル tool で行います。`system_help` の返答には `prompt_guides` の summary が入っていて、Agent が `prompts/list` と `prompts/get` を見つける軽い入口になります。

plugin 内 component。

- `plugin/runtime/mcp_http_server.gd` — MCP HTTP service
- `plugin/runtime/mcp_resources_service.gd` — MCP Resources の list / read service
- `plugin/runtime/mcp_prompts_service.gd` — MCP Prompts の list / read service
- `plugin/runtime/server_runtime_controller.gd` — service lifecycle 管理
- `plugin/runtime/plugin_roslyn_service.gd` — plugin 内 Roslyn service façade
- `tools/core/tool_loader.gd` — tool catalog と load

## tool の階層

### Editor-attached

すべての tool は今の editor state に依存します。

- `system_*` — project snapshot、scene analysis、script structure check、C# binding audit、symbol search
- `script_*` — script read/write、C# syntax analysis
- `scene_*` — scene query と modification
- `node_*` — node 操作

### plugin 内開発能力

次の能力は plugin 内の診断と保守に使います。

- `plugin_runtime_*`
- `plugin_developer_*`
- `plugin_evolution_*`

---

## session model

plugin は外部 session の概念を管理しません。すべての tool は editor process の中で直接動きます。

Godot executable path の方針。

- Godot path は、ユーザーが明示的に設定したものか、local のよくある directory から見つけたものを使う
- 広い磁気 scan はしない
- machine 依存 path を release artifact に埋め込まない

---

## routing の責務

### plugin

担当するもの。

- MCP HTTP service の listen と request 処理
- tool catalog registration と dispatch
- realtime editor environment での tool 実行
- local service と diagnostic panel の提供
- plugin 側 tool runtime と `user_*` extension の維持

### plugin 内 Roslyn

担当するもの。

- C# syntax tree parse（syntax-only、SemanticModel なし）
- type、method、export member の抽出
- `script_inspect`、`script_exports`、`script_edit_cs` などの C# tool の syntax analysis

---

## error semantics

editor-required tool では、plugin は structure 化された error を返します。

- `project_not_selected`
- `godot_executable_not_found`
- `script_not_found`
- `parse_error`
- `binding_audit_error`

---

## 現在の実装境界

- plugin は local HTTP MCP service address を提供する
- C# analysis は plugin 内 Roslyn（syntax-first）を使う
- `addons/godot_dotnet_mcp/dotnet_bridge/` は plugin 内共有 .NET library であり、外部 executable ではない
