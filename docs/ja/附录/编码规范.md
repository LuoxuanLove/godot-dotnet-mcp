# エンコーディング規約

この文書は `godot-dotnet-mcp` repository の text file encoding を定めます。狙いは次の 3 つを同時に満たすことです。

- cross-platform な code と config file の保守性
- Windows 開発環境での安定した読み取り
- 現在の `Windows PowerShell 5.1` workflow での扱いやすさ

今の方針の核心は次の通りです。

- 既定は `UTF-8` 無 BOM
- `Windows PowerShell 5.1` の default read 行動、または Agent の memory file 消費に明確な互換性が必要なときだけ `UTF-8 with BOM` を使う

今の規則は次の file で落としています。

- `godot-dotnet-mcp/.editorconfig`: repository 内の正式 source、config、document、`*.ps1` を縛る
- workspace root の `.editorconfig`: root directory の協働 memory file だけを縛る。plugin repository 自身は、この文書と repository 内 config を基準にする

---

## 全体規則

### UTF-8 無 BOM を使うもの

次の file type と directory は、既定で `UTF-8` 無 BOM にします。

- すべての source file
  - `*.cs`
  - `*.gd`
  - `*.shader`
- すべての project と config file
  - `*.csproj`
  - `*.props`
  - `*.targets`
  - `*.sln`
  - `*.json`
  - `*.yml`
  - `*.yaml`
  - `*.xml`
  - `*.toml`
  - `*.cfg`
  - `*.editorconfig`
  - `.gitignore`
  - `.gitattributes`
- すべての Godot text resource
  - `*.tscn`
  - `*.tres`
- すべての正式な外向き文書
  - `README*.md`
  - `docs/**/*.md`

理由。

- cross-platform toolchain で最も安定し、一般的な default encoding だから
- BOM が script header、config parser、一部の厳しい tool に悪影響を与えるのを避けるため
- 今の `.NET` / Godot text resource の主流な約束とそろえるため

### UTF-8 with BOM を使うもの

この repository では次を `UTF-8 with BOM` にします。

- `AGENTS.md`
- `CLAUDE.md`
- `*.ps1`

理由。

- これらは今の Windows 開発環境で、`Windows PowerShell 5.1` が直接読むか実行することが多い
- `PowerShell 5.1` は BOM のない UTF-8 中文 file を default で読むと文字化けしやすい
- Agent の memory file は、Windows の default toolchain でそのまま開いても正しく見える必要がある

---

## PowerShell 5.1 の制約

今の環境にはまだ `Windows PowerShell 5.1` があるので、次を守ります。

### UTF-8 file の読み方

- BOM なし UTF-8 file を読むときは、必ず encoding を明示する
- 正式 source、config、`docs/**/*.md` の中文内容を読むときに、default `Get-Content` に頼るのは禁止

推奨。

```powershell
Get-Content -Encoding UTF8 -Path .\docs\ja\附录\编码规范.md
```

### UTF-8 file の書き方

- default `Set-Content` / `Out-File` で repository file を書くのは禁止。default は ANSI や目的外 encoding になることがある
- 書き込みでは target encoding を明示する
- BOM なし UTF-8 を `PowerShell 5.1` で書くときに `Set-Content -Encoding UTF8` へ頼るのはやめる。これは BOM を付けてしまう

推奨 strategy。

- 正式 source、config、外向き文書
  - editor で `UTF-8` 無 BOM として保存する
  - あるいは `.NET` API で BOM なしを書き込む
- `AGENTS.md`、`CLAUDE.md`、`*.ps1`
  - `UTF-8 with BOM` で明示的に書く

無 BOM の書き込み例。

```powershell
[System.IO.File]::WriteAllText(
    $path,
    $content,
    (New-Object System.Text.UTF8Encoding($false))
)
```

BOM ありの書き込み例。

```powershell
[System.IO.File]::WriteAllText(
    $path,
    $content,
    (New-Object System.Text.UTF8Encoding($true))
)
```

## 実行規則

### 新規 file

- 新しく source、config、正式文書を作るときは、既定で `UTF-8` 無 BOM にする
- 新しく `*.ps1`、`AGENTS.md`、`CLAUDE.md` を作るときは、既定で `UTF-8 with BOM` にする

### 既存 file を変えるとき

- 既存 file を直すときは、その category の target encoding を優先し、混ぜない
- 既存 file の encoding がこの規約と合っていないのを見つけたら、今回の task に支障がない範囲で target encoding へ揃える
- encoding rule を変えるときは、`.editorconfig` とこの文書の両方を更新する。片方だけではだめ

### review と refactor のとき

- 中文が文字化けしたら、まず `PowerShell 5.1` の default read で BOM なし UTF-8 を読んでいないかを疑う。壊れているとは決めつけない
- 「repository がきれいか」を見るときは、内容だけでなく encoding もこの規約に合っているかを見る

---

## 例外

- もし将来の主開発環境が `PowerShell 7` に移るなら、この規約は再検討できる。そのときは BOM file の範囲をもっと減らせるかもしれない
- ある third-party tool が特別な encoding を明示的に要求するなら、その tool の hard rule を優先する。ただし、なぜそうするかを対応文書に書くこと
