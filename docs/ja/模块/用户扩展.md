# User Extension

この文書は、User tool interface の規約、load mechanism、`plugin_evolution` tool、authorized flow、audit record を説明します。

---

## User tool とは何か

User tool は、project 専用の拡張です。plugin 本体を変えずに、その project だけの MCP capability を足せます。

---

## 規約

- `user_*` という名前を使う
- `custom_tools/` に置く
- built-in tool と混ぜて考えない
- project ごとに違ってよい

User tool は、「plugin の中核を増やす」のではなく、「project に合う助けを足す」ためのものです。

---

## load mechanism

`custom_tools/` にある合法な GDScript file は、plugin が hot load できます。

- editor を再起動しなくても検出できる
- Tools page に source、状態、待機中 reload、最新 error を出せる
- 不正な script は無理に読み込まない

---

## scaffold と authorized flow

`plugin_evolution_scaffold_user_tool` は、まず未承認の preflight で使います。

1. scaffold 結果を先に見る
2. 内容がよければ `authorized=true` を付けて作る
3. 必要なら audit を確認する

この流れは、安全に project 専用 tool を増やすためのものです。

---

## audit

`plugin_evolution_user_tool_audit` は、承認と削除の記録を見るためにあります。

- 誰が作ったか
- どの tool があるか
- 削除されたか
- authorization の流れがどうだったか

audit は、後から「何がいつ入ったのか」を追えるようにします。

---

## `plugin_developer_user_visibility`

`plugin_developer_user_visibility` は、Dock で `User` category を見せるのに使えます。

- built-in と user を同じ tree で見せたいときに便利
- ただし、見せ方は user の責務と built-in の責務を混ぜないようにする

---

## 安全性

User tool の安全性は重要です。

- 不明な script をそのまま実行しない
- preflight を飛ばさない
- authorization を曖昧にしない
- 失敗したら audit できるようにする
