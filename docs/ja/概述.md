# Godot.NET MCP 文書概要

この文書集は `addons/godot_dotnet_mcp` の完全な技術実装を説明するためのもので、次の内容もカバーします。

- plugin の入口、lifecycle、runtime service、protocol routing
- plugin と Host が共有する protocol / version facts source
- Dock UI scene、page tab script、layout と data flow
- tool system、tool domain の分け方、system layer、configuration persistence、localization、user extension 能力
- test module、plugin headless harness、CI guardrail
- directory tree、重要 file の責務、よく使う persistence format

想定読者は主に次の 3 種類です。

- Godot editor で plugin を接続して使う人
- `plugin.gd`、`plugin/runtime/*`、`ui/*`、`tools/*` を保守し続ける人
- test、smoke、CI guardrail、regression 面を保守する協力者
- directory 構造、file の責務、troubleshoot の入口をすばやく把握したい協力者

## よくある workflow

### 1. ローカル MCP service を起動する

1. Godot editor で plugin を有効化する。
2. `MCPDock > 主页` を開く。
3. port、auto start、log level、language を確認する。
4. `启动` を押すか、auto start のままにする。
5. `http://127.0.0.1:3000/mcp` または現在 port に対応する address で client から接続する。

対応説明は [架构/配置与界面.md](架构/配置与界面.md)、[界面/Server与Config页实现.md](界面/Server与Config页实现.md)、[架构/运行时服务.md](架构/运行时服务.md) を参照してください。

### 2. tool exposure 範囲と preset を調整する

1. `MCPDock > 工具` を開く。
2. built-in profile か custom profile を選ぶ。
3. `domain -> category -> tool` の 3 層 tree 構造で tool を有効・無効にする。
4. enabled 数の変化を見て、`disabled_tools` と現在の preset が一致しているか確かめる。
5. 現在の tool set を共有または再生したいなら、import / export 設定を使う。

対応説明は [界面/Tools页实现.md](界面/Tools页实现.md)、[模块/工具系统.md](模块/工具系统.md)、[附录/配置与持久化.md](附录/配置与持久化.md) を参照してください。

### 3. client connection 設定を確認・書き込む

1. `MCPDock > 配置` を開く。
2. 目的の client platform を選ぶ。
3. 現在の service address、生成された text、target path を確認する。
4. ローカルへ書き込みたいなら one-click write を使い、手動で扱いたいなら copy を使う。

対応説明は [界面/Server与Config页实现.md](界面/Server与Config页实现.md)、[架构/配置与界面.md](架构/配置与界面.md)、[附录/配置与持久化.md](附录/配置与持久化.md) を参照してください。

### 4. C# export binding と scene の問題を調べる

1. `script_inspect` か `script_exports` で script export member を読む。
2. `scene_bindings` で現在の scene、または指定 scene の binding 状況を分析する。
3. `scene_audit` で構造化された問題一覧を取る。
4. 必要なら `node_query`、`scene_hierarchy`、`script_references` を組み合わせて node path と script reference を追う。

対応説明は [模块/脚本与场景分析.md](模块/脚本与场景分析.md)、[模块/NET支持.md](模块/NET支持.md)、[模块/工具域索引.md](模块/工具域索引.md) を参照してください。

### 5. User tool を管理し audit する

1. `plugin_evolution_list_user_tools` で現在の User tool を確認する。
2. `plugin_evolution_scaffold_user_tool` で未承認の preflight を行う。
3. 結果を確認したら `authorized=true` を渡して作成する。
4. `plugin_evolution_user_tool_audit` で承認と削除の記録を確認する。
5. Dock に `User` category を出したいなら、`plugin_developer_user_visibility` を組み合わせる。

対応説明は [模块/用户扩展.md](模块/用户扩展.md)、[模块/核心实现.md](模块/核心实现.md)、[模块/工具域索引.md](模块/工具域索引.md) を参照してください。

### 6. test matrix と regression 検証を回す

1. `tests/godot_plugin_harness` で plugin headless harness を走らせる。
2. 環境依存の問題を掘る必要があるときだけ、real Godot headless の経路を追加で回す。

対応説明は [测试/总览.md](测试/总览.md)、[测试/插件Headless测试.md](测试/插件Headless测试.md)、[测试/Smoke与CI.md](测试/Smoke与CI.md) を参照してください。

## 文書の保守ルール

- 文書は、既に `dev` に統合された最新実装を基準にし、廃止された dynamic dock の説明は残さない
- tool の return field、setting key、profile file format、client configuration template、permission boundary を変えたら、対応する章も更新する
- UI scene 構造、split container、control 名、page tab の挙動を変えたら、[界面/](界面/) の該当文書を更新する
- runtime service、Autoload、reload flow、自診断 record field、server lifecycle を変えたら、[架构/生命周期与装配.md](架构/生命周期与装配.md) と [架构/运行时服务.md](架构/运行时服务.md) を更新する
- 新しい tool domain を追加したり、executor directory を移したり、古い root-level entry を消したり、User tool scaffold 能力を追加したら、[模块/工具域索引.md](模块/工具域索引.md) と [附录/目录树与文件职责.md](附录/目录树与文件职责.md) を更新する
- test matrix、plugin harness、smoke structure、CI gate policy を変えたら、[测试/](测试/) の該当文書を更新する
- encoding policy、script read / write 方式、Windows PowerShell compatibility を変えたら、[附录/编码规范.md](附录/编码规范.md) を更新する
