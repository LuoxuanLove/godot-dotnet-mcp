# UI 概要

この文書は `addons/godot_dotnet_mcp/ui/` directory にある scene と script の関係、そして Dock root scene が統一 model を `Home`、`Tools`、`Resources`、`Prompts`、`Config`、`Settings` の 6 つの page にどう配るかを説明します。

---

## UI file の構成

現在の `addons/godot_dotnet_mcp/ui/` directory は次の file でできています。

| Path | 役割 |
|---|---|
| `addons/godot_dotnet_mcp/ui/mcp_dock.tscn` | Dock root scene |
| `addons/godot_dotnet_mcp/ui/mcp_dock.gd` | Dock root controller |
| `addons/godot_dotnet_mcp/ui/server_panel.tscn` | `Home` page scene（元の `server` file 名を継承） |
| `addons/godot_dotnet_mcp/ui/server_tab.gd` | `Home` page controller |
| `addons/godot_dotnet_mcp/ui/server_tab_model_projection.gd` | `Home` page の純投影 collaborator |
| `addons/godot_dotnet_mcp/ui/tools_tab.tscn` | `Tools` page scene |
| `addons/godot_dotnet_mcp/ui/tools_tab.gd` | `Tools` page controller |
| `addons/godot_dotnet_mcp/ui/mcp_catalog_tab.tscn` | 共通の `Resources` / `Prompts` page scene |
| `addons/godot_dotnet_mcp/ui/mcp_catalog_tab.gd` | 共通の MCP protocol catalog page controller |
| `addons/godot_dotnet_mcp/ui/config_panel.tscn` | `Config` page scene |
| `addons/godot_dotnet_mcp/ui/config_tab.gd` | `Config` page controller |
| `addons/godot_dotnet_mcp/ui/settings_panel.tscn` | `Settings` page scene |
| `addons/godot_dotnet_mcp/ui/settings_tab.gd` | `Settings` page controller |
| `addons/godot_dotnet_mcp/ui/settings_tab_model_projection.gd` | `Settings` page の pure projection collaborator |

---

## root scene の責務

`mcp_dock.tscn` は次を担当します。

- title bar
- status light
- 現在の状態 text
- `TabContainer`
- page scene を置く枠

`mcp_dock.gd` は次を担当します。

- 6 つの page scene を instantiate する
- page controller が上げる signal をつなぐ
- `plugin.gd` から渡される統一 model を受け取る
- page title、localization text、root-level status light を設定する
- 宿主 Dock の tab 切り替えと focus 復元を管理する

---

## root controller の data flow

現在の Dock は一方向の data flow を使います。

```text
plugin.gd
  -> mcp_dock.gd.apply_model(model)
  -> server_tab.gd / tools_tab.gd / mcp_catalog_tab.gd / config_tab.gd / settings_tab.gd
  -> server_tab_model_projection.gd / settings_tab_model_projection.gd（page 内の pure projection）
  -> user action signal
  -> plugin.gd
```

利点。

- UI layer は server や settings を直接読まない
- すべての page が同じ model を基準にする
- language 切り替え、scale、state refresh を同時に再描画できる

---

## signal bridge

`mcp_dock.gd` が橋渡しする signal は、おおまかに 4 つの種類です。

### service control

- `port_changed`
- `log_level_changed`
- `language_changed`
- `start_requested`
- `restart_requested`
- `stop_requested`
- `full_reload_requested`
- `clear_self_diagnostics_requested`
- `copy_requested`

### Tools page の操作

- `delete_user_tool_requested`
- `tool_toggled`
- `category_toggled`
- `domain_toggled`
- `tree_collapse_changed`

### MCP catalog page の操作

- `copy_requested`

### Config page の操作

- `cli_scope_changed`
- `config_platform_changed`
- `config_client_action_requested`
- `config_client_launch_requested`
- `config_client_path_pick_requested`
- `config_client_path_clear_requested`
- `config_client_open_config_dir_requested`
- `config_client_open_config_file_requested`
- `config_write_requested`
- `config_remove_requested`
- `copy_requested`

### Settings page の操作

- `port_changed`
- `log_level_changed`
- `language_changed`
- `update_source_changed`
- `update_custom_branch_changed`
- `update_check_requested`
- `update_apply_requested`

これらはすべて `plugin.gd` に戻り、そこから service object を呼びます。

## page の instantiate 方法

`mcp_dock.gd` は `_ensure_tabs()` の中で次を行います。

1. `TabContainer` の今ある child を空にする
2. 次を順に load して instantiate する
   - `server_panel.tscn`（`Home` page として使う）
   - `tools_tab.tscn`
   - `mcp_catalog_tab.tscn`（`Resources` page として使う）
   - `mcp_catalog_tab.tscn`（`Prompts` page として使う）
   - `config_panel.tscn`
   - `settings_panel.tscn`
3. page controller が `apply_model()` を実装しているか確認する

直接の page order は `Home` index 0、`Tools` index 1、`Resources` index 2、`Prompts` index 3、`Config` index 4、`Settings` index 5 です。共通の catalog controller は `set_catalog_mode("resources")` または `set_catalog_mode("prompts")` で mode を切り替えます。

その結果。

- 各 page は独立して node tree を保てる
- entry script は page の中身を知らなくてよい
- 新しい page を足すときは、scene と controller を追加して root scene に接続すればよい

## scale と layout の policy

UI scale は今も `EditorInterface.get_editor_scale()` を唯一の倍率源にしますが、実装では 2 種類の layout parameter を分けています。

### script でまだ管理するもの

- control の minimum height
- tool tree の column width
- 動的に作る card content の minimum height
- shadow size

### scene で優先的に持つもの

- `MarginContainer` の余白
- `VBoxContainer` / `HBoxContainer` / `GridContainer` の spacing
- separator の相対位置
- `VSplitContainer` の split layout

つまり page script は scale に関わる強い制約だけを残し、普通の UI spacing は `.tscn` 側で手で調整する方がよい、ということです。

---

## 今の UI directory の保守方針

- page controller は自分の page の表示と interaction だけを扱う
- Dock root controller は page 間の協調と signal 転送を担当する
- `Resources` と `Prompts` は共有 Dock catalog projection から MCP protocol metadata を render し、private catalog facts を作り直さない
- scene control 名は意味がわかるようにし、`XxxPanel`、`XxxMargin`、`XxxSeparator`、`XxxContent` を優先する
- 必要がない限り、script で普通の margin や separation を上書きしない
