# Tools ページの実装

この文書は、`addons/godot_dotnet_mcp/ui/tools_tab.tscn` と `addons/godot_dotnet_mcp/ui/tools_tab.gd` の node structure、tool tree、preview panel、現在の layout constraint を説明します。

---

## 目標責務

現在の `Tools` tab は 4 つの capability に集中しています。

1. 現在 enabled な tool 数を表示する
2. runtime が生成した Tool Presentation Model を受け取り、現在の tool を `domain -> category -> tool -> atomic/action` hierarchy で表示する
3. `system_*` tool が使う atomic tool chain を展開する
4. 選択 item の description、parameter、runtime info、atomic-tool preview を表示する

この tab は、profile selection、saving、renaming、deletion をもう扱いません。

## System Tool Tree

現在の tree は runtime Tool Presentation Model から生成されます。主な hierarchy は次の通りです。

```text
root
  ├─ core
  │   ├─ system
  │   │   ├─ system_editor_state
  │   │   │   ├─ editor_status
  │   │   │   ├─ editor_inspector
  │   │   │   ├─ editor_filesystem
  │   │   │   ├─ debug_runtime_bridge
  │   │   │   └─ debug_dotnet
  │   │   ├─ system_project_index_build
  │   │   │   ├─ filesystem_directory
  │   │   │   ├─ script_inspect
  │   │   │   └─ resource_query
  │   │   ├─ system_runtime_control
  │   │   │   ├─ status / enable / disable
  │   │   │   └─ runtime_control
  │   │   ├─ system_runtime_step
  │   │   │   ├─ step / capture / input
  │   │   │   ├─ runtime_step
  │   │   │   ├─ runtime_capture
  │   │   │   └─ runtime_input
  │   │   ├─ system_dap_debugger
  │   │   │   ├─ status / get_settings / set_settings / initialize / launch / attach / configuration_done / threads / disconnect
  │   │   │   ├─ set_breakpoint / remove_breakpoint / pause / continue / step_over / stack_trace / output / terminate
  │   │   │   └─ dap_debugger
  │   │   └─ ...
  │   └─ ... internal atomic categories
  └─ user
      └─ user
          ├─ user_tool_a
          └─ user_tool_b
```

補足:

- root は最初に domain node、次に category node を描画します。`system` と `user` はもう hard-coded root node ではありません
- `system_*` high-level tool は `SystemTreeCatalog` を通じて、実際の atomic / action chain に展開されます。たとえば `system_editor_control` は `click_control` や `right_click_control` のような control-local click action を表示します
- `runtime_*` は internal atomic category です。`system_runtime_*` の child chain としてだけ表示され、MCP tool として単独公開されません
- atomic tool node は recursive にさらに展開できます
- atomic tool の check state は通常の tool row と同じ logic に従い、`tool_toggled` を通じて戻ります

## 右クリック Menu と Popup 座標契約

Tools tab は現在、tool tree 上に Dock-local の `PopupMenu` を 1 つ作ります。これは name、English ID、schema の copy、または tree node の expand / collapse に使われます。`Tree.gui_input` が受け取る `mouse_event.position` は `ToolTree` の local coordinates であり、そのまま `PopupMenu.popup(Rect2i)` に渡せません。

座標境界:

- **local**: `ToolTree.gui_input` の `mouse_event.position` のような `Control` local coordinates
- **canvas global**: `Control` / `CanvasItem` transform 後の canvas coordinates。`get_global_transform_with_canvas()` などで得られ、hit testing や viewport input conversion に適しています
- **viewport**: 現在の `Viewport` 内 coordinates。`Viewport.push_input()`、screenshot cropping、visible-area conversion に使います
- **screen**: screen coordinates。`PopupMenu.popup(Rect2i)` など editor popup positioning entry は screen coordinates を使う必要があります。ここでは Godot popup placement を指し、desktop window control ではありません

そのため popup positioning は `_get_tree_context_menu_screen_position(local_position)` のような testable helper を通し、`ToolTree.get_screen_transform() * local_position` か同等の local-to-screen transform を使います。`mouse_event.position`、`get_screen_position() + local_position`、canvas-global coordinate を直接 `popup(Rect2i)` に渡してはいけません。別の Dock-local `PopupMenu` や `PopupPanel` を追加する場合も、先に同種の helper で包み、軽い contract test を追加します。

## Controller の責務

`tools_tab.gd` は現在次を扱います。

- model を受け取り text を refresh する
- model の `toolTree`、`toolGroups`、`tool_presentation` を優先して `TreeItem` を構築する
- presentation model がないときだけ旧 local-tree rebuild logic に fallback する
- selected item、context menu、preview scroll restoration を追跡する
- tool toggle と expand / collapse signal を emit する
- とても小さい layout で tree area と preview area を trim する

main controller は、すべての pure-logic helper を保持する形ではなくなりました。現在の責務は main controller として `ui/tools_tab.gd` にあります。

扱わないこと:

- profile persistence
- profile UI interaction
- server lifecycle control
- client config generation

## Search 実装

`ToolSearchEdit.text_changed` は tree rebuild を駆動します。

現在の search strategy:

- system tool name が一致したら、その tool を残す
- atomic tool name または description が一致したら、その system ancestor を残す
- search は `SYSTEM_TOOL_ATOMIC_CHILDREN` を recursive に照合するため、atomic tool を検索しても上位の system tool を見つけられる
- 現在の filtered result は `tools_tab.gd` 内で直接計算され、group ごとに render される

Search は persistent collapse state を書き換えません。現在の tree rebuild result だけを変えます。

## Preview Panel 実装

preview area は read-only `TextEdit` をまだ使います。

現在の preview target:

- domain
- category
- tool
- atomic
- action

System-tool preview には次も表示します。

- description
- action overview
- parameter schema summary
- recursive atomic-tool list
- tool を展開して atomic tool を確認できるという hint

---

## Split と Shadow 実装

### Split

tree area と preview area は `ContentSplit` (`VSplitContainer`) が管理します。script はもう `split_offset` を強制しません。今後の layout tuning は、まず `.tscn` 側で行うべきです。

### Shadow

tree area の top / bottom shadow は次で初期化されます。

- `TopShadow`
- `BottomShadow`

これらは `_configure_tree_shadow()` と対になり、scroll position に応じて runtime で表示 / 非表示を切り替えます。

---

## Minimum-Height Protection

とても小さい height に対して、2 層の protection があります。

1. tree area と preview area が縮み続けられるよう、低めの `custom_minimum_size` を使う
2. `TopPane`、`BottomPane`、tool-tree panel、preview panel で `clip_contents` を有効にする

これにより content は overlap や layout 外逃げの前に clip されます。

---

## 現在の UI 制約

`tools_tab.gd` は profile 関連の runtime override をもう適用しません。そのため、次はまず `tools_tab.tscn` で調整してください。

- search box 周辺の vertical spacing
- tool tree 周辺の vertical padding
- preview area と separator の距離

script に残っている主な UI-level control:

- control minimum height
- tree column width
- shadow size
