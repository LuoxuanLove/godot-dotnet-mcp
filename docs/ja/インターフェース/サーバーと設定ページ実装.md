# Home と Config ページの実装

この文書は、`Home` と `Config` ページの scene script の責務、動的 layout logic、config 生成 flow を説明します。file 名の `server_panel.tscn` と `server_tab.gd` はそのままですが、最新の README では最初の表示 tab はすでに `Home` として再整理されています。

---

## `Home` ページ

### 目標責務

`Home` は次を担当します。

- 現在の service state と service address を表示する
- connection count、request count、latest request を表示する
- port、auto-start、log level、language を変更する
- embedded server を start、restart、stop する
- full plugin reload を実行する
- plugin 自身の diagnostic summary を表示する

現在の Home ページは CORS allowlist を直接公開しません。local HTTP MCP へ cross-origin access が必要な browser 型 client は、`GODOT_DOTNET_MCP_ALLOWED_CORS_ORIGINS` environment variable に正確な origin を設定してください。CLI や desktop の config-file client は通常 CORS を必要としません。

### Controller の責務

`server_tab.gd` は現在、大きく 4 つのことを行います。

1. `server_tab_model_projection.gd` に model を pure presentation data へ投影させる
2. 投影結果を status text、button state、dropdown に書き戻す
3. Home ページの responsive layout と scaling logic を保つ
4. button と setting の action を signal に変換する

status overview、self-diagnostic summary、log / language option model は、もう `server_tab.gd` の中で直接組み立てていません。現在は `server_tab_model_projection.gd` にあります。

### Responsive Layout

`server_tab.gd` は `Tools` ページよりも多くの runtime layout control をまだ持っています。理由は次の control に依存しているためです。

- `GridContainer`
- diagnostic card
- multi-column settings area

これらは width に応じて、より詰めた配置へ切り替える必要があります。

### Self-Diagnostic Card

Home ページ上部の self-diagnostic card に表示される data は次から来ます。

- `plugin_runtime_state(action=get_lsp_diagnostics_status)`: 詳細な runtime self-check snapshot
- `project_state(include_runtime_health=true)`: User tool の検出と読み込み失敗診断を含む軽量 health summary

この内容は Home ページに残します。service state、service address、reload entry、plugin self-diagnostics が、別の service flow ではなく front page にまとまるためです。

## `Config` ページ

### 目標責務

`Config` は次を担当します。

- platform switching
- desktop client config display
- CLI command display
- Claude Code scope switching
- `godot-mcp` の one-click install、write、uninstall
- config text や command の copy
- install status と install location / scope を明確に表示する

### Controller 構造

`config_tab.gd` は、もうすべての client card を `.tscn` に事前配置しません。代わりに runtime で card を作ります。理由は次の通りです。

- platform switch 後は、現在の target client だけを表示する
- card content は model によって駆動され、multi-client expansion に向いている
- CLI client と desktop client では button combination が違う

### Client Card 生成

各 client card は runtime に `_create_client_card()` で作られます。

- `PanelContainer`
- `MarginContainer`
- `VBoxContainer`
- title、description、path text、content area、button area

Config ページの static group card と dynamic client card は、どちらも `config_tab.gd::_make_framed_panel_style()` を通して `PanelContainer.panel` を override します。background は editor theme の `Tree.panel` をコピーし、`StyleBoxFlat` に `Editor.separator_color` の `1px` border を加えます。これにより `Tools` ページと同じ background depth を保ちながら、card boundary を明確に戻します。

config content area は、もう editable control を直接使いません。代わりに `PanelContainer + Label` を使い、`TextEdit.read_only` theme style を適用します。copy button は content area の右上に浮かび、既定では hidden です。mouse が content area に入ると表示されます。これにより read-only text area の visual hierarchy を保ちつつ、狭い layout で `TextEdit` が追加する scroll や focus behavior を避けます。

button behavior:

- Desktop clients: capability に応じて `Write Config`、`Remove Config`、open client、path management、copy action を表示する
- CLI clients: capability に応じて one-click install / uninstall、open terminal、path management、copy action を表示する

### Platform Groups

`Config` は現在 platform を次に分けます。

- `desktop`
- `cli`

Claude Code には専用の scope-row display もあります。

## Config 生成と Write Flow

runtime flow:

```text
plugin.gd
  -> build model
  -> config_tab.gd
  -> user clicks Write / Copy
  -> mcp_dock.gd signal
  -> plugin.gd
  -> plugin/config/config_tab_action_service.gd
  -> plugin/config/client_config_service.gd
  -> ClientConfigService.write_config_file()
```

writing 中:

1. まず現在の UI に表示されている JSON text を parse する
2. target file が存在し parse できる場合は、元の config を読む
3. `mcpServers` node だけを触る
4. `godot-mcp` entry だけを update し、他の MCP server を overwrite しない

---

## `Server` と `Config` ページ共通の制約

- text は localization service によって駆動され、Godot auto-translation に依存しない
- action は signal を通じて `plugin.gd` に戻る
- tab 自身は `MCPHttpServer` や `SettingsStore` instance を保持しない
- read-only text area は、可能な限り Godot text-control theme を再利用する。Config ページの content area は `PanelContainer + Label` を使い、外観を揃えるために `TextEdit.read_only` style を適用する
