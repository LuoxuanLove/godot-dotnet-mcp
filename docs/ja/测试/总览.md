# テスト概要

この文書は、現在の test system の 3 層構造、実行方法、既知の coupling point、安定性 risk、CI gate policy を説明します。

---

## 3 層の考え方

test は、だいたい次の 3 層で考えると整理しやすいです。

1. unit / contract
2. plugin headless harness
3. smoke / CI gate

---

## 現在の方向

plugin の test は、個々の関数を細かく見るだけでなく、実際の editor flow に近いところまで確認します。

- tool contract が壊れていないか
- headless harness で plugin が動くか
- CI gate が危ない変更を止められるか

---

## 既知の coupling point

複雑な plugin なので、次のような coupling point があります。

- editor UI と runtime state の同期
- tool tree の構造と presenter
- localization と tool description
- settings persistence と client config

test 文書は、これらを隠すためではなく、どこを見ればいいかを示すためにあります。

---

## 使い方

1. まず全体の test 構造を把握する
2. 次に headless harness の詳細を見る
3. 最後に smoke / CI の gate を確認する

---

## 何を大事にするか

- 実際に動かす
- 失敗の理由を残す
- harness が壊れたら、壊れたまま放置しない
- test と文書をそろえる
