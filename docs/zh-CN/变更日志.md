# 变更日志


本项目的所有重要变更都会记录在此文件中。

本文档格式基于 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)，本项目遵循 [Semantic Versioning](https://semver.org/lang/zh-CN/spec/v2.0.0.html)。

## [Unreleased] ([2.0.0])

目标版本：2.0.0。

### Added

- 新增隔离的 Roslyn runtime bundle，使 Asset Library 和准备好的 addon 安装仍保留 C# 语义读取 / patch 工作流，同时不把插件 Roslyn 或 bridge 源码编译进宿主项目。
- 新增 MCP 2025-11-25 Resources、Resource Templates、Prompts 与 Tools metadata，包括 title、icon、annotation、input schema、output schema 和 JSON Schema 2020-12 声明。
- 新增 Dock Resources 和 Prompts 页，提供协议目录计数、ID 复制、resource preview、prompt 参数输入、生成 prompt 预览和受限 icon 渲染。
- 新增只读 editor log resources：`godot-dotnet-mcp://logs/editor/output` 与 `godot-dotnet-mcp://logs/editor/errors`。
- 为 `runtime_step(action=input)` 新增 mouse move / click 支持，并在 tool schema 中公开 viewport coordinate 字段。
- 新增结构化 User-tool recovery diagnostics，包含 diagnostic code、recommended action 和 follow-up tool hint。
- 新增空闲进程与 User-tool 监视诊断，使自诊断能够报告帧预算、扫描分片和监视器进度，而不必在每次 Dock 刷新时都触发较重的 runtime 查询。
- 新增 Config 页的 Antigravity 客户端接入指引，包括应用检测、应用打开、复制 MCP 配置和手动设置目录提示，同时不假设存在已公开文档化的可写配置文件契约。
- 新增轻量 Godot `Performance` 自定义监视器，覆盖插件 process time、slow-frame count 与 1 秒节奏的引擎采样，使编辑器卡顿可从 Debugger Monitor 和自诊断中检查。

### Changed

- 将默认 MCP 协议基线切换到 `2025-11-25`，包括 initialize metadata、tool-name validation、schema dialect policy 和明确的 optional capability boundary。
- 将默认 stdio transport 改为 newline-delimited JSON-RPC，旧 `Content-Length` framing 仅作为显式 compatibility mode 保留。
- 将默认 HTTP endpoint `127.0.0.1:3000/mcp` 调整为 MCP Streamable HTTP 语义，包括 protocol/session header、JSON 与 SSE `Accept` negotiation、Origin/CORS 检查、GET SSE stream、可恢复 event history、有限 POST SSE response、heartbeat、queued server-to-client delivery 和 `DELETE /mcp` session termination。
- 将公开 discovery 改为 resource-first / prompt-first：被动 help、activity、catalog、editor log、plugin maintenance 与 scene validation discovery 改由 Resources、Prompts 或 canonical action tools 承担，不再依赖旧 public discovery tools。
- 将 `tools/list` 改为 flat callable tool list，并携带 schema、annotation 与 output metadata；tree/group presentation data 转移到 catalog resources 和共享 Dock presentation snapshot。
- 将 catalog snapshots、catalog resources、`/api/tools`、Dock model metadata 与 Tools tab preview/search/schema-copy 路径统一到 `ToolCatalogManifest` 和 `ToolCatalogSnapshotService` 共享事实源。
- 将 Dock Tools rows、action previews、Resources、Prompts 与 schema inspection 改为渲染共享协议 metadata，而不是重建私有 UI catalog facts。
- 将 Dock Tools 页默认调整为 Agent Tools 调用面，并通过独立的 Internal 与 Diagnostics 视图查看 executor 布局和 legacy/public-tool 诊断。
- 将 Dock Resources 与 Prompts 页改为消费显式 presentation trees，按共享协议 metadata 分组 resource URI、resource template、workflow prompt 与 prompt argument，不再在 Dock 侧按 URI 或名称猜测分类。
- 将 Dock Resources 与 Prompts 页拆分为 Catalog 与 Diagnostics 视图，用户可在可读协议条目和 source / visibility / callability / group metadata 之间切换。
- 将编辑器启动与空闲刷新改为轻量 MCP server startup，将 auto-start 移出 `_enter_tree` 同步路径，懒加载非活动 Dock 页，按需加载 HTTP service bundle 和 tool runtime，将 disabled-tool filter 缓存到 runtime 初始化时再应用，让 Resources / Prompts 协议列表 projection 不触发 loader，仅为当前 Dock 页构建 catalog projection，并更保守地安排 User-tool 轮询和扫描分片，以减少大型项目中的编辑器卡顿。
- 将 Dock Tools 刷新检查和 User-tool runtime definition 对比改为复用轻量 signature，避免在空闲刷新期间反复序列化完整 presentation tree、metadata map 或 tool definition array。
- 将 User-tool 轮询改为在 runtime loading 关闭时跳过同步扫描，并把大目录遍历拆成有预算的分片，使空闲刷新保持响应。
- 将 audio、animation、signal、TileMap、UI、filesystem、node、project、resource、scene、group、geometry、material、lighting、navigation、particle、physics、shader、debug 与 editor 等根 domain 实现改为 split executors；debug/editor 仅保留薄 compatibility wrappers。
- 将 AtomicBridge、`MCPToolLoader`、stdio routing、plugin lifecycle wiring、reload handling、runtime context wiring、status/query projections 与 User-tool maintenance 拆入专用 services，同时保留 public facade。
- 将项目与随附插件许可证从 MIT 切换为 Apache-2.0，适用于 v2.0 line。

### Fixed

- 加强 HTTP 与 stdio JSON-RPC envelope handling、malformed framing、重复 / 冲突 HTTP body headers、response-envelope handling、disabled-tool parity 与 session validation，使 transport error 在支持的 MCP transports 间保持确定性。
- 修复 Prompt 与 Resource validation：未知或类型错误的 prompt 参数会带 allowed-argument metadata 被拒绝，binary `.scn` / `.res` 不再作为 text resource 读取。
- 修复 Dock catalog rendering，使可见 tool families 不会丢失，并在 SVG loading 前限制无效 Resource/Prompt icons。
- 修复 C# bridge patch/write actions，使写入前后都会重新验证 project-root 与 reparse-point boundary。
- 修复 clean Asset Library validation，使 exported addon install 会证明 isolated Roslyn runtime 可用、排除 plugin bridge/Roslyn source files，并拒绝 dirty addon/archive inputs。
- 修复 PR policy validation，使带 BOM 的 title/heading 可被识别，policy/version workflows 也覆盖 merge queue events。
- 修复升级后的 addon 副本启动稳定性：split tool executor 不再注册旧式全局 `MCP*Tools` class name，Dock 也不再执行会输出 `Cannot reload script while instances exist` 的脚本重载。
- 修复 Dock 更新同步：现在会按安全保留名单镜像 addon 目录，删除 GitHub archive 中已不存在的旧插件文件，例如旧的根级工具 monolith 脚本，而不是只覆盖写入新文件。
- 修复升级后的 addon 自更新恢复：新的插件实例会移除旧覆盖式 updater 遗留的已知根级工具 monolith 残留，并让 Dock 与 MCP 插件更新请求走同一个 archive-sync 入口，同时继续保留 `.import` 与 `dotnet_bridge/obj` 缓存文件。
- 修复插件更新同步反馈：Settings 页会在解析目标、下载、写入和刷新插件文件时显示阶段进度，避免较长同步操作看起来像界面空闲或卡住。
- 修复 MCP 工具发起插件更新同步时的可靠性：带 `/` 的 custom branch 会先解析目标 commit，再通过 commit/ref archive fallback 下载；基于 release 的目标尚未发现时会先触发 ref discovery，而不是在 Dock 路径仍可恢复时直接失败。
- 修复 Config 页的一键 CLI 接入操作：客户端命令改为非阻塞进程路径，并立即在面板内显示状态，避免编辑器一直卡到命令退出才弹出结果。
- 修复 Dock Tools 页首次打开响应性：默认只预先构建当前工具展示视图，Internal Executors / Diagnostics 树延后到用户切换对应视图时再构建。
- 修复 Dock Tools 页重复刷新：工具目录未变化时会通过轻量 catalog revision 复用上一次 presentation model，而不是每次当前页刷新都重建完整工具 snapshot。
- 修复 Dock 状态快照，使轻量视图复用缓存的 lifecycle context，并且只有当前页明确需要时才调用较重的 server diagnostics。
- 修复更新或热重载后的 MCP 工具发现恢复：`tools/list` / `tools/call` 会懒初始化空工具注册表，重叠的编辑器自动化调用会以 `editor_automation_busy` 快速失败，并避免空闲 GDScript LSP tick 日志刷屏导致编辑器或 MCP 客户端看起来卡住。
- 修复空闲 runtime tick：HTTP / stdio transport 不再每个编辑器帧都驱动已加载的 tool executor 与 GDScript LSP diagnostics，同时在性能诊断中公开 lifecycle tick 耗时。

### Documentation

## [1.3.0] - 2026-06-08

### Added

- 新增 v1.3.0 语义化编辑器自动化模型：编辑器 UI 指引要求客户端优先使用语义工作流，其次使用控件级聚焦 / 文本 / 数值 / 弹窗动作，仅在 fallback 场景中使用控件本地鼠标或指针事件。
- 新增 `system_editor_control(action="wait_for_ui")`，客户端可在继续自动化流程前按存在、可见性、文本和启用 / 禁用状态等待真实编辑器控件。
- 新增 `system_editor_control(action="get_popup")` 与 `system_editor_control(action="capture_popup")`，客户端可按返回的弹窗路径检查并裁切可见浮动编辑器弹窗或窗口。
- 为 `system_editor_control` 与低层 `ui_control` 点击动作新增点击 fallback 观测证据，包含已派发输入事件、Button 类目标点击前后状态、已观测控件信号，以及输入已送达但无激活证据时的提示。
- 新增 `system_editor_evidence` 高层视觉证据工作流，可捕获 editor、control、popup、active-dialog 与 automatic surface，并显式返回目标、fallback、降级、可见弹窗与截图策略元数据。
- 新增 `system_settings_dialog` Project Settings / Editor Settings 高层工作流，覆盖打开、状态、搜索、导航、标签页与分类聚焦、行模型、行解析、值读取 / 聚焦 / 设置 / 验证、界面截图、关闭和可信 `run_task` 编排。
- 新增 `system_inspector` 高层 Inspector 属性工作流，覆盖可见属性模型、唯一属性解析、类型化读取、值控件聚焦、受保护的 text/number/bool 写入、验证、截图，以及针对当前或已准备目标的可信属性任务。
- 新增 `system_project_lifecycle(action=start|stop)` 作为规范项目运行时会话生命周期入口，包含 marker 验证、自动停止、停止控制、前台窗口 fallback 元数据和运行时能力上下文。
- 新增 `system_tool_catalog`，客户端可按 query、category 或 domain 搜索公开工具，并查看匹配原因、动作、参数、可见性、启用状态和可选 schema。
- 新增 `system_tool_activity` 查询过滤与慢调用 / 失败诊断，客户端可按状态、工具和慢调用阈值检查运行中或最近调用，而无需读取无关活动记录。
- 新增 User 工具命名诊断，在 User 工具列表、脚手架预览和兼容性报告中暴露声明名、规范化名与公开 MCP 工具名。
- 新增 `system_scene_inspect` 统一只读场景检查入口，提供 `validate`、`analyze` 与 `full` 动作，同时保留既有场景校验和分析工具。
- 新增 `system_plugin_maintenance` 插件维护 canonical 高层入口，可统一执行状态、重载、更新状态、更新引用刷新、更新来源选择和启动更新流程。
- 新增项目配置检查能力，可读取导出预设和单个输入动作，并对敏感导出 option key 与本机绝对导出路径做脱敏。
- 本地化 MCP resource 与 resource template metadata，使 `resources/list` 与 `resources/templates/list` 跟随当前插件语言，不再硬编码英文。
- 新增 v1.4 canonical MCP resources，覆盖指南发现、项目与编辑器状态、活动状态 / 最近记录，以及公开 / 可见工具目录，同时保留既有兼容 resource URI。
- 为 Config 客户端卡片新增稳定能力矩阵，包含支持层级、可用动作元数据与说明 key。
- 为每个 `tools/call` result 新增 `structuredContent`，同时保留既有客户端使用的 text JSON content。

### Changed

- 将插件 metadata、protocol facts、.NET bridge metadata、plugin-update contract expectation、本地化 changelog 与发布说明源提升到 `1.3.0`。
- 调整 `system_settings_dialog(action="capture")`，优先按可见设置弹窗 / 窗口边界取证，其次按对话框控件边界取证，最后才回退到整编辑器截图，并返回 `capture_backend` 与 `capture_target_path` 证据元数据。

### Fixed

- 修复发布 workflow：当已有 release tag 已指向目标提交但 GitHub Release 仍需创建时可继续补建，并明确 tag 触发 workflow 现在只验证发布源文件，不创建正式 Release。
- 修复发布验证，使其稳定选择 Godot console 可执行文件，并让渲染出的 commit summary 遵守配置的 commit 数量上限。
- 限制 Settings 更新来源与分支选择器弹窗高度，使很长的已发现引用列表在菜单内滚动，而不会覆盖编辑器。
- 修复 Tools 页已启用和总数统计，使 plugin-domain 工具与 core、user 工具 domain 一起纳入统计。
- 加强 MCP resource diagnostics 脱敏，使大小写混合的 URL credential、bearer / API-key 变体、敏感文本 marker 与嵌套 metadata secret 在输出上报前被遮蔽。

### Documentation

- 新增本地化 v1.4.0 协议重构计划，并从四语路线图链接该计划。

## [1.2.0] - 2026-06-06

### Added

- 为 MCP resources 与 prompts 新增输出大小保护：超大的文件型 resource 会在完整读取前被拒绝，超长 prompt 文本会被裁剪并带上 `_meta` 字节大小详情。
- 为 `system_editor_control` 新增顶部菜单、弹窗选择、hover / leave、主屏幕切换和专注模式控制动作，让 Agent 在不依赖 OS 鼠标自动化的情况下覆盖更多 Godot 编辑器 UI。
- 新增 `system_tool_activity` 与 MCP 工具调用可选 `_mcp_context` 元数据，客户端可轻量查看正在运行的调用、最近完成记录、执行顺序和 Agent 自报协作上下文，同时不改变各具体工具 schema。
- 为 `/health` 新增 HTTP client session identity 与请求审计字段，包含 per-connection ID、request ID、client summary、活跃 session 与最近断开 session，便于多客户端诊断。
- 通过 `plugin_evolution_runtime_diagnostics` 与 `project_state(include_runtime_health=true)` 新增 User 工具运行时诊断，覆盖发现数量、加载失败、监视器状态、兼容性摘要与近期审计记录。
- 新增韩语作为可选择的 Dock 界面语言，并补齐主页、工具、配置、设置、工具预览、分类与插件开发者等关键界面标签的韩语文案。
- 扩展 Dock 本地化覆盖与验证，使韩语界面以及已有 locale 的可见标签、工具元数据、客户端配置说明与 Prompt Guide 文案能更稳定地使用本地化内容；产品名、路径、标识符和技术缩写继续保留为共享文本。

- 修复 `editor_status` 与 `node_transform` 对非法参数类型过于宽松的问题，增强输入校验鲁棒性。

## [0.3.0] - 2026-03-12

### Added

- 新增 Godot .NET / C# 工作流支持：`.csproj` 解析、模板化 C# 脚本写入、跨文件脚本引用索引，以及基于 `dotnet restore/build` 的结构化诊断。
- 新增运行时与插件自检能力，覆盖运行时错误上下文、编译错误定位、插件自检摘要、错误时间线与健康查询。
- 新增用户工具治理能力，包括脚手架版本化与兼容性检查、审计过滤与会话标识、删除前备份与最近恢复入口。
- 新增工具使用统计，可查看调用次数与最近调用时间。
- 新增工具配置导入导出，支持 profile 与 disabled tools 的 JSON 往返。
- 新增完整技术文档体系，覆盖插件结构、界面、组件与附录。

### Changed

- 将 Dock 中的插件自检摘要统一移动到 `Server` 页顶部，减少跨页重复信息。
- 重构 `Tools` 页的树形交互与信息层次，收口搜索、tooltip、状态标记、预览面板、拖动分隔与 profile 操作链路。
- 补齐新增分类、工具说明与提示的本地化资源。
- 将公开版本号提升到 `0.3.0`，并同步插件元数据与运行时版本字符串。

### Fixed

- 修复兼容执行器聚合导致的重复插件注册，保留 `plugin_runtime`、`plugin_evolution`、`plugin_developer` 三个独立入口。
- 修复继承脚本热重载不完整导致的工具域加载缺失，恢复 `script` 域及其扩展工具的稳定发现。
- 修复插件启停与运行时重载期间 HTTP 传输中断的问题，将软重载改为延迟调度。

## [0.2.0] - 2026-03-11

### Added

- 新增主项目运行时回读能力，可通过 `debug_runtime_bridge` 追踪 Godot 编辑器启动/停止后的调试会话状态。
- 新增更完整的插件治理层，包括运行时控制、自动化工具管理、开发者入口与使用引导。
- 新增插件权限级别与授权边界，用于区分稳定使用、自动化扩展和开发调试能力。
- 新增 `User` 分类管理支持，便于发现、审计与清理用户侧扩展工具。

### Changed

- 重新整理工具分组与插件分类，减少单个工具入口暴露过多动作的问题，提升可发现性。
- 简化 Dock 界面布局与文档，重点优化 `Server`、`Config`、`Tools` 在窄宽度下的可用性。
- 补充更多分类、工具说明与提示的多语言内容，减少未翻译标记。
- 同步 `README`、中文 README 与发布文档，使首次接入、安装与配置流程保持一致。

### Fixed

- 修复 `Tools` 页在折叠和重建过程中出现的 `Tree blocked` / 空实例报错，减少 Dock 使用时的中断和连锁错误。

### Known Limitations

- 当前运行时回读更适合读取结构化状态与生命周期信息，而不是完整镜像 Godot 原生 Output / Debugger 面板。
- 如果项目中已存在同名 `MCPRuntimeBridge` Autoload，插件不会强制覆盖该设置，相关运行时回读会显示为未安装。

## [0.1.0] - 2026-03-11

### Added

- 首个公开发布版本。
- 基于 Dock 的配置界面与工具 Profile 管理。
- 75 个顶层 MCP 工具。
- 场景、节点、资源、脚本、动画、材质、TileMap、导航、物理、音频与 UI 能力。
- Godot .NET / C# 场景绑定分析与导出成员审计。
- TileSet 最小闭环支持：`create_empty` 与 `assign_to_tilemap`。
- 调试事件缓冲与基础运行时诊断回读工具。
- 受控的临时场景目录与场景保存链路。
- 继承感知的资源类型过滤。
- 安装与发布打包文档。

### Known Limitations

- `/root/...` 路径兼容已做补丁，但最终行为仍依赖插件重载后的稳定性。
