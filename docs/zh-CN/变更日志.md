# 变更日志


本项目的所有重要变更都会记录在此文件中。

本文档格式基于 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)，本项目遵循 [Semantic Versioning](https://semver.org/lang/zh-CN/spec/v2.0.0.html)。

## [Unreleased] ([1.2.1])

目标版本：1.2.1。

### Added

- 新增 `system_editor_control(action="wait_for_ui")` 有界等待与验证动作，可轮询编辑器控件的存在、可见性、文本和启用 / 禁用状态，并在成功时返回匹配的 UI 证据，失败时返回超时观测负载。
- 新增 `system_settings_dialog` 设置类对话框高层工作流，可打开 Project Settings 或 Editor Settings、等待可见、搜索候选设置行、聚焦结果、截图取证并关闭界面，但不写入设置值。
- 新增只读 `system_settings_dialog(action=list_rows)` 设置行模型，可用保守置信度和证据字段描述可见设置类控件，且不会写入设置搜索框。
- 新增只读 `system_settings_dialog(action=read_value)` 设置值检查，可针对唯一可见设置行返回带行和值控件证据的 text、bool、number、enum 类型化结果，且不会写入设置值。
- 新增只读 `system_settings_dialog(action=resolve_row)` 设置行解析，客户端可在读取值或选择后续 UI 动作前确认唯一可见设置行。

### Internal

- 将插件 metadata、protocol facts、.NET bridge metadata、plugin-update contract fixture expectation、本地化 changelog 与发布说明源切换到 `1.2.1` 开发版本线。
- 扩展 Tools 页渲染契约与文档示例，使 `plugin` domain 与 core、user 工具 domain 一起纳入覆盖。
- 修复 Tools 页标题计数，使 `plugin` domain 工具也纳入已启用和总工具数量。

## [1.2.0] - 2026-06-06

### Added

- 为 MCP resources 与 prompts 新增输出大小保护：超大的文件型 resource 会在完整读取前被拒绝，超长 prompt 文本会被裁剪并带上 `_meta` 字节大小详情。
- 为 `system_editor_control` 新增顶部菜单、弹窗选择、hover / leave、主屏幕切换和专注模式控制动作，让 Agent 在不依赖 OS 鼠标自动化的情况下覆盖更多 Godot 编辑器 UI。
- 新增 `system_tool_activity` 与 MCP 工具调用可选 `_mcp_context` 元数据，客户端可轻量查看正在运行的调用、最近完成记录、执行顺序和 Agent 自报协作上下文，同时不改变各具体工具 schema。
- 为 `/health` 新增 HTTP client session identity 与请求审计字段，包含 per-connection ID、request ID、client summary、活跃 session 与最近断开 session，便于多客户端诊断。
- 通过 `plugin_evolution_runtime_diagnostics` 与 `project_state(include_runtime_health=true)` 新增 User 工具运行时诊断，覆盖发现数量、加载失败、监视器状态、兼容性摘要与近期审计记录。
- 新增韩语作为可选择的 Dock 界面语言，并补齐主页、工具、配置、设置、工具预览、分类与插件开发者等关键界面标签的韩语文案。
- 扩展 Dock 本地化覆盖与验证，使韩语界面以及已有 locale 的可见标签、工具元数据、客户端配置说明与 Prompt Guide 文案能更稳定地使用本地化内容；产品名、路径、标识符和技术缩写继续保留为共享文本。
- 为 health、插件 reload 与插件 update 响应新增维护窗口契约，使客户端能在生命周期 reload 或 update sync 期间识别临时断连、重连要求、重新获取工具列表要求和 retry guidance。
- 为所有支持的 Dock 语言本地化 maintenance window 响应中的重连提示。
- 新增 `system_editor_plugin_control`，客户端可检查第三方 EditorPlugin 的 project-setting 状态、editor-session 状态、可见 UI 提示、restart/manual-activation guidance 以及带保护的 enable/disable 行为。

### Changed

- 插件更新同步写入 addon 文件后，现在会刷新并等待 Godot 编辑器文件系统扫描完成，再调度插件生命周期 reload。
- 公开文档入口改为位于本地化文档树中，并使用各 locale 自己的目录名和文件名。
- 发布说明渲染改为使用英文 `v1.2.0` 发布说明生成 GitHub Release 正文，同时持久化发布说明会链接到英文、简体中文、日文和韩文版本。

### Fixed

- 修复 malformed JSON-RPC 参数处理，使 HTTP 与 stdio request 会一致地以 `-32602` 拒绝非对象顶层 `params`，同时非对象 `tools/call.arguments` 仍保持 tool-level `isError` result。
- 修复 C# 空 method 生成，使内部 edit helper 在缺少 body 时不再生成含义模糊的 fallback body。
- 修复 plugin evolution runtime diagnostics，使公开 `runtime_diagnostics` 入口转发实时 User 工具 runtime snapshot，让报告与 project health diagnostics 对齐。
- 修复 HTTP transport pipelining，使 keep-alive 连接中已 buffer 的多个 request 会在 async route 完成后继续 drain，而不是等待更多 socket byte。
- 为多客户端重连恢复新增 HTTP reconnect backpressure safeguard：每 frame 可接收多个 pending connection，拒绝过大的 pending request buffer，并在 response write failure 后关闭 client connection。
- 为 stdio frame processing 加入 async reentry guard、stop/restart response write 防护与单帧 request burst 处理，同时保留 tool-loader ticking，提高连续 stdio request 的稳定性。
- 修复 lifecycle reload scheduling failure，失败的 schedule attempt 不再让插件 reload state 保持 pending。
- 修复 project file reimport handling，使 `project.godot`、文本文件、sidecar metadata 和不支持的路径返回结构化 `not_importable_resource` 错误，而不是交给 Godot import pipeline。
- 修复 popup menu 自动化防护，使隐藏弹窗、禁用项、分隔线、子菜单行、重复文本和冲突选择器会清晰失败，而不是选中错误条目。
- 修复 DAP debugger 大小与超时防护，使异常 endpoint 返回清晰的 `dap_limit_exceeded` 错误，而不是占用长时间 Agent 请求。
- 修复本地化文档事实、链接、编码示例、发布说明措辞、UI / Config 引用、过时草稿片段以及日文 README 中的无效截图引用。

### Documentation

- 在 `docs/en/ROADMAP.md` 与 `docs/zh-CN/路线图.md` 中新增英文和简体中文路线图入口。
- 在 `docs/` 下补齐完整英文、简体中文、日文与韩文文档树，并让每个 locale 使用本语言目录名与文件名。
- 将公开文档导航迁移到本地化文档树，并从公开文档集中移除旧的根目录技术结构页面。
- 在本地化文档树承载 README 与变更日志入口后，移除根目录冗余的本地化 README 与 changelog 副本。
- 最终整理英文、简体中文、日文和韩文的持久化 `v1.2.0` 发布说明，并在标题与简介后加入跨语言发布说明链接。
- 更新发布 runbook 与发布说明渲染文档，使正式 GitHub Release 使用英文发布说明和英文 changelog 作为渲染正文来源。

### Internal

- 扩展 JSON-RPC request、HTTP server、stdio resources/prompts 与 tool router contract，结合 `2026-06-05.6` tool schema facts 更新覆盖 malformed `params` 与 `tools/call.arguments` 边界。
- 扩展 `mcp_resources_prompts_contracts`，验证 resource 输出限制、prompt 裁剪元数据和 `2026-06-05.5` tool schema facts 更新。
- 扩展 script edit service harness 覆盖，要求 C# 空 method body 使用明确的 `NotImplementedException` guard body，而不是含义模糊的 generated fallback body。
- 扩展 User-tool service、runtime health 与 project-state harness 覆盖，验证 runtime diagnostics 与 failed custom-tool load reporting。
- 扩展 plugin-evolution harness 覆盖，使公开 runtime diagnostics 持续转发实时 User 工具 runtime snapshot。
- 提升 tool schema facts 版本，并扩展菜单控制、弹窗选择、hover / leave、主屏幕切换和专注模式动作的 editor UI harness 覆盖。
- 将 tool activity registry 覆盖加入 router、stdio、registry 与 tool-loader harness contract，验证 context stripping、response activity summary、transport coverage 与公开 `system_tool_activity` entry。
- 更新 Tools 页面文档，加入 `system_tool_activity` tree entry 与 `_mcp_context` protocol boundary。
- 更新 protocol facts，使其覆盖公开 `system_tool_activity` 表面对应的新 tool schema version。
- 新增并扩展 docs i18n 验证，覆盖 tree-shape hash、本地化路径映射、Markdown 链接、草稿措辞、跨 locale 路径泄漏、冗余根文档、README 展示资产和重复 path key。

## [1.1.1] - 2026-05-31

### Added

- 将 `system_dap_debugger` 扩展为完整 Debug Adapter Protocol 会话入口，支持运行时设置、持久 session ID、`initialize`、`launch`、`attach`、`configuration_done`、`threads`、`terminate` 与 `disconnect` 动作，同时保持单一高层 DAP 工具表面。

### Changed

- 强化内置 MCP Prompt Guides：`godot.scene_bootstrap`、`godot.debug_triage` 与 `godot.binding_fix` 现在会返回包含推荐工具顺序、验证要求和避免事项的可执行工作流说明，不再只是单行提示。

### Fixed

- 修复 `system_bindings_audit` 在大型项目中可能冻结 Godot 编辑器的问题：同一次调用内会缓存场景审计结果，使每个唯一场景只加载和实例化一次，并复用连续原子调用中的 executor，让 reference index 与 Roslyn 缓存可跨脚本检查保留。
- 修复 atomic executor 缓存失效判断：`get_settings` 等读操作不再因子字符串命中被误判为写操作；成功写入后会清理 cached executor，避免 reference 与 Roslyn 数据过期。
- 修复 `system_project_state(summary=true)` 与仅请求 summary 分段时仍会先构建完整脚本、场景和资源路径数组的问题；现在会使用一次批量轻量文件计数，再返回紧凑载荷。
- 通过 `system_help` 暴露 MCP Prompt Guides，使 Agent 能从主要能力说明中发现 `prompts/list`、`prompts/get` 和三个内置 prompt ID。

### Documentation

- 记录 `system_project_state(sections=[...])` 会优先于 `summary=true`，`health` 分段会触发插件健康采集，并明确 `files` 分段才是大型项目中需要完整路径数组的边界。
- 在工具系统、服务路由和运行时服务文档中记录 Prompt Guides 的发现与使用方式，并说明 MCP prompts 与可执行 tools 的边界。

### Internal

- 扩展 DAP 契约 harness，覆盖持久 fake server 生命周期流程、默认仅允许 loopback 端点的安全边界和原始响应脱敏处理，并公开 `dap_invalid_session_state` / `dap_invalid_settings` / `dap_limit_exceeded` 协议错误标识。
- 复用 `atomic_bridge.call_atomic` / `call_atomic_async` 中的原子 executor 实例，不再每次调用都重建，以便连续原子调用保留 `reference_service._reference_index`、`inspect_service._plugin_roslyn_service` 和其他实例级缓存。
- 增加契约覆盖，验证 `system_project_state` 紧凑读取会跳过完整路径枚举、通过一次 count-only 请求批量统计项目文件总数，而默认完整载荷与 `files` 分段仍会按需收集文件路径。
- 扩展 prompt guide、system help、router 和本地化 harness 契约，防止 prompt 内容深度、prompt 可发现性、真实 prompt ID 和多语言 Help 描述再次退化。

## [1.1.0] - 2026-05-28

### Added

- 新增 `system_dap_debugger` 与内部 `dap` 工具分类，支持 Godot Debug Adapter Protocol 的端点状态、断点设置 / 移除 / 列表、暂停 / 继续 / 单步跳过、调用栈和输出事件读取，使用 `Content-Length` JSON 帧格式，并公开 `dap_unavailable` / `dap_response_failed` 错误标识。
- 新增一等 MCP Resources 与 Prompts 支持：客户端可发现项目信息与诊断摘要 resources，通过严格 `res://` 模板读取 scene/script/resource 文件，并获取 `godot.scene_bootstrap`、`godot.debug_triage` 与 `godot.binding_fix` 引导 prompts。
- 新增 `system_project_state(summary=true)` 紧凑摘要和 `system_project_state(sections=[...])` 分段读取，使大型项目可按需读取关键健康、文件、运行时、能力位和插件健康段落，不必每次返回完整状态载荷。

### Fixed

- 修复插件启动与设置持久化路径：运行时状态、设置存储和核心服务会先完成初始化，再被 load/save 或更新回调访问。
- 修复插件 harness 验证：Godot stdout/stderr 中出现 `SCRIPT ERROR:`、`Invalid call.`、`Parse Error:` 等运行时或解析错误标记时会直接失败，不再被成功的进程退出码掩盖。

### Documentation

- 新增 `v1.1.0` 手写发布说明源文件，用于本次调试、resources、project state 与启动验证版本，并在版本线推进后移除过时的 `v1.0.1` 源说明。
- 更新 README、运行时服务、工具系统、Tools 页、测试与 CI 文档，覆盖 MCP Resources 与 Prompts、DAP 调试器工具、`system_project_state` 紧凑读取、tool catalog resources 和 harness 验证行为。
- 补齐并修正英文、中文、德文、西班牙文、法文、日文、葡萄牙文与俄文 locale resources 中的 DAP 与 system 工具说明，并在发布 Runbook 中记录 emoji 发布说明模板和 Documentation/Internal changelog 维护规则。

### Internal

- 扩展插件 harness 与契约测试覆盖，涵盖 DAP 调试器流程、MCP Resources 与 Prompts 路由、`system_project_state` 紧凑读取、JSON-RPC resource/prompt 方法、tool-loader catalog 分类、debug executor 兼容性、更新 fixture 和插件入口初始化。
- 为 Godot harness 增加运行时 / 解析错误标记检测，使 stdout/stderr 诊断即使在 Godot 进程成功退出时也会让验证失败。
- 隔离 Tools 页渲染 harness 用例，并更新插件侧 Roslyn harness 路径，使新增协议与工具面覆盖扩展后 required validation 仍保持稳定。

- `intelligence_script_analyze(include_diagnostics=true)` 改为“结构先返回、诊断后补齐”的模式，不再阻塞等待 `publishDiagnostics`。
- `/api/tools`、MCP `tools/list` 与 Dock Tools 统一基于同一份可见工具集生成；兼容别名仍可调用，但不再作为主展示入口。
- GDScript LSP diagnostics 服务由 `tool_loader` 统一持有，并跨 `reload_domain`、`reload_all_domains`、`soft_reload_plugin` 接管生命周期，减少旧实例残留。
- 运行时说明与对外文档统一围绕 `plugin_runtime_state`、`intelligence_project_state` 和当前路由行为收口。

### Fixed

- 修复 `soft_reload_plugin` 偶发出现的“HTTP 服务仍在线但工具注册表为空”问题；现在会一起重建 server/controller 与 tool loader，保持 `/health`、`/api/tools` 与 `tools/call` 一致。
- 修复 Tools 树在递归展开/折叠后的状态回填错乱；根节点与 `atomic` 层现在会按统一状态模型正确恢复，不再反复回弹。

## [0.4.0] - 2026-03-17

### Added

- 新增 Intelligence 工具层，提供 15 个面向项目级推理与操作的高层工具，分为四类：
  - **Project（6）**：`intelligence_project_state`、`intelligence_project_advise`、`intelligence_project_configure`、`intelligence_project_run`、`intelligence_project_stop`、`intelligence_runtime_diagnose`
  - **Scene（3）**：`intelligence_scene_validate`、`intelligence_scene_analyze`、`intelligence_scene_patch`
  - **Script（3）**：`intelligence_bindings_audit`、`intelligence_script_analyze`、`intelligence_script_patch`
  - **Index（3）**：`intelligence_project_index_build`、`intelligence_project_symbol_search`、`intelligence_scene_dependency_graph`
- 新增 Atomic Bridge 调度层，用于连接 Intelligence 工具与底层原子工具并支持工具链组合。
- 新增用户自定义工具集成：放置在 `custom_tools/` 下的工具需要使用 `user_*` 前缀，并实现 `handles()`、`get_tools()` 与 `execute()`。
- 新增插件目录写保护（`PLUGIN_PROTECTED_PATHS`），防止插件自有文件被未授权修改。
- 新增 9 种语言的 Intelligence 文档本地化：de/en/es/fr/ja/pt/ru/zh_cn/zh_tw。

### Changed

- 重构 `Tools` 页树结构：顶层直接显示 Intelligence 工具，每个工具可展开查看其依赖的原子工具链，原子工具还可继续展开到 Action 节点。
- 新增 `Shift` 递归展开/折叠，以及右键菜单（复制工具名、Schema、删除用户工具）。
- 重构 `MCPDebugBuffer` 日志系统：统一 source 命名、增加日志级别（`trace/debug/info/warning/error`），并补齐 `tool_loader`、`intelligence`、`atomic_bridge`、`impl_*` 的关键日志点。
- 仓库目录重组为 Godot Asset Library 规范的 `addons/godot_dotnet_mcp/` 布局，并新增 `.gitattributes` 控制发布 ZIP 内容。

### Removed

- 移除 `Tools` 页 Profile 预设管理 UI；Profile 管理迁移到 `plugin_developer_*` 工具组中通过 MCP 完成。
- 暂时移除 `Tools` 页用户工具管理 UI；用户工具的创建、删除与恢复目前统一通过 `plugin_evolution_*` 工具组完成，后续版本可能恢复独立 UI。

### Fixed

- 修复多项 MCP 工具在 `array` 类型参数缺少 `items` 定义时触发的 `Invalid schema` 错误，涉及 `node_call`、`undo_redo`、`group`、`signal`、`collision_shape` 等工具。
- 修复 `editor_status` 与 `node_transform` 对非法参数类型过于宽松的问题，增强输入校验鲁棒性。

## [0.3.0] - 2026-03-12

### Added

- 新增 Godot .NET / C# 工作流支持：`.csproj` 解析、模板化 C# 脚本写入、跨文件脚本引用索引，以及基于 `dotnet restore/build` 的结构化诊断。
- 新增运行时与插件自检能力，覆盖运行时错误上下文、编译错误定位、插件自检摘要、错误时间线与健康查询。
- 新增用户工具治理能力，包括脚手架版本化与兼容性检查、审计过滤与会话标识、删除前备份与最近恢复入口。
- 新增工具使用统计，可查看调用次数与最近调用时间。
- 新增工具配置导入导出，支持 profile 与 disabled tools 的 JSON 往返。
- 新增完整技术文档体系，覆盖插件结构、界面、组件与附录。

### Changed

- 将 Dock 中的插件自检摘要统一移动到 `Server` 页顶部，减少跨页重复信息。
- 重构 `Tools` 页的树形交互与信息层次，收口搜索、tooltip、状态标记、预览面板、拖动分隔与 profile 操作链路。
- 补齐新增分类、工具说明与提示的本地化资源。
- 将公开版本号提升到 `0.3.0`，并同步插件元数据与运行时版本字符串。

### Fixed

- 修复兼容执行器聚合导致的重复插件注册，保留 `plugin_runtime`、`plugin_evolution`、`plugin_developer` 三个独立入口。
- 修复继承脚本热重载不完整导致的工具域加载缺失，恢复 `script` 域及其扩展工具的稳定发现。
- 修复插件启停与运行时重载期间 HTTP 传输中断的问题，将软重载改为延迟调度。

## [0.2.0] - 2026-03-11

### Added

- 新增主项目运行时回读能力，可通过 `debug_runtime_bridge` 追踪 Godot 编辑器启动/停止后的调试会话状态。
- 新增更完整的插件治理层，包括运行时控制、自动化工具管理、开发者入口与使用引导。
- 新增插件权限级别与授权边界，用于区分稳定使用、自动化扩展和开发调试能力。
- 新增 `User` 分类管理支持，便于发现、审计与清理用户侧扩展工具。

### Changed

- 重新整理工具分组与插件分类，减少单个工具入口暴露过多动作的问题，提升可发现性。
- 简化 Dock 界面布局与文档，重点优化 `Server`、`Config`、`Tools` 在窄宽度下的可用性。
- 补充更多分类、工具说明与提示的多语言内容，减少未翻译标记。
- 同步 `README`、中文 README 与发布文档，使首次接入、安装与配置流程保持一致。

### Fixed

- 修复 `Tools` 页在折叠和重建过程中出现的 `Tree blocked` / 空实例报错，减少 Dock 使用时的中断和连锁错误。

### Known Limitations

- 当前运行时回读更适合读取结构化状态与生命周期信息，而不是完整镜像 Godot 原生 Output / Debugger 面板。
- 如果项目中已存在同名 `MCPRuntimeBridge` Autoload，插件不会强制覆盖该设置，相关运行时回读会显示为未安装。

## [0.1.0] - 2026-03-11

### Added

- 首个公开发布版本。
- 基于 Dock 的配置界面与工具 Profile 管理。
- 75 个顶层 MCP 工具。
- 场景、节点、资源、脚本、动画、材质、TileMap、导航、物理、音频与 UI 能力。
- Godot .NET / C# 场景绑定分析与导出成员审计。
- TileSet 最小闭环支持：`create_empty` 与 `assign_to_tilemap`。
- 调试事件缓冲与基础运行时诊断回读工具。
- 受控的临时场景目录与场景保存链路。
- 继承感知的资源类型过滤。
- 安装与发布打包文档。

### Known Limitations

- `/root/...` 路径兼容已做补丁，但最终行为仍依赖插件重载后的稳定性。
