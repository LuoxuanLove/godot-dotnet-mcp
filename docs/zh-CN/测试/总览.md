## 当前结构判断

### 已经合理的部分

- 测试已经从"单个 smoke 脚本"演进为独立的 harness 层，不再把所有验证都堆在一个入口里。
- 插件测试已经开始使用 fake collaborator 验证 `impl_runtime`、`impl_index` 等组件，说明不是所有测试都依赖真实运行时。
- Config 页运行时链已经补入 `serializer / inspection / file transaction / launcher adapter` 四类轻量契约。

### 当前边界

#### 1. 插件 contract tests 已脱离私有方法名，但 seam 仍可继续收口

当前 `http_server_contract_test.gd` 与 `runtime_bridge_contract_test.gd` 已改为走公共入口，不再直接依赖下划线方法。
这一轮已经显著降低了"内部方法改名即测试碎裂"的风险，而且 runtime fallback / reply 行为也已经从 bridge 节点里抽出第一轮独立 helper；但 `mcp_http_server.gd` 与 `mcp_runtime_bridge.gd` 仍然持有一部分测试 seam。

#### 2. CI 中环境依赖测试仍未完全硬门禁

当前 `validate-plugin.yml` 会先下载 Godot 4.6，再运行 plugin harness。
这意味着插件测试层已经作为强门禁接入 CI，而不是可选快测。

## 设计原则

当前测试体系的演进原则如下：

- 测试能力是一级结构关注点，不再附属于 smoke 脚本或人工真机验证。
- 尽量通过稳定 seam 测试对外行为，而不是依赖私有实现细节。
- 大文件先拆再改，测试文件也遵循相同规则。
- 公开工具行为、UI 结构、生命周期语义或 workflow 行为变化时，受影响 contract tests 必须同批次更新，不能把旧契约失败当作无关失败带过。
- Review 阶段发现测试或文档仍引用旧结构时，按返修项处理；只有契约测试、文档和 changelog 同步后，才视为完成。若测试、harness 或 workflow 行为属于重要内部变化，也必须以 `Internal` 条目进入 changelog。
- 环境依赖用例必须单独声明门禁策略，不能和快测层混成一类。
