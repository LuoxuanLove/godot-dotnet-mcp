# Dock 界面风格规范

本文档是 Godot .NET MCP 所有 Dock 页面的统一视觉与交互约束。新增页面或对既有页面进行重要调整时都应遵循本规范；若受编辑器限制无法遵循，必须记录原因并用针对性测试覆盖。

## 基本原则

- 保持 Godot 原生风格：继承编辑器主题、控件、图标、焦点行为与缩放比例。
- 保持界面安静：优先展示当前任务和主操作，再展示元数据与诊断信息。
- 使用渐进披露：关键状态常驻，审计和技术细节按需展开。
- 简化展示时不能削弱功能；移动次要信息时，相关操作和证据仍必须可达。
- 当前、警告、错误、选中和禁用状态都不能只依靠颜色表达。

## 页面层级

页面最多使用三级结构。

| 层级 | 用途 | 约束 |
|---|---|---|
| 页面 | 一个 Dock 页签 | 至多使用一个页面级 `ScrollContainer`；专用 `Tree` 或预览窗格可以独立滚动，且不允许页面级横向滚动。 |
| 卡片 | 一个功能区域 | 每张卡只保留一个标题、至多一条常驻说明和一个状态区域。 |
| 控件组 | 一组相关字段或操作 | 标签、控件与反馈保持相邻，并使用稳定间距。 |

视觉顺序必须与键盘焦点顺序一致。把最常用流程放在前面，将固定仓库信息、哈希、时间戳和审计轨迹放入次级详情。

用于限定列表、表格、预览或编辑器范围的选择器必须紧邻放在对应内容之前；选择器和其控制内容之间不能插入无关状态、元数据或操作。

## 间距与布局单位

所有数值均为逻辑像素，并乘以当前编辑器缩放比例。

| 单位 | 用途 |
|---|---|
| `4` | 紧密关联的图标、徽标或辅助内容 |
| `8` | 同一控件组内的控件和按钮 |
| `10` | 卡片正文或内嵌状态面板的内容节奏 |
| `12` | 页面边距、卡片纵向内边距和主要控件组间距 |
| `14` | 卡片横向内边距 |
| `16` | 仅用于宽布局的大区域间距 |

普通边距和容器间距优先写在 `.tscn` 场景中。脚本可以按缩放比例调整数值或在断点处重排，但没有运行时原因时不应重复覆盖静态场景间距。

## 主题、文字与图标

- 复制并调整编辑器的 `PanelContainer`、`Tree`、`LineEdit`、`TextEdit` 等样式，不建立脱离编辑器的独立配色体系。
- 从 `Editor` 主题读取强调色、分隔线、错误色、字体色和禁用字体色。
- 熟悉的编辑器操作使用 `EditorIcons`。纯图标操作必须提供 tooltip 和可理解的动作名称。
- 主要内容使用普通 Label 字色；说明、提示和元数据逐级弱化，但在明暗编辑器主题下都必须可读。
- 除非所有页面都引入统一语义变体，否则章节标题沿用编辑器默认字号。

## 表单与控件宽度

- 常规宽度使用两列 `GridContainer` 排列标签与字段。
- 标签的常规最小宽度约为 `112` 逻辑像素；字段自适应扩展，不依赖最长本地化选项决定宽度。
- 超窄布局切换为单列，清除固定字段宽度，并让标签紧邻对应控件之前。
- 长路径、引用和 ID 只有在 tooltip 或详情中能查看完整值时才可省略显示。
- 禁用控件不能成为唯一说明；附近状态文本或本地化 tooltip 必须解释不可用原因。

## 状态、帮助与详情

- 每张卡最多保留一条常驻说明和一个实时状态区域；控件、状态或空态已经能解释流程时应移除说明，两者也不得重复同一指引。
- 空闲提示要明确下一步操作；加载状态要说明作用范围、锁定冲突操作，并在可度量时显示进度。
- 成功提示应简短；错误提示必须保留原因，并在已知时给出恢复动作。
- 触发来源、HTTP 状态、限流恢复时间、哈希和比较数量等运维元数据应放入可折叠详情。
- 常驻状态区负责给出主要结论；详情只补充信息，不得重复同一错误或摘要，只有能增加可操作诊断证据时才自动展开。
- 错误或额度耗尽且详情能提供上述证据时可以自动展开；普通审计信息默认折叠。

## 列表、表格与空态

- 只展示选择或判断所需的列；窄布局下将次要日期与标识移入 tooltip 或详情。
- 当前行除颜色外还必须有文字或图标标记，并且不能提供重复选择当前项的操作。
- 行选择用于确定目标时必须高亮整行。选择只更新这个无副作用目标；实际变更、导航或切换必须由独立的行操作执行。
- 行级操作属于三级操作；即使使用编辑器图标，也要提供本地化标签或 tooltip。
- 空列表应隐藏空 `Tree`，并以简短空态区分尚未加载、加载中、无结果和错误。
- 模型刷新期间要保持选择、滚动位置与延迟执行的行操作稳定。

## 操作语义

| 优先级 | 典型用途 | 位置 |
|---|---|---|
| 主要 | 启动、应用或一键更新 | 每张卡一个，位于视觉和焦点顺序末尾 |
| 次要 | 刷新、复制、重试或展开详情 | 靠近受影响范围 |
| 三级 | 逐行切换或紧凑工具操作 | 对应行或上下文菜单内 |
| 破坏性 | 移除、清除或删除 | 与常规操作分隔，可能丢失内容时需要确认 |

仅 hover 显示的控件可以作为已有操作的快捷入口，但不能成为重要操作的唯一入口。

恢复缓存状态不得触发联网或操作性修改。被动选择器可以持久化所选值并重置依赖的临时本地状态，但不得启动发现、更新、切换、导航或其他外部操作。这些操作必须由专用的显式用户动作触发，重复重试应遵守已知冷却或限流状态。

## Dock 响应式行为

| 内容宽度 | 预期布局 |
|---|---|
| `>= 560` | 两列表单、紧凑摘要行和并排动作按钮 |
| `360-559` | 在可读前提下保留两列表单，减少元数据并压缩表格 |
| `< 360` | 单列表单与动作、清零固定字段宽度，并降低表格高度 |

使用容器和 size flags 保证页面在 Dock 最小宽度下仍可用。避免固定列宽总和超过可用宽度。除编辑器缩放 `1`、`1.5`、`2` 外，还要验证矮 Dock 和高 Dock。

## 可访问性

- 所有重要操作都要保留键盘焦点，并让焦点顺序符合视觉顺序。
- 每个语义状态都要用文字、图标、形状或位置与颜色共同表达。
- 纯图标控件需要 tooltip 和有意义的可访问文本。
- 理解或操作页面不能依赖 hover、动画或指针坐标。
- 目标尺寸与对比度要与 Godot 编辑器主题保持一致。

## 本地化

- 所有可见标签、tooltip、空态、加载状态和错误信息都通过插件 locale 文件本地化。
- 不用片段拼接可翻译句子；优先使用带明确格式参数的完整消息。
- 正文使用智能换行，并同时测试德语或俄语扩展以及中文、日文、韩文布局。
- 按钮必须保留动作动词；需要压缩时先缩短辅助文案，不截断操作名称。

## 场景与脚本职责

- `.tscn` 场景负责语义化控件名称、普通容器、基础边距、间距和初始可见性。
- 页签脚本负责 model 渲染、信号、编辑器缩放、断点、动态行、tooltip，以及必须从编辑器读取的主题值。
- model 投影服务负责状态归一化和可直接展示的数据；view 脚本不能通过匹配翻译文本推断行为。
- Dock 根代码只负责跨页签协调；页面专属布局留在页面场景与控制器中。

## 验收矩阵

重要 UI 变更应在自动化契约或编辑器证据中覆盖以下维度：

| 维度 | 最低覆盖 |
|---|---|
| 宽度 | `280`、`360`、`560` 和一个宽布局 |
| 缩放 | 几何受缩放影响时覆盖 `1`、`1.5`、`2` |
| 语言 | 英语、一种较长的拉丁或西里尔语言、一种 CJK 语言 |
| 状态 | 空闲、加载、成功、错误、限流和空列表 |
| 主题与输入 | 兼容明暗主题的颜色值和键盘焦点 |

验收要求：无重叠、无页面级横向滚动、无纯颜色状态、动作本地化完整，并且受影响界面原已暴露的全部功能仍然可达。
