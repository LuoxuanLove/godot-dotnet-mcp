# v2.0.0 协议重构计划

## Summary

Godot .NET MCP v2.0.0 采用“强力清债 + 协议纯化 + 2025-11-25 conformance”路线：按 MCP 2025-11-25 规范，把上下文、状态、目录迁回 Resources，把工作流指南留给 Prompts，把 Tools 收窄为真正执行动作或计算性工作流的入口。

旧的 2025-06-18 对齐成果作为兼容基础保留；v2.0.0 发布目标改为默认 MCP surface 符合 2025-11-25。公开工具面允许 breaking cleanup，但每个删除都必须有替代入口、replacement metadata 和 removal guard 测试。

目标形态：少量 canonical public tools + resource-first 认知入口 + 单一工具目录事实源 + 2025-11-25 transport/schema/metadata 门禁。

## Key Changes

- 协议基线切换为 `protocolVersion = 2025-11-25`；`serverInfo` / `Implementation` 增补 `description` 等人类可读 metadata。
- Resources 保留 canonical URI：`guides/index`、`guides/capabilities`、`guides/ui-automation`、`state/project/summary`、`state/editor`、`activity/status`、`activity/recent`、`activity/call/{id}`、`tools/catalog/exposed`、`tools/catalog/visible`，并补 2025-11-25 `icons` / title metadata。
- Prompts 继续保留 6 条工作流；不再推荐先调用 `system_help`，并补 `icons`、参数 schema、路径/枚举/布尔参数 guard。
- Tools 公共面继续删除认知型/重复型入口：`system_help`、`system_tool_catalog`、`system_tool_activity`、scene aliases、plugin reload/update aliases、editor log aliases、旧 internal aliases。
- `tools/list` 保持标准 MCP 工具列表，只返回可调用工具、`inputSchema`、`outputSchema`、annotations、icons、必要 `_meta`；tree/group/action 展示数据只放 catalog resources。
- `inputSchema` / `outputSchema` 默认按 JSON Schema 2020-12；旧 schema 若不能保证兼容，显式声明 `$schema`。
- 工具名新增 guard：长度 1-128、大小写敏感，推荐 ASCII 字母/数字/`_`/`-`/`.`，禁止破坏客户端解析的字符。
- 调整 Dock 与 Tools UI 设计，使其从 resources/snapshot 消费 2025-11-25 catalog metadata（`icons`、title、description、schema dialect、output schema、exposure state），而不是重建私有展示树。
- 默认 MCP endpoint 保留 `http://127.0.0.1:3000/mcp`，但语义升级为 MCP 2025-11-25 Streamable HTTP transport，而不是插件私有 JSON-RPC API。
- HTTP 默认请求形态为 `POST /mcp`，带 `Accept: application/json, text/event-stream`、`Content-Type: application/json`、`MCP-Protocol-Version: 2025-11-25`。
- `/api/tools`、`/health`、旧 JSON-only POST 行为和旧 `Content-Length` stdio 只作为 legacy compatibility surface。
- stdio 默认迁移到 2025-11-25 newline-delimited JSON-RPC；旧 `Content-Length` framing 仅作为 legacy compatibility mode。
- HTTP 迁移为完整 Streamable HTTP：校验 `MCP-Protocol-Version`、`Mcp-Session-Id`、`Accept`、Origin 403、SSE polling/resumption 行为。
- Sampling / Elicitation / Tasks 作为可选能力：不声明则不实现；声明后必须按 2025-11-25 contract 实现。

## Implementation Plan

### 1. 测试护栏先行

- 扩展 contract case manifest：新增 `mcp_version=2025-11-25|2025-06-18|legacy`、`conformance=required|compat|optional`。
- 建立 `mcp_2025_11_25_conformance_contracts`，覆盖 lifecycle、stdio、Streamable HTTP、Tools、Resources、Prompts、schema、metadata。
- 旧 2025-06-18 测试降级为 compatibility / migration guard，不再代表发布目标。
- 所有 breaking removal 必须同时验证：不在 `tools/list`、不在 visible catalog、legacy call 返回 replacement error。

### 2. 协议面纯化

- `initialize` 返回 `2025-11-25`、标准 capabilities、serverInfo description。
- `mcp_resources_service.gd` 继续作为 guide/state/activity/catalog 入口，并补 icons/title。
- Prompts 文本固定为 resource -> prompt -> canonical tool -> resource/activity 验证路径。
- `tools/list` 移除所有展示树、分组、atomic/action 内部数据。
- HTTP 与 stdio 共用同一 JSON-RPC router、result normalization、resources/prompts/tools dispatch。

### 3. Transport 适配

- `http://127.0.0.1:3000/mcp` 是默认 MCP Streamable HTTP endpoint，用于 Godot 编辑器已打开且客户端要控制当前编辑器的场景。
- 支持 remote MCP 的客户端优先配置 Streamable HTTP URL；不支持 HTTP MCP、只支持本地 command 的客户端使用 Godot headless/stdin-stdout stdio launcher。
- stdio 默认 newline-delimited JSON-RPC；stderr 可用于所有日志输出。
- legacy `Content-Length` stdio 只在显式兼容配置下启用，并有 migration warning。
- Streamable HTTP 支持 POST JSON-RPC、GET SSE/polling、session id、resumption、server-initiated disconnect。
- 无效 Origin 必须返回 HTTP 403。
- HTTP response/request contract 覆盖 `Accept`、`MCP-Protocol-Version`、`Mcp-Session-Id`、SSE event id。

### 4. 公开工具强力清债

- 删除 redundant public tools，并统一返回 `removed_public_tool` structured error。
- replacement 必须指向 canonical resource URI、canonical tool 或 prompt。
- 输入校验错误优先作为 Tool Execution Error：`isError=true` + `structuredContent.success=false`，避免误用 JSON-RPC protocol error。
- 保留必要迁移层：protocol facts fallback、runtime fallback event store、legacy user data cleanup、`trace -> debug`、旧 user-tool 设置迁移、client config 迁移。

### 5. 工具目录重构

- 建立 `ToolCatalogManifest`：category、domain_key、executor_path、source、exposure、hot_reloadable、presentation order、icons、schema dialect。
- `MCPToolManifest` / `MCPToolRegistry` 只做 adapter，随后删除重复事实源。
- `ToolCatalogSnapshotService` 一次生成 exposed/visible/all tools、domain states、presentation tree、search index、metadata。
- RPC、Tools API、Dock、catalog resources、search 全部消费同一 snapshot。
- 围绕协议 metadata 重设 Dock / Tools UI 模型：icons 用于快速扫描，title/description 作为展示文本，schema dialect/output schema indicator 用于检查，exposed/visible/internal state 明确呈现。
- UI 控制保持紧凑和操作导向：不新增营销式 catalog surface，不保留会与 `tools/list` 或 catalog resources 分叉的私有目录事实。
- `atomic_bridge` 降级为 facade，执行路径走统一 internal execution。

### 6. Optional 能力边界

- Sampling：只有确实需要 server 请求 client-side LLM 时才声明；实现时支持 `tools` / `toolChoice`。
- Elicitation：优先支持 URL mode；form mode 禁止收集密码、API key、access token 等敏感字段。
- Tasks：仅用于长耗时 durable workflows，如运行验证、批量审计、更新同步、全项目扫描。
- Authorization：本地编辑器默认不强制 OAuth；远程 HTTP 模式按 OIDC discovery、Protected Resource Metadata、`WWW-Authenticate` scope challenge 实现。

### 7. 旧 monolith 删除与内部服务收敛

- 继续迁移并删除根级 `tools/<domain>_tools.gd` monolith，split executor 成为唯一稳定入口。
- `MCPToolLoader` 拆为 runtime facade、definition catalog、execution service、visibility policy、activity recorder。
- `plugin.gd` 瘦身为 EditorPlugin 生命周期和服务挂接；更新、诊断、Dock 模型、配置动作迁入独立 feature service。

## Test Plan

- Fast static：dotnet build、manifest lint、tool-name lint、schema 2020-12 lint、refactor guardrails、version policy、文档本地化、actionlint。
- Protocol conformance：initialize、tools/list、tools/call、resources/list/read/templates、prompts/list/get。
- Transport：newline stdio、legacy stdio migration、Streamable HTTP、SSE polling/resumption、Origin 403。
- Public cleanup：removed tools absence、visible catalog absence、replacement errors、structuredContent parity。
- Metadata：icons/title/description/schema dialect/outputSchema snapshot parity。
- UI adaptation：Dock / Tools page models 必须从共享 catalog snapshot 渲染，并保留 icons、title、description、schemas、exposure state，不得另造目录事实源。
- Optional features：sampling/elicitation/tasks 只在 capability 声明时跑 required contracts。
- Release preflight：full harness、clean install build、release notes render、changelog/i18n、version/tag boundary。

## Assumptions

- v2.0.0 允许 breaking cleanup，默认协议目标为 MCP 2025-11-25。
- 2025-06-18 行为只作为 migration/legacy 兼容层，不再阻止 2025-11-25 默认形态。
- Sampling、Elicitation、Tasks 是 optional capabilities；不成熟时不得声明。
- 每个 PR 仍处理一个重构轴：transport、protocol surface、public cleanup、manifest/snapshot、monolith deletion、loader/atomic、optional capability。
