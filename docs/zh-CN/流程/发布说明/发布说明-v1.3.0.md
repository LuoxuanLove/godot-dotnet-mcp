## 🧭 Godot .NET MCP v1.3.0：语义化编辑器自动化与证据

Godot .NET MCP v1.3.0 将插件从一组编辑器工具推进为更一致的自动化层：Agent 可以定位相关编辑器界面，优先使用语义工作流，在受保护的高层任务中读取或修改值，验证结果，并附带说明实际观测对象的证据。

### 🧭 语义化编辑器控制

v1.3.0 的核心设计方向很明确：语义工作流优先，控件级操作其次，鼠标或坐标 fallback 最后。Agent 不应在已有设置工作流、Inspector 属性任务、菜单选择、标签页导航、树选择、弹窗按钮、聚焦、文本或数值编辑时默认下探到屏幕点击。

`system_editor_control(action="wait_for_ui")` 让客户端可以在继续前等待真实编辑器状态。它可轮询控件存在、可见性、文本匹配以及启用 / 禁用状态，并返回匹配 UI 证据或说明最后观测结果的超时负载。

当流程确实需要指针行为时，点击 fallback 现在更容易诊断。`click_control` 与 `right_click_control` 会返回输入派发元数据和 Button 类目标观测，包括点击前后状态、信号计数，以及鼠标输入已送达但没有激活证据时的提示。

### ⚙️ 可信设置工作流

`system_settings_dialog` 是本版本最大的工作流收口。Project Settings 与 Editor Settings 不再只是松散坐标或原始控件列表，而是可打开、等待、搜索、列标签页、切标签页、列分类、聚焦唯一分类、列行模型、解析唯一行、读取值、聚焦值控件、写入受支持值、验证期望值、截图取证并关闭的任务界面。

该工作流刻意分离只读发现和写入。只有唯一解析、可见、置信度足够且值控件受支持的 text、number、bool 行才会写入。Enum 值可读取和验证；复杂编辑器保持 unsupported，而不是猜测写入。

`run_task` 将安全链路组合为一个操作：打开并缩小界面、解析唯一行、读取修改前值、可选写入受支持值、验证结果并附带截图证据。选择器歧义、隐藏控件写入、置信度过低或无法在写入前生成要求的证据时，任务会在交互前拒绝修改。

### 🧩 Inspector 属性自动化

`system_inspector` 将同一哲学扩展到 Inspector。Agent 可以列出可见属性模型、解析唯一属性、读取类型化值、聚焦值编辑器、写入受支持的 text、number、bool 值、验证结果、捕获属性证据，或针对当前编辑对象及已准备节点 / 资源目标运行完整可信属性任务。

Inspector 工作流默认保守。隐藏控件写入、歧义属性、禁用值编辑器、资源选择器、颜色、数组、字典、对象选择器、文件选择器等复杂编辑器都会被拒绝，直到有专门安全工作流为止。

### 🪟 证据化截图

截图现在被视为带目标和可信边界的证据，而不只是图片文件。`system_editor_evidence` 可以捕获 editor、control、popup、active-dialog 或 automatic surface，并返回请求 surface、实际 backend、目标路径、可见弹窗、fallback 原因、降级状态和截图策略。

Settings 与 Inspector 工作流也使用更明确的取证行为。Settings 截图会优先捕获可见设置弹窗 / 窗口边界，其次是对话框控件边界，最后才回退到更宽的编辑器截图。客户端可以区分精确目标截图和宽泛 fallback。

本版本还通过 `system_editor_control(action="get_popup")` 与 `system_editor_control(action="capture_popup")` 增加弹窗检查和裁切截图，使浮动编辑器窗口与 PopupMenu 成为一等证据界面。

### 🚀 项目运行时生命周期

项目执行现在表达为生命周期界面：`system_project_lifecycle(action=start|stop)`。启动动作覆盖主场景或指定场景运行、marker 等待、成功 / 失败 marker 匹配、marker 超时、自动停止和前台窗口 fallback 指引。停止动作也通过同一生命周期入口关闭当前运行会话。

旧项目 run / stop 工具名被有意移除，而不是保留 alias。新名称反映了真实契约：客户端控制的是带能力上下文和验证钩子的运行时会话，而不是一次性启动命令。

### 🔎 工具、活动与 User 工具诊断

`system_tool_catalog` 为当前工具目录提供可搜索视图。Agent 可按 query、category 或 domain 搜索工具，并查看匹配原因、动作、参数、可见性、启用状态与可选 schema。

`system_tool_activity` 现在支持状态、工具、慢调用和失败导向查询。长时间或并行自动化可以只查看相关运行中或最近任务，而不必读取无关活动记录。

User 工具命名也更清晰。列表、脚手架预览与兼容性报告会显示声明名、规范化名与公开 MCP 工具名。旧式 `user_` 前缀声明会得到诊断提示；生成脚手架通过资源路径继承基础工具，在 headless catalog 扫描中更可靠。

### 🛠 场景、插件、项目与缓存工作流

`system_scene_inspect` 提供统一只读场景检查入口，包含 `validate`、`analyze` 与 `full` 动作，同时保留既有场景校验与分析工具。

`system_plugin_maintenance` 聚合常用插件状态、重载、更新状态、更新来源和启动更新流程，同时保留底层 reload 与 update 工具。维护响应继续携带 reload 或 update sync 期间客户端需要的重连与重新获取工具指引。

项目配置检查也得到扩展。客户端可以读取导出预设摘要，并遮蔽敏感 option key 与本机绝对导出路径；也可以检查单个输入动作的 deadzone 与具体输入绑定。

托管 user-data 维护仍然要求显式执行，清理工作流默认 dry-run。客户端可检查截图缓存并预览清理，再决定是否应用，同时保留 symlink、junction 与 reparse point 防护。

### ✅ 兼容性与升级提示

插件公开版本、.NET bridge metadata、protocol facts、本地化 changelog 与发布说明源现在都指向 `1.3.0`。

使用旧项目 run 或 stop 工具名的客户端必须迁移到 `system_project_lifecycle(action=start)` 与 `system_project_lifecycle(action=stop)`。这是 v1.3.0 的主要有意兼容性断点。

既有场景校验与分析工具仍保持可用。`system_scene_inspect` 是新增组合入口。

`system_plugin_maintenance` 是新增高层封装。既有 `system_plugin_reload` 与 `system_plugin_update` 调用仍保持支持。

复杂 Settings 与 Inspector 编辑器仍保持保守。unsupported 编辑器应等待未来专用工作流，或在明确证据下使用更低层 UI 操作，而不是猜测。
