## 🧩 Godot .NET MCP v1.2.1：可验证的编辑器 UI 自动化

该版本线改进编辑器 UI 自动化体验，让客户端能在继续下一步之前等待 Godot 编辑器里的可见状态。Agent 可以通过既有编辑器控件执行动作，然后验证期望的界面条件是否真正出现。

### ✨ 等待真实 UI 状态

`system_editor_control` 现在包含 `wait_for_ui`，可在有界时间内轮询控件存在、可见性、文本匹配以及启用 / 禁用状态。等待成功会返回匹配控件摘要与耗时信息；超时会返回最后一次观测负载，方便客户端调整定位条件或下一步动作。

### 🔧 更安全的自动化循环

新的等待动作与菜单、弹窗、点击、hover 和文本输入控制能力互补，不需要 OS 鼠标自动化。打开编辑器对话框、过滤设置、确认临时面板等流程可以在 Godot 内部得到更可靠的验证。

### 🧭 设置对话框导航

`system_settings_dialog` 新增面向 Project Settings 与 Editor Settings 的高层工作流。客户端可以通过编辑器菜单打开设置界面，等待对话框可见，搜索候选设置行，聚焦返回结果，截图保留证据，并在不直接写入设置值的前提下关闭界面。

该工作流现在还通过 `list_rows` 暴露只读设置行模型，用保守置信度和证据字段描述可见设置类控件，为后续值编辑层打基础。

它还可以通过 `read_value` 读取唯一匹配的可见设置行当前值，返回带行和值控件证据的 text、bool、number 或 enum 类型化结果，同时仍避免直接写入设置。

### 🔎 可搜索的工具发现

`system_tool_catalog` 为当前工具目录提供只读搜索入口。客户端可以按关键词、分类或域搜索，并查看每个工具为什么匹配、公开了哪些动作和参数、当前是否可见以及是否启用。

这能帮助 Agent 在 profile、plugin 域工具或 user 工具状态变化后重新选择合适的 system、project、editor、runtime、script 或用户侧工具，而不是依赖可能过期的工具名称记忆。

### ✅ Compatibility and Upgrade Notes

这些变更仅扩展公开工具 schema。现有 `system_editor_control` 动作保持可用；不调用 `wait_for_ui`、`system_settings_dialog` 或 `system_tool_catalog` 的客户端无需调整请求。
