## 🧩 Godot .NET MCP v1.2.1：可验证的编辑器 UI 自动化

该版本线改进编辑器 UI 自动化体验，让客户端能在继续下一步之前等待 Godot 编辑器里的可见状态。Agent 可以通过既有编辑器控件执行动作，然后验证期望的界面条件是否真正出现。

### ✨ 等待真实 UI 状态

`system_editor_control` 现在包含 `wait_for_ui`，可在有界时间内轮询控件存在、可见性、文本匹配以及启用 / 禁用状态。等待成功会返回匹配控件摘要与耗时信息；超时会返回最后一次观测负载，方便客户端调整定位条件或下一步动作。

### 🔧 更安全的自动化循环

新的等待动作与菜单、弹窗、点击、hover 和文本输入控制能力互补，不需要 OS 鼠标自动化。打开编辑器对话框、过滤设置、确认临时面板等流程可以在 Godot 内部得到更可靠的验证。

### 🪟 浮动窗口证据

`system_editor_control` 现在可通过 `get_popup` 与 `capture_popup` 读取并截取可见浮动弹窗 / 窗口界面。客户端在选择按钮、菜单项、文本输入框或关闭动作前，可以直接取得 modal 编辑器窗口与 PopupMenu 的证据。

### 🧭 设置对话框导航

`system_settings_dialog` 新增面向 Project Settings 与 Editor Settings 的高层工作流。客户端可以通过编辑器菜单打开设置界面，等待对话框可见，搜索候选设置行，聚焦返回结果，截图保留证据，并在不直接写入设置值的前提下关闭界面。

该工作流还通过 `list_rows` 暴露只读设置行模型，用保守置信度和证据字段描述可见设置类控件，随后可按需读取、写入或断言值。

它还可以通过 `list_tabs` 和 `activate_tab` 列出并激活设置标签页，并支持 `open(tab=...)`，让客户端无需坐标点击即可在 Project Settings 或 Editor Settings 标签页之间移动。

该设置工作流可以列出可见分类树项，并在检查设置行之前聚焦唯一分类，让 Project Settings 与 Editor Settings 导航更少依赖原始控件枚举。

它还可以通过 `read_value` 读取唯一匹配的可见设置行当前值，返回带行和值控件证据的 text、bool、number 或 enum 类型化结果，同时仍避免直接写入设置。

客户端现在还可以通过 `resolve_row` 在读取值或选择后续 UI 动作前解析唯一可见设置行。响应会携带行路径、置信度、选择器证据和歧义诊断，同时保持只读。

当 Agent 只需要把键盘焦点移动到匹配的值编辑控件时，`focus_value` 会聚焦该值控件并返回聚焦证据，不会修改设置。

受支持的唯一可见设置行现在还可以通过 `set_value` 编辑 text、number 与 bool 控件。该流程会通过编辑器 UI 控件写入，并在操作后重新观测设置行，让客户端验证实际值已经变化，而不是假设点击或文本编辑成功。

Agent 也可以使用只读 `verify_value` 检查，将预期的 text、bool、number 或 enum 值与唯一匹配的可见设置行进行比较。这样设置工作流可以在 UI 动作之前或之后加入不改变设置值的断言步骤。

设置截图现在提供 `capture_mode` 选择和 `capture_surface` 元数据。默认 `auto` 模式会优先捕获当前设置弹窗 / 窗口，`editor` 会强制完整编辑器截图，`popup` 则要求存在可见的 Godot 编辑器弹窗 / 窗口且不会静默回退。

### ✅ Compatibility and Upgrade Notes

此变更仅扩展公开工具 schema。现有 `system_editor_control` 与 `system_settings_dialog` 动作保持可用；不调用新增动作的客户端无需调整请求。
