## 🧩 Godot .NET MCP v1.2.0：面向重连的 Agent 工作流

Godot .NET MCP `v1.2.0` 是一次面向可靠性与编辑器控制的版本更新，适合需要在项目、插件和自定义工具持续变化时仍保持连接的 Agent。它增强了重连提示、多客户端诊断、Godot UI 自动化、User 工具可观测性和协议边界保护，同时保持 Godot 4.6+ .NET 支持、Godot Asset Library 安装、直接复制源文件安装以及现有高层工具名称兼容。

### 🔁 更清晰的重连与多客户端会话

health、插件 reload 和插件 update 响应现在会报告维护窗口状态、重连预期、重试时机和工具列表过期提示。客户端可以判断断连是否只是临时维护窗口，是否需要重新获取 schema，以及 update sync 或生命周期 reload 是否仍在进行。

HTTP health 也会提供稳定 connection ID、request ID、client summary、活跃 session 和最近断开的 session。多个 MCP 客户端或多个 Agent session 同时连接时，插件能给出更清晰的连接状态和 reload 后恢复路径。

### 🖱️ 更强的 Godot 编辑器 UI 控制

`system_editor_control` 现在能直接覆盖更多 Godot 编辑器 UI 流程。Agent 可以列出顶部菜单，打开 `MenuButton` 弹窗，按文本、索引或 id 选择可见 `PopupMenu` 行，切换已注册的编辑器主屏幕，控制专注模式，并发送 hover 或 leave 事件来检查 tooltip 与浮动面板。

这些能力减少了对操作系统级鼠标移动的依赖。弹窗菜单自动化还会拒绝隐藏弹窗、禁用项、分隔线、子菜单行、重复文本匹配和冲突选择器，让 UI 操作在失败时给出更明确的原因，而不是静默选错菜单项。

### 🧰 工具活动与 User 工具诊断

新增的 `system_tool_activity` 可以报告正在运行的工具调用、最近完成记录、执行顺序，以及客户端可选自报的 `_mcp_context`。并行 Agent 在启动另一个长耗时操作前，可以轻量了解当前已经发生了什么。

User 工具运行时诊断现在会通过插件演进诊断和 project health 暴露已发现的自定义工具、加载失败、监视器状态、兼容性摘要和近期审计记录。诊断是只读的，不改变自定义工具加载行为，但能显著降低排查扩展工具失败的成本。

### 🛡️ 更安全的协议与调试边界

HTTP 与 stdio 现在会用标准 `-32602` 错误一致处理 malformed JSON-RPC 顶层 `params`，而非法 `tools/call.arguments` 仍继续走普通 MCP tool-result 错误通道。Resource 与 Prompt Guide 输出也加入了大小保护：过大的文件型 resource 会在昂贵读取前失败，被缩短的 prompt 文本会带上 `_meta` 裁剪信息。

DAP 调试调用现在会用清晰的限额错误拒绝过大的帧和过长 timeout。脚本编辑在生成空 C# 方法时也会使用明确的 `NotImplementedException` guard body，减少含义不清的生成方法体。

### 🌐 更完整的本地化文档与发布说明

公开文档树现在以英文、简体中文、日文和韩文维护，并使用本地化目录名与文件名。Dock UI 增加韩语覆盖，也补齐了各支持语言中的工具元数据、客户端配置提示、Prompt Guide 文本、重连提示和 fallback 标签。

`v1.2.0` 发布说明会在四种语言的文档树中持久化保留。GitHub Release 正文由英文发布说明渲染，同时发布说明本身链接到其他语言版本，读者可以选择适合自己的文档语言。

### ✅ 兼容性与升级说明

现有高层工具名称保持兼容。由于编辑器控制、工具活动和 User 工具诊断暴露了新能力，公开工具 schema 版本会更新；客户端升级后应重新连接并重新获取工具列表。

现有安装不需要文件布局迁移。继续使用 Godot Asset Library 安装，或直接从源码树复制 `addons/godot_dotnet_mcp/`。插件 reload 或 update sync 期间，客户端应轮询 health；如果 transport 断开则重连，并在维护窗口提示 schema 可能过期时刷新工具列表。
