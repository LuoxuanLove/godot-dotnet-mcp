## 🧩 Godot .NET MCP v1.2.0: 面向重连的 Agent 工作流

本版本让多个 MCP 客户端或多个 Agent session 同时使用插件时更容易恢复。它强化了维护窗口上报、重连提示、传输层韧性、health 诊断、更新同步刷新流程与编辑器 UI 控制，让客户端在插件 reload 或 update sync 后能更明确地重连、重新获取工具列表，并继续导航已注册的编辑器主屏幕和可见的 Godot UI 流程。

### ✨ 亮点

- `system_editor_control` 新增顶部菜单控制，Agent 可以列出编辑器菜单、打开 `MenuButton`，并按文本或索引选择 `PopupMenu` 菜单项，再继续进行弹窗检查、文本输入或按钮操作。
- 为 health、插件 reload 与插件 update 响应新增维护窗口元数据，帮助客户端识别临时断连、重试时机和工具列表刷新要求。
- 在 `/health` 中新增 HTTP client session identity 与请求审计字段，包括稳定 connection ID、request ID、client summary、活跃 session 与最近断开的 session。
- 新增 User 工具运行时诊断，客户端可从插件演进工具或 project health 查看已发现的自定义工具、加载失败、监视器状态、兼容性与近期审计记录。
- 新增 `system_tool_activity`，客户端可在并行协作时查看 HTTP 与 stdio 工具调用中的当前运行记录、最近完成记录、执行顺序和可选的 Agent 自报上下文。
- 为支持的 Dock 语言补齐本地化重连提示。
- 为 MCP resources 与 Prompt Guide 新增输出大小保护：超大文件型 resource 会在昂贵读取前被拒绝，过长的生成 prompt 文本会报告字节大小裁剪元数据。
- 新增编辑器 UI hover 与 leave 动作，让 Agent 能通过 Godot 输入事件验证 tooltip、hover-only 菜单和浮动面板，而不需要 OS 鼠标自动化。
- 新增编辑器插件会话诊断，客户端可检查第三方 EditorPlugin 的项目设置、当前编辑器状态、可见 UI 提示，以及带保护的启用/禁用行为。
- 新增编辑器控制动作，可列出主屏幕按钮、切换到已注册的插件主屏幕，并控制专注模式。
- 让本地化文档树与当前插件 UI、工具和绑定引用保持一致。
- 新增按 index、id 或精确文本选择可见 `PopupMenu` 项的高层编辑器控制动作。
- 增加文档 i18n 验证，覆盖各语言文件对齐、Markdown 链接目标和跨语言链接泄漏。

### 🔧 修正

- 修正英文和日文文档中关于服务路由、.NET 支持、UI 流程和工具域索引的事实。
- 插件更新同步写入文件后，会先刷新 Godot 编辑器文件系统，再调度插件生命周期重载。
- C# 空方法 guard body 现在会显式使用 `NotImplementedException`，不再生成容易被误用的 fallback 方法体。
- 公开 plugin-evolution runtime diagnostics 路径现在会转发实时 User 工具 runtime snapshot，使摘要与 project health 保持一致。
- 防止弹窗菜单自动化误触隐藏弹窗、禁用项、分隔项、子菜单行、冲突选择器和重复文本项。
- 将失效或过时的本地化草稿内容替换为当前面向用户的正文。
- 移除日文 README 中无效的截图引用。
- 改进 HTTP keep-alive 处理，使 async tool execution 结束后，已缓冲的 pipelined request 会继续 drain。
- 为多客户端重连恢复加入 backpressure safeguard，包括 pending request buffer 上限和 response write failure 后的连接清理。
- 加固 stdio burst 处理与 lifecycle reload scheduling，避免旧 response 或失败的 reload schedule 留下误导性的 pending state。
- 改进插件 harness 失败报告，在 CI 输出中区分 Godot 退出清理警告、运行时错误标记和测试 case 失败。
- 统一 HTTP 与 stdio 的 malformed JSON-RPC 参数处理：非法顶层 `params` 返回标准错误，而非法工具 arguments 仍通过工具结果错误通道上报。

### ✅ 兼容性与升级说明

- 现有工具名称保持兼容。
- 由于 `system_editor_control` 新增 `list_menus`、`open_menu` 与 `select_menu_item`，工具 schema 版本已更新。
- `system_editor_plugin_control` 是新增工具；本插件自身仍应使用专用 reload/update 工具，而不是通用自禁用流程。
- 更新同步现在会在生命周期重载前要求编辑器重新扫描插件文件。
- 客户端应在 update sync 或插件 reload 期间轮询 health；如果 transport 断开，应重连，并在维护窗口提示 schema 可能过期时重新获取工具列表。
- User 工具诊断为只读能力，不改变现有自定义工具加载行为。
- 不需要进行文件布局或工具 schema 迁移。
- 客户端可在工具调用中传入简短 `_mcp_context` 对象用于协作说明；它只作为自报上下文处理，不是身份认证。
- 切换到插件主屏幕要求当前编辑器会话已经注册该主屏幕。
- 弹窗菜单选择新增了工具 schema 动作；升级后请重新连接并重新获取工具列表。
- 不需要进行文件布局迁移。
- 现有安装不需要迁移。
- 客户端可在所有 transport 中把非对象 JSON-RPC `params` 视为 `-32602`；`tools/call.arguments` 校验继续返回普通 MCP tool error result。
- 读取 resources 的客户端应处理超大文件型 resource 的标准 JSON-RPC 错误，并在 prompt 响应文本被缩短时检查 `_meta`。
