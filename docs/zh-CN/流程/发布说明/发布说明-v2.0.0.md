## 🧩 Godot .NET MCP v2.0.0：Companion 会话

Godot .NET MCP v2.0.0 从可选 Companion 方向开始，先建立 project-scoped .NET contract layer。首批内容定义了未打开编辑器时如何保持 static project analysis，以及只有匹配的 Godot editor bridge 在线后才如何开放 editor-live 自动化能力。

### ✨ 静态分析不伪装成 live 状态

Companion 契约将 static/headless 能力与 live editor 能力分开。Project session 可以暴露 C# 与资源分析类能力，同时在 editor bridge 连接前明确不声明选中节点、Inspector、Dock、截图与运行时验证状态。

static analyzer 现在会为这一层生成只读 project inventory：项目根是否是 Godot 项目、有哪些 `.csproj` 文件、插件目录是否已安装，以及未连接 editor bridge 时 editor-live 能力为什么仍不可用。

它还会从项目 XML 记录未求值的 .NET workspace graph：SDK 名称、target frameworks、package references、project references，以及 compile include/remove 条目。这样无需 restore、build 或 MSBuild 条件求值，也能获得早期 C# 结构线索。

静态资源分析现在会把文本 `.tscn` 与 `.tres` 文件索引成引用图谱。它会记录 external resources、sub-resources、`uid://` 标记、`res://` preload/load 用法、缺失目标、项目边界 warning，以及不支持的二进制 `.res` 文件，而且无需在编辑器中加载项目。

### 🔐 项目级会话隔离

工具调用必须同时携带 `project_id` 与 `session_id`，broker 会拒绝跨项目复用 session。这样 v2.0 版本线在加入多项目编排前先获得清晰的隔离边界。

Bridge 升级契约现在记录编辑器侧 handshake 状态。只有 bridge 对同一项目在线、报告兼容插件版本，并提供非空 `editor_session_id` 时，project session 才能升级为 editor-live。

### ✅ 兼容性与升级提示

当前 Companion layer 仍是契约库，不会启动后台进程、打开端口、拉起 Godot，也不会改变现有 editor-native 插件启动行为。Broker manifest 将这一承诺写成显式边界：broker 启动、loopback HTTP transport、项目注册与编辑器拉起都必须由用户或客户端明确触发。
