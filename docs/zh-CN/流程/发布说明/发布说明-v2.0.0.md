## 🧩 Godot .NET MCP v2.0.0：协议重构草稿

这是未发布 v2.0.0 协议重构线的发布说明草稿源。它总结当前仍放在 changelog `Unreleased` 下的用户可见变化；在版本正式发布前，它不是发布公告。

v2.0.0 是一次大型协议与内部服务重构，不是外观清理。它的目标是让 Godot .NET MCP 更像一个一等 MCP 2025-11-25 server：被动上下文迁入 Resources，可复用工作流规划迁入 Prompts，Tools 聚焦动作与计算结果，编辑器 Dock 则预览和 MCP 客户端相同的 metadata。这意味着客户端不必靠猜测发现能力，也不必调用大量旧 helper tools；插件可以对外保持更小、更清晰、更强验证的 public surface，同时把复杂内部实现留在表面之后。

### ✨ Protocol-First MCP Surface

默认 MCP 协议目标切到 2025-11-25。`initialize` 会公布 v2.0 server description 和协议基线，公开 tool name 会经过规范校验，公开 metadata 的默认 schema dialect 也对齐 JSON Schema 2020-12。

公开面按 MCP 的职责重新划分：

- Resources 暴露被动上下文，例如指南文本、项目 / 编辑器状态、编辑器日志、活动视图和工具目录。
- Prompts 保存工作流起手说明，让客户端能请求结构化规划，而不是调用被动 help tool。
- Tools 聚焦动作、变更、截图、诊断或计算型 workflow result。

旧 discovery 型 public tools 不再作为首选入口。需要兼容时，退场入口会返回明确替代指引，帮助客户端迁移到 Resources、Prompts 和 canonical action tools。

### 🌊 Streamable HTTP 与 Stdio

默认 endpoint 仍是 `http://127.0.0.1:3000/mcp`，但端点形态已对齐 v2.0 的 Streamable HTTP：protocol/session headers、JSON/SSE `Accept` negotiation、Origin/CORS checks、GET SSE streams、可恢复 event history、有限 POST SSE responses、heartbeat events、queued server-to-client delivery，以及 `DELETE /mcp` session termination。

Stdio 默认改为当前 MCP 客户端使用的 newline-delimited JSON-RPC。旧 `Content-Length` framing 只作为显式 compatibility mode 保留，旧本地 launcher 不会被立刻破坏，但默认 transport 会向新规范前进。

Transport validation 也更严格。HTTP 与 stdio 现在对 malformed request、response envelope、disabled tool、重复或冲突 HTTP body headers、session validation 等 JSON-RPC envelope 行为保持确定性。

### 🧭 Resource 与 Prompt UI

Dock 新增一等 Resources 和 Prompts 页。用户可以查看协议目录计数、复制 resource 或 prompt ID、预览 resource、填写 prompt 参数、预览生成的 prompt messages，并在客户端消费同一批 entry 前看到受限 icon rendering。

Tools 页也转向共享 catalog fact path。Titles、icons、annotations、input schemas、output schemas、previews、search、schema copy actions 和 visible tool families 都来自共享协议 metadata，而不是独立私有 UI catalog model。

这让 Dock 成为 MCP server surface 的预览，而不是另一套平行解释。客户端可见 metadata 改变时，UI 应展示同一份事实。

### 🧠 C# 语义 Runtime

C# semantic tooling 是安装契约的一部分。Asset Library 和准备好的 addon 安装都会携带隔离 Roslyn runtime bundle，使 semantic read 与 patch workflows 在安装后继续可用。

这个 bundle 与宿主项目 compile surface 隔离。随附 addon 不要求用户项目编译插件 Roslyn 或 bridge source files，从而减少依赖冲突，同时保留 C# 语义能力。

Clean install validation 现在同时验证两侧契约：导出的 addon 安装必须排除插件 bridge/Roslyn 源码，也必须证明隔离 Roslyn runtime 存在且可用。

### 🛠️ Tools、Catalog 与兼容性

`tools/list` 现在返回 flat callable tool list，并带有 input schema、output schema、annotations 和 JSON Schema 2020-12 metadata。Tree/group presentation data 迁入 catalog resources 和共享 Dock presentation snapshots。

Catalog snapshots、catalog resources、`/api/tools`、Dock model metadata、Tools tab preview、search 与 schema-copy paths 都使用 `ToolCatalogManifest` 和 `ToolCatalogSnapshotService` 作为共享 catalog fact path。这减少了 client discovery、HTTP diagnostics 和 editor UI preview 之间的漂移。

v2.0 也把许多大型 root domain implementation 拆成更聚焦的 executors，同时在兼容需要处保留 public facades。Audio、animation、signal、TileMap、UI、filesystem、node、project、resource、scene、group、geometry、material、lighting、navigation、particle、physics、shader、debug 和 editor domain 都转向更小的实现单元。

### ✅ 兼容性与验证

这份草稿记录的不只是功能文字，也包括重构护栏。验证覆盖 public tool removals、root monolith closure、catalog facts、optional capability advertisement、changelog structure、release-note draft wording、Roslyn runtime bundle shape、clean Asset Library installs、safe bridge writes 和 MCP 2025-11-25 conformance contracts。

兼容路径是明确的：旧 discovery calls 与 legacy transports 被记录为兼容路径，而默认客户端指引会指向 Resources、Prompts、canonical Tools、Streamable HTTP 和 newline stdio。

### 📦 升级提示

- 现有客户端应优先使用 `resources/list`、`resources/read`、`resources/templates/list`、`prompts/list`、`prompts/get` 和 canonical action tools，而不是旧 public discovery tools。
- HTTP 客户端应发送 `MCP-Protocol-Version: 2025-11-25`，处理 `Mcp-Session-Id`，并声明 `Accept: application/json, text/event-stream`。
- Stdio launcher 应使用 newline-delimited JSON-RPC，除非明确选择 legacy `Content-Length` compatibility mode。
- C# semantic workflows 应依赖随包隔离 Roslyn runtime，而不是在宿主项目中编译插件 Roslyn source。
- Antigravity 用户可以在 Config 页检测并打开应用，复制 Godot MCP 配置，并按照手动设置目录指引接入。插件不会在该契约公开文档化之前假设存在可写的 Antigravity 配置文件。
