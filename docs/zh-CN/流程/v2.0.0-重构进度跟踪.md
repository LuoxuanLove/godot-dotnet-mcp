# v2.0.0 重构进度跟踪

本文将 v2.0.0 协议重构计划拆成可执行检查清单。每一项都应能对应到可审查、可验证并合入 v2.0 重构分支的 PR。

状态说明：

- `Done`：已实现、验证、审查，并合入 v2.0 重构分支。
- `Partial`：已有有效进展，但仍有必须补完的后续工作。
- `Pending`：尚无实质实现。
- `Blocked`：存在明确外部前置条件。

## 当前阶段

v2.0.0 已完成计划中的协议纯化与 UI metadata 重构范围。当前目标是默认符合 MCP 2025-11-25，早期 MCP 2025-06-18 对齐成果保留为兼容基础。分支已经具备强测试脚手架、显式 MCP 2025-11-25 聚合 conformance gate、广泛的协议/UI metadata 覆盖、release-contract Streamable HTTP 覆盖，以及防止 loader、transport、atomic bridge 和插件生命周期重新回到 monolithic facade 的 service-convergence 护栏。后续新增工作应作为新的 scoped requirement 追踪，而不是继续视为 v2.0 计划债务。

## 下一批 PR 队列

1. 后续 Tools tab context actions 继续使用共享 catalog snapshot metadata，避免新增 private tree fact source。
2. Atomic helper/collection 行为继续留在 `AtomicBridgeHelperService`，防止回流到 `AtomicBridgeExecutionService` 或 bridge facade。
3. 继续用 root monolith guard 与 debug/editor compatibility-wrapper contracts 保持 monolith cleanup 闭环。
4. 扩展 Streamable HTTP 行为前先补显式 transport contracts。
5. 后续 loader、transport、plugin lifecycle assembly 保持在专用 services，而不是在 facade 中重建 callback maps。

## 跟踪规则

- 每个 breaking removal 必须在错误中返回 replacement method 或 resource URI。
- 每个删除的公开工具必须有测试证明它不在 `tools/list`、不在 visible catalog resource，并且不能作为成功动作调用。
- Prompt 指引必须描述 resource-first 路径，不得把已删除 discovery tool 作为起点。
- v2.0 默认 endpoint 是作为 MCP Streamable HTTP 的 `http://127.0.0.1:3000/mcp`；legacy `/api/tools`、`/health`、JSON-only POST 行为和 `Content-Length` stdio 必须标为兼容面。
- UI catalog 模型必须消费共享 catalog snapshot metadata，不得另造私有目录事实。
- 后续 Tools tab context actions 必须保持在共享 manifest/snapshot metadata 上，不得新增 private tree fact source。
- 后续 atomic helper 与 collection 行为必须保持在 `AtomicBridgeHelperService` / system implementation helper services，而不是回流到 `AtomicBridgeExecutionService` 或 bridge facade。
- Changelog entries 必须保持 `Added / Changed / Fixed / Documentation / Internal` 顺序，且同一版本不得重复 section。
- PR 合入 v2.0 重构分支前，必须完成本地验证、相关 GitHub 检查、所有 conversation 和 Codex review gate。
