# v1.4.0 重构进度跟踪

本文将 v1.4.0 协议重构计划拆成可执行检查清单。每一项都应能对应到可审查、可验证并合入 v1.4 重构分支的 PR。

状态说明：

- `Done`：已实现、验证、审查，并合入 v1.4 重构分支。
- `Partial`：已有有效进展，但仍有必须补完的后续工作。
- `Pending`：尚无实质实现。
- `Blocked`：存在明确外部前置条件。

## 当前阶段

v1.4.0 已完成初始护栏，并进入协议面准备中段。当前分支已有测试脚手架和多项 MCP 协议改进，但尚未完成破坏性公开工具清债、单一工具目录事实源、旧 monolith 删除和内部服务收敛。

## 下一批 PR 队列

1. 从公开工具列表移除 `system_help`，旧调用返回 replacement error。
2. 删除 prompt 和本地化文本中以 `system_help` 起手的旧指引。
3. 将公开工具目录发现从 `system_tool_catalog` 迁到 catalog resources。
4. 将 `system_plugin_reload` 与 `system_plugin_update` 收敛到 `system_plugin_maintenance` 并加 removal guard。
5. 引入 `ToolCatalogManifest` 作为单一声明式目录来源。
6. 引入 `ToolCatalogSnapshotService` 并迁移 catalog resources、search、presentation。
7. 删除第一批 monolith：audio、animation、signal、tilemap、UI。
8. 将 `atomic_bridge` 降级到统一内部执行 facade 之后。
9. 在 snapshot service 稳定后拆分 `MCPToolLoader` 职责。
10. 统一 HTTP 与 stdio JSON-RPC 路由和结果归一化。

## 跟踪规则

- 每个 breaking removal 必须在错误中返回 replacement method 或 resource URI。
- 每个删除的公开工具必须有测试证明它不在 `tools/list`、不在 visible catalog resource，并且不能作为成功动作调用。
- Prompt 指引必须描述 resource-first 路径，不得把已删除 discovery tool 作为起点。
- Changelog 必须保持 `Added / Changed / Fixed / Documentation / Internal` 顺序，且同一版本不得重复 section。
- PR 合入 v1.4 重构分支前，必须完成本地验证、相关 GitHub 检查、所有 conversation 和 Codex review gate。
