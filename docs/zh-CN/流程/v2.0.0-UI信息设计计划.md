# v2.0.0 UI 信息设计计划

## 概要

v2.0.0 协议重构已经把 public MCP tool surface 收窄到 canonical `system_*` 和 `user_*` 入口，但实现层仍保留许多 internal executor category。Dock 需要把这两层拆清楚：默认页面展示 Agent 或用户应该调用、读取或请求的内容；更深的视图解释组成和运行状态，避免把所有 executor 混进同一棵普通工具树。

本文覆盖 Tools、Resources 和 Prompts 页面，是分阶段 PR 的设计目标，不是 release note。

## 共享展示模型

Dock 页面应消费共享 presentation model，而不是用 category 名称、URI 片段或 prompt 名称重建私有树。每个节点应带有明确字段：

```text
id
label
kind
tool_name
resource_uri
prompt_name
category
domain
visibility
callability
source
path
schema
status
children
metadata
```

必须支持的节点类型：

```text
public_tool
tool_group
executor_category
executor_tool
legacy_tool
resource_entry
resource_template
prompt_entry
prompt_argument
service_dependency
data_source
schema_node
diagnostic_node
```

可见性值：

```text
public
internal
advanced
hidden
legacy
removed
```

可调用性值：

```text
callable
compat_callable
not_callable
disabled
blocked
load_error
```

## Tools 页面

Tools 页面默认进入 Agent Tools 视图。这个视图回答：我能调用什么？

默认分组：

```text
Agent Tools
├─ Project & Context
├─ Editor Automation
├─ Scene & Resource
├─ Script & C# Semantics
├─ Runtime & Debugging
├─ Plugin Maintenance
└─ User Tools
```

规则：

- 默认只展示 canonical public tools 和 user tools。
- 默认树不展示 internal executor categories。
- removed 或 legacy tools 不作为普通工具显示。
- resource 或 prompt discovery 入口不作为普通 callable tool 显示。
- 默认总数只统计默认可见的 public tools。
- 用 implemented by executor 这类 cross-link 表达关系，而不是重复节点。

Tools 页面还应支持两个更深视图：

- Structure 视图：展示某个 public tool 背后的 actions、inputs、outputs、data sources、services 和 internal executors。
- Diagnostics 视图：展示 exposure、callability、source file、manifest entry、policy decision、load status、schema status、recent activity 和 replacement guidance。

Internal executors 放在明确标注的 advanced section：

```text
Internal Executors
├─ core
├─ visual
├─ gameplay
├─ interface
├─ plugin
└─ user
```

每个 internal executor 行展示 loaded state、enabled tool count、total tool count、source path、load errors、reload status、hot reload status、public tools produced 和 internal tools produced。

## Resources 页面

Resources 页面默认进入 Resource Catalog 视图。这个视图回答：我能读取什么？

默认分组：

```text
Resources
├─ Guides
├─ Project State
├─ Editor State
├─ Activity & Logs
├─ Tool Catalog
├─ Resource Templates
└─ Advanced Resources
```

规则：

- 展示来自 `resources/list` 和 `resources/templates/list` 的 canonical resource URIs 和 templates。
- 显示 title、description、icons、MIME type、template parameters 和 stable URI。
- 默认 resource tree 不混入 tool-like actions；只链接相关 tools。
- 当 `_meta.resourceKind` 或等价 catalog metadata 存在时，Dock 不再按 URI substring 分类。
- templates 是可复用读取目标，不是 callable tools。

Resources 页面应包含：

- Reader 视图：预览选中 resource content、MIME type、metadata，并提供 copy URI。
- Template 视图：展示 template parameters、examples、validation hints，并提供 copy expanded URI。
- Diagnostics 视图：展示 source service、resource kind、visibility、last read status、content size、template binding errors、stale cache status 和 fallback guidance。

协议和安全规则：

- 将 `resources/list`、`resources/templates/list` 和 `resources/read` 作为页面内容、preview 和错误行为的 source of truth。
- 保留 logs 与 diagnostics 的 redaction 行为。
- 保留 template path validation、traversal rejection、absolute/user path rejection、binary rejection 和 oversized content handling。
- 将 compatibility resources 标记为 compatibility entries，而不是提升到 canonical resources 之上。

Resources 验收点：

- Guides、state、activity、logs、catalog 和 templates 在默认目录中只出现一次。
- Template entries 不计入 tools。
- Resource kind 来自共享 metadata，而不是 Dock 侧字符串猜测。
- Resource preview 能处理大内容、空内容、不支持的 MIME type 和 read errors，且不发生视觉重叠。
- Diagnostics 能解释 missing、hidden 或 failed resource reads。
- Resource preview 语义保持等价于 `resources/read(uri)`。

## Prompts 页面

Prompts 页面默认进入 Prompt Catalog 视图。这个视图回答：我能请求什么工作流指引？

默认分组：

```text
Prompts
├─ Project Understanding
├─ Editor Workflow
├─ Runtime Validation
├─ Script & C# Workflow
├─ Plugin Maintenance
└─ Advanced Prompts
```

规则：

- 展示来自 `prompts/list` 的 prompts，并显示 title、description、icons、arguments 和 stable name。
- Prompt entries 与 tools、resources 分离。
- Prompt arguments 作为参数显示，而不是 child tools。
- 当 metadata 可用时，不按 prompt name substring 推断 prompt kind。
- required、optional、enum、bool 和 path-like arguments 需要有清晰视觉区分。

Prompts 页面应包含：

- Prompt builder 视图：argument editors、validation hints、preview request 和 copy prompt name。
- Message preview 视图：rendered messages、roles、text content，以及 resource/tool links。
- Diagnostics 视图：prompt source、prompt kind、argument schema、unknown-argument policy、type validation status、last render error 和 related resources/tools。

协议和安全规则：

- 将 `prompts/list` 和 `prompts/get` 作为页面内容、preview 和错误行为的 source of truth。
- 保留 prompt unknown-argument 和 wrong-type validation semantics。
- 保留 prompt service 提供的 truncation metadata、本地化 title、description 和 argument text。
- Prompt preview 语义保持等价于 `prompts/get(name, arguments)`。

Prompts 验收点：

- Workflow prompts 在默认目录中只出现一次。
- Arguments 不会在窄面板中撑破布局或覆盖 label。
- Unknown 和 wrong-type arguments 会显示为 validation concerns。
- Rendered messages 保持 role 和 content 清晰。
- Diagnostics 能解释 prompt visibility、argument validation 和 render failures。

## 共享交互规则

有多层深度的页面使用共享模式切换：

```text
Default
Structure
Diagnostics
Advanced
```

搜索在所有模式中通用，但每个结果必须显示类型 badge：

```text
Public
Internal
Legacy
Removed
Disabled
Error
Resource
Template
Prompt
Argument
```

Preview panel 使用稳定尺寸和紧凑 label。按钮优先使用 icon，并为不熟悉的动作提供 tooltip。Disabled 或 non-callable nodes 不能显示 run-style actions。

## 数据来源计划

新增或强化 presentation services：

```text
ToolTreePresentationService
ResourceTreePresentationService
PromptTreePresentationService
```

输入：

```text
ToolCatalogSnapshotService snapshot
ToolCatalogManifest facts
ToolPublicSurfacePolicy policy
ToolLoader status and diagnostics
ToolActivityRegistry recent activity
Resources service metadata
Prompts service metadata
Resource and prompt catalog metadata
```

输出：

```text
build_agent_tool_tree()
build_tool_structure_tree()
build_tool_diagnostics_tree()
build_resource_catalog_tree()
build_resource_diagnostics_tree()
build_prompt_catalog_tree()
build_prompt_diagnostics_tree()
```

Dock tabs 直接消费这些输出。

## PR 计划

### PR 1：计划和模型契约

- 将本计划存入 docs tree。
- 添加 Tools、Resources 和 Prompts 的 presentation model contracts。
- UI 改动保持最小。

### PR 2：Agent Tools 默认视图

- 将 Tools tab 默认树切到 canonical public tools plus user tools。
- 将 executor categories 移到 advanced 或 diagnostics path。
- 修复默认计数和重复的 DAP/runtime/project 类行。

### PR 3：Resources 和 Prompts 默认视图

- 让 Resources 和 Prompts 消费明确 presentation models。
- 添加稳定 previews、argument/template panels 和 metadata badges。
- 当共享 metadata 存在时，移除私有 Dock 分类猜测。

### PR 4：Structure 和 Diagnostics 视图

- 为 Tools、Resources 和 Prompts 添加更深视图。
- 展示 exposure、callability、data source、validation、activity、replacement 和 load/read/render status。
- 添加 errors、hidden entries、legacy entries、internal entries 和 disabled entries 过滤。

### PR 5：视觉验证和 polish

- 验证桌面和窄面板渲染。
- 确认 labels、buttons、previews、schemas 和 badges 不重叠。
- 为 Tools、Resources 和 Prompts 捕获视觉证据。

## 验收标准

- 默认 Tools 页面只展示 canonical callable tools 一次，并从默认计数中排除 internal executor categories。
- DAP、runtime、project、scene 和 resource capabilities 不再以同级普通工具重复出现。
- Removed legacy tools 不出现在 Agent Tools，但在 diagnostics 中带 replacement guidance。
- Resources 页面只展示一次 resource entries 和 templates，并使用 metadata-driven kinds 和安全 previews。
- Prompts 页面只展示一次 prompts，并将 argument editors 和 message preview 与 tools 分离。
- Structure 和 diagnostics 视图让 non-callable nodes 明确不可调用。
- 每个视图都能解释 entry 为什么 visible、hidden、disabled、removed 或 failing。
- 实现 PR 后，视觉验证覆盖 Tools、Resources 和 Prompts。
