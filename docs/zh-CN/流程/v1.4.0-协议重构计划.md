# v1.4.0 协议重构计划

Godot .NET MCP v1.4.0 采用“强力清债 + 协议纯化”路线。重构会按 MCP 2025-06-18 规范的职责分工，把上下文、状态和目录迁回 Resources，把工作流指南留给 Prompts，把 Tools 收窄为真正会执行动作或计算性工作流的入口。

目标形态是：少量 canonical public tools、resource-first 认知入口、单一工具目录事实源，以及可按速度、隔离级别、行为类型与迁移状态分层分片的测试门禁。

## Key Changes

- 新增 canonical resource URI：`guides/index`、`guides/capabilities`、`guides/ui-automation`、`state/project/summary`、`state/editor`、`activity/status`、`activity/recent`、`activity/call/{id}`、`tools/catalog/exposed`、`tools/catalog/visible`。
- Prompts 继续保留 6 条工作流，但不再推荐先调用 `system_help`；客户端应读取 guide resources，或直接使用 `prompts/list` 与 `prompts/get`。
- Tools 公共面删除认知型和重复型入口：`system_help`、`system_tool_catalog`、`system_tool_activity` 不再出现在 `tools/list`；旧调用必须返回明确错误和 replacement resource URI。
- Tools 公共面收敛高层重复入口：移除 `system_scene_validate` 与 `system_scene_analyze`，统一到 `system_scene_inspect(action=validate|analyze|full)`；移除 `system_plugin_reload` 与 `system_plugin_update`，统一到 `system_plugin_maintenance(action=reload|update|...)`；移除只读 `system_editor_log` 用法，改由 log/activity resources 承担。
- `tools/list` 回归 MCP 标准工具列表，只返回可调用工具、schema、annotations 和必要 `_meta`；完整 tree、group、atomic、action 展示数据只放 catalog resources。
- 工具结果开始补 `structuredContent` 和可选 `outputSchema`；为了兼容当前客户端，同步保留 text JSON，但 `structuredContent` 成为内部 contract 的 canonical 字段。
- 只读项目文件、scene、script、resource 文本读取迁到 resource templates；`system_project_files` 保留写入、移动、删除、scan、reimport 等动作，不再作为默认读上下文入口。

## Implementation Plan

### 1. 测试护栏先行

- 建立 contract case manifest，字段固定为：`name`、`layer`、`domain`、`behavior=current|migration|deprecation|removal_guard`、`speed=fast|headless|editor|release`、`isolation=pure|user_fs|stage_root|editor`、`v1_4_disposition=keep|rewrite|delete|expires`。
- 将现有 hardcoded required cases 改为由 manifest 标签选择。
- 把旧行为测试分成三类：必须保留的 compatibility、迁移窗口 migration、旧结构不得复活的 removal_guard。

### 2. 协议面纯化

- 在 `mcp_resources_service.gd` 中实现 guide、state、activity、catalog resources。
- 让现有 project/info、diagnostics、tools/catalog resources 复用同一 snapshot 数据。
- 修改 prompts 文本，使认知路径固定为 resource、prompt、canonical tool、resource/activity 验证。
- 修改 `mcp_tool_rpc_router.gd` 与 tools list 构建，使公开工具只包含 canonical action tools。
- 增加 contract，证明 `resources/list`、`resources/read`、`prompts/get`、`tools/list`、`tools/call` 在 HTTP 与 stdio 上输出一致。

### 3. 公开工具强力清债

- 删除 redundant public tools：`system_help`、`system_tool_catalog`、`system_tool_activity`、`system_scene_validate`、`system_scene_analyze`、`system_plugin_reload`、`system_plugin_update`、`system_editor_log`。
- 删除旧 internal aliases：`filesystem_file`、`debug_log`、`resource_manage`。
- 先替换所有内部引用，再进行删除。
- 将测试从“不可 exposed”升级为“不可 callable / 不在 visible catalog”。
- 保留必要安全和迁移层：protocol facts fallback、runtime fallback event store、legacy user data cleanup、`trace -> debug` 归一化、旧 user-tool 设置键迁移、客户端配置读取迁移。

### 4. 工具目录重构

- 建立单一 `ToolCatalogManifest`，承载 category、domain_key、executor_path、source、exposure、hot_reloadable、presentation order。
- 旧 `MCPToolManifest` / `MCPToolRegistry` 只做 adapter，直到重复事实源可删除。
- 建立 `ToolCatalogSnapshotService`，一次生成 exposed/visible/all tools、domain states、presentation tree、search index。
- RPC、Tools API、Dock、catalog resource 全部消费同一快照。
- 将 `atomic_bridge` 降级为 `AtomicToolFacade`：保留写保护和 helper，但执行路径走统一 internal execution，不再维护第二套 executor path map。
- 将每个 system impl 的 schema、handler、atomic dependencies 合并为 declarative specs，并从 specs 派生 `SystemTreeCatalog`。

### 5. 旧 monolith 删除

- 对每个已有 `tools/<domain>/executor.gd` 的 domain，迁移并删除根级 `tools/<domain>_tools.gd` monolith。
- `base_tools.gd` 和真正共享 helper 不在删除范围。
- 最终 contract 不再写“split executor 完成后应删除”，而是直接断言旧 monolith 文件不存在。
- 优先顺序：已被 contract 明确点名的 audio、animation、signal、tilemap、UI；随后处理 filesystem、debug、resource、node、project、scene 等大体量域。

### 6. 内部服务收敛

- 将 `MCPToolLoader` 拆为 runtime facade、definition catalog、execution service、visibility policy、activity recorder，并保留外部 adapter 直到所有调用方迁移完成。
- HTTP 与 stdio 共用同一 JSON-RPC method/router/tool router、结果归一化、resources/prompts 分发路径。
- 将 tiny callable context bags 收敛为 service graph 或 ports 对象。
- 最后瘦身 `plugin.gd`：只保留 EditorPlugin 生命周期和服务挂接；更新、用户工具、诊断、Dock 模型、配置动作迁入独立 feature service。

## Test Plan

- Fast static：.NET build、manifest lint、refactor guardrails、version policy、documentation localization、workflow lint。
- Headless smoke：resource-first MCP contract、canonical `tools/list`、`tools/call` `structuredContent`、removal guards、tool snapshot parity。
- Headless integration：按 domain shard 跑 runtime、resources/prompts/tools、client config migration、user tools、localization、transport parity。
- Editor probe：插件 entrypoint、settings persistence、真实 editor-only lifecycle、UI evidence/settings/inspector workflow。
- Migration/deprecation：旧 user tool 命名、旧 client config、旧 stdio config、旧 C# reference path-first 行为只验证迁移诊断，不再永久保护旧实现。
- Release preflight：full harness、clean install build、release notes render、changelog/i18n、version/tag 边界。

## Assumptions

- v1.4.0 允许 breaking cleanup；破坏面集中在公开工具名收敛和旧 internal alias 删除。
- Resources/Prompts 支持不足的客户端不再决定协议方向；插件按 MCP 规范纯化，同时保留清晰错误与 replacement URI。
- `script_references` legacy path-first 暂不删除，除非另立 C# 引用系统专项；本计划只把相关测试标为 migration/deprecation 候选。
- 每个 PR 只处理一个重构轴：测试护栏、协议面、公开工具清债、manifest/snapshot、monolith 删除、loader/atomic、plugin 瘦身。
