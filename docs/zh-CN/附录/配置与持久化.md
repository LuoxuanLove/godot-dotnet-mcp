# 配置与持久化

本文档汇总插件当前使用的配置路径、持久化文件格式和导入导出约束。

---

## 持久化路径

| 路径 | 类型 | 作用 |
|---|---|---|
| `user://godot_dotnet_mcp/settings.json` | JSON | 插件设置 |
| `user://godot_dotnet_mcp/profiles/*.json` | JSON | 自定义工具 profile |
| `user://godot_dotnet_mcp/captures/editor/` | 目录 | 编辑器整窗截图默认目录；传入根级 `user://file.png` 时会收敛到该目录 |
| `user://godot_dotnet_mcp/captures/editor_controls/` | 目录 | 控件截图与 `activate_ui` 附带截图默认目录；传入根级 `user://file.png` 时会收敛到该目录 |
| `user://godot_dotnet_mcp/runtime/captures/<session_id>/` | 目录 | 运行时截图与低频帧序列的默认会话级临时产物；传入 `capture_dir` 时可改写到指定目录 |
| `user://godot_dotnet_mcp/runtime/events.json` | JSON | 运行时 bridge fallback 事件缓存 |
| `user://godot_dotnet_mcp/logs/user_tool_audit.log` | 日志 | User Tool 审计日志 |
| 用户指定路径 | JSON | `plugin_developer` 导入 / 导出工具配置 |

## 插件设置文件

路径：

```text
user://godot_dotnet_mcp/settings.json
```

当前主要字段：

| 字段 | 说明 |
|---|---|
| `port` | 内嵌 server 端口 |
| `host` | 监听地址 |
| `auto_start` | 是否自动启动 |
| `debug_mode` | 是否输出调试日志 |
| `log_level` | 日志等级 |
| `permission_level` | 当前 permission level |
| `disabled_tools` | 禁用工具全名列表 |
| `tool_profile_id` | 当前选中 profile |
| `language` | 当前语言 |
| `show_user_tools` | 是否在 Tools 页显示 User 分类 |
| `collapsed_categories` | 当前折叠的 category 列表 |
| `collapsed_domains` | 当前折叠的 domain 列表 |
| `collapsed_system_tools` | Tools 页中默认折叠的系统工具名列表（默认覆盖公开内置工具名） |

缺失字段会在加载时用 `PluginRuntimeState.build_default_settings()` 补齐。

## 缓存与清理

插件不会在启动时自动清理 `user://`，避免意外删除用户仍需要的验证截图或诊断文件。Agent 如需整理旧版本遗留的根级缓存，应先调用：

```json
{"action": "cleanup_legacy_cache", "dry_run": true}
```

需要查看当前受管理截图缓存时，调用 `system_userdata_maintenance(action=list_capture_cache)`；需要清理当前 `captures/editor/`、`captures/editor_controls/` 与 `runtime/captures/` 中的缓存文件时，先调用 `system_userdata_maintenance(action=cleanup_capture_cache, dry_run=true)` 预览，再用 `dry_run=false` 应用。当前截图缓存清理会跳过 symlink、Windows junction 与 reparse point，并在结果的 `skipped_links` 中返回这些条目。

确认 legacy 候选项后，再显式调用 `system_userdata_maintenance(action=cleanup_legacy_cache, dry_run=false)`。该清理入口会迁移旧的 runtime 事件、User Tool 审计日志和 profile 文件，并删除旧版本散落在 `user://` 根目录的 MCP 临时截图。

当前格式：

```json
{
	"name": "My Profile",
	"disabled_tools": [
		"scene_scene_run",
		"plugin_evolution_plugin_evolution_delete_user_tool"
	]
}
```

说明：

- 文件名不直接等于 profile id，profile id 为 `custom:<slug>`
- `disabled_tools` 必须是字符串数组
- 重命名 profile 时会新写文件，再删除旧文件

## 工具配置导入 / 导出文件

由 `plugin_developer_export_config` / `plugin_developer_import_config` 使用。

当前格式：

```json
{
	"format_version": 1,
	"profile_id": "default",
	"disabled_tools": [
		"scene_scene_run"
	]
}
```

校验规则：

- `profile_id` 不能为空
- `disabled_tools` 必须是字符串数组
- 数组内元素不能为空字符串

导入成功后不会直接改变文件格式，只回读为结构化数据再交给插件状态。

## 客户端配置写入策略

桌面端客户端配置写入由 `ClientConfigService.write_config_file()` 实现。

策略如下：

1. 先解析当前 UI 中展示的 JSON 文本。
2. 若目标文件已存在，尝试读取并解析原 JSON。
3. 只操作 `mcpServers` 节点。
4. 只更新 `godot-mcp` 对应项，不清空其它 server。
5. 目录不存在时先递归创建。

这意味着插件写入是“最小合并”，不是“全文件覆盖模板”。

## CLI 配置

CLI 客户端当前不做直接写盘，而是生成命令文本，例如：

- Claude Code
- Codex

其中 Claude Code 还区分：

- `user`
- `project`

作用域切换只影响生成的命令文本，不影响其它设置。

## HTTP CORS 安全配置

内嵌 HTTP MCP 服务默认不启用 wildcard CORS，不会对所有响应写出 `Access-Control-Allow-Origin: *`。无 `Origin` 的本地 CLI / 桌面 MCP 客户端继续按 `http://127.0.0.1:<port>/mcp` 直连；带 `Origin` 的浏览器请求必须精确命中 allowlist。

当前 allowlist 通过环境变量配置：

```text
GODOT_DOTNET_MCP_ALLOWED_CORS_ORIGINS=http://localhost:5173,http://127.0.0.1:5173
```

规则：

- 多个 origin 使用英文逗号或分号分隔。
- 只做精确匹配，不做后缀、前缀或 wildcard 匹配。
- `Origin: null` 与未在 allowlist 内的 origin 会被拒绝。
- Host 校验默认允许 loopback，并允许当前实际监听 host；若通过 `GODOT_DOTNET_MCP_SERVER_HOST` 或设置文件改为非默认 host，CLI / 桌面客户端配置仍会按该 host 直连。
- CORS 只控制浏览器跨源读取，不是认证机制；本地 HTTP 认证 token 属于后续独立加固项。

## 客户端安装检测缓存

客户端安装检测由 `ClientInstallDetectionService` 在内存中维护短期缓存：

- 缓存 TTL：`5000ms`
- 缓存内容：客户端 executable path、config entry 状态、runtime running 状态
- 缓存不会写入 `user://`

当前缓存失效入口：

- Config 页手动选择 / 清除客户端路径
- Config 写入 / 删除完成后
- Dock 切换到 Config 页时

这意味着客户端检测属于运行期投影状态，而不是持久化配置本身。

## 本地化资源

语言资源并不写入 `user://`，而是直接来自：

- `localization/locale_*.gd`

当前本地化切换策略是：

- 设置文件里记录用户选择的语言
- 插件启动时恢复该语言
- 所有 UI 文本由 `LocalizationService` 统一取值

---

## 运行时桥持久化相关约束

运行时桥通过 Autoload 方式挂入项目：

- 名称：`MCPRuntimeBridge`
- 路径：`res://addons/godot_dotnet_mcp/plugin/runtime/mcp_runtime_bridge.gd`

这类配置写入的是 Godot 项目设置，而不是插件自己的 `user://` JSON。

## 常见排障点

- 改了场景中的 margin 但不生效：先确认对应页签脚本是否仍在运行时覆盖该属性。
- profile 导入失败：优先检查 `profile_id` 是否为空、`disabled_tools` 是否是字符串数组。
- 一键写入客户端失败：优先检查目标目录是否可写、现有 JSON 是否能解析。
- 语言切换后有 key 原样显示：优先检查目标 `locale_*.gd` 是否缺键。
