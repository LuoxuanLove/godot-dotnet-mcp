# 编码与架构规范

本规范是 `godot-dotnet-mcp` 的强约束文档。  
本文件中的“必须/禁止”条款均为硬规则，由 `scripts/validate_refactor_guardrails.ps1` 直接阻断。

---

## 1. 适用范围与执行等级

- 适用范围：仅 `godot-dotnet-mcp` 仓库。
- 执行等级：立即硬阻断，无过渡期。
- 兼容策略：允许破坏性重构；替换后必须删除旧实现，不保留兼容层。

---

## 2. 分层边界矩阵

允许依赖方向：

```text
plugin composition -> plugin runtime -> tools domain
plugin composition -> plugin presenters/ui
```

禁止依赖方向：

- `tools/*` 反向依赖 `plugin/*`。
- `plugin runtime` 反向依赖 `ui/*`。
- 跨层通过字符串方法名或全局单例绕过协作者注入。

---

## 3. 注入与装配规则

必须：

- 使用 typed context 或显式参数注入协作者。
- composition root 只负责对象装配与生命周期连接，不承载业务分支。
- 协作者 `configure()` 必须可幂等重入，并支持 `dispose/reset` 解除引用。

禁止：

- `configure(callbacks: Dictionary)`。
- 运行主路径依赖“任意键名”的回调字典分发。
- 在 context/factory 中返回跨功能域的大字典并作为事实源传递。

---

## 4. 规模阈值（硬上限）

按职责分层执行：

- `plugin.gd`、`plugin/runtime/mcp_http_server.gd`：`<= 360` 行。
- `plugin/runtime/*service*.gd`：`<= 320` 行。
- `plugin/*coordinator*.gd`：`<= 260` 行。
- `ui/*tab*.gd`：`<= 420` 行。
- `tools/*/catalog.gd`：
  - 函数 `get_tools` `<= 120` 行。
  - 超限时必须改为静态数据源 + 稳定读取入口。
- 任意 GDScript 单函数：`<= 90` 行（数据表函数除外，但仍受 catalog 规则限制）。
- 任意 GDScript 文件公开函数数量：`<= 28`。
- 新增 `*context*.gd` 需满足：
  - 单文件 `<= 28` 行。
  - 仅允许字段定义与极少量无分支辅助，不得承载业务逻辑。

---

## 5. 微型空壳文件规则

允许的微型空壳文件（`<= 8` 行）仅限：

- `tools/*/executor.gd` 继承桥接入口。
- 明确被列入白名单的稳定重导出入口。

禁止：

- 为规避文件阈值而拆出大量无语义薄壳文件。
- 在空壳文件中隐藏真实行为分发。

---

## 6. 反模式禁令

禁止项：

- 双轨实现（新旧路径并存且都可达）。
- 兼容 wrapper、兼容 alias、过渡 helper 长期保留。
- 跨层直接访问内部可变状态字段。
- 字符串方法名回调（如 `call("method_name")`）作为主路径。
- “未来再删”的过时代码保留策略。

必须项：

- 替换完成后，立即删除旧入口、旧 helper、旧测试路径。
- 结构变更同批次补契约测试，不允许长期测试债务。

---

## 7. 外部协议与工具接口策略

- 外部 MCP 工具名、协议载荷形状允许调整，只要新设计更优。
- 发生外部形状变更时，必须同批次完成：
  - 协议事实源更新（文档与代码一致）。
  - 契约测试更新。
  - 变更说明更新（`docs/`）。

---

## 8. 护栏与债务基线

护栏脚本必须覆盖并硬阻断：

- 新增 `callbacks: Dictionary` 注入签名。
- 新增大字典装配入口。
- 文件/函数阈值超标。
- 微型空壳文件泛滥。
- 已识别反模式回流。

遗留债务基线规则：

- 基线只允许下降，不允许上升。
- 当批次清理掉一项债务，必须同步下调基线。
- 不允许通过调整阈值掩盖新增耦合。

---

## 9. 执行顺序要求

每个批次必须按顺序执行：

1. 更新 `agent_workflow` 计划与执行项。
2. 实施代码重构与过时代码删除。
3. 更新文档与协议说明。
4. 运行护栏与契约测试。
5. 记录验证结果与剩余风险。

---

## 10. 违例处理

- 任何违反本规范的改动不得合并。
- 若出现紧急修复需要临时放宽，必须在同一批次补回并恢复硬约束，不得跨批次拖延。

---

## 11. 遗留债务基线

仓库当前保留的遗留债务基线：

- `callbacks: Dictionary` 注入残留：
  - 当前 runtime 主路径已清零，新增残留由护栏直接阻断。
- 大字典装配残留：
  - 当前插件组合层主路径已清零，新增残留由护栏直接阻断。
- 大文件残留（持续收口）：
  - `plugin/runtime/mcp_runtime_command_service.gd`（331行，阈值320）
  - `plugin/runtime/user_tool_maintenance_service.gd`（418行，阈值320）
  - 多个 `tools/*/catalog.gd:get_tools`

上述债务只允许减少，不允许增加，也不允许迁移为新的同类结构。

---

## 12. 执行顺序要求

按以下顺序执行，不得跳步扩散：

1. runtime 回调字典清零。
2. 组合层去字典化。
3. HTTP 组合层减负。
4. UI 巨型文件拆分。
5. catalog 静态数据外置。
6. 删除所有对应旧实现与兼容路径。
