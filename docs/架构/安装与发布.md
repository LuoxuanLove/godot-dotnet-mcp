# 安装与发布

本文档描述 Godot .NET MCP 插件的安装方式、启用步骤和发布前检查。

插件是自包含的：Roslyn 语法分析运行在 Godot .NET 运行时内部，不需要外部宿主进程。

---

## 安装方式

### 方式一：Godot 插件商城

用 Godot 打开目标项目，进入 `AssetLib` 页签，搜索 `Godot .NET MCP` 并点击 `Install`。也可以打开 Godot 插件商城页面：

```text
https://godotengine.org/asset-library/asset/4923
```

安装完成后保持目录结构：

```text
addons/godot_dotnet_mcp
```

然后：

1. 用 Godot 打开目标项目。
2. 进入 `Project Settings > Plugins`。
3. 启用 `Godot .NET MCP`。
4. 打开 `MCPDock`。
5. 在 `主页` 页签中启动服务。

### 方式二：直接复制源文件

适用于仓库开发调试，或在本地项目中直接使用当前源码树：

1. 从源码复制 `addons/godot_dotnet_mcp/` 到目标 Godot 项目。
2. 用 Godot 打开项目。
3. 进入 `Project Settings > Plugins`。
4. 启用 `Godot .NET MCP`。
5. 打开 `MCPDock > 主页` 启动服务。

---

## 运行时要求

- Godot `4.6+`（需要 .NET 支持，即 Godot Mono/.NET build）
- 项目需启用 .NET 脚本支持

### C# 分析说明

- C# 语法分析由插件内 Roslyn 处理（syntax-first），运行在 Godot .NET 运行时内部。
- 仅提取语法树信息，不使用 SemanticModel，不做项目编译加载。
- 无需外部 Roslyn 安装或配置。

---

## 分支与合并流程

- 不维护长期 `develop` 或 `main` 分支；`dev` 是唯一长期集成分支，并应始终保持最新可验证状态。
- 功能开发从 `dev` 拉取 `feature/*` 短分支，缺陷修复从 `dev` 拉取 `fix/*` 短分支，验证后合并回 `dev`。
- PR、`dev` 推送和手动运行会触发插件验证工作流；普通短分支 PR 通过 `pull_request` 验证，避免同一提交同时触发短分支 `push` 与 PR 验证。PR 必须指向 `dev`，合并前必须通过验证，并同步必要的 README、CHANGELOG、docs 与 CI required subset；CHANGELOG 需要覆盖重要的 Documentation 与 Internal 变化，不只记录用户可见功能和修复。
- 正式发布收尾仍使用短分支，例如 `release/v1.0.1`；确认版本号、变更记录、文档和验证结果后再合并回 `dev`。

## 发布流程入口

详细发布步骤见 `docs/流程/发布Runbook.md`。发布流程只保留 Godot Asset Library 安装和直接复制 `addons/godot_dotnet_mcp/` 源文件两种交付路径；不制作、上传或记录 zip 包、发布包、本地打包产物及其安装流程。`dev` 更新后可维护 `next` draft release 作为下一版说明草稿，草稿和正式发布都由 `docs/流程/release-notes/release-notes-v*.md` 的手写摘要、`docs/i18n/zh-CN/CHANGELOG.md` 明细和 commit summary 渲染为同一结构；正式 `v*` 发布会执行版本一致性和发布说明源文件 preflight，并可复用同版本同提交的成功 dry-run 记录跳过重复 build 与 harness 检查。

Agent 或 bot 参与开发时，按 `docs/流程/Agent与Bot流程.md` 执行：短分支提交和推送可以自动完成；不使用额外账号时，可用 `actions-bot-relay` 让 `github-actions[bot]` 从 patch 创建 PR。远程 `dev` 合并必须由维护者在 GitHub PR 页面手动确认。

## 源码仓边界

### 保留

- `addons/godot_dotnet_mcp/dotnet_bridge/` — 插件内独立 .NET 库，Roslyn façade 的共享代码，不是外部可执行文件
- `tests/godot_plugin_harness/` — 插件 headless harness
- `tests/godot_plugin_harness_fixture/` — harness fixture 和合约测试

## 验证建议

### 安装闭环

建议按以下顺序验证：

1. 插件在 Godot 中可启用，`MCPDock` 可打开。
2. `MCPDock > 主页` 能正确显示服务状态。
3. `GET http://127.0.0.1:3000/health` 返回正常。
4. `GET http://127.0.0.1:3000/api/tools` 返回工具列表。
5. MCP 客户端能连接到 `http://127.0.0.1:3000/mcp`。
6. C# 脚本工具（`script_inspect`、`script_exports` 等）返回 `engine=roslyn`、`mode=syntax`。

### 发布前检查

建议至少检查：

1. `plugin.cfg`、协议事实和变更记录中的版本一致。
2. README、CHANGELOG、`docs/流程/release-notes/release-notes-v*.md`、相关文档与验证结果已同步；CHANGELOG 已记录重要的 Documentation / Internal 变化，release notes 仍只保留用户可感知发布叙事。
3. 源码树中未引入非插件代码或本地构建产物。
4. `.github/workflows/**` 变更已通过 workflow lint。
5. PR 目标分支为 `dev`，正式发布 `v*` tag、`plugin.cfg`、英文 changelog 与简体中文 changelog 与发布说明源文件版本一致。
6. 发布说明只包含插件自身的摘要、兼容性提示、验证信息和 commit summary。
