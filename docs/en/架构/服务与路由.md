# Services and Routing

This document describes the plugin service entry points, session layering, and routing direction.

The core principles are:

- the plugin-internal MCP HTTP server is the only public entry point
- plugin-local Roslyn runs inside the Godot .NET runtime with a syntax-first approach
- there is no external host and no child process

---

## Service Entry Point

### Public entry

The plugin MCP server is provided by `plugin/runtime/mcp_http_server.gd`:

- HTTP listens on `http://127.0.0.1:3000/mcp` or the configured port
- tool registration and dispatch are handled by `tools/core/tool_loader.gd`
- MCP Resources and Prompts are exposed directly by the JSON-RPC method layer so the client can read project information, diagnostic summaries, safe file templates, and guided prompts

External MCP clients should connect to:

```text
http://127.0.0.1:3000/mcp
```

### Protocol methods

`POST /mcp` uses JSON-RPC 2.0 and supports these first-class MCP methods:

| Method | Purpose |
|---|---|
| `initialize` | Returns the protocol version, tool schema version, server info, and the `tools`, `resources`, and `prompts` capabilities. |
| `tools/list` / `tools/call` | Exposes the high-level tool list and executes tool calls. |
| `resources/list` / `resources/templates/list` / `resources/read` | Lists built-in server resources, exposes scene/script/resource reading templates, and reads read-only content with strict `res://` path validation. |
| `prompts/list` / `prompts/get` | Lists built-in prompts and returns six parameterized workflow guide messages for project orientation, content authoring, debug triage, reference integrity, runtime validation, and editor UI control. |
| `ping` | Returns an empty result for connection keepalive. |

### Internal components

The boundary between Prompts and Tools stays separate: `prompts/get` returns only workflow instructions that are suitable for conversation context and does not perform editor actions. Actual reading, validation, modification, and runtime work still happen through the high-level tools in `tools/call`. The `system_help` payload includes a `prompt_guides` summary so the Agent can discover `prompts/list` and `prompts/get` from the main help surface.

Plugin-internal components:

- `plugin/runtime/mcp_http_server.gd` - MCP HTTP server
- `plugin/runtime/mcp_resources_service.gd` - MCP Resources listing and read service
- `plugin/runtime/mcp_prompts_service.gd` - MCP Prompts listing and read service
- `plugin/runtime/server_runtime_controller.gd` - service lifecycle manager
- `plugin/runtime/plugin_roslyn_service.gd` - plugin-local Roslyn facade
- `tools/core/tool_loader.gd` - tool catalog and loading

## Tool Layering

### Editor-attached

All tools depend on live editor state:

- `system_*` - project snapshot, scene analysis, script structure checks, C# binding audit, and symbol search
- `script_*` - script read and write, C# syntax analysis
- `scene_*` - scene query and modification
- `node_*` - node operations

### Plugin-internal development capabilities

These capabilities are used for plugin diagnostics and maintenance:

- `plugin_runtime_*`
- `plugin_developer_*`
- `plugin_evolution_*`

---

## Session Model

The plugin does not manage an external session concept. All tools run directly in the editor process.

Godot executable path strategy:

- the path comes from explicit user configuration or local common-path discovery
- there is no broad disk scan
- machine-specific paths are never baked into release artifacts

---

## Routing Responsibilities

### Plugin

Responsible for:

- MCP HTTP server listening and request handling
- tool catalog registration and dispatch
- running tools in the live editor environment
- providing the local service and diagnostics panels
- maintaining plugin-side tool runtime and `user_*` extensions

### Plugin-local Roslyn

Responsible for:

- C# syntax tree parsing, syntax only, no SemanticModel
- type, method, and exported member extraction
- syntax analysis for `script_inspect`, `script_exports`, `script_edit_cs`, and related C# tools

---

## Error Semantics

Editor-required tools return structured errors such as:

- `project_not_selected`
- `godot_executable_not_found`
- `script_not_found`
- `parse_error`
- `binding_audit_error`

---

## Current Implementation Boundary

- the plugin provides a local HTTP MCP service address
- C# analysis uses plugin-local Roslyn with a syntax-first approach
- `addons/godot_dotnet_mcp/dotnet_bridge/` is a plugin-local shared .NET library, not an external executable
