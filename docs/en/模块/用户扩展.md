# User Extensions

User extensions, or User tools, are the plugin’s capability growth mechanism inside the authorization boundary. You can place `.gd` scripts in `custom_tools/` to add new MCP tools without changing the plugin itself and without rebuilding.

The management entry points are the `plugin_evolution` tool group, which contains 7 tools, and the User category inside `MCPDock > Tools`.

---

## Loading Mechanism

`system/executor.gd` automatically scans the `custom_tools/` directory during `_init()`. Every `.gd` file goes through three checks:

1. **Instantiable**: the script loads and instantiates correctly
2. **Interface implemented**: it has the `handles`, `get_tools`, and `execute` methods
3. **Prefix compliant**: every tool name returned by `get_tools()` starts with `user_`

If all three checks pass, the script is marked with `set_meta("is_user_tool", true)` and added to the System tool list. If any step fails, the file is skipped and a warning is recorded.

**Load path**: `res://addons/godot_dotnet_mcp/custom_tools/`

## Tool Interface Rules

```gdscript
@tool
extends RefCounted

func handles(tool_name: String) -> bool:
    return tool_name == "user_my_tool"

func get_tools() -> Array:
    return [
        {
            "name": "user_my_tool",          # must start with user_
            "description": "tool description",
            "inputSchema": {
                "type": "object",
                "properties": {
                    "param": {"type": "string"}
                },
                "required": ["param"]
            }
        }
    ]

func execute(tool_name: String, args: Dictionary) -> Dictionary:
    if tool_name == "user_my_tool":
        var param = str(args.get("param", ""))
        return {"success": true, "result": "done: %s" % param}
    return {"success": false, "error": "Unknown tool: %s" % tool_name}
```

**Notes**:

- if any tool name in a script does not start with `user_`, the whole file is skipped
- one script can declare multiple tools as long as `handles` and `get_tools` or `execute` match them
- script files must live in the root of `custom_tools/`. Subdirectory scanning is not supported

## Dock Visibility

User tools are hidden from the Dock Tools page by default. Turn them on through:

- MCP tool: pass `enabled: true` to `plugin_developer_user_visibility`
- Dock action: `MCPDock > Tools > Settings > Show User Tools`

When enabled, the User category appears as its own root group in the tool tree.

## `plugin_evolution` Tool Reference

The following 7 tools manage the full User-tool lifecycle, all called with the `plugin_evolution_` prefix:

| Tool Name | Purpose | Key Parameters |
|---|---|---|
| `list_user_tools` | List all registered User tools | — |
| `scaffold_user_tool` | Preview or create a User tool script scaffold | `tool_name` required, `authorized` for the two-step flow, `display_name`, `description` |
| `delete_user_tool` | Preview or delete a User tool script | `script_path` required, `authorized`, `agent_hint` |
| `restore_user_tool` | Preview or restore the most recently deleted User tool | `authorized`, `agent_hint` |
| `user_tool_audit` | Read the latest user-tool audit records | `limit`, `filter_action`, `filter_session` |
| `check_compatibility` | Compare existing User tools with the current scaffold version | — |
| `usage_guide` | Return the recommended authorization workflow and usage guide | — |

## Two-Step Authorization Flow

`scaffold_user_tool`, `delete_user_tool`, and `restore_user_tool` all use two-step confirmation:

**Step 1, preview**: do not pass `authorized`, or pass `authorized: false`. The tool returns the operation preview without writing anything.

**Step 2, execute**: after confirming the preview, pass `authorized: true` to run the operation.

```text
# Preview
plugin_evolution_scaffold_user_tool(tool_name="user_my_tool")
# -> returns scaffold preview

# Execute
plugin_evolution_scaffold_user_tool(tool_name="user_my_tool", authorized=true)
# -> writes custom_tools/user_my_tool.gd
```

---

## Backup Mechanism

When a User tool is deleted, the script file is automatically backed up to `custom_tools/.backup/`, so it is not lost immediately.

Use `restore_user_tool` to recover the most recent backup script.

---

## Audit Records

All User-tool actions, including create, delete, and restore, are written to audit records:

**Path**: `user://godot_dotnet_mcp_user_tool_audit.json`

Read them through `user_tool_audit`:

```text
plugin_evolution_user_tool_audit(limit=20, filter_action="scaffold")
```

You can filter by `filter_action` (`scaffold`, `delete`, `restore`) or `filter_session`.
