#### Detailed `system` Domain Notes

**Directory structure**:

```text
tools/system/
├── executor.gd                # scheduler
├── atomic_bridge.gd           # atomic-tool call bridge, with write protection
├── impl_help.gd               # MCP capability guidance and recommended Agent workflow
├── impl_editor.gd             # editor UI control aggregation entry
├── impl_runtime.gd            # runtime control, unified screenshots, input, and step
├── impl_dap.gd                # high-level DAP debugging protocol entry
├── impl_scene.gd              # scene-level tools
├── impl_index.gd              # indexing and search tools (with internal index cache)
├── lsp_client.gd              # Godot LSP client (used by system/script and script-editing services)
├── impl_project.gd            # project-level and editor-aggregation system tools
└── impl_script.gd             # script-level system tools
```

## Shared Root-Level Scripts

The `tools/` root directory now keeps only shared helpers or legacy domain scripts that have not yet been fully moved into directories, such as:

- `base_tools.gd`
- `plugin_shared.gd`

Aside from shared scripts such as `base_tools.gd` and `plugin_shared.gd`, the old root entries for builtin tool domains have already been removed. The official entry point is now `tools/<category>/executor.gd`.

## Documentation Maintenance Rules

- When adding a new executor directory, update this index at the same time.
- When an old root-level script is fully moved into a directory or deleted, update this document accordingly.
- When new `plugin_*` tools are added or the `custom_tools/` workflow changes, update this index and [用户扩展.md](用户扩展.md) as well.
