# v2.0.0 Protocol Refactor Plan

## Summary

Godot .NET MCP v2.0.0 follows a debt-reduction, protocol-purification, and 2025-11-25 conformance line. The refactor aligns the public MCP surface with the MCP 2025-11-25 specification: context, state, and catalogs move to Resources; workflow guidance stays in Prompts; Tools narrow to entries that execute actions or computational workflows.

The earlier MCP 2025-06-18 alignment remains as a compatibility foundation. The v2.0.0 release target changes to a default MCP surface that conforms to 2025-11-25. The public tool surface may use breaking cleanup, but every removal must include a replacement entry, replacement metadata, and removal guard tests.

The target shape is a small canonical public tool surface, resource-first cognitive entry points, a single tool-catalog fact source, and 2025-11-25 transport, schema, and metadata gates.

## Key Changes

- Switch the protocol baseline to `protocolVersion = 2025-11-25`; add human-readable metadata such as `description` to `serverInfo` / `Implementation`.
- Keep canonical resource URIs: `guides/index`, `guides/capabilities`, `guides/ui-automation`, `state/project/summary`, `state/editor`, `activity/status`, `activity/recent`, `activity/call/{id}`, `tools/catalog/exposed`, and `tools/catalog/visible`; add 2025-11-25 `icons` and title metadata.
- Keep the six workflow prompts; stop recommending `system_help` as the first step; add prompt `icons`, argument schemas, and path/enum/bool argument guards.
- Continue removing cognitive or duplicate public tool entries: `system_help`, `system_tool_catalog`, `system_tool_activity`, scene aliases, plugin reload/update aliases, editor log aliases, and old internal aliases.
- Keep `tools/list` as the standard MCP tool list: callable tools, `inputSchema`, `outputSchema`, annotations, icons, and required `_meta` only. Tree, group, and action presentation data belongs only in catalog resources.
- Treat JSON Schema 2020-12 as the default dialect for `inputSchema` and `outputSchema`; explicitly declare `$schema` for legacy schemas when compatibility is uncertain.
- Add tool-name guards: length 1-128, case-sensitive names, ASCII letters/digits/`_`/`-`/`.` preferred, and no characters that break client parsing.
- Update Dock and Tools UI design to consume 2025-11-25 catalog metadata (`icons`, title, description, schema dialect, output schema, and exposure state) from resources/snapshots instead of rebuilding private presentation trees.
- Keep `http://127.0.0.1:3000/mcp` as the default MCP endpoint, but define it as the MCP 2025-11-25 Streamable HTTP transport instead of a plugin-private JSON-RPC API.
- Define the default HTTP request shape as `POST /mcp` with `Accept: application/json, text/event-stream`, `Content-Type: application/json`, and `MCP-Protocol-Version: 2025-11-25`.
- Treat `/api/tools`, `/health`, old JSON-only POST behavior, and old `Content-Length` stdio as legacy compatibility surfaces.
- Migrate default stdio to 2025-11-25 newline-delimited JSON-RPC; keep old `Content-Length` framing only as a legacy compatibility mode.
- Migrate HTTP to complete Streamable HTTP semantics: validate `MCP-Protocol-Version`, `Mcp-Session-Id`, `Accept`, invalid-Origin 403 behavior, and SSE polling/resumption.
- Treat Sampling, Elicitation, and Tasks as optional capabilities: do not implement or advertise them by default; once advertised, they must satisfy 2025-11-25 contracts.

## Implementation Plan

### 1. Test Guardrails First

- Extend the contract case manifest with `mcp_version=2025-11-25|2025-06-18|legacy` and `conformance=required|compat|optional`.
- Add `mcp_2025_11_25_conformance_contracts` covering lifecycle, stdio, Streamable HTTP, Tools, Resources, Prompts, schema, and metadata.
- Reclassify old 2025-06-18 tests as compatibility or migration guards; they no longer represent the release target.
- Every breaking removal must prove absence from `tools/list`, absence from the visible catalog, and legacy-call replacement errors.

### 2. Protocol Surface Purification

- Return `2025-11-25`, standard capabilities, and serverInfo description from `initialize`.
- Keep `mcp_resources_service.gd` as the guide/state/activity/catalog entry point and add icons/title metadata.
- Make prompt text consistently describe the path: resource -> prompt -> canonical tool -> resource/activity verification.
- Remove all presentation trees, groups, atomic internals, and action-only presentation data from `tools/list`.
- Make HTTP and stdio share one JSON-RPC router, result normalization path, and resources/prompts/tools dispatch.

### 3. Transport Adaptation

- Use `http://127.0.0.1:3000/mcp` as the default MCP Streamable HTTP endpoint when the Godot editor is already open and a client needs to control the current editor session.
- Prefer Streamable HTTP URLs for remote-MCP-capable clients; provide a Godot headless stdin/stdout stdio launcher for clients that only support local commands.
- Make newline-delimited JSON-RPC the default stdio mode; all logs go to stderr.
- Enable legacy `Content-Length` stdio only through explicit compatibility configuration and emit migration warnings.
- Support Streamable HTTP POST JSON-RPC, GET SSE/polling, session ids, resumption, and server-initiated disconnects.
- Return HTTP 403 for invalid Origin.
- Cover `Accept`, `MCP-Protocol-Version`, `Mcp-Session-Id`, and SSE event id behavior in HTTP request/response contracts.

### 4. Public Tool Debt Cleanup

- Remove redundant public tools and return a consistent `removed_public_tool` structured error.
- Replacement metadata must point to canonical resource URIs, canonical tools, or prompts.
- Prefer Tool Execution Errors for input validation failures: `isError=true` and `structuredContent.success=false`, avoiding JSON-RPC protocol errors for tool-argument repair cases.
- Keep required migration layers: protocol facts fallback, runtime fallback event store, legacy user data cleanup, `trace -> debug`, old user-tool settings migration, and client config migration.

### 5. Tool Catalog Refactor

- Add `ToolCatalogManifest` for category, domain key, executor path, source, exposure, hot-reloadability, presentation order, icons, and schema dialect.
- Keep `MCPToolManifest` and `MCPToolRegistry` as adapters, then remove duplicate fact sources.
- Use `ToolCatalogSnapshotService` to generate exposed/visible/all tools, domain states, presentation trees, search indexes, and metadata in one pass.
- Make RPC, Tools API, Dock, catalog resources, and search consume the same snapshot.
- Redesign Dock/Tools UI models around protocol metadata: icons for quick scanning, title/description as display text, schema dialect/output schema indicators for inspection, and explicit exposed/visible/internal states.
- Keep UI controls compact and operational: no separate marketing-style catalog surface, no private tree facts that can diverge from `tools/list` or catalog resources.
- Demote `atomic_bridge` to a facade whose execution path goes through unified internal execution.

### 6. Optional Capability Boundaries

- Sampling: advertise it only when the server really needs to request client-side LLM work; support `tools` and `toolChoice` when implemented.
- Elicitation: prefer URL mode; form mode must not collect passwords, API keys, access tokens, or similar sensitive fields.
- Tasks: use only for long-running durable workflows such as run validation, batch audits, update sync, and full-project scans.
- Authorization: local editor mode does not require OAuth by default; remote HTTP mode follows OIDC discovery, Protected Resource Metadata, and `WWW-Authenticate` scope challenges.

### 7. Old Monolith Removal and Internal Service Convergence

- Continue migrating and deleting root-level `tools/<domain>_tools.gd` monoliths so split executors become the only stable entries.
- Split `MCPToolLoader` into a runtime facade, definition catalog, execution service, visibility policy, and activity recorder.
- Slim `plugin.gd` down to EditorPlugin lifecycle and service wiring; move updates, diagnostics, Dock models, and configuration actions into dedicated feature services.

## Test Plan

- Fast static: dotnet build, manifest lint, tool-name lint, schema 2020-12 lint, refactor guardrails, version policy, docs localization, actionlint.
- Protocol conformance: initialize, tools/list, tools/call, resources/list/read/templates, prompts/list/get.
- Transport: newline stdio, legacy stdio migration, Streamable HTTP, SSE polling/resumption, Origin 403.
- Public cleanup: removed tools absence, visible catalog absence, replacement errors, structuredContent parity.
- Metadata: icons/title/description/schema dialect/outputSchema snapshot parity.
- UI adaptation: Dock/Tools page models must render from the shared catalog snapshot and preserve icons, titles, descriptions, schemas, and exposure state without inventing separate catalog facts.
- Optional features: Sampling, Elicitation, and Tasks run required contracts only when their capabilities are advertised.
- Release preflight: full harness, clean install build, release-note rendering, changelog/i18n, version/tag boundary.

## Assumptions

- v2.0.0 allows breaking cleanup, and the default protocol target is MCP 2025-11-25.
- 2025-06-18 behavior remains only as a migration or legacy compatibility layer and must not block the 2025-11-25 default shape.
- Sampling, Elicitation, and Tasks are optional capabilities; immature implementations must not advertise them.
- Each PR still handles one refactor axis: transport, protocol surface, public cleanup, manifest/snapshot, monolith deletion, loader/atomic, or optional capability.
