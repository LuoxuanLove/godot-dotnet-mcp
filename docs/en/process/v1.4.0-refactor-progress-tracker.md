# v1.4.0 Refactor Progress Tracker

This tracker turns the v1.4.0 protocol refactor plan into an execution checklist. It is intentionally narrower than the full plan: each row should map to PR-sized work that can be reviewed, tested, and merged into the v1.4 refactor branch.

Status legend:

- `Done`: implemented, validated, reviewed, and merged into the v1.4 refactor branch.
- `Partial`: useful work has landed, but the plan item still has required follow-up work.
- `Pending`: no substantial implementation has landed yet.
- `Blocked`: blocked by a known external prerequisite.

## Current Phase

The v1.4.0 line is past the initial guardrail phase and in the middle of protocol-surface preparation. The branch has strong test scaffolding and several MCP protocol improvements, but it has not yet completed the breaking public-tool cleanup, single catalog fact source, monolith removal, or internal service convergence.

## Next PR Queue

1. Remove `system_help` from the public tool list and return a replacement error for legacy calls.
2. Remove stale Prompt and localization guidance that recommends starting with `system_help`.
3. Move public catalog discovery from `system_tool_catalog` to catalog resources, with call-time replacement errors.
4. Collapse `system_plugin_reload` and `system_plugin_update` into `system_plugin_maintenance` with removal guards.
5. Introduce `ToolCatalogManifest` as the single declarative catalog source while keeping existing adapters.
6. Introduce `ToolCatalogSnapshotService` and migrate catalog resources/search/presentation consumers.
7. Continue monolith cleanup with the larger filesystem, debug, resource, node, project, and scene domains.
8. Demote `atomic_bridge` behind a unified internal execution facade.
9. Split `MCPToolLoader` responsibilities after the catalog snapshot service exists.
10. Unify HTTP and stdio JSON-RPC routing and result normalization.

## Tracking Rules

- Every breaking removal must include a replacement method or resource URI in the returned error.
- Every removed public tool must have tests proving it is absent from `tools/list`, absent from visible catalog resources, and not callable as a successful action.
- Prompt guidance must describe the resource-first path and must not reference removed discovery tools as the starting point.
- Changelog entries for this line must keep the order `Added / Changed / Fixed / Documentation / Internal` and must not duplicate section headings inside a version.
- A PR is not ready to merge into the v1.4 refactor branch until local validation, relevant GitHub checks, all conversations, and the Codex review gate are complete.
