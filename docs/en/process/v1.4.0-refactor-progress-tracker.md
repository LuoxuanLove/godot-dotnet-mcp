# v1.4.0 Refactor Progress Tracker

This tracker turns the v1.4.0 protocol refactor plan into an execution checklist. It is intentionally narrower than the full plan: each row should map to PR-sized work that can be reviewed, tested, and merged into the v1.4 refactor branch.

Status legend:

- `Done`: implemented, validated, reviewed, and merged into the v1.4 refactor branch.
- `Partial`: useful work has landed, but the plan item still has required follow-up work.
- `Pending`: no substantial implementation has landed yet.
- `Blocked`: blocked by a known external prerequisite.

## Current Phase

The v1.4.0 line is past the initial guardrail phase and in the middle of protocol-surface preparation. The refactor target is now MCP 2025-11-25 conformance by default, with the earlier 2025-06-18 alignment retained as a compatibility foundation. The branch has strong test scaffolding and several MCP protocol improvements, but it has not yet completed the 2025-11-25 transport/schema/metadata gates, breaking public-tool cleanup, single catalog fact source, monolith removal, or internal service convergence.

## Tracking Rules

- Every breaking removal must include a replacement method or resource URI in the returned error.
- Every removed public tool must have tests proving it is absent from `tools/list`, absent from visible catalog resources, and not callable as a successful action.
- Prompt guidance must describe the resource-first path and must not reference removed discovery tools as the starting point.
- The default v1.4 endpoint is `http://127.0.0.1:3000/mcp` as MCP Streamable HTTP; legacy `/api/tools`, `/health`, JSON-only POST behavior, and `Content-Length` stdio must be labeled as compatibility surfaces.
- UI catalog models must consume shared catalog snapshot metadata instead of inventing separate private catalog facts.
- Changelog entries for this line must keep the order `Added / Changed / Fixed / Documentation / Internal` and must not duplicate section headings inside a version.
- A PR is not ready to merge into the v1.4 refactor branch until local validation, relevant GitHub checks, all conversations, and the Codex review gate are complete.
