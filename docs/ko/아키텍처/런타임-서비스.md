# 런타임 서비스

이 문서는 `plugin/runtime/`, `plugin/config/`, 도구 로더가 어떻게 함께 동작하는지, 그리고 HTTP 진입점에서 실제 executor까지 요청이 어떻게 흐르는지 설명합니다.

## 서비스 계층

현재 런타임은 대략 네 계층으로 나뉩니다.

```text
EditorPlugin 조립 계층
  ├─ plugin.gd
  ├─ plugin/plugin_dock_coordinator.gd
  ├─ plugin/plugin_runtime_coordinator.gd
  └─ plugin/plugin_action_router.gd

상태와 설정 계층
  ├─ plugin/runtime/plugin_runtime_state.gd
  ├─ plugin/config/settings_store.gd
  └─ plugin/config/client_config_service.gd

표현과 Dock 모델 계층
  ├─ plugin/presenters/dock_model_service.gd
  ├─ plugin/presenters/dock_presenter.gd
  └─ plugin/presenters/client_config_presenter.gd

서비스와 진단 계층
  ├─ plugin/runtime/server_runtime_controller.gd
  ├─ plugin/runtime/mcp_http_server.gd
  ├─ plugin/runtime/mcp_http_request_router.gd
  ├─ plugin/runtime/mcp_json_rpc_router.gd
  ├─ plugin/runtime/mcp_tool_rpc_router.gd
  ├─ plugin/runtime/mcp_resources_service.gd
  ├─ plugin/runtime/mcp_prompts_service.gd
  ├─ plugin/runtime/mcp_runtime_bridge.gd
  ├─ plugin/runtime/runtime_control_service.gd
  └─ plugin/runtime/plugin_self_diagnostic_store.gd

도구 로딩과 실행 계층
  ├─ tools/core/tool_loader.gd
  ├─ tools/tool_manifest.gd
  ├─ tools/tool_registry.gd
  ├─ tools/<category>/executor.gd
  └─ tools/shared/
```

## 상태와 설정

`plugin_runtime_state.gd`는 가벼운 런타임 상태 컨테이너입니다. 현재 설정 dictionary, custom profile cache, CLI scope, Config platform, tab state 같은 UI 상태와 mutable runtime field를 보관합니다. 정적 schema나 profile directory 규칙은 이 객체가 직접 소유하지 않습니다.

`settings_store.gd`는 설정과 profile persistence를 담당합니다.

- `user://godot_dotnet_mcp/settings.json`
- `user://godot_dotnet_mcp/profiles/*.json`
- 사용자가 지정한 import/export JSON 경로

`plugin_runtime_coordinator.gd`는 사용자 도구 watcher, runtime bridge Autoload, debugger bridge 설치와 해제를 조정합니다.

## HTTP와 JSON-RPC 서비스

`server_runtime_controller.gd`는 `plugin.gd`와 `MCPHttpServer` 사이의 proxy 계층입니다.

- 서버 노드를 생성하고 mount합니다.
- soft reload 중 controller와 server node를 다시 구성합니다.
- 서버 시작, 중지, 재시작을 조정합니다.
- 설정과 disabled tool list를 서버에 동기화합니다.
- 시작과 reload phase timing을 기록합니다.

`mcp_http_server.gd`는 내장 HTTP와 MCP 서비스 노드입니다.

- TCP port listen
- HTTP request 수신
- JSON-RPC와 MCP request body parsing
- path routing을 `mcp_http_request_router.gd`에 위임
- JSON-RPC method routing을 `mcp_json_rpc_router.gd`에 위임
- `tools/list`, `tools/call`을 `mcp_tool_rpc_router.gd`에 위임
- `resources/list`, `resources/read`, `prompts/list`, `prompts/get`을 각각 service에 위임
- health snapshot과 response formatting을 전용 service에 위임

## MCP 리소스와 프롬프트

`mcp_resources_service.gd`와 `mcp_prompts_service.gd`는 도구 실행 경로를 거치지 않는 MCP 표면입니다.

- Resources는 project info, diagnostics summary, capability guide, tool catalog를 제공합니다.
- Resource templates는 scene, script, resource 파일을 읽는 경로를 제공합니다.
- Prompts는 프로젝트 파악, 콘텐츠 작성, 디버그 triage, 참조 무결성, 런타임 검증, 편집기 UI 제어 workflow를 제공합니다.

HTTP transport와 stdio transport는 같은 method service를 사용하므로 반환 구조가 일관되어야 합니다.

## 도구 로더 감독

`mcp_tool_loader_supervisor.gd`는 현재 `MCPToolLoader`를 소유합니다.

- tool loader initialize, rebuild, recovery
- disabled tool synchronization
- loader health classification
- loader summary와 status view
- tool loader performance summary 수집

이 계층 덕분에 `mcp_http_server.gd`는 protocol handling과 loader lifecycle을 뒤섞지 않아도 됩니다.

## 런타임 브리지

`mcp_runtime_bridge.gd`는 메인 프로젝트 런타임 이벤트 통로입니다. editor-side 도구가 runtime-side 이벤트를 읽고, runtime command와 reply를 구조화해서 연결할 수 있게 합니다.

관련 service는 다음을 담당합니다.

- `mcp_runtime_command_service.gd`: runtime command 생성과 전달
- `mcp_runtime_reply_service.gd`: success와 error payload 정규화
- `mcp_runtime_fallback_store.gd`: fallback reply persistence와 trimming
- `runtime_control_service.gd`: runtime control entry 조정
- `mcp_runtime_control_session_selector.gd`: 대상 session 선택
- `mcp_runtime_control_error_mapper.gd`: runtime error 구조화
- `mcp_runtime_control_reply_resolver.gd`: reply resolution과 fallback 처리

## 편집기 생명주기 endpoint

`mcp_editor_lifecycle_endpoint.gd`는 `/api/editor/lifecycle`의 `POST` body를 parsing하고, `status`, `close`, `restart` action을 dispatch합니다.

`mcp_editor_lifecycle_action_service.gd`는 close와 restart의 confirmation semantics, accepted payload, deferred shutdown을 담당합니다.

`mcp_editor_lifecycle_state_builder.gd`는 open scene, dirty scene, current scene path, lifecycle hint를 조립합니다.

## 응답과 CORS 경계

HTTP 서비스는 모든 응답에 무조건 `Access-Control-Allow-Origin: *`를 붙이지 않습니다. Host, Origin, POST `Content-Type`을 먼저 검증합니다.

- Origin이 없는 local CLI와 desktop client는 loopback direct access를 유지합니다.
- browser request는 allowlist와 정확히 일치해야 합니다.
- 명시적으로 허용되지 않은 cross-origin request는 `403`을 반환합니다.
- non-CORS `OPTIONS` request는 `405`와 `Allow` header를 반환합니다.

## 설계 원칙

- 상태 저장과 요청 처리를 섞지 않습니다.
- 장기 cache는 service 단위로 유지합니다.
- 실패 정보는 가능한 한 구조화된 payload로 반환합니다.
- router, bridge, loader supervisor는 서로의 책임을 침범하지 않습니다.
- transport가 달라도 protocol facts와 도구 catalog는 같은 source of truth를 사용합니다.
