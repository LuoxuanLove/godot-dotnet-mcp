# 서비스와 라우팅

이 문서는 plugin의 service 진입점, session 계층, routing 방향을 설명합니다.

---

## 핵심 원칙

- plugin 내부 MCP HTTP service가 유일한 공개 진입점입니다.
- plugin 내부 Roslyn은 Godot .NET runtime 안에서 syntax-first 방식으로 동작합니다.
- 외부 host도 없고 child process도 없습니다.

---

## 서비스 진입점

### 공개 진입점

plugin의 MCP service는 `plugin/runtime/mcp_http_server.gd`가 제공합니다.

- HTTP listen은 `http://127.0.0.1:3000/mcp` 또는 현재 설정된 port를 사용합니다.
- tool registration과 dispatch는 `tools/core/tool_loader.gd`가 담당합니다.
- MCP Resources와 Prompts는 JSON-RPC method layer에서 직접 제공하며, project information, diagnostic summary, 안전한 file template, guidance prompt를 읽을 수 있습니다.

외부 MCP client는 다음 주소로 연결합니다.

```text
http://127.0.0.1:3000/mcp
```

### protocol method

`POST /mcp`는 JSON-RPC 2.0을 사용하며 다음 주요 MCP method를 지원합니다.

| Method | 용도 |
|---|---|
| `initialize` | protocol version, tool schema version, server info, `tools`, `resources`, `prompts` capability를 반환합니다. |
| `tools/list` / `tools/call` | high-level tool list를 공개하고 tool call을 실행합니다. |
| `resources/list` / `resources/templates/list` / `resources/read` | built-in server resource를 열거하고, scene/script/resource 읽기 template을 제공하며, 엄격한 `res://` path 검사로 읽기 전용 내용을 반환합니다. |
| `prompts/list` / `prompts/get` | built-in prompt를 열거하고, project orientation, content authoring, diagnostic triage, reference integrity, runtime validation, editor UI control용 6개의 parameterized workflow guide message를 반환합니다. |
| `ping` | 빈 결과를 반환해 connection keep-alive에 사용합니다. |

### 내부 component

Prompts와 Tools의 경계는 분리합니다. `prompts/get`은 대화 context에 넣을 workflow 설명만 반환하고 editor action은 수행하지 않습니다. 실제 읽기, 검증, 수정, 실행은 `tools/call`의 high-level tool에서 이뤄집니다. `system_help` 응답에는 `prompt_guides` summary가 포함되어 Agent가 `prompts/list`와 `prompts/get`을 쉽게 찾을 수 있습니다.

plugin 내부 component:

- `plugin/runtime/mcp_http_server.gd` - MCP HTTP service
- `plugin/runtime/mcp_resources_service.gd` - MCP Resources list/read service
- `plugin/runtime/mcp_prompts_service.gd` - MCP Prompts list/read service
- `plugin/runtime/server_runtime_controller.gd` - service lifecycle manager
- `plugin/runtime/plugin_roslyn_service.gd` - plugin 내부 Roslyn façade
- `tools/core/tool_loader.gd` - tool catalog와 loading

## tool 계층

### Editor-attached

모든 tool은 현재 editor state에 의존합니다.

- `system_*` - project snapshot, scene analysis, script structure check, C# binding audit, symbol search
- `script_*` - script read/write, C# syntax analysis
- `scene_*` - scene query와 modification
- `node_*` - node 조작

### plugin 내부 개발 기능

다음 기능은 plugin 내부 진단과 유지보수에 사용합니다.

- `plugin_runtime_*`
- `plugin_developer_*`
- `plugin_evolution_*`

---

## session model

plugin은 외부 session 개념을 관리하지 않습니다. 모든 tool은 editor process 안에서 직접 동작합니다.

Godot executable path 방침:

- Godot path는 사용자가 명시적으로 설정했거나, local의 흔한 directory에서 찾은 것을 사용합니다.
- 넓은 범위의 디스크 스캔은 하지 않습니다.
- machine 의존 path를 release artifact에 넣지 않습니다.

---

## routing 책임

### plugin

담당하는 항목:

- MCP HTTP service의 listen과 request 처리
- tool catalog registration과 dispatch
- 실시간 editor environment에서의 tool 실행
- local service와 diagnostic panel 제공
- plugin 측 tool runtime과 `user_*` extension 유지

### plugin 내부 Roslyn

담당하는 항목:

- C# syntax tree parse, syntax-only, SemanticModel 없음
- type, method, export member 추출
- `script_inspect`, `script_exports`, `script_edit_cs` 같은 C# tool의 syntax analysis

---

## error semantics

editor-required tool에서는 plugin이 구조화된 error를 반환합니다.

- `project_not_selected`
- `godot_executable_not_found`
- `script_not_found`
- `parse_error`
- `binding_audit_error`

---

## 현재 구현 경계

- plugin은 local HTTP MCP service address를 제공합니다.
- C# analysis는 plugin 내부 Roslyn syntax-first 방식을 사용합니다.
- `addons/godot_dotnet_mcp/dotnet_bridge/`는 plugin 내부의 공유 .NET library이며 외부 executable이 아닙니다.
