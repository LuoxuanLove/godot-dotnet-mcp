# 코딩 및 아키텍처 규범

이 규범은 `godot-dotnet-mcp`의 강한 제약 문서입니다.
이 문서의 “반드시 / 금지” 항목은 모두 hard rule이며, `scripts/validate_refactor_guardrails.ps1`가 직접 차단합니다.

---

## 1. 적용 범위와 실행 등급

- 적용 범위: `godot-dotnet-mcp` 저장소만 해당
- 실행 등급: 즉시 hard block, 유예기간 없음
- 호환 전략: 파괴적 리팩터링 허용, 교체 후에는 옛 구현을 삭제하고 호환층을 남기지 않음

---

## 2. 계층 경계 행렬

허용되는 의존 방향:

```text
plugin composition -> plugin runtime -> tools domain
plugin composition -> plugin presenters/ui
```

금지되는 의존 방향:

- `tools/*`가 역으로 `plugin/*`에 의존하는 것
- `plugin runtime`이 역으로 `ui/*`에 의존하는 것
- 문자열 method name이나 global singleton으로 협력자 주입을 우회하는 것

---

## 3. 주입과 조립 규칙

반드시:

- typed context 또는 명시적 parameter로 협력자를 주입
- composition root는 객체 조립과 생명주기 연결만 담당하고 business branch는 들지 않음
- 협력자 `configure()`는 여러 번 호출해도 안전해야 하며, `dispose/reset`으로 참조 해제를 지원해야 함

금지:

- `configure(callbacks: Dictionary)`
- 실행 주 경로가 “임의 key name” callback dictionary에 의존하는 것
- context/factory가 기능 영역을 넘는 큰 dictionary를 반환하고 이를 사실 원천으로 넘기는 것

---

## 4. 규모 임계값(hard upper bound)

책임별로 다음을 지킵니다.

- `plugin.gd`, `plugin/runtime/mcp_http_server.gd`: `<= 360` lines
- `plugin/runtime/*service*.gd`: `<= 320` lines
- `plugin/*coordinator*.gd`: `<= 260` lines
- `ui/*tab*.gd`: `<= 420` lines
- `tools/*/catalog.gd`:
  - `get_tools` 함수는 `<= 120` lines
  - 초과하면 static data source + 안정적 read entry로 바꿔야 함
- 어떤 GDScript든 단일 함수는 `<= 90` lines (data table 함수 제외, 하지만 catalog rule은 여전히 적용)
- 어떤 GDScript든 공개 함수 수는 `<= 28`
- 새 `*context*.gd`는 다음을 만족해야 함:
  - 단일 파일 `<= 28` lines
  - field 선언과 거의 분기 없는 보조만 허용, business logic을 담으면 안 됨

---

## 5. 미니 빈 껍데기 파일 규칙

허용되는 미니 빈 껍데기 파일(`<= 8` lines)은 다음뿐입니다.

- `tools/*/executor.gd`의 bridge entry
- 명시적으로 화이트리스트에 들어간 안정적인 재노출 entry

금지:

- 파일 임계값을 피하려고 의미 없는 얇은 shell 파일을 대량으로 만드는 것
- 빈 껍데기 파일 안에 실제 동작 분배를 숨기는 것

---

## 6. 반패턴 금지

금지 항목:

- 이중 경로 구현(새 path와 옛 path가 둘 다 살아 있고 둘 다 도달 가능함)
- 호환 wrapper, 호환 alias, 전환 helper를 장기 보관하는 것
- 계층을 넘어 내부 mutable state field에 직접 접근하는 것
- 문자열 method callback(예: `call("method_name")`)을 주 경로로 쓰는 것
- “나중에 지울 것”이라는 이유로 오래된 코드를 남겨 두는 방식

반드시:

- 교체가 끝나면 옛 entry, 옛 helper, 옛 test path를 즉시 삭제
- 구조 변경과 같은 배치에서 contract test도 함께 보강, 장기 test debt 허용하지 않음

---

## 7. 외부 protocol과 tool interface 전략

- 외부 MCP tool 이름과 protocol payload shape는, 새 설계가 더 좋다면 바뀔 수 있습니다.
- 외부 shape가 바뀌면 반드시 같은 배치에서 다음을 함께 합니다.
  - protocol facts 업데이트(문서와 코드 일치)
  - contract test 업데이트
  - 변경 설명 업데이트(`docs/`)

---

## 8. 가드레일과 debt 기준선

가드레일 script는 다음을 hard block해야 합니다.

- 새 `callbacks: Dictionary` 주입 signature
- 새 큰 dictionary 조립 entry
- 파일 / 함수 임계값 초과
- 미니 빈 껍데기 파일의 과도한 생성
- 이미 발견된 반패턴의 재유입

기존 debt 기준선 규칙:

- 기준선은 내려가야 하며 올라가면 안 됨
- 한 배치에서 debt를 하나 줄였다면 기준선도 같이 낮춰야 함
- threshold 조정으로 새 coupling을 덮어쓰면 안 됨

---

## 9. 실행 순서 요구

각 배치는 반드시 아래 순서로 실행합니다.

1. 현재 요구, 범위, 위험, 검증 기준 확인
2. 코드 리팩터링과 옛 코드 삭제
3. 문서와 protocol 설명 갱신
4. 가드레일과 contract test 실행
5. 검증 결과와 남은 위험 기록

---

## 10. 위반 처리

- 이 규범을 위반하는 변경은 merge할 수 없습니다.
- 긴급 수정을 위해 잠시 완화해야 하더라도, 같은 배치에서 반드시 되돌리고 hard constraint를 복구해야 하며 다음 배치로 미루면 안 됩니다.

---

## 11. 남아 있는 debt 기준선

현재 저장소가 유지하는 debt 기준선:

- `callbacks: Dictionary` 주입 잔류:
  - 현재 runtime 주 경로는 비워졌고, 새 잔류는 가드레일이 바로 막음
- 큰 dictionary 조립 잔류:
  - 현재 플러그인 composition 주 경로는 비워졌고, 새 잔류는 가드레일이 바로 막음
- 큰 파일 잔류(계속 정리 중):
  - `plugin/runtime/mcp_runtime_command_service.gd` (331 lines, threshold 320)
  - `plugin/runtime/user_tool_maintenance_service.gd` (418 lines, threshold 320)
  - 여러 `tools/*/catalog.gd:get_tools`

이 debt는 줄이기만 가능하며, 늘리거나 새로운 같은 종류 구조로 바꾸는 것은 허용되지 않습니다.

---
