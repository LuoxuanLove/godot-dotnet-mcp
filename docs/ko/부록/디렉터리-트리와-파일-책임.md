# 디렉터리 트리와 파일 책임

이 문서는 디렉터리 트리 관점에서 `addons/godot_dotnet_mcp`의 주요 파일 구조와 책임 분담을 설명하며, 유지보수자가 구현 진입점을 빠르게 찾도록 돕습니다.

---

## 최상위 디렉터리

```text
addons/godot_dotnet_mcp
├─ custom_tools/
├─ docs/
├─ localization/
├─ plugin/
├─ release/
├─ tools/
├─ ui/
├─ plugin.cfg
├─ plugin.gd
└─ README.md
```

---

## 최상위 파일

| 경로 | 역할 |
|---|---|
| `plugin.gd` | 플러그인 진입점, 생명주기 총괄, 안정적인 브리지 진입점, 최상위 Dock 호출 진입점 |
| `plugin.cfg` | Godot 플러그인 선언과 버전 정보 |
| `README.md` | 외부 사용 안내와 언어 전환 진입점 |
| `docs/en/CHANGELOG.md` / 각 언어의 지역화된 변경 로그 진입점 | 저장소 수준 버전 증가 기록과 다국어 진입점, 플러그인 패키지 내부 디렉터리는 아님 |
| `.gitignore` | `.backup/` 같은 실행 시 산출물을 포함한 무시 규칙 |

## `docs/`

현재 공개 문서는 locale별로 정리되며, 각 locale은 같은 트리 구조를 유지합니다.

- `UI/`
- `테스트/`
- `프로세스/`
- `부록/`

문서 자체도 프로젝트의 일부이므로 코드와 함께 유지해야 합니다.

## `custom_tools/`

이곳은 User 도구 디렉터리입니다. 일반적인 내용은 다음과 같습니다.

- 사용자 스크립트
- self-evolution scaffolding 생성 결과
- 삭제 전 백업 디렉터리 `.backup/`

이 부분은 실행 중에 변하는 영역이며, 내장 도구 도메인과 섞이면 안 됩니다.

---

## `release/`

외부 배포 관련 내용을 담는 영역입니다. 플러그인 런타임 조립에는 참여하지 않습니다.
