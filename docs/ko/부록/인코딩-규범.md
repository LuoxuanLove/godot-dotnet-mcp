# 인코딩 규범

이 문서는 `godot-dotnet-mcp` 저장소의 텍스트 파일 인코딩을 규정합니다. 목표는 다음을 동시에 만족하는 것입니다.

- 크로스플랫폼 코드와 설정 파일의 유지보수성
- Windows 개발 환경에서의 안정적 읽기
- 현재 `Windows PowerShell 5.1` 워크플로의 실용성

현재 전략의 핵심 원칙은 다음입니다.

- 기본은 `UTF-8` 무 BOM
- `Windows PowerShell 5.1`의 기본 읽기 동작이나 Agent 기억 파일 소비와의 호환이 명확히 필요할 때만 `UTF-8 with BOM`

이 규칙은 이미 다음 설정 파일로 반영되어 있습니다.

- `godot-dotnet-mcp/.editorconfig`: 저장소 내 정식 source, 설정, 문서, `*.ps1` 제약
- workspace root `.editorconfig`: 루트 협업 기억 파일만 제약, 플러그인 저장소 자체는 이 문서와 저장소 내 설정을 따름

---

## 전체 규칙

### 반드시 UTF-8 무 BOM 사용

다음 파일 종류와 디렉터리는 기본적으로 `UTF-8` 무 BOM이어야 합니다.

- 모든 source 파일:
  - `*.cs`
  - `*.gd`
  - `*.shader`
- 모든 프로젝트와 설정 파일:
  - `*.csproj`
  - `*.props`
  - `*.targets`
  - `*.sln`
  - `*.json`
  - `*.yml`
  - `*.yaml`
  - `*.xml`
  - `*.toml`
  - `*.cfg`
  - `*.editorconfig`
  - `.gitignore`
  - `.gitattributes`
- 모든 Godot 텍스트 리소스:
  - `*.tscn`
  - `*.tres`
- 모든 외부 공개 문서:
  - `README*.md`
  - `docs/**/*.md`

이유:

- 크로스플랫폼 툴체인에서 가장 안정적이고 범용적인 기본 인코딩이기 때문입니다.
- BOM이 script header, configuration parser, 일부 엄격한 도구를 방해하는 일을 피할 수 있습니다.
- 현재 `.NET` / Godot 텍스트 리소스의 일반적 약속과 맞습니다.

### 반드시 UTF-8 with BOM 사용

다음 파일 종류와 디렉터리는 이 저장소에서 `UTF-8 with BOM`을 써야 합니다.

- `AGENTS.md`
- `CLAUDE.md`
- `*.ps1`

이유:

- 이 파일들은 현재 Windows 개발 환경에서 `Windows PowerShell 5.1`이 직접 읽거나 실행하는 경우가 많습니다.
- PowerShell 5.1은 BOM 없는 UTF-8 중국어 파일을 기본 읽기할 때 깨질 수 있습니다.
- Agent 기억 파일은 기본 Windows toolchain에서 바로 열었을 때 올바르게 보여야 합니다.

## PowerShell 5.1 제약

현재 환경에는 `Windows PowerShell 5.1`이 남아 있으므로 다음 규칙을 지켜야 합니다.

### UTF-8 파일 읽기

- BOM 없는 UTF-8 파일을 읽을 때는 반드시 인코딩을 명시해야 합니다.
- 공식 source, 설정, `docs/**/*.md`의 중국어 내용을 읽을 때 기본 `Get-Content`에 의존하면 안 됩니다.

권장 예:

```powershell
Get-Content -Encoding UTF8 -Path .\docs\附录\编码规范.md
```

### UTF-8 파일 쓰기

- 기본 `Set-Content` / `Out-File`로 저장소 파일을 쓰면 ANSI 또는 잘못된 인코딩이 될 수 있으므로 쓰면 안 됩니다.
- 쓰기 시에는 항상 대상 인코딩을 명시해야 합니다.
- BOM 없는 UTF-8을 쓰려면 PowerShell 5.1에서 `Set-Content -Encoding UTF8`에 기대면 안 됩니다. 이것은 BOM을 씁니다.

권장 방식:

- 정식 source, 설정, 공개 문서:
  - 에디터에서 `UTF-8` 무 BOM으로 저장
  - 또는 `.NET` API로 BOM 없이 직접 쓰기
- `AGENTS.md`, `CLAUDE.md`, `*.ps1`:
  - 명시적으로 `UTF-8 with BOM`으로 쓰기

무 BOM 쓰기 예:

```powershell
[System.IO.File]::WriteAllText(
    $path,
    $content,
    (New-Object System.Text.UTF8Encoding($false))
)
```

BOM 쓰기 예:

```powershell
[System.IO.File]::WriteAllText(
    $path,
    $content,
    (New-Object System.Text.UTF8Encoding($true))
)
```

## 실행 규칙

### 새 파일

- 새 source, 설정, 공개 문서는 기본적으로 `UTF-8` 무 BOM으로 만듭니다.
- 새 `*.ps1`, `AGENTS.md`, `CLAUDE.md`는 기본적으로 `UTF-8 with BOM`으로 만듭니다.

### 기존 파일 수정

- 수정할 때는 파일이 속한 종류의 목표 인코딩을 유지하고, 섞어 쓰지 않습니다.
- 기존 파일의 인코딩이 이 규범과 충돌하면 현재 작업에 지장이 없는 한 목표 인코딩으로 정리해야 합니다.
- 인코딩 규칙을 바꾸면 `.editorconfig`와 이 문서를 동시에 갱신해야 하며, 한쪽만 바꾸면 안 됩니다.

### 검토와 리팩터링 시

- 중국어가 깨져 보이면 파일 손상이라고 단정하기 전에 PowerShell 5.1의 BOM 없는 UTF-8 기본 읽기 문제인지 먼저 확인합니다.
- 저장소가 “깨끗한가”를 볼 때는 내용뿐 아니라 인코딩도 이 규범에 맞는지 함께 봅니다.

## 예외 설명

- 앞으로 저장소의 주 개발 환경이 PowerShell 7로 완전히 바뀌면, 이 규범은 다시 평가해서 BOM 파일 범위를 더 줄일 수 있습니다.
- 어떤 third-party 도구가 특별한 인코딩을 요구하면 그 도구의 hard constraint를 우선하지만, 이유는 대응 문서에 적어야 합니다.
