# 설정과 지속화

이 문서는 플러그인이 사용하는 설정 경로, 지속화 파일 형식, import/export 제약을 정리합니다.

---

## 지속화 경로

| 경로 | 유형 | 역할 |
|---|---|---|
| `user://godot_dotnet_mcp/settings.json` | JSON | 플러그인 설정 |
| `user://godot_dotnet_mcp/profiles/*.json` | JSON | 사용자 정의 tool profile |
| `user://godot_dotnet_mcp/captures/editor/` | 디렉터리 | editor 전체 창 스크린샷 기본 디렉터리, root 수준 `user://file.png`가 들어오면 여기로 모음 |
| `user://godot_dotnet_mcp/captures/editor_controls/` | 디렉터리 | control 스크린샷과 `activate_ui`가 붙인 스크린샷 기본 디렉터리 |
| `user://godot_dotnet_mcp/runtime/captures/<session_id>/` | 디렉터리 | runtime 스크린샷과 저빈도 frame sequence의 기본 session-level 임시 산출물 |
| `user://godot_dotnet_mcp/runtime/events.json` | JSON | runtime bridge fallback event cache |
| `user://godot_dotnet_mcp/logs/user_tool_audit.log` | 로그 | User Tool 감사 로그 |
| 사용자가 지정한 경로 | JSON | `plugin_developer` import/export 도구 설정 |

## 플러그인 설정 파일

경로:

```text
user://godot_dotnet_mcp/settings.json
```

주요 필드:

| 필드 | 설명 |
|---|---|
| `port` | 내장 server port |
| `host` | listen address |
| `auto_start` | 자동 시작 여부 |
| `debug_mode` | debug 로그 출력 여부 |
| `log_level` | 로그 레벨 |
| `permission_level` | 현재 permission level |
| `disabled_tools` | 비활성 tool 전체 이름 목록 |
| `tool_profile_id` | 현재 선택된 profile |
| `language` | 현재 언어 |
| `show_user_tools` | Tools 페이지에서 User 카테고리를 보일지 여부 |
| `collapsed_categories` | 현재 접힌 category 목록 |
| `collapsed_domains` | 현재 접힌 domain 목록 |
| `collapsed_system_tools` | Tools 페이지에서 기본으로 접는 system tool 이름 목록 |

없는 필드는 로드할 때 `PluginRuntimeState.build_default_settings()`로 보완합니다.

## 캐시와 정리

플러그인은 시작 시 `user://`를 자동 정리하지 않습니다. 사용자가 여전히 필요로 하는 검증 스크린샷이나 진단 파일을 실수로 지우지 않기 위해서입니다. Agent가 옛 버전의 root-level cache를 정리하려면 먼저 다음을 호출해야 합니다.

```json
{"action": "cleanup_legacy_cache", "dry_run": true}
```

현재 관리 중인 스크린샷 cache를 보려면 `system_userdata_maintenance(action=list_capture_cache)`를 호출합니다. `captures/editor/`, `captures/editor_controls/`, `runtime/captures/` 안의 cache 파일을 정리하려면 먼저 `system_userdata_maintenance(action=cleanup_capture_cache, dry_run=true)`로 미리 보고, 그 뒤 `dry_run=false`로 적용합니다. 현재 스크린샷 cache 정리는 symlink, Windows junction, reparse point를 건너뛰고 결과의 `skipped_links`에 그 항목을 돌려줍니다.

legacy 후보를 확인한 뒤에는 `system_userdata_maintenance(action=cleanup_legacy_cache, dry_run=false)`를 명시적으로 호출합니다. 이 정리 진입점은 옛 runtime event, User Tool audit log, profile 파일을 옮기고, 예전 버전에서 `user://` root에 흩어져 있던 MCP 임시 스크린샷을 지웁니다.

현재 형식:

```json
{
	"name": "My Profile",
	"disabled_tools": [
		"scene_scene_run",
		"plugin_evolution_plugin_evolution_delete_user_tool"
	]
}
```

설명:

- 파일명은 profile id와 직접 같지 않으며, profile id는 `custom:<slug>` 형식입니다.
- `disabled_tools`는 문자열 배열이어야 합니다.
- profile 이름을 바꾸면 새 파일을 쓰고 옛 파일을 삭제합니다.

## tool 설정 import / export 파일

`plugin_developer_export_config` / `plugin_developer_import_config`에서 사용합니다.

현재 형식:

```json
{
	"format_version": 1,
	"profile_id": "default",
	"disabled_tools": [
		"scene_scene_run"
	]
}
```

검증 규칙:

- `profile_id`는 비어 있으면 안 됩니다.
- `disabled_tools`는 문자열 배열이어야 합니다.
- 배열 안 요소는 빈 문자열이면 안 됩니다.

가져오기가 성공해도 파일 형식 자체를 직접 바꾸지 않고, 구조화 데이터로 다시 읽은 뒤 플러그인 상태에 넘깁니다.

## 클라이언트 설정 쓰기 전략

데스크톱 client 설정 쓰기는 `ClientConfigService.write_config_file()`가 수행합니다.

전략은 다음과 같습니다.

1. 현재 UI에 보이는 JSON 텍스트를 먼저 파싱합니다.
2. 대상 파일이 이미 있으면 원래 JSON을 읽고 파싱을 시도합니다.
3. `mcpServers` 노드만 조작합니다.
4. `godot-mcp` 항목만 갱신하고 다른 server는 지우지 않습니다.
5. 디렉터리가 없으면 먼저 재귀 생성합니다.

즉, 플러그인의 쓰기는 “최소 병합”이지 “전체 파일 덮어쓰기 템플릿”이 아닙니다.

## CLI 설정

CLI client는 현재 직접 파일에 쓰지 않고 command text를 생성합니다. 예:

- Claude Code
- Codex

Claude Code는 추가로 다음을 구분합니다.

- `user`
- `project`

scope 전환은 생성되는 command text에만 영향을 주며, 다른 설정에는 영향이 없습니다.

## HTTP CORS 보안 설정

내장 HTTP MCP 서비스는 기본적으로 wildcard CORS를 켜지 않으며, 모든 응답에 `Access-Control-Allow-Origin: *`를 쓰지 않습니다. `Origin`이 없는 로컬 CLI / 데스크톱 MCP client는 계속 `http://127.0.0.1:<port>/mcp`로 직접 연결합니다. `Origin`이 있는 브라우저 요청은 반드시 allowlist와 정확히 맞아야 합니다.

현재 allowlist는 환경 변수로 설정합니다.

```text
GODOT_DOTNET_MCP_ALLOWED_CORS_ORIGINS=http://localhost:5173,http://127.0.0.1:5173
```

규칙:

- 여러 origin은 영어 쉼표 또는 세미콜론으로 구분합니다.
- 정확한 일치만 허용하고, 접미사 / 접두사 / wildcard 일치는 하지 않습니다.
- `Origin: null`과 allowlist에 없는 origin은 거부합니다.
- Host 검사는 기본적으로 loopback을 허용하고, 현재 실제 listen host도 허용합니다. `GODOT_DOTNET_MCP_SERVER_HOST` 또는 설정 파일로 비기본 host를 쓰면 CLI / 데스크톱 client 설정도 그 host로 직접 연결합니다.
- CORS는 브라우저의 cross-origin 읽기만 제어하며 인증 수단은 아닙니다. 로컬 HTTP 인증 token은 나중의 별도 강화 과제입니다.

## 클라이언트 설치 감지 캐시

클라이언트 설치 감지는 `ClientInstallDetectionService`가 메모리에서 짧게 캐시합니다.

- cache TTL: `5000ms`
- cache 내용: client executable path, config entry 상태, runtime running 상태
- cache는 `user://`에 쓰지 않음

현재 cache 무효화 진입점:

- Config 페이지에서 client path를 수동 선택/지우기
- Config write/remove 완료 후
- Dock이 Config 페이지로 전환될 때

즉, client detection은 지속화 설정 그 자체가 아니라 실행 중 투영 상태입니다.

## 로컬라이제이션 리소스

언어 리소스는 `user://`에 쓰지 않고, 다음에서 직접 가져옵니다.

- `localization/locale_*.gd`

현재 언어 전환 전략:

- 설정 파일에 사용자가 고른 언어를 기록
- 플러그인 시작 시 그 언어를 복원
- 모든 UI 텍스트는 `LocalizationService`가 통합 조회

---

## runtime bridge 지속화 관련 제약

runtime bridge는 Autoload 방식으로 프로젝트에 붙습니다.

- 이름: `MCPRuntimeBridge`
- 경로: `res://addons/godot_dotnet_mcp/plugin/runtime/mcp_runtime_bridge.gd`

이 설정은 플러그인 자신의 `user://` JSON이 아니라 Godot 프로젝트 설정에 쓰입니다.

## 흔한 문제 지점

- 씬의 margin을 바꿨는데 반영되지 않으면, 해당 tab script가 여전히 runtime에서 그 속성을 덮는지 확인합니다.
- profile import가 실패하면 `profile_id`가 비어 있지 않은지, `disabled_tools`가 문자열 배열인지 먼저 봅니다.
- one-click write가 실패하면 대상 directory가 쓰기 가능한지, 기존 JSON이 파싱 가능한지 확인합니다.
- 언어를 바꿨는데 key가 그대로 보이면 대상 `locale_*.gd`에 key가 빠졌는지 확인합니다.
