# UI 개요

이 문서는 `ui/` 디렉터리 아래 장면과 스크립트의 관계, 그리고 Dock 루트 장면이 통합 model을 `Home`, `Tools`, `Resources`, `Prompts`, `Config`, `Settings` 여섯 탭에 어떻게 나눠주는지 설명합니다.

## UI 파일 구성

현재 `ui/` 디렉터리는 다음 파일로 구성됩니다.

| 경로 | 역할 |
|---|---|
| `ui/mcp_dock.tscn` | Dock 루트 장면 |
| `ui/mcp_dock.gd` | Dock 루트 컨트롤러 |
| `ui/server_panel.tscn` | `Home` 탭 장면, 예전 `server` 파일명을 유지 |
| `ui/server_tab.gd` | `Home` 탭 컨트롤러 |
| `ui/server_tab_model_projection.gd` | `Home` 탭의 순수 projection 협력자 |
| `ui/tools_tab.tscn` | `Tools` 탭 장면 |
| `ui/tools_tab.gd` | `Tools` 탭 컨트롤러 |
| `ui/mcp_catalog_tab.tscn` | 공용 `Resources` 및 `Prompts` 탭 장면 |
| `ui/mcp_catalog_tab.gd` | 공용 MCP protocol catalog 탭 컨트롤러 |
| `ui/config_panel.tscn` | `Config` 탭 장면 |
| `ui/config_tab.gd` | `Config` 탭 컨트롤러 |
| `ui/settings_panel.tscn` | `Settings` 탭 장면 |
| `ui/settings_tab.gd` | `Settings` 탭 컨트롤러 |
| `ui/settings_tab_model_projection.gd` | `Settings` 탭의 순수 projection 협력자 |

## 루트 장면 책임

`mcp_dock.tscn`은 다음을 담당합니다.

- 제목 표시줄
- 상태등
- 현재 실행 상태 텍스트
- `TabContainer`
- 탭 장면 인스턴스 자리

`mcp_dock.gd`는 다음을 담당합니다.

- 여섯 탭 장면 인스턴스 생성
- 탭 컨트롤러가 내보낸 signal 연결
- `plugin.gd`가 내리는 통합 model 수신
- 탭 제목, 현지화 텍스트, 루트 상태등 설정
- 호스트 Dock 탭 전환과 포커스 복원 관리

## 루트 컨트롤러 데이터 흐름

현재 Dock은 단방향 데이터 흐름을 씁니다.

```text
plugin.gd
  -> Dock 모델 구성 및 발행
  -> mcp_dock.gd.apply_model(model)
  -> server_tab.gd / tools_tab.gd / mcp_catalog_tab.gd / config_tab.gd / settings_tab.gd
  -> server_tab_model_projection.gd / settings_tab_model_projection.gd, 탭 내부 순수 projection
  -> 사용자 동작 signal
  -> plugin.gd
```

장점은 다음과 같습니다.

- UI 계층이 server나 settings를 직접 읽거나 쓰지 않습니다.
- 모든 탭이 같은 model을 기준으로 합니다.
- 언어 전환, 스케일, 상태 갱신을 함께 다시 그릴 수 있습니다.

## signal 연결

`mcp_dock.gd`가 현재 연결하는 signal은 크게 네 가지입니다.

### 서비스 제어

- `port_changed`
- `log_level_changed`
- `language_changed`
- `start_requested`
- `restart_requested`
- `stop_requested`
- `full_reload_requested`
- `clear_self_diagnostics_requested`

### 도구 페이지 동작

- `delete_user_tool_requested`
- `tool_toggled`
- `category_toggled`
- `domain_toggled`
- `tree_collapse_changed`

### MCP catalog 탭 동작

- `copy_requested`

### Config 탭 동작

- `cli_scope_changed`
- `config_platform_changed`
- `config_client_action_requested`
- `config_client_launch_requested`
- `config_client_path_pick_requested`
- `config_client_path_clear_requested`
- `config_client_open_config_dir_requested`
- `config_client_open_config_file_requested`
- `config_write_requested`
- `config_remove_requested`
- `copy_requested`

### Settings 탭 동작

- `port_changed`
- `log_level_changed`
- `language_changed`
- `update_source_changed`
- `update_custom_branch_changed`
- `update_check_requested`
- `update_apply_requested`

이 signal들은 모두 `plugin.gd`로 되돌아가고, 진입점이 서비스 객체를 호출합니다.

## 탭 인스턴스 방식

`mcp_dock.gd`는 `_ensure_tabs()`에서 다음을 합니다.

1. `TabContainer` 아래 기존 자식을 지웁니다.
2. 다음을 차례대로 로드하고 인스턴스화합니다.
   - `server_panel.tscn`, `Home` 탭으로 로드
   - `tools_tab.tscn`
   - `mcp_catalog_tab.tscn`, `Resources` 탭으로 로드
   - `mcp_catalog_tab.tscn`, `Prompts` 탭으로 로드
   - `config_panel.tscn`
   - `settings_panel.tscn`
3. 탭 컨트롤러가 `apply_model()`을 구현했는지 확인합니다.

직접 탭 순서는 `Home` index 0, `Tools` index 1, `Resources` index 2, `Prompts` index 3, `Config` index 4, `Settings` index 5입니다. 공용 catalog controller는 `set_catalog_mode("resources")` 또는 `set_catalog_mode("prompts")`로 모드를 전환합니다.

직접적인 결과는 다음과 같습니다.

- 각 탭이 독립된 노드 트리를 유지할 수 있습니다.
- 진입 스크립트가 탭 내부 컨트롤을 알 필요가 없습니다.
- 나중에 새 탭을 만들려면 새 장면과 컨트롤러를 추가하고 루트 장면에 연결하면 됩니다.

## 스케일과 레이아웃 전략

UI 스케일은 여전히 `EditorInterface.get_editor_scale()`를 공통 배율 원천으로 쓰지만, 현재 구현은 두 종류의 레이아웃 매개변수를 나눠 다룹니다.

### 스크립트가 계속 제어하는 항목

- 컨트롤 최소 높이
- 도구 트리 열 너비
- 동적으로 생성되는 카드 내용의 최소 높이
- 그림자 크기

### 장면이 우선 제어하는 항목

- `MarginContainer` 여백
- `VBoxContainer/HBoxContainer/GridContainer` 간격
- 분리선 상대 위치
- `VSplitContainer` 분할 레이아웃

즉, 탭 스크립트는 스케일 관련 하드 제약만 남기고, 일반 UI 간격은 `.tscn`에서 직접 조정하는 편이 좋습니다.

## 현재 UI 디렉터리 유지 원칙

- 탭 컨트롤러는 자기 탭의 표시와 상호작용만 맡습니다.
- Dock 루트 컨트롤러는 탭 간 조정과 signal 전달을 맡습니다.
- `Resources`와 `Prompts`는 공유 Dock catalog projection에서 MCP protocol metadata를 렌더링해야 하며, 별도의 private catalog facts를 다시 만들지 않습니다.
- 장면 컨트롤 이름은 의미가 분명해야 하며, `XxxPanel`, `XxxMargin`, `XxxSeparator`, `XxxContent`를 우선합니다.
- 꼭 필요하지 않다면 스크립트에서 일반 margin과 separation 값을 덮지 않습니다.
