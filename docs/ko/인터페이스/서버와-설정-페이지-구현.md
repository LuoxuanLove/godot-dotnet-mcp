# Home 및 Config 페이지 구현

이 문서는 `Home` 페이지와 `Config` 페이지의 scene script 책임, 동적 layout logic, 설정 생성 방식을 설명합니다. `server_panel.tscn` / `server_tab.gd`의 파일명은 그대로 유지하지만, 사용자가 보게 되는 첫 번째 tab은 최신 README 기준으로 `Home`으로 바뀌었습니다.

---

## `Home` 페이지

### 목표 책임

`Home` 페이지가 담당하는 일:

- 현재 서비스 상태와 서비스 주소 표시
- 연결 수, 요청 수, 최근 요청 표시
- 포트, 자동 시작, 로그 레벨, 언어 변경
- 내장 server 시작, 재시작, 중지
- 완전한 플러그인 재로드 트리거
- 플러그인 자체 진단 요약 표시

현재 Home 페이지는 CORS allowlist를 직접 노출하지 않습니다. 브라우저형 client가 로컬 HTTP MCP에 cross-origin 접근을 해야 한다면, 환경 변수 `GODOT_DOTNET_MCP_ALLOWED_CORS_ORIGINS`로 정확한 origin을 지정해야 합니다. CLI와 데스크톱 설정 파일형 client는 보통 CORS가 필요하지 않습니다.

### controller 책임

`server_tab.gd`는 현재 네 가지를 주로 합니다.

1. `server_tab_model_projection.gd`를 호출해 model을 순수 표시 데이터로 변환
2. 투영 결과를 상태 텍스트, 버튼 상태, 드롭다운에 반영
3. `Home` 페이지의 반응형 layout과 스케일 logic 유지
4. 버튼과 설정 동작을 signal로 바꾸기

상태 개요, 자가 진단 요약, 로그 / 언어 옵션 model은 더 이상 `server_tab.gd`에서 직접 만들지 않고, 전부 `server_tab_model_projection.gd`로 내렸습니다.

### 반응형 layout

`server_tab.gd`는 `Tools` 페이지보다 runtime layout control을 더 많이 유지합니다. 이유는 다음 control에 의존하기 때문입니다.

- `GridContainer`
- 진단 카드
- 여러 열로 된 설정 영역

이 control들은 폭에 따라 더 압축된 배치로 바뀌어야 합니다.

### 자가 진단 카드

Home 페이지 머리 부분의 자가 진단 카드 데이터는 다음에서 옵니다.

- `plugin_runtime_state(action=get_lsp_diagnostics_status)`: 상세 runtime 자가 점검 스냅샷
- `project_state(include_runtime_health=true)`: 가벼운 health 요약

이 내용은 `Home` 페이지 안에 함께 보여서, 서비스 상태, 서비스 주소, 재로드 진입점, 플러그인 자가 진단을 첫 화면에 고정하고 독립된 서비스 페이지 흐름은 더 이상 유지하지 않게 합니다.

## `Config` 페이지

### 목표 책임

`Config` 페이지가 담당하는 일:

- 플랫폼 전환
- 데스크톱 client 설정 표시
- CLI command 표시
- Claude Code scope 전환
- `godot-mcp`의 one-click 설치 / 쓰기 / 제거
- 설정 텍스트나 command 복사
- 설치 상태와 설치 위치 / scope를 명확히 표시

### controller 구조

`config_tab.gd`는 모든 client 카드를 `.tscn`에 미리 써 두지 않고, runtime에 동적으로 카드 생성합니다. 이유는 다음과 같습니다.

- 플랫폼이 바뀌면 현재 대상 client만 보여 주기 위해
- 카드 내용이 model에 의해 결정되어 여러 client 확장에 더 적합하기 때문에
- CLI와 데스크톱 client의 버튼 구성이 서로 다르기 때문에

### client 카드 생성

각 client 카드는 `_create_client_card()`에서 동적으로 생성합니다.

- `PanelContainer`
- `MarginContainer`
- `VBoxContainer`
- 제목, 설명, 경로 텍스트, 내용 영역, 버튼 영역

Config 페이지의 정적 그룹 카드와 동적 client 카드 모두 `config_tab.gd::_make_framed_panel_style()`로 `PanelContainer.panel`을 덮습니다. 배경은 editor theme의 `Tree.panel`을 복제하고, 그 위에 `StyleBoxFlat`으로 `Editor.separator_color` 1px border를 넣습니다. 이렇게 하면 `Tools` 페이지 tree 영역과 같은 배경 깊이를 유지하면서 카드 경계는 다시 보이게 됩니다.

설정 내용 영역은 더 이상 직접 편집 가능한 control을 쓰지 않고, `PanelContainer + Label`로 만들고 `TextEdit.read_only` theme style을 적용합니다. 복사 버튼은 내용 영역 오른쪽 위에 떠 있는 형태로 보이며, 기본적으로 숨겨져 있다가 mouse가 내용 영역에 들어오면 나타납니다. 이렇게 하면 read-only text 영역의 시각적 계층은 유지하면서도, 좁은 폭에서 TextEdit이 불필요한 scroll이나 focus 동작을 만들지 않게 됩니다.

버튼 logic:

- 데스크톱 client: 능력에 따라 `Write Config`, `Remove Config`, client 열기, path 관리, 복사 동작을 표시
- CLI client: 능력에 따라 one-click 설치 / 제거, 터미널 열기, path 관리, 복사 동작을 표시

### 플랫폼 그룹

`Config` 페이지는 현재 platform을 다음 두 그룹으로 나눕니다.

- `desktop`
- `cli`

또한 Claude Code는 별도의 scope 행 표시를 합니다.

## 설정 생성과 쓰기 경로

runtime 경로는 다음과 같습니다.

```text
plugin.gd
  -> build model
  -> config_tab.gd
  -> 사용자가 Write / Copy 클릭
  -> mcp_dock.gd signal
  -> plugin.gd / config_feature.gd
  -> config_feature_config_workflow.gd
  -> ClientConfigService.write_config_file()
```

쓰기 시:

1. UI에 표시 중인 JSON 텍스트를 먼저 파싱합니다.
2. 대상 파일이 이미 있고 파싱 가능하면 원본 설정을 읽습니다.
3. `mcpServers` node만 조작합니다.
4. `godot-mcp` 항목만 갱신하고 다른 MCP server는 덮어쓰지 않습니다.

---

## `Server`와 `Config` 페이지의 공통 제약

- 텍스트는 전부 로컬라이제이션 서비스가 만들며, Godot 자동 번역에 의존하지 않습니다.
- 동작은 모두 signal로 `plugin.gd`에 되돌아갑니다.
- tab 자체는 `MCPHttpServer`나 `SettingsStore` 인스턴스를 직접 보유하지 않습니다.
- read-only text 영역은 Godot text control theme를 우선 재사용하고, Config 페이지의 설정 내용 영역은 `PanelContainer + Label`로 텍스트를 담은 뒤 `TextEdit.read_only` style을 적용해 외형을 맞춥니다.

## 관련 파일

| 경로 | 역할 |
|---|---|
| `ui/server_panel.tscn` | Server 페이지 scene |
| `ui/server_tab.gd` | Server 페이지 controller, projection 결과 반영, layout, signal 담당 |
| `ui/server_tab_model_projection.gd` | Server 페이지 순수 projection 협력자, 상태 요약, 자가 진단, 옵션 model 생성 |
| `ui/config_panel.tscn` | Config 페이지 scene |
| `ui/config_tab.gd` | Config 페이지 controller |
| `plugin/config/client_config_service.gd` | Config 페이지 설정 서비스 façade, serializer / inspection / transaction / launcher adapter 일괄 위임 |
| `plugin/config/config_paths.gd` | 각 client 경로와 command 템플릿 |
