# 플러그인 헤드리스 테스트

이 문서는 `Godot Headless Harness`의 현재 구조, 검증 범위, 알려진 경계를 설명합니다.

---

## 목표

플러그인 측 테스트 시스템의 목표는 다음과 같습니다.

- `gdUnit`이나 `GUT` 같은 외부 테스트 framework를 도입하지 않습니다.
- repository-owned fixture project에서 `headless Godot`을 직접 실행합니다.
- plugin runtime, tool loading, routing, system impl의 핵심 동작을 검증합니다.
- runtime refactor에 대한 빠른 회귀 표면을 제공합니다.

## 현재 핵심 구현 포인트

### 1. `Program.cs`는 임시 실제 환경을 구성합니다

harness는 repository directory에서 직접 실행하지 않습니다. 대신 fixture와 addon을 임시 stage root로 복사하고, 그곳에서 Godot을 시작하며, `res://tests/headless_suite_runner.gd`를 실행하고, harness가 시작한 `dotnet build`와 headless Godot PID를 `.tmp/godot_plugin_harness/processes/<runId>.json`에 기록합니다.

장점:

- 테스트 환경이 실제 assembly path에 가깝습니다.
- 작업 directory를 직접 오염시키지 않습니다.
- `--keep-stage-root`를 쓰면 실패 현장을 유지할 수 있습니다.
- process cleanup은 registry에 기록된 harness-owned 임시 process만 대상으로 합니다.

### 2. suite는 단일 case와 다중 case 실행을 지원합니다

`headless_suite_runner.gd`는 case-level start/end log, single-case filter, multi-case selection, per-case/suite duration output, per-case cleanup hook, suite-level final cleanup을 지원합니다.

이는 hang, performance 문제, cleanup 문제를 디버깅할 때 유용합니다.

### 3. headless path에는 default tool access provider가 있습니다

plugin parent가 없는 headless path에서 `MCPHttpServer.new()`를 bare로 만들면 default tool access provider가 생성됩니다. 그래서 loader가 tool directory를 load하고 tool state를 expose할 수 있습니다.

### 4. 첫 안정 테스트 seam이 이미 들어갔습니다

plugin side에는 위에 나열한 HTTP, JSON-RPC, editor lifecycle, runtime fallback, runtime reply, runtime control, user tool, Config workflow, Dock, tool loader, runtime bridge seam이 이미 포함되어 있습니다.

즉 headless contract test는 더 이상 production underscore method name에 직접 의존하지 않습니다.

## 현재 경계

### 1. 테스트는 private method name에 더 이상 의존하지 않지만 seam은 더 나눌 수 있습니다

`http_server_contract_test.gd`와 `runtime_bridge_contract_test.gd`는 public test entry point를 통합니다. 내부 method rename이나 split이 먼저 test를 깨뜨릴 위험이 크게 줄었습니다.

### 2. 현재 형태는 structural contract와 local fake가 섞여 있습니다

이것이 현재 단계의 실제 test shape입니다.

## 현재 실행 명령

권장 명령:

```powershell
dotnet run --project .\tests\godot_plugin_harness\GodotPluginHarness.csproj -c Release -- --godot-path "<Godot Editor Path>"
```

자주 쓰는 추가 option:

- `--keep-stage-root`
- `--cases case_a,case_b`
- `--cleanup-stale-processes`

현재 출력에는 다음이 포함됩니다.

- suite success와 success-marker detection
- stage root
- 각 case의 result와 `duration_ms`
- 전체 suite duration과 phase timing
- Godot exit code
- exit cleanup diagnostics
- stderr summary

일반 headless suite에서 `ObjectDB instances leaked at exit`나 `resources still in use at exit`이 보이면 harness는 여전히 실패하며 `reason=godot_exit_leaks_detected`를 유지합니다. editor probe mode는 editor exit noise를 계속 무시하고 `exitCleanupWarningPolicy=ignored_editor_probe`로 표시합니다.

## 결론

plugin headless harness는 준비되었고 실제 runtime 문제를 찾아 수정하는 데 이미 도움을 주었습니다. 현재 초점은 testing seam과 cleanup boundary를 안정적으로 유지하는 것입니다.
