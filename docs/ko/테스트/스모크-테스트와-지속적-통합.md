# 스모크 테스트와 지속적 통합

이 문서는 smoke 검증과 CI 방어선의 역할을 설명합니다.

## 기본 구조

CI는 빠른 검증과 무거운 검증을 나눕니다.

- `.NET` build는 빠르게 컴파일 문제를 잡습니다.
- guardrail script는 refactor policy, docs i18n, release source 같은 구조 규칙을 검사합니다.
- plugin harness는 Godot fixture project에서 실제 plugin path를 검증합니다.
- release workflow는 tag, version, changelog, release note source가 맞는지 확인합니다.

## PR 검증

PR에서는 변경 범위에 맞는 필수 검증이 통과해야 합니다.

- 문서 변경은 docs i18n validation을 통과해야 합니다.
- 코드 변경은 build와 관련 guardrail을 통과해야 합니다.
- plugin runtime이나 tool behavior가 바뀌면 harness subset을 통과해야 합니다.
- required check 이름은 안정적으로 유지되어야 합니다.

## `dev` push와 merge group

`dev`는 안정적인 통합 branch입니다. merge group과 `dev` push는 PR보다 더 넓은 신뢰 경계를 가집니다.

- 병합 직전에는 required subset이 최신 head를 기준으로 실행되어야 합니다.
- merge group은 branch protection과 같은 의미의 방어선입니다.
- `dev` push 후에는 draft release note나 release source가 최신 상태를 유지해야 합니다.

## release 전 검증

정식 release tag 전에는 다음 항목을 확인합니다.

- tag가 `v*` 형식인지 확인합니다.
- tag version이 `plugin.cfg` version과 맞는지 확인합니다.
- changelog가 목표 version을 언급하는지 확인합니다.
- `docs/ko/프로세스/릴리스-노트/릴리스-노트-v*.md`가 존재하고 version을 언급하는지 확인합니다.
- release notes renderer가 hand-written summary와 commit summary를 결합할 수 있는지 확인합니다.

## 실패 처리 원칙

CI 실패를 숨기지 않습니다.

- 실패 원인은 구조화된 log나 error message로 남깁니다.
- 오래 걸리는 harness는 필요한 경우에만 실행하되, 필요한 변경에서는 생략하지 않습니다.
- 실패가 workflow 자체 문제라면 workflow나 script를 수정합니다.
- 실패가 문서 source 문제라면 문서와 changelog를 함께 수정합니다.

Plugin harness JSON report는 suite 성공 marker와 Godot exit cleanup warning을 구분합니다. 일반 headless suite에서 `ObjectDB instances leaked at exit`나 `resources still in use at exit`이 보이면 여전히 실패하지만, `suiteSuccess`, `successMarkerDetected`, `exitCleanupWarningMarkers`, `exitCleanupWarningPolicy`, `exitCleanupWarningFailure`, `failureClasses`, `primaryFailureClass`를 함께 보고합니다. Script failure summary는 full JSON 앞에 이 field를 표시하므로 CI log에서 exit cleanup warning, runtime error marker, case logic failure를 더 쉽게 구분할 수 있습니다.

## PR 완료 기준

PR은 단순히 branch가 push되었다고 끝나지 않습니다.

- required check가 통과해야 합니다.
- unresolved conversation이 없어야 합니다.
- 최신 head가 review와 CI의 대상이어야 합니다.
- review comment가 유효하면 수정하고, 무효하면 이유를 남겨야 합니다.
- 최종 상태가 maintainer가 병합할 수 있는 상태여야 합니다.

## 권장 실행

문서 i18n 검증:

```powershell
.\scripts\validate_docs_i18n.ps1
```

refactor guardrail:

```powershell
.\scripts\validate_refactor_guardrails.ps1 -SkipVersionPolicy
```

plugin harness:

```powershell
.\scripts\test_plugin_side_roslyn.ps1 -GodotPath "<Godot Path>"
```
