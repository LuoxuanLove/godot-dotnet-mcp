# v1.4.0 프로토콜 리팩터 계획

Godot .NET MCP v1.4.0은 기술 부채 정리와 protocol surface 순화를 중심으로 진행합니다. MCP 2025-06-18의 역할 분리에 맞춰 context, state, catalog는 Resources로 옮기고, workflow guidance는 Prompts에 남기며, Tools는 실제 action이나 계산형 workflow를 실행하는 entry로 좁힙니다.

목표 형태는 적은 수의 canonical public tools, resource-first discovery, 단일 tool catalog fact source, speed, isolation, behavior, migration status로 나눌 수 있는 layered test gates입니다.

## Key Changes

- canonical resource URI를 추가합니다: `guides/index`, `guides/capabilities`, `guides/ui-automation`, `state/project/summary`, `state/editor`, `activity/status`, `activity/recent`, `activity/call/{id}`, `tools/catalog/exposed`, `tools/catalog/visible`.
- 6개의 workflow prompts는 유지하지만, 첫 discovery step으로 `system_help`를 권장하지 않습니다. client는 guide resources 또는 `prompts/list` / `prompts/get`을 사용해야 합니다.
- cognitive / duplicate public tools를 `tools/list`에서 제거합니다: `system_help`, `system_tool_catalog`, `system_tool_activity`. legacy call은 명확한 error와 replacement resource URI를 반환해야 합니다.
- 중복 high-level tools를 통합합니다. `system_scene_validate`와 `system_scene_analyze`는 `system_scene_inspect(action=validate|analyze|full)`로, `system_plugin_reload`와 `system_plugin_update`는 `system_plugin_maintenance(action=reload|update|...)`로 통합합니다. read-only `system_editor_log` usage는 log/activity resources로 옮깁니다.
- `tools/list`는 standard MCP tool list로 돌아가 callable tools, schema, annotations, 필요한 `_meta`만 반환합니다. 전체 tree, group, atomic, action presentation data는 catalog resources에 둡니다.
- tool result에 `structuredContent`와 optional `outputSchema`를 추가합니다. client compatibility를 위해 text JSON은 유지하지만, internal contract의 canonical field는 `structuredContent`입니다.
- read-only project file, scene, script, resource text access는 resource templates로 이동합니다. `system_project_files`는 write, move, delete, scan, reimport 같은 action 용도로 유지합니다.

## Implementation Plan

### 1. Test Guardrails First

- contract case manifest를 만들고 field를 `name`, `layer`, `domain`, `behavior=current|migration|deprecation|removal_guard`, `speed=fast|headless|editor|release`, `isolation=pure|user_fs|stage_root|editor`, `v1_4_disposition=keep|rewrite|delete|expires`로 고정합니다.
- hard-coded required cases를 manifest label selection으로 바꿉니다.
- 이전 behavior tests를 유지해야 하는 compatibility, migration window, 이전 구조가 되살아나지 않도록 하는 removal_guard로 분류합니다.

### 2. Protocol Surface Purification

- `mcp_resources_service.gd`에 guide, state, activity, catalog resources를 구현합니다.
- 기존 project/info, diagnostics, tools/catalog resources가 같은 snapshot data를 재사용하게 합니다.
- prompt text를 수정해 cognitive path를 resource, prompt, canonical tool, resource/activity verification으로 고정합니다.
- `mcp_tool_rpc_router.gd`와 tools list construction을 수정해 public tools가 canonical action tools만 포함하게 합니다.
- `resources/list`, `resources/read`, `prompts/get`, `tools/list`, `tools/call`이 HTTP와 stdio에서 같은 output을 내는 contract를 추가합니다.

### 3. Public Tool Debt Cleanup

- redundant public tools를 제거합니다: `system_help`, `system_tool_catalog`, `system_tool_activity`, `system_scene_validate`, `system_scene_analyze`, `system_plugin_reload`, `system_plugin_update`, `system_editor_log`.
- old internal aliases를 제거합니다: `filesystem_file`, `debug_log`, `resource_manage`.
- 제거 전에 모든 internal references를 교체합니다.
- tests를 "not exposed"에서 "not callable / not present in visible catalog" guard로 강화합니다.
- 필요한 safety / migration layers는 유지합니다: protocol facts fallback, runtime fallback event store, legacy user data cleanup, `trace` to `debug` normalization, old user-tool settings key migration, client config read migration.

### 4. Tool Catalog Refactor

- category, domain key, executor path, source, exposure, hot-reloadability, presentation order를 담는 단일 `ToolCatalogManifest`를 추가합니다.
- `MCPToolManifest`와 `MCPToolRegistry`는 duplicate fact sources를 제거할 때까지 adapter로만 유지합니다.
- `ToolCatalogSnapshotService`를 추가해 exposed, visible, all-tool sets, domain states, presentation trees, search indexes를 한 번에 생성합니다.
- RPC, Tools API, Dock, catalog resources가 같은 snapshot을 사용하게 합니다.
- `atomic_bridge`를 `AtomicToolFacade`로 낮추고 write guards와 helpers는 유지하되, execution은 unified internal execution으로 위임합니다.
- 각 system impl의 schema, handler, atomic dependencies를 declarative specs로 합치고, `SystemTreeCatalog`를 specs에서 파생합니다.

### 5. Old Monolith Removal

- 이미 `tools/<domain>/executor.gd`가 있는 각 domain에서 root-level `tools/<domain>_tools.gd` monolith를 migration한 뒤 삭제합니다.
- `base_tools.gd`와 실제 shared helpers는 삭제 대상이 아닙니다.
- final contracts는 "split executor 이후 제거해야 한다"가 아니라 old monolith file이 존재하지 않음을 직접 assert해야 합니다.
- 우선순위는 contract가 명시한 audio, animation, signal, tilemap, UI이고, 이후 filesystem, debug, resource, node, project, scene 같은 큰 domain을 처리합니다.

### 6. Internal Service Convergence

- `MCPToolLoader`를 runtime facade, definition catalog, execution service, visibility policy, activity recorder로 나눕니다. 모든 caller가 이동할 때까지 external adapter는 유지합니다.
- HTTP와 stdio가 같은 JSON-RPC method router, tool router, result normalization, resources/prompts dispatch path를 공유하게 합니다.
- tiny callable context bags를 service graph 또는 ports objects로 수렴합니다.
- 마지막으로 `plugin.gd`를 EditorPlugin lifecycle과 service wiring만 남기도록 slim화합니다. update, user tools, diagnostics, Dock models, configuration actions는 dedicated feature services로 옮깁니다.

## Test Plan

- Fast static gates: .NET build, manifest lint, refactor guardrails, version policy, documentation localization, workflow lint.
- Headless smoke gates: resource-first MCP contracts, canonical `tools/list`, `tools/call` `structuredContent`, removal guards, tool snapshot parity.
- Headless integration gates: domain-sharded runtime, resources/prompts/tools, client config migration, user tools, localization, transport parity.
- Editor probes: plugin entrypoint, settings persistence, real editor-only lifecycle, UI evidence, settings, inspector workflows.
- Migration / deprecation gates: old user-tool naming, old client config, old stdio config, old C# reference path-first behavior는 migration diagnostics 검증으로 제한하고 old implementation을 영구 보호하지 않습니다.
- Release preflight: full harness, clean install build, release-note rendering, changelog/i18n, version/tag boundary validation.

## Assumptions

- v1.4.0은 breaking cleanup을 허용하며, 대상은 public tool-name convergence와 old internal alias removal에 집중됩니다.
- Resources / Prompts support가 부족한 client가 protocol surface 방향을 결정하지 않습니다. plugin은 MCP specification을 따르며 clear errors와 replacement URIs를 반환합니다.
- `script_references` legacy path-first behavior는 별도 C# reference-system task가 열리기 전까지 삭제하지 않습니다. 이 계획은 관련 tests를 migration / deprecation candidates로 표시하는 데 그칩니다.
- 각 PR은 test guardrails, protocol surface, public tool cleanup, manifest/snapshot, monolith removal, loader/atomic convergence, plugin slimming 중 하나의 refactor axis만 다룹니다.
