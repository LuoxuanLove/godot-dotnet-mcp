# v2.0.0 UI 정보 설계 계획

## 개요

v2.0.0 protocol refactor 는 public MCP tool surface 를 canonical `system_*` 와 `user_*` entry 로 좁힌다. 하지만 구현 내부에는 많은 internal executor category 가 남아 있다. Dock 은 이 두 층을 명확히 분리해야 한다. 기본 페이지는 Agent 또는 사용자가 호출, 읽기, 요청해야 하는 대상을 보여 주고, 더 깊은 보기는 구성과 운영 상태를 설명해야 한다.

이 계획은 Tools, Resources, Prompts 페이지를 다룬다. 단계별 PR 의 설계 목표이며 release note 가 아니다.

## 공유 표시 모델

Dock 페이지는 category 이름, URI 조각, prompt 이름에서 사설 tree 를 다시 만들지 말고 공유 presentation model 을 소비해야 한다. 각 node 는 명확한 field 를 가져야 한다.

## Tools 페이지

Tools 페이지는 기본으로 Agent Tools view 를 연다. 이 view 는 무엇을 호출할 수 있는지 답한다.

기본 group:

```text
Agent Tools
├─ Project & Context
├─ Editor Automation
├─ Scene & Resource
├─ Script & C# Semantics
├─ Runtime & Debugging
├─ Plugin Maintenance
└─ User Tools
```

규칙:

- canonical public tools 와 user tools 만 기본 표시한다.
- internal executor categories 는 기본 tree 에 표시하지 않는다.
- removed 또는 legacy tools 를 일반 tool 로 표시하지 않는다.
- resource 또는 prompt discovery entry 를 일반 callable tool 로 표시하지 않는다.
- 기본 합계에는 기본 표시 public tools 만 계산한다.
- 중복 node 대신 implemented by executor 같은 cross-link 로 관계를 표현한다.

Tools 페이지는 두 가지 깊은 view 도 제공한다.

- Structure view: 선택한 public tool 뒤의 actions, inputs, outputs, data sources, services, internal executors 를 보여 준다.
- Diagnostics view: exposure, callability, source file, manifest entry, policy decision, load status, schema status, recent activity, replacement guidance 를 보여 준다.

Internal executors 는 명확히 labelled advanced section 에 둔다.

```text
Internal Executors
├─ core
├─ visual
├─ gameplay
├─ interface
├─ plugin
└─ user
```

각 internal executor row 는 loaded state, enabled tool count, total tool count, source path, load errors, reload status, hot reload status, public tools produced, internal tools produced 를 보여 준다.

## Resources 페이지

Resources 페이지는 기본으로 Resource Catalog view 를 연다. 이 view 는 무엇을 읽을 수 있는지 답한다.

기본 group:

```text
Resources
├─ Guides
├─ Project State
├─ Editor State
├─ Activity & Logs
├─ Tool Catalog
├─ Resource Templates
└─ Advanced Resources
```

규칙:

- `resources/list` 와 `resources/templates/list` 의 canonical resource URIs 와 templates 를 보여 준다.
- title, description, icons, MIME type, template parameters, stable URI 를 표시한다.
- 기본 resource tree 에 tool-like actions 를 섞지 말고 관련 tools 로 link 한다.
- `_meta.resourceKind` 또는 동등한 catalog metadata 가 있으면 Dock 은 URI substring 으로 분류하지 않는다.
- templates 는 재사용 가능한 읽기 대상이며 callable tools 가 아니다.

Resources 페이지에 포함할 view:

- Reader view: 선택한 resource content, MIME type, metadata 를 preview 하고 copy URI 를 제공한다.
- Template view: template parameters, examples, validation hints 를 보여 주고 copy expanded URI 를 제공한다.
- Diagnostics view: source service, resource kind, visibility, last read status, content size, template binding errors, stale cache status, fallback guidance 를 보여 준다.

Protocol 과 safety rules:

- `resources/list`, `resources/templates/list`, `resources/read` 를 페이지 내용, preview, error behavior 의 source of truth 로 둔다.
- logs 와 diagnostics 의 redaction behavior 를 유지한다.
- template path validation, traversal rejection, absolute/user path rejection, binary rejection, oversized content handling 을 유지한다.
- Compatibility resources 는 compatibility entries 로 label 하고 canonical resources 보다 위로 올리지 않는다.

Resources 수락 기준:

- Guides, state, activity, logs, catalog, templates 는 기본 catalog 에 한 번만 나타난다.
- Template entries 는 tools 로 계산하지 않는다.
- Resource kind 는 공유 metadata 에서 온다.
- Resource preview 는 큰 내용, 빈 내용, 지원하지 않는 MIME type, read errors 를 겹침 없이 처리한다.
- Diagnostics 는 missing, hidden, failed resource reads 를 설명할 수 있다.
- Resource preview semantics 는 `resources/read(uri)` 와 동등해야 한다.

## Prompts 페이지

Prompts 페이지는 기본으로 Prompt Catalog view 를 연다. 이 view 는 어떤 workflow guidance 를 요청할 수 있는지 답한다.

기본 group:

```text
Prompts
├─ Project Understanding
├─ Editor Workflow
├─ Runtime Validation
├─ Script & C# Workflow
├─ Plugin Maintenance
└─ Advanced Prompts
```

규칙:

- `prompts/list` 의 prompts 를 title, description, icons, arguments, stable name 과 함께 표시한다.
- Prompt entries 는 tools 와 resources 에서 분리한다.
- Prompt arguments 는 child tools 가 아니라 arguments 로 표시한다.
- metadata 가 있으면 prompt name substring 으로 prompt kind 를 추론하지 않는다.
- required, optional, enum, bool, path-like arguments 를 시각적으로 구분한다.

Prompts 페이지에 포함할 view:

- Prompt builder view: argument editors, validation hints, preview request, copy prompt name.
- Message preview view: rendered messages, roles, text content, resource/tool links.
- Diagnostics view: prompt source, prompt kind, argument schema, unknown-argument policy, type validation status, last render error, related resources/tools.

Protocol 과 safety rules:

- `prompts/list` 와 `prompts/get` 을 페이지 내용, preview, error behavior 의 source of truth 로 둔다.
- prompt unknown-argument 와 wrong-type validation semantics 를 유지한다.
- prompt service 가 제공하는 truncation metadata, localized title, description, argument text 를 유지한다.
- Prompt preview semantics 는 `prompts/get(name, arguments)` 와 동등해야 한다.

Prompts 수락 기준:

- Workflow prompts 는 기본 catalog 에 한 번만 나타난다.
- Arguments 는 narrow panel 에서 layout 을 깨거나 label 과 겹치지 않는다.
- Unknown 과 wrong-type arguments 는 validation concerns 로 표시된다.
- Rendered messages 는 role 과 content 를 명확히 유지한다.
- Diagnostics 는 prompt visibility, argument validation, render failures 를 설명할 수 있다.

## 공유 상호작용 규칙

여러 깊이를 가진 페이지는 공유 mode switch 를 사용한다.

```text
Default
Structure
Diagnostics
Advanced
```

검색은 모든 mode 에서 공통이지만 각 result 는 type badge 를 가져야 한다.

```text
Public
Internal
Legacy
Removed
Disabled
Error
Resource
Template
Prompt
Argument
```

Preview panel 은 안정적인 크기와 compact labels 를 사용한다. Buttons 는 가능하면 icon 을 쓰고 익숙하지 않은 action 에 tooltip 을 붙인다. Disabled 또는 non-callable nodes 에 run-style actions 를 표시하지 않는다.

## PR 계획

### PR 1: 계획과 모델 계약

- 이 계획을 docs tree 에 저장한다.
- Tools, Resources, Prompts 의 presentation model contracts 를 추가한다.
- UI 변경은 최소로 유지한다.

### PR 2: Agent Tools 기본 view

- Tools tab 기본 tree 를 canonical public tools plus user tools 로 전환한다.
- executor categories 를 advanced 또는 diagnostics path 로 이동한다.
- 기본 count 와 중복 DAP/runtime/project 계열 row 를 수정한다.

### PR 3: Resources 와 Prompts 기본 view

- Resources 와 Prompts 가 명확한 presentation models 를 소비하게 한다.
- 안정적인 previews, argument/template panels, metadata badges 를 추가한다.
- 공유 metadata 가 있는 곳에서는 사설 Dock 분류 추측을 제거한다.

### PR 4: Structure 와 Diagnostics views

- Tools, Resources, Prompts 에 깊은 view 를 추가한다.
- exposure, callability, data source, validation, activity, replacement, load/read/render status 를 표시한다.
- errors, hidden entries, legacy entries, internal entries, disabled entries filter 를 추가한다.

### PR 5: Visual verification 과 polish

- desktop 과 narrow-panel rendering 을 검증한다.
- labels, buttons, previews, schemas, badges 가 겹치지 않는지 확인한다.
- Tools, Resources, Prompts 의 visual evidence 를 캡처한다.

## 수락 기준

- 기본 Tools 페이지는 canonical callable tools 를 한 번만 보여 주고 internal executor categories 를 기본 count 에서 제외한다.
- DAP, runtime, project, scene, resource capabilities 는 동등한 일반 tool 로 중복 표시되지 않는다.
- Removed legacy tools 는 Agent Tools 에 없고 diagnostics 에서 replacement guidance 와 함께 보인다.
- Resources 페이지는 resource entries 와 templates 를 한 번만 보여 주며 metadata-driven kinds 와 안전한 previews 를 사용한다.
- Prompts 페이지는 prompts 를 한 번만 보여 주고 argument editors 와 message preview 를 tools 에서 분리한다.
- Structure 와 diagnostics views 는 non-callable nodes 를 명확히 non-callable 로 보여 준다.
- 모든 view 는 entry 가 visible, hidden, disabled, removed, failing 인 이유를 설명할 수 있다.
- 구현 PR 뒤 visual verification 은 Tools, Resources, Prompts 를 대상으로 한다.
