# v1.4.0 리팩터 진행 추적

이 문서는 v1.4.0 protocol refactor plan을 실행 체크리스트로 나눕니다. 각 항목은 review, validation, v1.4 refactor branch merge가 가능한 PR 단위와 연결되어야 합니다.

상태:

- `Done`: 구현, 검증, review가 끝났고 v1.4 refactor branch에 merge됨.
- `Partial`: 유효한 진전은 있지만 필수 follow-up이 남아 있음.
- `Pending`: 아직 실질 구현이 없음.
- `Blocked`: 명확한 외부 prerequisite이 있음.

## Current Phase

v1.4.0은 초기 guardrail 단계를 지나 protocol surface 준비 중반에 있습니다. refactor target은 이제 default MCP 2025-11-25 conformance이며, 기존 2025-06-18 alignment는 compatibility foundation으로 유지합니다. 현재 branch에는 test scaffolding과 여러 MCP protocol improvement가 들어갔지만, 2025-11-25 transport/schema/metadata gates, breaking public-tool cleanup, single catalog fact source, old monolith removal, internal service convergence는 아직 완료되지 않았습니다.

## Next PR Queue

1. MCP 2025-11-25 conformance gate taxonomy와 protocol-version/schema/tool-name metadata contracts를 추가한다.
2. `http://127.0.0.1:3000/mcp`를 default Streamable HTTP endpoint로 정의하고 version/session/Accept/SSE/Origin contracts를 추가한다.
3. newline-delimited stdio를 default mode로 만들고 `Content-Length`는 명시적 legacy compatibility로 유지한다.
4. Resources, Resource Templates, Prompts, Tools에 2025-11-25 icons/title/description/schema metadata를 추가한다.
5. Dock / Tools UI model을 shared catalog snapshot metadata에서 render하도록 바꾸고 private tree facts를 만들지 않는다.
6. `ToolCatalogSnapshotService`를 추가하고 catalog resources, search, presentation, Tools API, Dock consumer를 `ToolCatalogManifest` / `ToolCatalogSnapshotService`로 이동한다.
7. debug/editor compatibility entry와 남은 root-level visual-domain monolith cleanup을 계속한다.
8. `atomic_bridge`를 unified internal execution facade 뒤로 이동한다.
9. snapshot service 안정 후 `MCPToolLoader` 책임을 분리한다.
10. catalog consumer가 manifest/snapshot path를 공유한 뒤 internal service convergence를 계속한다.

## Tracking Rules

- breaking removal은 error에 replacement method 또는 resource URI를 반드시 포함한다.
- 삭제된 public tool은 `tools/list`, visible catalog resource, successful call에서 모두 사라졌음을 test로 증명한다.
- Prompt guidance는 resource-first path를 설명하고 삭제된 discovery tool을 시작점으로 쓰지 않는다.
- default v1.4 endpoint는 MCP Streamable HTTP로서의 `http://127.0.0.1:3000/mcp`이다. legacy `/api/tools`, `/health`, JSON-only POST behavior, `Content-Length` stdio는 compatibility surface로 표시해야 한다.
- UI catalog models는 shared catalog snapshot metadata를 consume하고 별도 private catalog facts를 만들지 않는다.
- Changelog는 `Added / Changed / Fixed / Documentation / Internal` 순서를 지키고 같은 version 안에서 section을 중복하지 않는다.
- PR은 local validation, 관련 GitHub check, 모든 conversation, Codex review gate가 끝나기 전에는 v1.4 refactor branch에 merge하지 않는다.
