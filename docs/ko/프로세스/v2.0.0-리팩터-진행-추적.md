# v2.0.0 리팩터 진행 추적

이 tracker는 v2.0.0 protocol refactor plan을 실행 checklist로 나눕니다. 각 행은 review, test, v2.0 refactor branch merge가 가능한 PR-sized work와 대응해야 합니다.

상태:

- `Done`: 구현, 검증, review가 끝났고 v2.0 refactor branch에 merge됨.
- `Partial`: 유효한 진전은 있지만 필수 follow-up이 남아 있음.
- `Pending`: 아직 실질 구현이 없음.
- `Blocked`: 명확한 외부 prerequisite이 있음.

## Current Phase

v2.0.0 line은 계획된 protocol-purity와 UI metadata refactor scope를 완료했습니다. refactor target은 기본적으로 MCP 2025-11-25 conformance이며, 이전 2025-06-18 alignment는 compatibility foundation으로 유지됩니다. branch에는 강한 test scaffolding, 명시적인 MCP 2025-11-25 aggregate conformance gate, 넓은 protocol/UI metadata coverage, release-contract Streamable HTTP coverage, loader / transport / atomic bridge / plugin lifecycle wiring이 monolithic facade로 돌아가지 않도록 하는 service-convergence guards가 있습니다. 향후 작업은 v2.0 plan debt가 아니라 새로운 scoped requirement로 추적해야 합니다.

## Next PR Queue

1. future Tools tab context actions는 shared catalog snapshot metadata에 유지하고 private tree fact sources를 추가하지 않는다.
2. Atomic helper/collection behavior는 `AtomicBridgeHelperService`에 유지하고 `AtomicBridgeExecutionService`나 bridge facade로 되돌리지 않는다.
3. root monolith guard와 debug/editor compatibility-wrapper contracts로 monolith cleanup을 닫힌 상태로 유지한다.
4. Streamable HTTP behavior를 확장하기 전에 explicit transport contracts를 추가한다.
5. future loader, transport, plugin lifecycle assembly는 dedicated services에 두고 facade에서 callback maps를 재구축하지 않는다.

## Tracking Rules

- breaking removal은 error에 replacement method 또는 resource URI를 반드시 포함한다.
- 삭제된 public tool은 `tools/list`, visible catalog resource, successful call에서 모두 사라졌음을 test로 증명한다.
- Prompt guidance는 resource-first path를 설명하고 삭제된 discovery tool을 시작점으로 쓰지 않는다.
- default v2.0 endpoint는 MCP Streamable HTTP로서의 `http://127.0.0.1:3000/mcp`이다. legacy `/api/tools`, `/health`, JSON-only POST behavior, `Content-Length` stdio는 compatibility surface로 표시해야 한다.
- UI catalog models는 shared catalog snapshot metadata를 consume하고 별도 private catalog facts를 만들지 않는다.
- future Tools tab context actions는 shared manifest/snapshot metadata 위에 있어야 하며 private tree fact sources를 만들지 않는다.
- future atomic helper / collection behavior는 `AtomicBridgeHelperService` / system implementation helper services에 두고 `AtomicBridgeExecutionService`나 bridge facade로 되돌리지 않는다.
- Changelog entries는 `Added / Changed / Fixed / Documentation / Internal` 순서를 지키고 같은 version 안에서 section을 중복하지 않는다.
- PR은 local validation, 관련 GitHub check, 모든 conversation, Codex review gate가 끝나기 전에는 v2.0 refactor branch에 merge하지 않는다.
