# v2.0.0 프로토콜 리팩터 계획

## Summary

Godot .NET MCP v2.0.0은 기술 부채 정리, protocol surface 순화, 2025-11-25 conformance를 중심으로 진행합니다. MCP 2025-11-25 specification에 맞춰 context, state, catalog는 Resources로 옮기고, workflow guidance는 Prompts에 남기며, Tools는 실제 action이나 계산형 workflow를 실행하는 entry로 좁힙니다.

기존 MCP 2025-06-18 alignment는 compatibility foundation으로 유지합니다. v2.0.0 release target은 default MCP surface가 2025-11-25를 따르는 형태로 바뀝니다. public tool surface는 breaking cleanup을 허용하지만, 모든 제거에는 replacement entry, replacement metadata, removal guard tests가 필요합니다.

목표 형태는 적은 수의 canonical public tools, resource-first cognitive entry points, 단일 tool-catalog fact source, 2025-11-25 transport/schema/metadata gates입니다.

## Key Changes

- protocol baseline을 `protocolVersion = 2025-11-25`로 전환하고, `serverInfo` / `Implementation`에 `description` 같은 human-readable metadata를 추가합니다.
- canonical resource URI를 유지합니다: `guides/index`, `guides/capabilities`, `guides/ui-automation`, `state/project/summary`, `state/editor`, `activity/status`, `activity/recent`, `activity/call/{id}`, `tools/catalog/exposed`, `tools/catalog/visible`. 여기에 2025-11-25 `icons` / title metadata를 추가합니다.
- 6개의 workflow prompts는 유지합니다. `system_help`를 첫 단계로 권장하지 않고, prompt `icons`, argument schemas, path/enum/bool argument guard를 추가합니다.
- cognitive 또는 duplicate public tool entries 제거를 계속합니다: `system_help`, `system_tool_catalog`, `system_tool_activity`, scene aliases, plugin reload/update aliases, editor log aliases, old internal aliases.
- `tools/list`는 standard MCP tool list로 유지합니다. callable tools, `inputSchema`, `outputSchema`, annotations, icons, 필요한 `_meta`만 반환합니다. tree, group, action presentation data는 catalog resources에만 둡니다.
- `inputSchema` / `outputSchema`는 JSON Schema 2020-12를 default dialect로 취급합니다. legacy schema의 compatibility가 불확실하면 `$schema`를 명시합니다.
- tool-name guard를 추가합니다: 길이 1-128, case-sensitive, ASCII letters/digits/`_`/`-`/`.` 권장, client parsing을 깨는 문자 금지.
- Dock과 Tools UI design을 업데이트해 resources/snapshots에서 2025-11-25 catalog metadata(`icons`, title, description, schema dialect, output schema, exposure state)를 소비하고 private presentation tree를 다시 만들지 않게 합니다.
- default MCP endpoint는 `http://127.0.0.1:3000/mcp`로 유지하되, plugin-private JSON-RPC API가 아니라 MCP 2025-11-25 Streamable HTTP transport로 정의합니다.
- default HTTP request shape는 `POST /mcp`, `Accept: application/json, text/event-stream`, `Content-Type: application/json`, `MCP-Protocol-Version: 2025-11-25`입니다.
- `/api/tools`, `/health`, old JSON-only POST behavior, old `Content-Length` stdio는 legacy compatibility surfaces로만 취급합니다.
- default stdio는 2025-11-25 newline-delimited JSON-RPC로 migration합니다. old `Content-Length` framing은 legacy compatibility mode에서만 사용합니다.
- HTTP는 complete Streamable HTTP semantics로 migration합니다: `MCP-Protocol-Version`, `Mcp-Session-Id`, `Accept`, invalid-Origin 403, SSE polling/resumption을 검증합니다.
- Sampling, Elicitation, Tasks는 optional capabilities입니다. default로 advertise하지 않으며, advertise한 경우 2025-11-25 contracts를 만족해야 합니다.

## Implementation Plan

### 1. Test Guardrails First

- contract case manifest를 `mcp_version=2025-11-25|2025-06-18|legacy`와 `conformance=required|compat|optional`로 확장합니다.
- lifecycle, stdio, Streamable HTTP, Tools, Resources, Prompts, schema, metadata를 포괄하는 `mcp_2025_11_25_conformance_contracts`를 추가합니다.
- old 2025-06-18 tests는 compatibility 또는 migration guards로 재분류합니다. 더 이상 release target을 대표하지 않습니다.
- 모든 breaking removal은 `tools/list` absence, visible catalog absence, legacy-call replacement errors를 증명해야 합니다.

### 2. Protocol Surface Purification

- `initialize`에서 `2025-11-25`, standard capabilities, serverInfo description을 반환합니다.
- `mcp_resources_service.gd`는 guide/state/activity/catalog entry point로 유지하고 icons/title metadata를 추가합니다.
- prompt text는 resource -> prompt -> canonical tool -> resource/activity verification path를 일관되게 설명합니다.
- `tools/list`에서 presentation trees, groups, atomic internals, action-only presentation data를 제거합니다.
- HTTP와 stdio가 하나의 JSON-RPC router, result normalization path, resources/prompts/tools dispatch를 공유하게 합니다.

### 3. Transport Adaptation

- Godot editor가 열려 있고 client가 현재 editor session을 제어해야 하는 경우 `http://127.0.0.1:3000/mcp`를 default MCP Streamable HTTP endpoint로 사용합니다.
- remote MCP를 지원하는 client에는 Streamable HTTP URL을 우선합니다. local command만 지원하는 client에는 Godot headless stdin/stdout stdio launcher를 제공합니다.
- newline-delimited JSON-RPC를 default stdio mode로 사용하고 모든 logs는 stderr로 보냅니다.
- legacy `Content-Length` stdio는 명시적 compatibility configuration에서만 활성화하고 migration warning을 냅니다.
- Streamable HTTP POST JSON-RPC, GET SSE/polling, session ids, resumption, server-initiated disconnects를 지원합니다.
- invalid Origin에는 HTTP 403을 반환합니다.
- HTTP request/response contracts로 `Accept`, `MCP-Protocol-Version`, `Mcp-Session-Id`, SSE event id behavior를 검증합니다.

### 4. Public Tool Debt Cleanup

- redundant public tools를 제거하고 일관된 `removed_public_tool` structured error를 반환합니다.
- replacement metadata는 canonical resource URIs, canonical tools, prompts 중 하나를 가리켜야 합니다.
- input validation failures는 Tool Execution Errors를 우선합니다: `isError=true`와 `structuredContent.success=false`. tool-argument repair cases에서는 JSON-RPC protocol errors를 피합니다.
- 필요한 migration layers는 유지합니다: protocol facts fallback, runtime fallback event store, legacy user data cleanup, `trace -> debug`, old user-tool settings migration, client config migration.

### 5. Tool Catalog Refactor

- category, domain key, executor path, source, exposure, hot-reloadability, presentation order, icons, schema dialect를 담는 `ToolCatalogManifest`를 추가합니다.
- `MCPToolManifest`와 `MCPToolRegistry`는 adapters로 유지한 뒤 duplicate fact sources를 제거합니다.
- `ToolCatalogSnapshotService`로 exposed/visible/all tools, domain states, presentation trees, search indexes, metadata를 한 번에 생성합니다.
- RPC, Tools API, Dock, catalog resources, search가 같은 snapshot을 사용하게 합니다.
- Dock / Tools UI models를 protocol metadata 중심으로 다시 설계합니다. icons는 quick scanning, title/description은 display text, schema dialect/output schema indicator는 inspection, exposed/visible/internal state는 명시적 상태 표시에 사용합니다.
- UI controls는 compact하고 operational하게 유지합니다. marketing-style catalog surface를 추가하지 않고, `tools/list` 또는 catalog resources와 분기되는 private catalog facts를 남기지 않습니다.
- `atomic_bridge`를 facade로 낮추고 execution path는 unified internal execution을 사용합니다.

### 6. Optional Capability Boundaries

- Sampling: server가 client-side LLM work를 정말 필요로 할 때만 advertise합니다. 구현 시 `tools`와 `toolChoice`를 지원합니다.
- Elicitation: URL mode를 우선합니다. form mode는 passwords, API keys, access tokens 같은 sensitive fields를 수집하면 안 됩니다.
- Tasks: run validation, batch audits, update sync, full-project scans 같은 long-running durable workflows에만 사용합니다.
- Authorization: local editor mode는 기본적으로 OAuth를 요구하지 않습니다. remote HTTP mode는 OIDC discovery, Protected Resource Metadata, `WWW-Authenticate` scope challenges를 따릅니다.

### 7. Old Monolith Removal and Internal Service Convergence

- root-level `tools/<domain>_tools.gd` monolith migration / deletion을 계속해 split executors가 유일한 stable entries가 되게 합니다.
- `MCPToolLoader`를 runtime facade, definition catalog, execution service, visibility policy, activity recorder로 나눕니다.
- `plugin.gd`는 EditorPlugin lifecycle과 service wiring만 남기도록 slim화하고, updates, diagnostics, Dock models, configuration actions는 dedicated feature services로 옮깁니다.

## Test Plan

- Fast static: dotnet build, manifest lint, tool-name lint, schema 2020-12 lint, refactor guardrails, version policy, docs localization, actionlint.
- Protocol conformance: initialize, tools/list, tools/call, resources/list/read/templates, prompts/list/get.
- Transport: newline stdio, legacy stdio migration, Streamable HTTP, SSE polling/resumption, Origin 403.
- Public cleanup: removed tools absence, visible catalog absence, replacement errors, structuredContent parity.
- Metadata: icons/title/description/schema dialect/outputSchema snapshot parity.
- UI adaptation: Dock / Tools page models must render from the shared catalog snapshot and preserve icons, titles, descriptions, schemas, and exposure state without inventing a separate catalog fact source.
- Optional features: Sampling, Elicitation, and Tasks run required contracts only when their capabilities are advertised.
- Release preflight: full harness, clean install build, release-note rendering, changelog/i18n, version/tag boundary.

## Assumptions

- v2.0.0은 breaking cleanup을 허용하며 default protocol target은 MCP 2025-11-25입니다.
- 2025-06-18 behavior는 migration / legacy compatibility layer로만 유지하고 2025-11-25 default shape를 막지 않습니다.
- Sampling, Elicitation, Tasks는 optional capabilities입니다. 미성숙한 구현은 advertise하면 안 됩니다.
- 각 PR은 transport, protocol surface, public cleanup, manifest/snapshot, monolith deletion, loader/atomic, optional capability 중 하나의 refactor axis를 다룹니다.
