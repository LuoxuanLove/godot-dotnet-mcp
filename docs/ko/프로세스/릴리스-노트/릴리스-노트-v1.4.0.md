## 🧩 Godot .NET MCP v1.4.0: Protocol Refactor Line Initialized

Godot .NET MCP v1.4.0은 protocol-refactor line을 시작하며 더 엄격한 plugin-first release surface, resource-first context entry, public MCP behavior를 위한 강화된 contract gate를 도입합니다.

### ✨ Release Highlights

v1.4.0 line은 protocol-refactor baseline을 세웁니다. passive context는 MCP Resources로 이동하고, workflow orientation은 Prompts에 남으며, public Tools는 action과 computed workflow entry로 좁아지고, legacy discovery call은 명확한 replacement guidance를 반환합니다.

### 📚 Resource-first Protocol Surface

v1.4.0 line은 passive context, state, catalog discovery를 MCP Resources로 옮기고, workflow planning은 Prompts에 남기며, public Tools는 action 또는 computed workflow result로 좁힙니다. legacy discovery call은 first-class public tool로 남지 않고 명확한 replacement guidance를 반환합니다.

Editor Output 읽기도 같은 resource-first model을 따릅니다. clients는 `godot-dotnet-mcp://logs/editor/output` 또는 `godot-dotnet-mcp://logs/editor/errors`를 읽고, Output clear는 passive Resource가 아니라 명시적인 editor-control action으로 처리합니다.

### 🧪 Reproducible Plugin Gates

Release-facing claims는 plugin-owned checks에 연결됩니다. localized documentation validation, manifest-backed public-tool guardrails, headless MCP contracts, clean install verification을 통해 release notes가 plugin repository에서 재현할 수 있는 behavior에만 집중하게 합니다.

v1.4 install surface는 C# syntax support도 first-class plugin capability로 취급합니다. Asset Library 및 direct source-copy install은 `plugin/runtime/roslyn_runtime/`의 isolated Roslyn runtime bundle을 유지해야 하며, plugin Roslyn / bridge C# source tree는 host project compile surface에 들어가지 않습니다.

### ✅ Compatibility and Upgrade Notes

이 version line은 plugin metadata를 v1.4.0으로 업데이트하며 계속 Godot 4.6+ .NET projects를 대상으로 합니다. client는 passive context와 planning에 새 Resources 및 Prompts entry를 우선 사용하고, legacy discovery call은 first-class public tool이 아니라 migration guidance로 취급해야 합니다.
