## 🧩 Godot .NET MCP v2.0.0: Protocol-First Editor Bridge

Godot .NET MCP `v2.0.0`은 editor-native MCP workflows를 위한 protocol-first refactor release입니다. MCP 2025-11-25 model에 맞춰 context, Prompts, Tools, transports, C# semantic support를 재구성하면서 installation은 plugin 자체를 중심으로 유지합니다.

v2.0.0은 큰 protocol 및 internal service refactor이며, 단순한 cosmetic cleanup이 아닙니다. 목표는 Godot .NET MCP를 first-class MCP 2025-11-25 server처럼 동작하게 만드는 것입니다. passive context는 Resources로, reusable workflow planning은 Prompts로, Tools는 actions와 computed results에 집중하고, editor Dock은 MCP clients가 받는 것과 같은 metadata를 preview합니다. 그 결과 clients는 guessing으로 discovery할 필요가 줄고, 많은 legacy helper tools를 호출하지 않아도 되며, plugin은 더 작고 명확하고 강하게 검증된 public surface를 유지하면서 복잡한 internals를 그 뒤에 둘 수 있습니다.

### ✨ Protocol-First MCP Surface

default MCP protocol target은 2025-11-25로 이동합니다. `initialize`는 v2.0 server description과 protocol baseline을 advertise하고, public tool names는 invalid public names를 막는 guard를 거치며, public metadata의 default schema dialect는 JSON Schema 2020-12입니다.

public surface는 MCP 역할에 맞춰 재구성됩니다.

- Resources는 guide text, project/editor state, editor logs, activity views, tool catalogs 같은 passive context를 노출합니다.
- Prompts는 workflow orientation을 보관해 clients가 passive help tool을 호출하지 않고 structured planning을 얻을 수 있게 합니다.
- Tools는 actions, mutations, captures, diagnostics, computed workflow results에 집중합니다.

legacy discovery-style public tools는 더 이상 primary entry point가 아닙니다. compatibility가 남는 경우에도 retired entries는 Resources, Prompts, canonical action tools로 가는 explicit replacement guidance를 반환합니다.

### 🌊 Streamable HTTP and Stdio

default endpoint는 `http://127.0.0.1:3000/mcp` 그대로지만 endpoint는 v2.0 Streamable HTTP shape를 따릅니다. protocol/session headers, JSON/SSE `Accept` negotiation, Origin/CORS checks, GET SSE streams, resumable event history, finite POST SSE responses, heartbeat events, queued server-to-client delivery, `DELETE /mcp` session termination을 포함합니다.

Stdio는 current MCP clients를 위해 newline-delimited JSON-RPC를 default로 사용합니다. legacy `Content-Length` framing은 explicit compatibility mode로만 남기 때문에 오래된 local launchers를 깨지 않으면서 default transport는 새 규격 쪽으로 이동합니다.

Transport validation도 더 엄격합니다. HTTP와 stdio는 malformed requests, response envelopes, disabled tools, duplicate/conflicting HTTP body headers, session validation에 대해 deterministic JSON-RPC envelope behavior를 공유합니다.

Streamable HTTP replay도 더 명확해졌습니다. GET SSE `open` metadata는 current streams에서 계속 observable하지만 resumable event log에는 들어가지 않습니다. proxy headers는 명시적으로 활성화된 경우에만 신뢰되며, generated session IDs에는 추가 random entropy가 포함됩니다.

Long-running editor sessions도 cleanup이 더 엄격해졌습니다. idle partial HTTP requests는 timeout window 뒤에 닫히고, User-tool definition refreshes는 explicit invalidation 뒤에만 실행되며, debug `dotnet build` diagnostics는 build servers를 비활성화하고, 중지된 debugger sessions는 live bridge map에서 즉시 제거됩니다.

### 🧭 Resource and Prompt UI

Dock은 first-class Resources 및 Prompts tabs를 제공합니다. Users는 protocol catalog counts, resource 또는 prompt ID copy, resource previews, prompt argument inputs, generated prompt messages preview, bounded icon rendering을 확인할 수 있습니다.

Tools tab도 shared catalog fact path로 이동합니다. Titles, icons, annotations, input schemas, output schemas, previews, search, schema copy actions, visible tool families는 separate private UI catalog model이 아니라 shared protocol metadata에서 render됩니다.

이로써 Dock은 MCP server surface의 preview가 되며 parallel interpretation이 아닙니다. client-visible metadata가 바뀌면 UI도 같은 facts를 보여야 합니다.

### 🎛️ Focused Settings Experience

Settings page는 port, log level, language, 정식 버전 / 개발 버전 channels, branch selection, Refresh List, one-click update, row-level Switch actions를 유지하면서 더 조용한 hierarchy로 표현합니다. 중복 policy / repository text를 제거하고 channel selector를 version list 바로 위에 두며 primary status는 결과를 표시하고 expandable details는 같은 error를 반복하지 않고 supplemental diagnostics만 제공합니다.

version list는 세 개의 focused columns만 사용하고 current row를 색상과 text로 함께 표시하며 date는 row tooltip으로 이동합니다. commit을 선택하면 row 전체가 highlight되고 해당 exact ref/commit이 comparison target이 됩니다. installed version은 별도 Switch action만 변경합니다. selection과 startup은 cache-only이며 GitHub request는 명시적인 refresh와 one-click verification에서만 수행됩니다. ultra-narrow Dock에서는 forms와 actions가 true single-column layout으로 쌓이므로 가로 혼잡 없이 update workflow를 사용할 수 있습니다.

4개 언어 Dock UI style guide는 이후 page가 따라야 할 information hierarchy, editor-native theme, spacing, responsive breakpoints, action priorities, status / empty-state behavior, accessibility, localization, validation matrix를 정의합니다.

### 🧠 C# Semantic Runtime

C# semantic tooling은 installation contract의 일부입니다. Asset Library와 prepared addon installs는 framework-dependent Roslyn runtime files를 포함하며, machine에 .NET 8 runtime이 있으면 installation 후에도 semantic read / patch workflows가 계속 동작합니다.

이 bundle은 host project compile surface와 격리됩니다. shipped addon은 user projects에 plugin Roslyn 또는 bridge source files compile을 요구하지 않으므로 dependency conflicts를 줄이면서 semantic C# capabilities를 유지합니다.

Clean install validation은 이 contract의 양쪽을 모두 확인합니다. exported addon installs는 plugin bridge/Roslyn source files를 제외해야 하고, framework-dependent Roslyn runtime files가 local `dotnet` host를 통해 usable하다는 것도 증명해야 합니다.

### 🛠️ Tooling, Catalogs, and Compatibility

`tools/list`는 input schema, output schema, annotations, JSON Schema 2020-12 metadata가 있는 flat callable tool list를 반환합니다. Tree/group presentation data는 catalog resources와 shared Dock presentation snapshots로 이동합니다.

Catalog snapshots, catalog resources, `/api/tools`, Dock model metadata, Tools tab previews, search, schema-copy paths는 `ToolCatalogManifest`와 `ToolCatalogSnapshotService`를 shared catalog fact path로 사용합니다. 이렇게 client discovery, HTTP diagnostics, editor UI previews 사이의 drift를 줄입니다.

Tool-call results는 `tools/list` entries가 output schemas를 광고하는 tools에만 `structuredContent`를 반환합니다. 동시에 모든 clients를 위해 text JSON content는 계속 제공됩니다. 이로써 strict MCP clients가 discovery metadata와 call results의 일관성에 의존할 수 있습니다.

v2.0 line은 많은 large root domain implementations를 focused executors로 나누고, compatibility가 필요한 곳에는 public facades를 유지합니다. audio, animation, signal, TileMap, UI, filesystem, node, project, resource, scene, group, geometry, material, lighting, navigation, particle, physics, shader, debug, editor domains는 더 작은 implementation units로 이동합니다.

### ✅ Compatibility and Validation

이 release는 feature text뿐 아니라 refactor guardrails도 포함합니다. Validation은 public tool removals, root monolith closure, catalog facts, optional capability advertisement, changelog structure, release-note wording, Roslyn runtime bundle shape, clean Asset Library installs, safe bridge writes, MCP 2025-11-25 conformance contracts를 다룹니다.

Runtime contracts는 JSON-RPC cancellation notifications, bounded non-editor tool-call timeouts, editor automation watchdog release, direct `ToolCatalogManifest` catalog path도 포함합니다.

Compatibility는 명시적입니다. older discovery calls와 legacy transports는 compatibility paths로 문서화되고, default client guidance는 Resources, Prompts, canonical Tools, Streamable HTTP, newline stdio를 가리킵니다.

### 📦 Upgrade Notes

- Existing clients는 legacy public discovery tools보다 `resources/list`, `resources/read`, `resources/templates/list`, `prompts/list`, `prompts/get`, canonical action tools를 우선 사용해야 합니다.
- HTTP clients는 `MCP-Protocol-Version: 2025-11-25`를 보내고, `Mcp-Session-Id`를 처리하며, `Accept: application/json, text/event-stream`를 advertise해야 합니다.
- Stdio launchers는 명시적으로 legacy `Content-Length` compatibility mode를 선택하지 않는 한 newline-delimited JSON-RPC를 사용해야 합니다.
- C# semantic workflows는 host project에서 plugin Roslyn source를 compile하지 말고 shipped framework-dependent Roslyn runtime files에 의존해야 하며 .NET 8 runtime이 필요합니다.
- Settings는 startup에서 cached update refs와 exact comparisons만 복원하고 GitHub에 접속하지 않습니다. Refresh List는 selected channel만 업데이트하며 exact local/cache result가 없을 때만 one-click update가 remote comparison을 request합니다.
- Antigravity users는 Config tab에서 app detection과 launch, Godot MCP configuration copy, `.gemini/config/mcp_config.json`의 `godot-mcp` entry write / remove를 사용할 수 있습니다.
