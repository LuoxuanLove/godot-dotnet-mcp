## 🧩 Godot .NET MCP v2.0.0: Companion Sessions

Godot .NET MCP v2.0.0은 optional Companion direction을 project-scoped .NET contract layer에서 시작합니다. 첫 요소는 editor가 열려 있지 않을 때 static project analysis를 제공하는 방식과, matching Godot editor bridge가 online이 된 뒤에만 editor-live automation을 제공하는 방식을 정의합니다.

### ✨ Live 상태로 가장하지 않는 static analysis

Companion contract는 static/headless capabilities와 live editor capabilities를 분리합니다. Project sessions는 C#과 resource-analysis 계열 work를 제공할 수 있지만, editor bridge가 연결되기 전에는 selected node, Inspector, Dock, screenshot, runtime validation state를 명확히 제공하지 않습니다.

static analyzer는 이 layer를 위한 read-only project inventory를 생성합니다. project root가 Godot project인지, 어떤 `.csproj` files가 있는지, plugin directory가 installed 상태인지, editor bridge가 online이 아닐 때 editor-live capabilities가 왜 unavailable인지 알려줍니다.

### 🔐 Project-scoped sessions

Tool calls는 `project_id`와 `session_id`를 모두 가져야 하며, broker는 다른 project로 session을 재사용하려는 시도를 거부합니다. 이로써 multi-project orchestration을 추가하기 전에 v2.0 line의 isolation boundary가 분명해집니다.

Bridge upgrade contract는 editor-side handshake states를 기록합니다. Project session이 editor-live가 되려면 bridge가 같은 project에서 online이고, compatible plugin version을 보고하며, 비어 있지 않은 `editor_session_id`를 제공해야 합니다.

### ✅ Compatibility and Upgrade Notes

현재 단계의 Companion layer는 contract library입니다. background process, port, Godot launch를 시작하지 않으며 기존 editor-native plugin startup behavior도 변경하지 않습니다. Broker manifest는 이 약속을 explicit boundary로 기록하며 broker startup, loopback HTTP transport, project registration, editor launch는 모두 명시적인 user 또는 client action을 필요로 합니다.
