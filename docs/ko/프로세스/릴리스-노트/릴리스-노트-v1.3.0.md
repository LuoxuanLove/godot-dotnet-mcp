## 🧭 Godot .NET MCP v1.3.0: Semantic Editor Automation and Evidence

Godot .NET MCP v1.3.0은 editor-facing tool 모음을 더 일관된 automation layer로 발전시키는 release입니다. Agent는 relevant editor surface를 찾고, raw control보다 semantic workflow를 우선 사용하며, guarded high-level task로 value를 read / change하고, result를 verify하며, 실제로 관측한 대상을 설명하는 evidence를 첨부할 수 있습니다.

### 🧭 Semantic Editor Control

v1.3.0의 core design direction은 명확합니다. semantic workflow를 먼저 사용하고, control-level operation을 다음으로 사용하며, mouse / coordinate fallback은 마지막에 사용합니다. settings workflow, Inspector property task, menu selection, tab navigation, tree selection, popup button, focus, text edit, numeric value edit을 사용할 수 있는 상황에서 Agent가 screen click을 default path로 삼지 않도록 하기 위한 원칙입니다.

`system_editor_control(action="wait_for_ui")`는 client가 다음 automation step으로 진행하기 전에 editor state를 bounded 방식으로 기다릴 수 있게 합니다. control existence, visibility, text match, enabled / disabled state를 poll하고, matched UI evidence 또는 마지막으로 관측한 state를 포함한 timeout payload를 반환합니다.

pointer behavior가 필요한 workflow에서도 click fallback은 더 진단하기 쉬워졌습니다. `click_control`과 `right_click_control`은 input-dispatch metadata와 Button-like target observation을 반환하며, before/after state, signal count, mouse input이 delivery되었지만 activation evidence가 없을 때의 hint를 제공합니다.

### ⚙️ Trusted Settings Workflows

`system_settings_dialog`는 이 release에서 가장 큰 workflow consolidation입니다. Project Settings와 Editor Settings를 loose coordinate나 raw control list가 아니라 task surface로 다룹니다. client는 surface를 open하고, 표시를 기다리고, search, tab list, tab activate, category list, unique category focus, conservative row model list, unique row resolve, value read, value editor focus, supported value write, expected value verify, evidence capture, close를 수행할 수 있습니다.

이 workflow는 read-only discovery와 mutation을 의도적으로 분리합니다. text, number, bool row는 row가 unique하게 resolve되고, visible이며, confidence가 충분하고, 올바른 value editor로 뒷받침될 때만 write됩니다. enum value는 read / verify할 수 있지만, complex editor type은 추측하지 않고 unsupported로 처리합니다.

`run_task`는 safe path를 composition합니다. surface를 open하고 scope를 좁힌 뒤 unique row를 resolve하고, before value를 read하며, 필요한 경우 supported value를 write하고, result를 verify한 다음 capture evidence를 첨부합니다. selector가 ambiguous하거나, hidden-control write가 요청되거나, confidence가 너무 낮거나, required pre-write evidence를 만들 수 없으면 task는 interaction 전에 mutation을 거부합니다.

### 🧩 Inspector Property Automation

`system_inspector`는 같은 philosophy를 Inspector로 확장합니다. Agent는 visible property model을 list하고, unique property를 resolve하고, typed value를 read하고, value editor를 focus하고, supported text / number / bool value를 set하고, result를 verify하고, property evidence를 capture하며, current edited object 또는 prepared node/resource target에 대해 trusted property task를 실행할 수 있습니다.

Inspector workflow는 보수적으로 설계되었습니다. hidden-control write, ambiguous property, disabled value editor, resource picker, color, array, dictionary, object selector, file selector 같은 complex editor는 dedicated safe workflow가 생길 때까지 거부됩니다. client는 raw editor control로 내려가기 전에 property-level path를 사용할 수 있습니다.

### 🪟 Evidence-Aware Capture

screenshot은 단순한 image file이 아니라 target과 confidence boundary를 가진 evidence로 취급됩니다. `system_editor_evidence`는 editor, control, popup, active-dialog, automatic surface를 capture할 수 있으며 requested surface, actual backend, target path, visible popup, fallback reason, degradation state, capture policy를 보고합니다.

Settings와 Inspector workflow도 더 명시적인 capture behavior를 사용합니다. Settings capture는 visible settings popup / window bounds를 우선하고, 다음으로 dialog control bounds, 마지막으로 wider editor screenshot으로 fallback합니다. client는 exact target capture와 broader fallback을 구분할 수 있고, fallback이 misleading할 수 있는 상황에서는 strict policy를 사용할 수 있습니다.

이 release는 `system_editor_control(action="get_popup")`와 `system_editor_control(action="capture_popup")`도 추가해 floating editor window와 popup menu를 first-class evidence surface로 다룹니다.

### 🚀 Project Runtime Lifecycle

project execution은 lifecycle surface로 표현됩니다. `system_project_lifecycle(action=start|stop)`의 start action은 main scene / specific scene launch, marker wait, success / failure marker match, marker timeout, auto-stop behavior, foreground-window fallback guidance를 처리합니다. stop action은 같은 lifecycle entry로 현재 running project session을 닫습니다.

이전 project run / stop tool name은 alias로 남기지 않고 의도적으로 제거되었습니다. 새 이름은 실제 contract를 나타냅니다. client는 one-off launch command가 아니라 capability context와 verification hook을 가진 runtime session을 제어합니다.

### 🔎 Tool, Activity, And User Diagnostics

`system_tool_catalog`는 current tool catalog의 searchable view를 제공합니다. Agent는 query, category, domain으로 검색하고 match reason, action, parameter, visibility, enabled state, optional schema를 확인한 다음 다음 tool을 선택할 수 있습니다.

`system_tool_activity`는 state, tool, slow-call, failure-focused query를 support합니다. long-running / parallel automation에서도 client는 unrelated activity record를 가져오지 않고 active / recent work를 inspect할 수 있습니다.

User-tool naming도 더 명확해졌습니다. listing, scaffold preview, compatibility report는 declared name, normalized name, public MCP tool name을 표시합니다. legacy `user_` prefix declaration은 diagnosable하며, generated scaffold는 resource path로 base tool을 상속하므로 headless catalog scan에서 더 안정적입니다.

### 🛠 Scene, Plugin, Project, And Cache Workflows

`system_scene_inspect`는 `validate`, `analyze`, `full` action을 가진 read-only scene inspection entry입니다. 기존 scene validation / analysis tool은 직접 호출하는 client를 위해 계속 사용할 수 있습니다.

`system_plugin_maintenance`는 plugin status, reload, update-status, update-source, update-start workflow를 grouped합니다. lower-level reload / update tool은 제거되지 않으며, maintenance response는 reload / update sync 중 client가 필요로 하는 reconnect / tool-refresh guidance를 유지합니다.

project configuration inspection도 확장되었습니다. client는 sensitive option key와 local absolute export path가 redacted된 export preset summary를 read할 수 있고, deadzone과 concrete input binding을 포함한 individual input action도 inspect할 수 있습니다.

managed user-data maintenance는 explicit하고 dry-run-first인 상태를 유지합니다. client는 capture cache를 inspect하고 removal을 apply하기 전에 cleanup을 preview할 수 있습니다. symlink, junction, reparse point guardrail도 유지됩니다.

### ✅ Compatibility and Upgrade Notes

public plugin version, .NET bridge metadata, protocol facts, localized changelog, release-note source는 `1.3.0`을 target으로 합니다.

이전 project run / stop tool name을 사용하는 client는 `system_project_lifecycle(action=start)`와 `system_project_lifecycle(action=stop)`으로 migrate해야 합니다. 이는 v1.3.0의 주요 intentional compatibility break입니다.

기존 scene validation / analysis tool은 계속 사용할 수 있습니다. `system_scene_inspect`는 additive combined route입니다.

`system_plugin_maintenance`는 additive high-level wrapper입니다. 기존 `system_plugin_reload`와 `system_plugin_update` call은 계속 support됩니다.

complex settings / Inspector editor는 conservative 상태를 유지합니다. unsupported editor는 future dedicated workflow 또는 explicit evidence가 있는 lower-level UI operation으로 처리해야 하며 guess write는 하지 않습니다.
