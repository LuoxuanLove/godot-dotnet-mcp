## 🧩 Godot .NET MCP v1.2.0: 재연결을 고려한 Agent 워크플로

Godot .NET MCP `v1.2.0`은 프로젝트, 플러그인, custom tool이 바뀌는 동안에도 Godot에 연결된 채 작업하는 Agent를 위한 안정성과 editor control 릴리스입니다. 재연결 안내, multi-client diagnostics, Godot UI automation, User tool observability, protocol guardrail을 개선하면서 Godot 4.6+ .NET 지원, Godot Asset Library 설치, source copy 설치, 기존 high-level tool name 호환성은 유지합니다.

### 🔁 재연결을 고려한 다중 클라이언트 세션

health, plugin reload, plugin update response는 이제 maintenance window state, reconnect expectation, retry timing, stale tool list guidance를 보고합니다. client는 연결 끊김이 임시 상태인지, schema를 다시 가져와야 하는지, update sync나 lifecycle reload가 아직 진행 중인지 판단할 수 있습니다.

HTTP health reporting에는 안정적인 connection ID, request ID, client summary, active session, 최근 disconnected session도 포함됩니다. 여러 MCP client나 Agent session이 동시에 붙어 있을 때, plugin은 누가 연결되어 있고 reload 뒤 어떻게 복구해야 하는지 더 분명히 보여 줍니다.

### 🖱️ 더 강한 Godot 에디터 UI 제어

`system_editor_control`은 이제 Godot editor UI의 더 많은 흐름을 직접 다룰 수 있습니다. Agent는 top menu를 나열하고, `MenuButton` popup을 열고, 보이는 `PopupMenu` row를 text, index, id로 선택하고, 등록된 editor main screen을 전환하고, distraction-free mode를 제어하고, tooltip과 floating panel 확인을 위해 hover / leave event를 보낼 수 있습니다.

이 기능들은 editor automation이 OS 수준 mouse movement에 덜 의존하게 만듭니다. popup menu automation은 hidden popup, disabled row, separator, submenu row, 중복 text match, 충돌 selector도 거부하므로, 잘못된 menu item을 조용히 고르는 대신 더 명확한 이유로 실패합니다.

### 🧰 도구 활동과 User tool diagnostics

새 `system_tool_activity`는 실행 중인 tool call, 최근 완료 기록, 실행 순서, client가 선택적으로 제공하는 자체 보고 `_mcp_context`를 보여 줍니다. 병렬 Agent는 또 다른 오래 걸리는 operation을 시작하기 전에 이미 무엇이 진행 중인지 가볍게 확인할 수 있습니다.

User tool runtime diagnostics는 plugin evolution diagnostics와 project health에서 발견된 custom tool, load failure, watcher state, compatibility summary, recent audit entry를 보여 줍니다. diagnostics는 read-only이고 custom-tool loading behavior를 바꾸지 않지만, extension tool 실패를 훨씬 쉽게 살펴볼 수 있게 합니다.

### 🛡️ 더 안전한 프로토콜과 디버그 경계

HTTP와 stdio는 malformed JSON-RPC top-level `params`를 표준 `-32602` error로 일관되게 처리합니다. 반면 invalid `tools/call.arguments`는 계속 일반 MCP tool-result error로 보고됩니다. Resource와 Prompt Guide output에도 size protection이 들어가, 과도하게 큰 file-backed resource는 비용 큰 읽기 전에 실패하고 짧아진 prompt text는 `_meta` truncation detail을 포함합니다.

DAP debugger call은 과도한 frame과 지나치게 긴 timeout을 명확한 limit error로 거부합니다. script editing도 생성된 빈 C# method에 명시적인 `NotImplementedException` guard body를 사용해 모호한 generated body behavior를 줄입니다.

### 🌐 지역화 문서와 릴리스 노트

공개 documentation tree는 영어, 간체 중국어, 일본어, 한국어로 유지되며 localized directory와 file name을 사용합니다. Dock UI에는 한국어 coverage가 추가되었고, 지원 언어 전반의 tool metadata, client guidance, Prompt Guide text, reconnect guidance, fallback label도 더 넓게 보완되었습니다.

`v1.2.0` release notes는 네 가지 documentation tree에 모두 보존됩니다. GitHub Release body는 영어 note에서 rendering되지만, note 자체가 다른 언어판으로 link하므로 독자는 자신에게 맞는 documentation language를 고를 수 있습니다.

### ✅ 호환성 및 업그레이드 안내

기존 high-level tool name은 호환성을 유지합니다. editor control, tool activity, User tool diagnostics가 새 capability를 공개하므로 public tool schema version은 바뀝니다. upgrade 뒤 client는 다시 연결하고 tool list를 다시 가져와야 합니다.

기존 install에는 file layout migration이 필요하지 않습니다. Godot Asset Library installation path나 source tree에서 `addons/godot_dotnet_mcp/`를 직접 copy하는 방법을 계속 사용할 수 있습니다. plugin reload나 update sync 중에는 client가 health를 poll하고, transport가 끊기면 재연결하며, maintenance window가 schema stale 가능성을 알리면 tool을 refresh해야 합니다.
