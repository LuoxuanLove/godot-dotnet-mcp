## 🧩 Godot .NET MCP v1.2.0: 재연결을 고려한 Agent 워크플로

이 릴리스는 여러 MCP client나 Agent session이 동시에 플러그인을 사용할 때 복구 흐름을 더 명확하게 만듭니다. maintenance window reporting, reconnect guidance, transport resilience, health diagnostics, update-sync refresh 동작, editor UI control을 강화해 플러그인 reload나 update sync 뒤에 client가 안전하게 재연결하고 도구 목록을 다시 가져오며 등록된 editor main screen과 보이는 Godot UI flow를 계속 다룰 수 있게 했습니다.

### ✨ 주요 내용

- `system_editor_control`에 상단 메뉴 제어를 추가해 Agent가 에디터 메뉴를 나열하고, `MenuButton`을 열고, 텍스트나 인덱스로 `PopupMenu` 항목을 선택한 뒤 팝업 검사나 텍스트/버튼 동작을 이어갈 수 있습니다.
- health, 플러그인 reload, 플러그인 update 응답에 maintenance window metadata를 추가해 임시 연결 끊김, retry timing, 도구 목록 refresh requirement를 client가 알 수 있게 했습니다.
- `/health`에 HTTP client session identity와 request audit field를 추가해 안정적인 connection ID, request ID, client summary, active session, 최근 disconnected session을 확인할 수 있습니다.
- User tool runtime diagnostics를 추가해 plugin evolution tools나 project health에서 발견된 custom tool, load failure, watcher state, compatibility, recent audit entry를 확인할 수 있습니다.
- `system_tool_activity`를 추가해 병렬 작업을 조율할 때 HTTP와 stdio tool call의 실행 중 기록, 최근 완료 기록, 실행 순서, 선택적 Agent 자체 보고 컨텍스트를 확인할 수 있습니다.
- 지원되는 Dock 언어의 reconnect guidance를 지역화했습니다.
- MCP resources와 Prompt Guide에 output size safeguard를 추가했습니다. 매우 큰 file-backed resource는 비용이 큰 읽기 전에 거부하고, 긴 생성 prompt text는 byte-size truncation metadata를 보고합니다.
- editor UI hover / leave action을 추가해 Agent가 OS mouse automation 없이 Godot input event로 tooltip, hover-only menu, floating panel을 검증할 수 있게 했습니다.
- editor plugin session diagnostics를 추가해 client가 third-party EditorPlugin의 project setting, live editor state, visible UI hint, 보호된 enable/disable behavior를 확인할 수 있게 했습니다.
- main-screen button 목록, 등록된 plugin main screen 전환, 집중 모드 제어를 위한 editor-control action을 추가했습니다.
- 현재 플러그인 UI, 도구, 바인딩 참조에 맞춰 지역화 문서 트리를 정렬했습니다.
- 로케일 파일 일치, Markdown 링크 대상, 로케일 간 링크 섞임을 확인하는 docs i18n 검증을 추가했습니다.
- 보이는 `PopupMenu` 항목을 index, id, 정확한 text로 선택하는 high-level editor-control action을 추가했습니다.

### 🔧 수정 사항

- 서비스 라우팅, .NET 지원, UI 흐름, 도구 도메인 색인에 관한 영어와 일본어 문서 사실을 바로잡았습니다.
- 플러그인 update sync가 파일을 쓴 뒤 plugin lifecycle reload를 예약하기 전에 Godot editor file system을 refresh하도록 했습니다.
- C# 빈 method guard body가 이제 `NotImplementedException`을 명시적으로 사용하며, 오용되기 쉬운 fallback body를 생성하지 않습니다.
- 공개 plugin-evolution runtime diagnostics path가 live user-tool runtime snapshot을 summary에 전달해 project health와 일치합니다.
- Popup menu automation이 숨겨진 popup, disabled 항목, separator, submenu row, 충돌하는 selector, 중복 text 항목을 잘못 실행하지 않도록 보호했습니다.
- 깨졌거나 오래된 지역화용 자리표시자를 현재 사용자 대상 내용으로 바꿨습니다.
- 일본어 README의 잘못된 스크린샷 참조를 제거했습니다.
- HTTP keep-alive handling을 개선해 async tool execution 뒤에도 이미 buffer된 pipelined request가 계속 drain됩니다.
- multi-client recovery를 위한 reconnect backpressure safeguard를 추가해 pending request buffer 한도와 response write failure 뒤 connection cleanup을 제공합니다.
- stdio burst processing과 lifecycle reload scheduling을 강화해 오래된 response나 실패한 reload schedule이 오해를 부르는 pending state를 남기지 않게 했습니다.
- DAP debugger에 size와 timeout guard를 추가해 비정상 debug endpoint가 agent request를 붙잡지 않고 명확한 limit error를 반환하도록 했습니다.
- HTTP와 stdio의 malformed JSON-RPC parameter handling을 맞췄습니다. invalid top-level `params`는 표준 error를 반환하고, invalid tool arguments는 tool-result error channel에 유지됩니다.

### ✅ 호환성 및 업그레이드 안내

- 기존 tool name은 호환성을 유지합니다.
- `system_editor_control`에 `list_menus`, `open_menu`, `select_menu_item`이 추가되어 tool schema version이 업데이트되었습니다.
- `system_editor_plugin_control`은 추가 tool입니다. 이 plugin 자체에는 일반 self-disable flow 대신 전용 plugin reload/update tool을 사용하세요.
- Update sync는 lifecycle reload 단계 전에 editor가 plugin file을 다시 scan하도록 요청합니다.
- client는 update sync나 플러그인 reload 중 health를 poll해야 합니다. transport가 끊기면 재연결하고, maintenance window가 schema stale 가능성을 알릴 때 도구 목록을 다시 가져오세요.
- User tool diagnostics는 read-only이며 기존 custom-tool loading behavior를 바꾸지 않습니다.
- 파일 레이아웃이나 tool schema migration은 필요하지 않습니다.
- client는 tool call에 짧은 `_mcp_context` object를 전달해 협업 설명을 남길 수 있습니다. 이는 자체 보고 컨텍스트이며 인증이 아닙니다.
- plugin main screen으로 전환하려면 현재 editor session이 해당 main screen을 이미 등록하고 있어야 합니다.
- Popup menu selection은 tool-schema action을 추가합니다. 업그레이드 뒤에는 다시 연결하고 tool list를 다시 가져오세요.
- 파일 레이아웃 migration은 필요하지 않습니다.
- 기존 설치에는 마이그레이션이 필요하지 않습니다.
- client는 transport와 관계없이 object가 아닌 JSON-RPC `params`를 `-32602`로 처리할 수 있습니다. `tools/call.arguments` validation은 일반 MCP tool error result를 계속 반환합니다.
- Resources를 읽는 client는 과도하게 큰 file-backed resource의 표준 JSON-RPC error를 처리하고, prompt response text가 짧아졌을 때는 `_meta`를 확인해야 합니다.
