# 도구 도메인 색인

이 문서는 도구 도메인 디렉터리, executor, 공유 루트 스크립트, 대표 도구를 빠르게 찾기 위한 색인입니다.

## 읽는 방법

도구 도메인은 구현 디렉터리와 공개 도구 이름을 함께 보아야 합니다.

- 도메인 디렉터리는 구현 위치입니다.
- executor는 해당 도메인의 안정적인 진입점입니다.
- 공유 루트 스크립트는 여러 도메인이 함께 쓰는 helper나 bridge입니다.
- Tools 페이지의 그룹은 Agent가 고르는 사용자 관점의 분류입니다.

## 대표 도메인

### `system`

프로젝트, 장면, 스크립트, 런타임, 진단을 묶는 고수준 흐름입니다. Agent가 처음 호출하는 주요 공개 입구가 이곳에 있습니다.

### `scene`

장면 구조 읽기, 계층 조회, 실행, 바인딩 검사, 장면 audit를 담당합니다.

### `script`

스크립트 inspection, 참조, 편집, C# syntax-first 분석을 담당합니다. C# 의미 분석은 플러그인 내부 Roslyn 경로를 사용하고, GDScript 진단은 Godot LSP 경로를 사용합니다.

### `node`

노드 조회, 속성 변경, 생명주기, 메타데이터, 표시 상태 변경을 담당합니다.

### `plugin_runtime`

플러그인 런타임 상태, reload, self-diagnostic, 업데이트 상태를 다룹니다.

### `plugin_evolution`

업데이트 source, release flow, 사용자 도구 scaffold, audit, 제거, 복원 같은 version-aware 유지보수 흐름을 담당합니다.

### `plugin_developer`

개발자용 진단, 언어 전환, 사용 가이드, 보조 기능을 제공합니다.

### `user`

프로젝트 전용 `user_*` 도구를 관리합니다. 이 도메인은 내장 도구가 아니라 사용자가 제공하는 확장 표면입니다.

## 주요 파일을 찾는 순서

도메인을 추적할 때는 대체로 다음 순서가 좋습니다.

1. `tools/<domain>/executor.gd`
2. `tools/<domain>/catalog.gd`
3. `tools/core/tool_loader.gd`
4. `tools/tool_manifest.gd`
5. 필요한 경우 `tools/shared/`의 helper

## 디렉터리와 책임

| 영역 | 역할 |
|---|---|
| `tools/system/` | 고수준 공개 입구와 atomic helper의 연결 |
| `tools/scene/` | 장면 query, audit, binding |
| `tools/script/` | 스크립트 inspect, analysis, patch |
| `tools/node/` | 노드 조작 |
| `tools/plugin_runtime/` | 플러그인 runtime state, self-diagnostic, reload |
| `tools/plugin_evolution/` | update source, release flow, 사용자 도구 관리 |
| `tools/plugin_developer/` | 개발자용 진단과 보조 기능 |
| `tools/user/` | 사용자 도구 관리 |
| `tools/shared/` | 도메인을 가로지르는 공통 helper |

## 공개 도구를 추가할 때

새 도구를 추가할 때는 다음을 함께 확인합니다.

- 도구 이름이 기존 도메인과 충돌하지 않는지 확인합니다.
- Tools 페이지에서 어느 루트 그룹과 category에 들어갈지 정합니다.
- `tools/list`, `/api/tools`, stdio transport가 같은 정보를 반환하는지 확인합니다.
- 도구 preview, schema 설명, 문서, harness fixture를 함께 갱신합니다.
- 오래된 root-level entry나 중복 helper가 남지 않도록 제거합니다.

## 기억할 점

- 도구를 찾을 때는 먼저 domain과 category를 봅니다.
- executor는 실제 진입점이지만, 거기만 보면 전체 흐름이 보이지 않을 수 있습니다.
- shared root script에 업무 logic이 너무 많이 쌓이면 재분리 신호입니다.
- 새 `plugin_*` 도구나 `custom_tools/` 흐름이 바뀌면 이 색인과 [사용자 확장](사용자-확장.md)을 함께 갱신합니다.
