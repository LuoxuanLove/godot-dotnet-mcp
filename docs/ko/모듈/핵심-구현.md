# 핵심 구현

이 문서는 `localization/`, `plugin/config/`, `plugin/runtime/`, `custom_tools/`, 그리고 공유 helper script의 책임 경계를 정리합니다. tool-domain 본체를 제외한 핵심 구현 개요입니다.

---

## 디렉터리 계층

```text
localization/
plugin/
  ├─ config/
  └─ runtime/
tools/
  ├─ core/
  ├─ *_tools.gd
  └─ <category>/executor.gd
custom_tools/
dotnet_bridge/
```

---

## `localization/`

### 구성

- `localization_service.gd`
- `locale_en.gd`
- `locale_zh_cn.gd`
- `locale_zh_tw.gd`
- `locale_ja.gd`
- `locale_de.gd`
- `locale_es.gd`
- `locale_fr.gd`
- `locale_pt.gd`
- `locale_ru.gd`

### 책임

- 모든 language dictionary를 load
- 현재 language 전환
- `get_text()`와 language-display-name helper 제공
- Dock UI와 tool-profile copy에 쓸 text 공급

### 제약

- 각 language file의 key set은 `locale_en.gd`와 맞아야 합니다.
- scene에 고정된 text를 최종 표시 source로 두면 안 됩니다.
- plugin root control은 일반적으로 `auto_translate_mode`를 끕니다.

## `plugin/config/`

### `config_paths.gd`

담당 범위는 다음과 같습니다.

- Claude Code와 Codex command template

### `client_config_service.gd`

담당 범위는 다음과 같습니다.

- Config page config flow의 facade 역할
- `client_config_serializer.gd` 위임
- `client_config_inspection_service.gd` 위임
- `client_config_file_transaction.gd` 위임
- `client_config_launcher_adapter.gd` 위임

### `settings_store.gd`

담당 범위는 다음과 같습니다.

- plugin settings file
- custom profile file
- profile rename과 delete
- tool config JSON import와 export

## `plugin/runtime/`

현재 플러그인 구현에서 가장 중요한 service layer입니다.

### State와 Lifecycle

- `plugin_runtime_state.gd`
- `plugin_runtime_state_service.gd`
- `tool_profile_catalog.gd`
- `server_runtime_controller.gd`
- `plugin_reload_coordinator.gd`

### Diagnostics와 Debugging

- `plugin_self_diagnostic_store.gd`
- `mcp_runtime_debug_store.gd`
- `mcp_editor_debugger_bridge.gd`: `EditorDebuggerPlugin`으로 등록되어 main project debugger session event를 받아 `MCPDebugBuffer`와 `MCPRuntimeDebugStore`로 전달
- `mcp_runtime_bridge.gd`: main project에 Autoload로 설치됨. project runtime은 `emit_event`, `emit_log`, `emit_info`, `emit_warning`, `emit_error`로 구조화된 event를 보낼 수 있음. `godot_mcp/runtime_event`와 `godot_mcp/runtime_log` 두 채널을 사용하고, 최대 300개 항목을 캐시하며, `EngineDebugger`가 비활성화된 경우 `user://godot_mcp_runtime_bridge_events.json`으로 되돌아감

### Service와 Catalog

- `mcp_http_server.gd`
- `mcp_tool_loader_supervisor.gd`
- `mcp_tool_rpc_router.gd`
- `tool_catalog_service.gd`
- `user_tool_service.gd`
- `user_tool_catalog_service.gd`
- `user_tool_maintenance_service.gd`

이 객체들은 함께 다음을 지원합니다.

- settings와 profile 투영
- embedded server 생명주기
- tool-loader 생명주기, self-recovery, supervision
- `tools/list`와 `tools/call`을 위한 tool routing과 결과 정규화
- tool-catalog와 permission trimming
- user-tool 발견과 관리
- self-diagnostic 경로

## `tools/`의 공유 계층

`tools/` 디렉터리는 category executor 외에도 공유 script를 담고 있습니다.

### 기본 및 공유 root script

- `base_tools.gd`
- `plugin_shared.gd`
- 기타 `*_tools.gd`

### 일반 helper

- `mcp_debug_buffer.gd`
- `mcp_file_utils.gd`
- `mcp_json_utils.gd`
- `mcp_node_utils.gd`
- `mcp_script_parser.gd`
- `mcp_type_utils.gd`

### Core

- `tool_manifest.gd`
- `tool_registry.gd`
- `core/tool_loader.gd`
- `core/tool_lsp_diagnostics_adapter.gd`

관계는 다음과 같습니다.

- `tool_registry.gd`는 builtin executor의 공식 registration chain을 정의합니다.
- `tool_manifest.gd`는 UI, permission layer, state layer용 안정적 domain 및 category metadata를 다룹니다.
- `tool_loader.gd`는 `tool_registry.gd`에서 executor를 직접 불러오고, loading, calling, reloading을 담당합니다.
- `tool_lsp_diagnostics_adapter.gd`는 loader main chain에서 GDScript LSP diagnostic, bridge binding, debug snapshot의 생명주기를 담당합니다.
- `base_tools.gd`와 다른 helper는 반복 코드를 줄입니다.

## `custom_tools/`

이 디렉터리는 `plugin_evolution` tool이나 scaffolding으로 관리되는 User tool script를 담습니다. 현재 규칙은 다음과 같습니다.

- builtin tool-domain directory에는 쓰지 않는다.
- script 생성이나 삭제는 반드시 두 단계 `plugin_evolution` authorization flow를 통해서만 한다.
- `system/executor.gd._load_custom_tools()`로 발견한다.
- 삭제할 때는 복구가 가능하도록 `.backup/`에 쓴다.

---

## 핵심 설계 방향

현재 구현은 다섯 가지 원칙을 따릅니다.

- 얇은 진입점: `plugin.gd`는 조립과 bridge만 담당한다.
- scene 기반 UI: 각 Dock 탭은 별도 scene과 controller를 가진다.
- domain 분리 도구: category를 하나의 큰 tool에 몰아넣지 않고 executor별로 나눈다.
- 구조화된 관찰: 오류, action, session, log를 가능한 한 구조화해서 기록한다.
- 단일 permission entry: `tool_access_feature.gd`가 plugin 측 유일한 permission provider다.
