# 스크립트와 씬 분석

이 문서는 `script_*`, `scene_bindings`, `scene_audit` 계열 분석 도구가 어떤 문제를 찾고, 어떤 순서로 사용하는지 설명합니다.

## 분석 목표

스크립트와 장면 분석은 C# export binding, NodePath, resource reference, 장면 구조 문제를 찾기 위한 흐름입니다. Godot 프로젝트에서는 코드가 성공적으로 빌드되어도 장면에 연결된 값, 노드 경로, 리소스 참조가 맞지 않으면 런타임에서 문제가 생길 수 있습니다.

따라서 분석은 코드와 장면을 따로 보지 않고 함께 봅니다.

## `script_*`

`script_*` 도구는 스크립트 내용을 읽고 구조를 파악합니다.

- class 이름
- base type
- method
- enum
- exported member
- 참조와 편집 대상

C# 분석은 syntax-first 방식입니다. 전체 semantic model을 만들지 않고, 플러그인 내부 Roslyn 경로로 구조를 읽습니다. GDScript 진단은 Godot LSP와 연결된 저장된 파일 내용을 기준으로 비동기 보강됩니다.

## `scene_bindings`

`scene_bindings`는 현재 장면 또는 지정 장면의 바인딩 상태를 검사합니다.

- 노드가 어떤 스크립트와 연결되어 있는지
- export 값이 장면에 어떻게 저장되어 있는지
- 필수 NodePath나 resource reference가 비어 있지 않은지
- C# custom Resource script가 기대한 타입과 맞는지

이 도구는 코드만 읽어서는 발견하기 어려운 “장면에 저장된 연결 문제”를 찾는 데 유용합니다.

## `scene_audit`

`scene_audit`는 장면 전체를 구조화해서 진단합니다.

- 장면 트리 문제
- 리소스 참조 문제
- NodePath 불일치
- C# custom Resource script 불일치
- 구조적으로 의심스러운 노드 배치

장면이 복잡하거나 한 번에 여러 문제가 의심될 때 먼저 audit를 실행하면, 이후 어떤 세부 도구를 써야 할지 좁힐 수 있습니다.

## 보조 도구

상황에 따라 다음 도구를 조합합니다.

- `node_query`: 노드 존재와 속성 확인
- `scene_hierarchy`: 장면 계층 확인
- `script_references`: 스크립트 참조 추적
- `system_scene_dependency_graph`: 장면 의존성 관계 파악

## 추천 사용 순서

1. `script_inspect`로 스크립트 구조를 확인합니다.
2. `script_exports`로 export member를 확인합니다.
3. `scene_bindings`로 장면에 저장된 연결을 확인합니다.
4. `scene_audit`로 장면 전체의 문제 목록을 읽습니다.
5. 필요한 경우 노드, 리소스, 참조 도구로 범위를 좁힙니다.

## 경계

- `dotnet build`가 성공해도 장면 바인딩 위험은 남을 수 있습니다.
- 저장되지 않은 editor buffer 변경은 일부 분석에서 제외될 수 있습니다.
- GDScript LSP 진단은 첫 호출에서 아직 준비 중인 상태를 반환할 수 있습니다.
- 분석 도구는 문제를 숨기기보다 구조화해서 노출하는 데 목적이 있습니다.
