# 변경 로그

이 프로젝트의 중요한 변경 사항은 모두 여기에 기록합니다.

이 문서는 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/) 형식을 따르며, [Semantic Versioning](https://semver.org/lang/zh-CN/spec/v2.0.0.html)도 함께 따릅니다.

## [Unreleased] ([2.0.0])

대상 버전은 2.0.0입니다.

### Added

- isolated Roslyn runtime bundle을 추가해 Asset Library와 prepared addon install에서도 C# semantic read / patch workflow를 유지하면서 plugin Roslyn 또는 bridge source files가 host project compile surface에 들어가지 않도록 했습니다.
- MCP 2025-11-25 Resources, Resource Templates, Prompts, Tools metadata를 추가했습니다. title, icon, annotation, input schema, output schema, JSON Schema 2020-12 declaration을 포함합니다.
- Dock Resources / Prompts tabs를 추가해 protocol catalog counts, ID copy actions, resource previews, prompt argument inputs, generated prompt previews, bounded icon rendering을 제공합니다.
- read-only editor log resources `godot-dotnet-mcp://logs/editor/output` 및 `godot-dotnet-mcp://logs/editor/errors`를 추가했습니다.
- `runtime_step(action=input)`에 mouse move / click support를 추가하고 tool schema에 viewport coordinate fields를 공개했습니다.
- diagnostic code, recommended action, follow-up tool hint를 포함하는 structured User-tool recovery diagnostics를 추가했습니다.
- idle-process 및 User-tool watch diagnostics를 추가해 매 Dock refresh마다 heavy runtime query를 강제하지 않고도 self diagnostics가 frame budget, scan slices, watcher progress를 보고할 수 있게 했습니다.
- Config tab에 Antigravity client support를 추가했습니다. app detection, app launch, `.gemini/config/mcp_config.json`에 대한 `godot-mcp` one-click write / remove, copied MCP configuration, setup directory hints를 제공합니다.
- lightweight Godot `Performance` custom monitors를 추가해 plugin process time, slow-frame count, 1초 간격 engine samples를 Debugger Monitor와 self diagnostics에서 확인할 수 있게 했습니다.

### Changed

- default MCP protocol baseline을 `2025-11-25`로 변경했습니다. initialize metadata, tool-name validation, schema dialect policy, explicit optional-capability boundaries를 포함합니다.
- default stdio transport를 newline-delimited JSON-RPC로 변경하고 legacy `Content-Length` framing은 explicit compatibility mode로만 유지했습니다.
- default HTTP endpoint `127.0.0.1:3000/mcp`를 MCP Streamable HTTP semantics에 맞췄습니다. protocol/session headers, JSON / SSE `Accept` negotiation, Origin/CORS checks, GET SSE streams, resumable event history, finite POST SSE responses, heartbeat events, queued server-to-client delivery, `DELETE /mcp` session termination을 포함합니다.
- public discovery를 resource-first / prompt-first로 변경했습니다. passive help, activity, catalog, editor-log, plugin maintenance, scene validation discovery는 legacy public discovery tools 대신 Resources, Prompts, canonical action tools를 사용합니다.
- `tools/list`를 schema, annotation, output metadata가 있는 flat callable tool list로 변경하고 tree/group presentation data는 catalog resources와 shared Dock presentation snapshots로 옮겼습니다.
- catalog snapshots, catalog resources, `/api/tools`, Dock model metadata, Tools tab preview/search/schema-copy paths를 `ToolCatalogManifest`와 `ToolCatalogSnapshotService` shared catalog fact path로 통합했습니다.
- Dock Tools rows, action previews, Resources, Prompts, schema inspection이 private UI catalog facts를 재구성하지 않고 shared protocol metadata를 render하도록 변경했습니다.
- Dock Tools tab은 Agent Tools call surface를 기본값으로 사용하고, executor 구성 및 legacy/public-tool diagnostics는 별도의 Internal / Diagnostics views에서 확인하도록 변경했습니다.
- Dock Resources / Prompts tabs가 explicit presentation trees를 소비하도록 변경해 resource URI, resource template, workflow prompt, prompt argument를 shared protocol metadata 기준으로 grouping하며 Dock 쪽 URI 또는 이름 추측 분류를 피합니다.
- Dock Resources / Prompts tabs에 Catalog / Diagnostics views를 추가해 읽기 쉬운 protocol entries와 source / visibility / callability / group metadata 사이를 전환할 수 있게 했습니다.
- editor startup과 idle refresh를 가볍게 만들어 auto-start를 `_enter_tree` synchronous path 밖으로 옮기고, active 상태가 아닌 Dock tab은 lazy-load하며, MCP server startup은 lightweight로 유지하고, HTTP service bundle과 tool runtime은 on demand로 load하고, disabled-tool filter는 runtime initialization까지 cache하며, Resources / Prompts protocol list projection은 loader를 건드리지 않게 하고, 현재 Dock tab에 필요한 catalog projection만 만들고, User-tool polling과 scan slices를 더 보수적으로 진행해 large projects의 editor stall을 줄였습니다.
- plugin freshness, health, Settings, self-diagnostic snapshots가 짧은 수명의 disk fingerprint summary를 재사용하도록 변경해 인접한 status request마다 addon tree 전체를 다시 scan하지 않도록 했습니다.
- Dock Tools refresh checks와 User-tool runtime definition comparison이 reusable lightweight signatures를 사용하도록 변경해 idle refresh 중 full presentation tree, metadata map, tool definition array를 반복 serialize하지 않습니다.
- Dock catalog model refresh checks를 deterministic lightweight signatures로 변경해 각 tool entry를 serialize하지 않으면서 nested schema와 presentation metadata 변경은 계속 감지하고 반복 Dock refresh work를 줄였습니다.
- shared tool presentation signatures가 presentation nodes, groups, metadata maps를 JSON serialize하지 않으면서 nested metadata invalidation은 유지하도록 변경했습니다.
- Config tab client-card refresh checks를 deterministic lightweight signatures로 변경해 client setup status update 중 nested card 및 localization payload를 serialize하지 않습니다.
- Dock Resources / Prompts catalog refresh checks를 deterministic lightweight signatures로 변경해 tab refresh 중 full protocol entries, presentation, preview, argument-value payload를 serialize하지 않습니다.
- C# semantic tooling의 production runtime path를 isolated Roslyn runtime process로만 제한해 source-tree 또는 direct-copy install이 plugin의 in-process C# facade를 host project 안에서 자동 load하지 않도록 변경했습니다.
- User-tool polling은 runtime loading이 꺼져 있을 때 synchronous scan을 건너뛰고 큰 directory walk를 budgeted slices로 나누도록 변경해 idle refresh 응답성을 유지합니다.
- User-tool watch scanning과 fallback runtime scanning을 dedicated scan service로 옮겨 file metadata traversal, slice budgets, scan diagnostics를 watch polling / reload coordination과 분리했습니다.
- audio, animation, signal, TileMap, UI, filesystem, node, project, resource, scene, group, geometry, material, lighting, navigation, particle, physics, shader, debug, editor domain implementations를 split executors로 변경하고 debug/editor는 thin compatibility wrappers로 유지했습니다.
- AtomicBridge, `MCPToolLoader`, stdio routing, plugin lifecycle wiring, reload handling, runtime context wiring, status/query projections, User-tool maintenance를 dedicated services로 분리하면서 public facades를 유지했습니다.
- MCPToolLoader lifecycle tick budget, interval selection, tick performance counters를 dedicated budget service로 옮기고 runtime tick side effects는 loader lifecycle path에 유지했습니다.
- MCPToolLoader service readiness checks를 변경해 status, catalog, tick, execution hot path에서 반복 service factory wiring을 건너뛰면서도 script reload 뒤에는 services를 다시 구성할 수 있게 했습니다.
- plugin update의 refs, sync, compare workflow state transitions를 dedicated transition service로 옮기고 Dock 및 MCP update status fields는 유지했습니다.
- plugin update endpoint, archive, timeout, marker, addon-root facts를 dedicated endpoint config service로 옮겨 해당 GitHub / update constants가 plugin entrypoint에 남지 않도록 했습니다.
- plugin update helper ownership을 더 정리해 사용하지 않는 branch-ref, archive-ref, ref-list wrapper를 dedicated update services에만 두고 plugin entrypoint에서는 제거했습니다.
- project와 bundled plugin license를 v2.0 line에서 MIT에서 Apache-2.0으로 변경했습니다.

### Fixed

- Tools tree collapse persistence를 수정해 같은 frame 안의 expand / collapse burst가 settings save 1회로 합쳐지도록 했습니다.
- Streamable HTTP Host validation을 수정해 Host header가 없거나 비어 있으면 MCP request가 router에 도달하기 전에 거부되도록 했습니다.
- Streamable HTTP pending request buffer를 수정해 TCP fragment를 decode 단계까지 byte-backed 상태로 유지하여 pipelined request handling을 보존하면서 반복 UTF-8 conversion을 줄였습니다.
- isolated Roslyn runtime process calls를 수정해 plugin C# inspect / patch paths가 editor thread를 synchronous polling하지 않고 process-frame progress를 await하도록 했습니다.
- HTTP / stdio JSON-RPC envelope handling, malformed framing, duplicate/conflicting HTTP body headers, response-envelope handling, disabled-tool parity, session validation을 강화해 supported MCP transports 사이의 transport error가 deterministic하게 동작하도록 했습니다.
- Prompt / Resource validation을 수정해 unknown 또는 type-invalid prompt arguments는 allowed-argument metadata와 함께 거부되고 binary `.scn` / `.res`는 text resource로 읽히지 않습니다.
- Dock catalog rendering을 수정해 visible tool families를 보존하고 invalid Resource/Prompt icons를 SVG loading 전에 bound합니다.
- C# bridge patch/write actions를 수정해 write 전후에 project-root와 reparse-point boundary를 다시 검증합니다.
- clean Asset Library validation을 수정해 exported addon install이 isolated Roslyn runtime availability, plugin bridge/Roslyn source exclusion, dirty addon/archive rejection을 검증합니다.
- PR policy validation을 수정해 BOM-prefixed titles/headings를 인식하고 policy/version workflows가 merge queue events에서도 실행됩니다.
- 업그레이드된 addon copy의 startup stability를 수정했습니다. split tool executors는 legacy global `MCP*Tools` class name을 등록하지 않으며, Dock도 `Cannot reload script while instances exist`를 출력할 수 있는 script reload를 실행하지 않습니다.
- Dock update sync를 수정해 기존 safe preserve list를 유지하면서 addon directory를 mirror하도록 했습니다. 이제 GitHub archive에 더 이상 없는 오래된 root tool monolith script 같은 stale plugin file은 단순 overwrite에 머무르지 않고 삭제됩니다.
- 업그레이드된 addon self-update recovery를 수정했습니다. 새 plugin instance는 오래된 overwrite-only updater가 남긴 알려진 root tool monolith leftovers를 제거하고, Dock과 MCP plugin update request는 같은 archive-sync entry path를 사용합니다. `.import`와 `dotnet_bridge/obj` cache files는 계속 보존됩니다.
- plugin update sync 피드백을 수정해 Settings tab이 target resolution, download, file write, editor refresh 단계의 progress를 표시하도록 했습니다. 긴 sync operation 중 UI가 idle처럼 보이는 상황을 줄입니다.
- MCP tools에서 시작하는 plugin update sync의 신뢰성을 수정했습니다. `/`가 포함된 custom branch는 archive download 전에 target commit을 먼저 해석하고 commit/ref archive fallback을 시도합니다. release-derived target이 아직 발견되지 않았을 때는 Dock path가 복구할 수 있는 상황에서 바로 실패하지 않고 ref discovery를 먼저 시작합니다.
- plugin update sync request planning을 수정해 Dock과 MCP update actions가 target resolution, branch-ref URL encoding, archive retry decision, sync marker payload construction을 공유하도록 했습니다. 이 rules가 plugin entrypoint에 중복으로 남지 않습니다.
- Config tab의 one-click CLI setup actions를 수정해 client command를 non-blocking process path로 실행하고 panel 안에 즉시 status를 표시하도록 했습니다. command exit까지 editor가 멈춘 것처럼 보이는 문제를 피합니다.
- Config tab의 직접 config write / remove actions를 수정해 file preflight와 writeback이 panel의 visible running state 진입 후 시작되도록 했습니다. 느린 config path에서 클릭 뒤 멈춘 것처럼 보이는 상황을 피합니다.
- Dock Tools tab의 first-open responsiveness를 수정해 처음에는 active tool presentation view만 만들고 Internal Executors / Diagnostics trees는 해당 view를 선택할 때까지 지연합니다.
- Dock Tools tab의 반복 refresh를 수정해 tool catalog가 바뀌지 않았을 때는 lightweight catalog revision으로 이전 presentation model을 재사용하고, active tab refresh마다 full tool snapshot을 다시 만들지 않도록 했습니다.
- Dock Tools tab의 search responsiveness를 수정해 같은 frame 안의 연속 query 변경을 deferred tree render 1회로 합치고, keystroke마다 catalog를 clear / rebuild하지 않도록 했습니다.
- Dock Tools tab refresh signatures를 수정해 disabled-tool lists, collapsed nodes, tool-load errors를 tab switch 중 JSON serialize하지 않고 deterministic lightweight strings로 비교하도록 했습니다.
- Dock status snapshots를 수정해 lightweight views는 cached lifecycle context를 재사용하고 active tab이 명시적으로 필요로 할 때만 heavy server diagnostics를 호출합니다.
- update 또는 hot reload 뒤 MCP tool discovery recovery를 수정해 `tools/list` / `tools/call`이 빈 tool registry를 lazy initialize하고, 겹치는 editor automation call은 `editor_automation_busy`로 빠르게 실패하며, idle GDScript LSP tick log spam 때문에 editor나 MCP client가 멈춘 것처럼 보이는 상황을 피합니다.
- idle runtime tick을 수정해 HTTP / stdio transports가 loaded tool executors와 GDScript LSP diagnostics를 editor frame마다 구동하지 않도록 했습니다. lifecycle tick timing도 performance diagnostics에 공개됩니다.
- 장시간 실행 안정성 문제를 수정했습니다. User-tool definitions는 explicit invalidation 뒤에만 refresh하고, partial idle HTTP requests는 timeout window 뒤에 닫으며, 중지된 debugger sessions는 bridge live map에서 즉시 제거합니다.
- plugin disable lifecycle cleanup을 수정해 plugin disable 시 runtime-owned services, watcher polling, client dialogs, debugger hooks, performance monitors, static self-diagnostic state를 해제하면서 runtime bridge autoload는 유지합니다.
- User-tool runtime definition comparison을 수정해 idle runtime checks에서 full definitions를 JSON signature로 serialize하지 않고 nested schema, presentation, icon metadata를 직접 비교하도록 했습니다.
- runtime automation budget validation을 수정해 과도한 frame captures, wait-frame counts, input batches, held input durations를 editor가 과도한 runtime work를 기다리기 전에 거부하도록 했습니다.

## [1.3.0] - 2026-06-08

### Added

- v1.3.0 semantic editor automation model을 추가했습니다. editor UI guidance는 semantic workflow를 먼저 사용하고, control-level focus/text/value/popup action을 다음으로 사용하며, control-local mouse / pointer event는 fallback으로만 사용하도록 합니다.
- `system_editor_control(action="wait_for_ui")`를 추가했습니다. client는 automation workflow를 계속하기 전에 실제 editor control을 존재, 표시 상태, text, enabled / disabled state로 기다릴 수 있습니다.
- `system_editor_control(action="get_popup")`와 `system_editor_control(action="capture_popup")`를 추가했습니다. 반환된 popup path로 표시 중인 floating editor popup / window를 inspect / crop할 수 있습니다.
- `system_editor_control`과 low-level `ui_control` click action에 click fallback observation evidence를 추가했습니다. dispatch된 input event, Button-like target의 click 전후 state, 관측된 control signal, activation evidence가 없을 때의 hint를 반환합니다.
- `system_editor_evidence`를 추가했습니다. editor, control, popup, active-dialog, automatic surface를 위한 high-level visual evidence workflow이며 target, fallback, degradation, visible-popup, capture-policy metadata를 명시합니다.
- `system_settings_dialog`를 추가했습니다. Project Settings / Editor Settings에 대해 open/status/search/navigation, tab/category focus, row model, row resolution, value read/focus/set/verify, surface capture, close, trusted `run_task` orchestration을 제공합니다.
- `system_inspector`를 추가했습니다. Inspector visible property model, unique property resolution, typed value read, value focus, guarded text/number/bool write, verification, capture, current/prepared target용 trusted property task를 제공합니다.
- `system_project_lifecycle(action=start|stop)`을 표준 project runtime session lifecycle entry로 추가했습니다. marker validation, auto-stop, stop control, foreground-window fallback metadata, runtime capability context를 포함합니다.
- `system_tool_catalog`을 추가했습니다. client는 공개 tool을 query, category, domain으로 검색하고 match reason, action, parameter, visibility, enabled state, optional schema를 확인할 수 있습니다.
- `system_tool_activity` query filter와 slow/failure diagnostics를 추가했습니다. client는 state, tool, slow-call threshold로 running / recent call을 확인할 수 있습니다.
- User tool naming diagnostics를 추가했습니다. User tool listing, scaffold preview, compatibility report에서 declared name, normalized name, public MCP tool name을 표시합니다.
- `system_scene_inspect`를 추가했습니다. `validate`, `analyze`, `full` action을 가진 unified read-only scene inspection entry이며 기존 scene validation / analysis tool도 유지합니다.
- `system_plugin_maintenance`를 추가했습니다. status, reload, update-status, update-reference refresh, update-source selection, update-start workflow를 묶는 canonical high-level plugin maintenance entry입니다.
- project configuration inspection을 추가해 export preset과 개별 input action을 읽을 수 있게 했습니다. sensitive export option key와 local absolute export path는 redact합니다.
- MCP resource와 resource template metadata를 지역화해 `resources/list`와 `resources/templates/list`가 hard-coded English 대신 현재 plugin language를 따르도록 했습니다.
- v1.4 canonical MCP resources를 추가해 guide discovery, project / editor state, activity status / recent read, exposed / visible tool catalog를 다루도록 했습니다. 기존 compatibility resource URI는 유지합니다.
- Config client card를 위한 안정적인 capability matrix를 추가해 support level, 사용 가능한 action metadata, note key를 포함했습니다.
- 모든 `tools/call` result에 `structuredContent`를 추가하고 기존 client용 text JSON content도 유지했습니다.

- `system_settings_dialog(action="capture")`를 변경해 visible settings popup / window bounds, dialog control bounds, full-editor screenshot 순서로 evidence를 가져오고 `capture_backend`와 `capture_target_path` metadata를 반환하도록 했습니다.

- 플러그인 재시작과 Dock 재생성 흐름을 고쳐, 재시작 뒤 설정을 더 안정적으로 유지하고, Dock model을 갱신하며, 진단 상태를 표시하게 했습니다.
- 런타임 서비스 종료와 포트 재사용 문제를 고쳐, 재시작 뒤 포트가 여전히 점유된 것처럼 보여 서비스 시작이 실패할 가능성을 낮췄습니다.
- `system_project_run`의 timeout 처리를 고쳐, 필요하면 오래 실행되는 장면을 자동으로 중지할 수 있게 했습니다.
- 도구 계층 재편 뒤 GDScript 진단과 스크립트 편집 보조 경로 접근 문제를 고쳤습니다.
- 사용자 도구의 추가, 수정, 삭제, 복원, 마지막 User 도구 삭제 뒤 정리 흐름을 고쳐, 도구 페이지가 Godot를 다시 시작하지 않아도 올바른 상태로 돌아오게 했습니다.
- 도구 메타데이터, 분류, 목록, 표시 정보 불일치를 고쳐, 도구 페이지와 MCP 도구 목록이 맞게 했습니다.
- headless 검증과 계약 테스트의 여러 빈틈을 고쳐, CI가 더 많은 플러그인 런타임, UI 표시, 도구 executor 동작을 덮도록 했습니다.

## [0.5.0] - 2026-03-19

### Added

- 비동기 GDScript 진단을 추가했습니다. `intelligence_script_analyze(include_diagnostics=true)`는 먼저 스크립트 구조를 돌려주고, 디스크에 저장된 파일을 바탕으로 백그라운드에서 `diagnostics`를 채우며, 첫 호출은 `pending`을 돌려줄 수 있습니다.
- 런타임 건강 요약과 자세한 자체 점검을 계층화했습니다.
  - `plugin_runtime_state(action=get_lsp_diagnostics_status)`는 유일한 상세 LSP 자체 점검 진입점으로, `loader / service / client`를 돌려줍니다.
  - `intelligence_project_state(include_runtime_health=true)`는 가벼운 `lsp_diagnostics` 건강 요약을 돌려줍니다.
- `stdio` 전송 계층(`plugin/runtime/mcp_stdio_server.gd`)을 추가해, 표준 `Content-Length` frame의 stdin/stdout MCP 채널을 지원하게 했습니다.
- 구조화 편집 능력을 확장했습니다.
  - `intelligence_scene_patch`에 `rename_node`, `update_property`를 추가
  - `intelligence_script_patch`에 `replace_method_body`, `delete_member`, `rename_member`를 추가
  - `intelligence_runtime_diagnose`에 `include_gd_errors`를 추가

### Changed

- `intelligence_script_analyze(include_diagnostics=true)`를 "구조 먼저 반환, 진단 나중 보강" 방식으로 바꿔, `publishDiagnostics`를 기다리느라 멈추지 않게 했습니다.
- `/api/tools`, MCP `tools/list`, Dock Tools를 모두 같은 visible tool set으로 만들었습니다. 호환 별칭은 여전히 호출할 수 있지만, 더 이상 주 표시 진입점은 아닙니다.
- GDScript LSP diagnostics 서비스는 이제 `tool_loader`가 일괄 소유하고, `reload_domain`, `reload_all_domains`, `soft_reload_plugin`을 거치며 생명주기를 맡아 오래된 인스턴스가 남지 않게 했습니다.
- 런타임 설명과 외부 문서를 `plugin_runtime_state`, `intelligence_project_state`, 현재 라우팅 동작을 중심으로 정리했습니다.

### Fixed

- `soft_reload_plugin`에서 가끔 "HTTP 서비스는 살아 있는데 도구 registry가 비어 있는" 문제가 생기던 것을 고쳤습니다. 이제 server/controller와 tool loader를 함께 다시 만들고, `/health`, `/api/tools`, `tools/call`이 서로 맞게 합니다.
- Tools tree가 재귀적으로 펼치고 접은 뒤 상태가 꼬이던 문제를 고쳤습니다. 루트 노드와 `atomic` 계층이 이제 통합 상태 모델에 따라 올바르게 복원되며, 계속 튀지 않습니다.

## [0.4.0] - 2026-03-17

### Added

- Intelligence 도구 계층을 추가해, 프로젝트 단위 추론과 조작을 위한 15개의 상위 도구를 네 분류로 제공했습니다.
  - **Project 6개**: `intelligence_project_state`, `intelligence_project_advise`, `intelligence_project_configure`, `intelligence_project_run`, `intelligence_project_stop`, `intelligence_runtime_diagnose`
  - **Scene 3개**: `intelligence_scene_validate`, `intelligence_scene_analyze`, `intelligence_scene_patch`
  - **Script 3개**: `intelligence_bindings_audit`, `intelligence_script_analyze`, `intelligence_script_patch`
  - **Index 3개**: `intelligence_project_index_build`, `intelligence_project_symbol_search`, `intelligence_scene_dependency_graph`
- Intelligence 도구와 하위 atomic 도구를 잇는 Atomic Bridge dispatch 계층을 추가했습니다.
- 사용자 정의 도구 통합을 추가했습니다. `custom_tools/` 아래 도구는 `user_*` 접두사를 쓰고, `handles()`, `get_tools()`, `execute()`를 구현해야 합니다.
- 플러그인 디렉터리 쓰기 보호(`PLUGIN_PROTECTED_PATHS`)를 추가해, 플러그인 자체 파일이 허가 없이 수정되지 않게 했습니다.
- 9개 언어의 Intelligence 문서 현지화를 추가했습니다. de/en/es/fr/ja/pt/ru/zh_cn/zh_tw입니다.

### Changed

- `Tools` 페이지 트리 구조를 다시 짜서, 최상위에 Intelligence 도구가 바로 보이고, 각 도구를 펼치면 의존하는 atomic tool chain을 볼 수 있으며, atomic tool도 다시 펼쳐 Action 노드까지 갈 수 있게 했습니다.
- `Shift` 재귀 펼침과 접기, 오른쪽 클릭 메뉴(도구 이름 복사, Schema 복사, 사용자 도구 삭제)를 추가했습니다.
- `MCPDebugBuffer` 로그 시스템을 다시 만들고, source 이름을 통일하고, 로그 수준(`trace/debug/info/warning/error`)을 늘리고, `tool_loader`, `intelligence`, `atomic_bridge`, `impl_*`의 주요 로그 지점을 채웠습니다.
- 저장소 디렉터리를 Godot Asset Library 규격의 `addons/godot_dotnet_mcp/` 배치로 재구성하고, 배포 ZIP 내용 제어용 `.gitattributes`를 추가했습니다.

### Removed

- `Tools` 페이지의 Profile preset 관리 UI를 제거했습니다. Profile 관리는 이제 `plugin_developer_*` 도구 모음에서 MCP를 통해 처리합니다.
- `Tools` 페이지의 사용자 도구 관리 UI를 잠시 제거했습니다. 사용자 도구 생성, 삭제, 복원은 현재 `plugin_evolution_*` 도구 모음으로 통합되며, 이후 버전에서 별도 UI가 돌아올 수 있습니다.

### Fixed

- `array` 타입 매개변수에 `items` 정의가 없을 때 발생하던 여러 MCP 도구의 `Invalid schema` 오류를 고쳤습니다. `node_call`, `undo_redo`, `group`, `signal`, `collision_shape` 같은 도구가 대상이었습니다.
- `editor_status`와 `node_transform`이 잘못된 매개변수 타입에 너무 느슨하게 반응하던 문제를 고쳐 입력 검증을 더 튼튼하게 했습니다.

## [0.3.0] - 2026-03-12

### Added

- Godot .NET / C# 작업 흐름 지원을 추가했습니다. `.csproj` 해석, 템플릿화 C# 스크립트 쓰기, 교차 파일 스크립트 참조 인덱스, `dotnet restore/build` 기반 구조화 진단을 포함합니다.
- 런타임과 플러그인 자체 점검 능력을 추가해, 런타임 오류 맥락, 컴파일 오류 위치, 플러그인 자체 점검 요약, 오류 타임라인, 건강 조회를 덮었습니다.
- 사용자 도구 관리 능력을 추가해, scaffold 버전과 호환성 점검, 감사 필터와 세션 식별자, 삭제 전 백업과 최근 복원 진입점을 다뤘습니다.
- 도구 사용 통계를 추가해 호출 횟수와 최근 호출 시간을 볼 수 있게 했습니다.
- 도구 설정 import/export를 추가해 profile과 disabled tools를 JSON으로 왕복할 수 있게 했습니다.
- 플러그인 구조, UI, 컴포넌트, 부록을 아우르는 완전한 기술 문서 체계를 추가했습니다.

### Changed

- Dock의 플러그인 자체 점검 요약을 `Server` 페이지 상단으로 모아, 페이지 사이의 중복 정보를 줄였습니다.
- `Tools` 페이지의 트리 상호작용과 정보 계층을 다시 짜서, 검색, tooltip, 상태 표시, 미리보기 패널, 분할선 드래그, profile 작업 흐름을 정리했습니다.
- 새로 생긴 분류, 도구 설명, 팁의 현지화 리소스를 보강했습니다.
- 공개 버전 번호를 `0.3.0`으로 올리고, 플러그인 메타데이터와 런타임 버전 문자열도 함께 맞췄습니다.

### Fixed

- 호환 executor 집계 때문에 중복 플러그인 등록되던 문제를 고쳐, `plugin_runtime`, `plugin_evolution`, `plugin_developer`의 세 독립 진입점을 유지했습니다.
- 상속 스크립트 hot reload가 불완전해 도구 도메인 로드가 빠지던 문제를 고쳐, `script` 도메인과 확장 도구의 안정적 발견을 되돌렸습니다.
- 플러그인 시작과 중지, 런타임 재로딩 중 HTTP 전송이 끊기던 문제를 고쳐, soft reload를 지연 예약으로 바꿨습니다.

## [0.2.0] - 2026-03-11

### Added

- 메인 프로젝트의 런타임 읽기 기능을 추가해, `debug_runtime_bridge`로 Godot 편집기 시작과 중지 뒤의 디버그 세션 상태를 추적할 수 있게 했습니다.
- 런타임 제어, 자동화 도구 관리, 개발자 진입점, 사용 안내를 포함한 더 완전한 플러그인 거버넌스 계층을 추가했습니다.
- 안정 사용, 자동화 확장, 개발 디버그 능력을 구분하는 플러그인 권한 수준과 승인 경계를 추가했습니다.
- `User` 분류 관리 지원을 추가해 사용자 측 확장 도구를 찾고, 감사하고, 정리하기 쉽게 했습니다.

### Changed

- 도구 그룹과 플러그인 분류를 다시 정리해, 하나의 도구 진입점이 너무 많은 동작을 노출하지 않게 하고, 발견성을 높였습니다.
- Dock UI와 문서를 단순화해, 좁은 폭에서 `Server`, `Config`, `Tools`가 더 잘 쓰이도록 했습니다.
- 더 많은 분류, 도구 설명, 팁의 다국어 내용을 보강해 번역되지 않은 표식을 줄였습니다.
- `README`, 중국어 README, 릴리스 문서를 맞춰, 처음 연결, 설치, 설정 흐름이 일관되게 했습니다.

### Fixed

- `Tools` 페이지가 접히고 다시 만들어질 때 생기던 `Tree blocked` / 빈 인스턴스 오류를 고쳐, Dock 사용 중 끊김과 연쇄 오류를 줄였습니다.

### Known Limitations

- 현재 런타임 읽기는 구조화된 상태와 생명주기 정보를 읽는 데 더 적합하고, Godot 원래 Output / Debugger 패널을 완전히 비추는 용도는 아닙니다.
- 프로젝트 안에 이미 같은 이름의 `MCPRuntimeBridge` Autoload가 있으면, 플러그인은 그 설정을 강제로 덮지 않으며 관련 런타임 읽기는 미설치로 보일 수 있습니다.
