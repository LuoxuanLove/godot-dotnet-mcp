# Godot.NET MCP 문서 개요

이 문서 집합은 `addons/godot_dotnet_mcp`의 전체 기술 구현을 설명하며, 다음을 함께 다룹니다.

- 플러그인 진입점, 생명주기, 런타임 서비스와 프로토콜 라우팅
- 플러그인과 Host가 공유하는 protocol / version facts 원본
- Dock UI scene, tab script, layout, data flow
- 도구 시스템, 도구 영역 분리, system layer, 설정 지속화, 로컬라이제이션, 사용자 확장 기능
- 테스트 모듈, 플러그인 headless harness, CI guardrail
- 디렉터리 트리, 핵심 파일 책임, 일반적인 지속화 형식

기본 독자는 세 부류입니다.

- Godot 에디터 안에서 플러그인을 접속하고 사용하는 사람
- `plugin.gd`, `plugin/runtime/*`, `ui/*`, `tools/*`를 계속 유지보수하는 개발자
- 테스트, smoke, CI guardrail, 회귀면을 유지하는 협업자
- 디렉터리 구조, 파일 책임, 장애 처리 진입점을 빠르게 이해하려는 협업자

## 일반 작업 흐름

### 1. 로컬 MCP 서비스 시작

1. Godot 에디터에서 플러그인을 활성화합니다.
2. `MCPDock > Home`을 엽니다.
3. 포트, 자동 시작, 로그 레벨, 언어를 확인합니다.
4. “시작”을 누르거나 자동 시작을 유지합니다.
5. `http://127.0.0.1:3000/mcp` 또는 현재 포트에 맞는 주소로 클라이언트를 연결합니다.

자세한 내용은 [아키텍처/설정과 인터페이스.md](아키텍처/설정과-사용자-인터페이스.md), [인터페이스/Server 및 Config 페이지 구현.md](인터페이스/서버와-설정-페이지-구현.md), [아키텍처/런타임 서비스.md](아키텍처/런타임-서비스.md)를 참조하세요.

### 2. 도구 노출 범위와 preset 조정

1. `MCPDock > Tools`를 엽니다.
2. 내장 profile 또는 사용자 정의 profile을 선택합니다.
3. `domain -> category -> tool` 3단계 트리 구조로 도구를 켜고 끕니다.
4. 활성화된 수가 바뀌는지 보고 `disabled_tools`와 현재 preset이 일치하는지 확인합니다.
5. 현재 도구 집합을 공유하거나 재현하려면 import/export 설정을 사용합니다.

자세한 내용은 [인터페이스/Tools 페이지 구현.md](인터페이스/도구-페이지-구현.md), [모듈/도구 시스템.md](모듈/도구-시스템.md), [부록/설정과 지속화.md](부록/설정과-지속화.md)를 참조하세요.

### 3. 클라이언트 연결 설정 보기와 쓰기

1. `MCPDock > Config`를 엽니다.
2. 대상 클라이언트 플랫폼을 선택합니다.
3. 현재 서비스 주소, 생성 텍스트, 대상 경로를 확인합니다.
4. 로컬에 기록하려면 “쓰기”를, 수동으로 처리하려면 “복사”를 사용합니다.

자세한 내용은 [인터페이스/Server 및 Config 페이지 구현.md](인터페이스/서버와-설정-페이지-구현.md), [아키텍처/설정과 인터페이스.md](아키텍처/설정과-사용자-인터페이스.md), [부록/설정과 지속화.md](부록/설정과-지속화.md)를 참조하세요.

### 4. C# export 바인딩과 씬 문제 추적

1. `script_inspect` 또는 `script_exports`로 스크립트 export 멤버를 읽습니다.
2. `scene_bindings`로 현재 씬 또는 지정 씬의 바인딩을 분석합니다.
3. `scene_audit`로 구조화된 문제 목록을 얻습니다.
4. 필요하면 `node_query`, `scene_hierarchy`, `script_references`로 노드 경로와 스크립트 참조를 역추적합니다.

자세한 내용은 [모듈/스크립트와 씬 분석.md](모듈/스크립트와-씬-분석.md), [모듈/NET 지원.md](모듈/닷넷-지원.md), [모듈/도구 영역 인덱스.md](모듈/도구-도메인-색인.md)를 참조하세요.

### 5. User 도구와 감사 관리

1. `plugin_evolution_list_user_tools`로 현재 User 도구를 봅니다.
2. `plugin_evolution_scaffold_user_tool`로 미승인 사전 배치를 실행합니다.
3. 결과를 확인한 뒤 `authorized=true`로 생성합니다.
4. `plugin_evolution_user_tool_audit`로 인증 및 삭제 기록을 검사합니다.
5. Dock에서 `User` 카테고리를 보이게 하려면 `plugin_developer_user_visibility`를 함께 사용합니다.

자세한 내용은 [모듈/사용자 확장.md](모듈/사용자-확장.md), [모듈/핵심 구현.md](모듈/핵심-구현.md), [모듈/도구 영역 인덱스.md](모듈/도구-도메인-색인.md)를 참조하세요.

### 6. 테스트 매트릭스와 회귀 검증 실행

1. `tests/godot_plugin_harness`로 plugin headless harness를 실행합니다.
2. 환경 의존성 문제를 추적해야 할 때는 real Godot headless 경로를 추가로 실행합니다.

자세한 내용은 [테스트/개요.md](테스트/개요.md), [테스트/플러그인 Headless 테스트.md](테스트/플러그인-헤드리스-테스트.md), [테스트/Smoke와 CI.md](테스트/스모크-테스트와-지속적-통합.md)를 참조하세요.

## 문서 유지 규칙

- 문서는 기본적으로 `dev`에 병합된 최신 구현을 기준으로 하며, 더 이상 사용하지 않는 동적 Dock 서술은 남기지 않습니다.
- 도구 반환 필드, 설정 키 이름, profile 파일 형식, 클라이언트 설정 템플릿, 권한 경계를 바꾸면 대응되는 절을 반드시 갱신해야 합니다.
